# Урок 00.5 — Установка Rust и RustRover

> **Этап 00 — Начало пути** · Урок 5 из 8 · ⏱ около 105 минут

## Что вы узнаете

- Какие инструменты нужны и что делает каждый: `rustup`, `rustc`, Cargo, Clippy, `rustfmt`, RustRover и Git.
- Как установить тулчейн Rust на Mac с чипом Apple silicon и как проверить, что он работает.
- Что такое релизные каналы stable, beta и nightly и что такое «редакция» (edition).
- Как установить и настроить IDE RustRover.
- Как исправить три самые частые проблемы при установке.

## Перед началом

- Вы прошли [Урок 00.4 — Терминал: первые команды](04-terminal-basics.md). Вы умеете открывать терминал, запускать команду и читать `command not found`.
- У вас есть подключение к интернету и около 5 ГБ свободного места на диске.
- Rust уже установлен? Не переустанавливайте: просто выполните проверки из раздела 3 и сравните.

## Новые слова

| Слово | Значение |
|---|---|
| **тулчейн** (toolchain) | Набор программ, нужных для сборки кода на Rust: компилятор, стандартная библиотека и помощники. |
| **rustup** | Установщик и обновлятор тулчейнов Rust. Вы устанавливаете его один раз, дальше он управляет всем остальным. |
| **rustc** | Компилятор Rust (Урок 00.3). Превращает один исходный файл в исполняемый файл. |
| **Cargo** | Инструмент сборки и менеджер пакетов Rust. Создаёт проекты, сам запускает компилятор, скачивает библиотеки и запускает тесты. Вы будете пользоваться им постоянно. |
| **Clippy** | «Линтер» для Rust: программа, которая читает ваш код и даёт советы об ошибках и плохом стиле. Запускается командой `cargo clippy`. |
| **rustfmt** | Инструмент, который форматирует ваш код в стандартном стиле Rust. Запускается командой `cargo fmt`. |
| **релизный канал** (release channel) | Один из трёх видов релизов Rust: **stable**, **beta** и **nightly**. |
| **редакция** (edition) | Именованная версия правил языка, например 2021 или 2024. Новые проекты используют самую новую редакцию. |
| **целевая тройка** (target triple) | Название платформы вида `cpu-vendor-os`, например `aarch64-apple-darwin`. |
| **компоновщик** (linker) | Программа, которая объединяет части, созданные компилятором, в один исполняемый файл. |
| **Xcode Command Line Tools** | Пакет от Apple с компилятором C, компоновщиком, `git` и другими инструментами разработчика. Rust на macOS нужен его компоновщик. |
| **IDE** (Integrated Development Environment, интегрированная среда разработки) | Программа для написания кода: редактор, кнопки запуска, подсветка ошибок и многое другое. Мы используем **RustRover**. |
| **Git** | Инструмент контроля версий из Этапа 01. Здесь мы лишь проверяем, что он установлен. |
| **Homebrew** | Популярный менеджер пакетов для macOS: команда `brew` для установки инструментов разработчика. Пока необязателен. |
| **URL** (Uniform Resource Locator, унифицированный указатель ресурса) | Веб-адрес, например `https://rustup.rs`. |
| **CPU** (Central Processing Unit, центральный процессор) | Микросхема-процессор, которая выполняет инструкции (Урок 00.3). |
| **ОС** (OS, Operating System, операционная система) | Главная программа компьютера, которая запускает другие программы; здесь macOS (Урок 00.3). |
| **PATH** | Список директорий, где оболочка ищет команды (Урок 00.4). |
| **HTTPS** (HyperText Transfer Protocol Secure, защищённый протокол передачи гипертекста) | Веб-протокол с шифрованием. Адреса, которые его используют, начинаются с `https://`. |
| **VPN** (Virtual Private Network, виртуальная частная сеть) | Сервис, который пропускает ваш интернет-трафик через другой сервер. Иногда он блокирует загрузки. |
| **LLVM** | Движок генерации кода внутри компилятора Rust. (Название когда-то было сокращением от «Low Level Virtual Machine».) |
| **ARM** | Название семейства проектов CPU. 64-битная форма называется arm64 или AArch64. |
| **ПК** (PC, Personal Computer, персональный компьютер) | Обычный настольный компьютер или ноутбук, например ПК с Windows. |
| **ГБ** (GB, gigabyte, гигабайт) | Около миллиарда байтов, единица размера для памяти и дисков. |

## 1. Что мы будем устанавливать

| Инструмент | Что это | Откуда берётся |
|---|---|---|
| Command Line Tools | компилятор C, компоновщик, `git` | Apple (`xcode-select --install`) |
| `rustup` | менеджер тулчейнов | официальный сайт rustup.rs |
| `rustc`, `cargo`, `clippy`, `rustfmt`, офлайн-документация | тулчейн | устанавливаются через `rustup` |
| RustRover | IDE | JetBrains |

Порядок важен: сначала инструменты Apple, затем Rust, затем IDE.

## 2. Шаг 1 — Command Line Tools от Apple

На Mac Rust использует компоновщик Apple, чтобы получить итоговый исполняемый файл. Проверьте, есть ли у вас уже
эти инструменты. В терминале выполните:

```text
% xcode-select -p
/Applications/Xcode.app/Contents/Developer
```

Если вы видите путь (либо `/Applications/Xcode.app/Contents/Developer`, либо
`/Library/Developer/CommandLineTools`), всё готово. Если видите ошибку вроде
`xcode-select: error: unable to get active developer directory`, установите инструменты:

```text
% xcode-select --install
```

Откроется окно. Нажмите **Установить** и согласитесь с лицензией. Загрузка может занять несколько минут. Затем
снова выполните `xcode-select -p`. Ещё одна проверка, которая заодно подтверждает наличие компилятора C:

```text
% cc --version
Apple clang version 21.0.0 (clang-2100.4.1.1)
Target: arm64-apple-darwin27.2.0
Thread model: posix
```

(Номера версий у вас будут другими. Важно слово `arm64`.)

## 3. Шаг 2 — Установка Rust через rustup

Откройте официальную страницу [rust-lang.org/tools/install](https://www.rust-lang.org/tools/install) и скопируйте
команду для macOS. На момент написания она такая:

```text
% curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh
```

Что происходит:

1. `curl` скачивает что-то из интернета. `--proto '=https' --tlsv1.2` означает «разрешить только защищённое соединение (HTTPS)». `-sSf` означает: молчать (`-s`), но показывать ошибки (`-S`) и считать ошибку сервера неудачей (`-f`).
2. Адрес `https://sh.rustup.rs` — **официальный**: это скрипт, который устанавливает `rustup`.
3. `|` (конвейер из Урока 00.4) отправляет скачанный скрипт в `sh`, который его выполняет.

> 🔒 **Безопасность:** запуск скрипта прямо из интернета безопасен, только если вы доверяете источнику
> *и* адресу. Проверьте три вещи, прежде чем нажать Enter: страница — официальный сайт
> `rust-lang.org`, адрес в команде в точности `https://sh.rustup.rs`, и вы набрали или
> скопировали его с этой страницы (а не из письма или сообщения в чате). Если хотите, сначала можете открыть
> `https://sh.rustup.rs` в браузере и прочитать скрипт.

Установщик печатает приветственный текст и показывает, что собирается делать: куда пойдут файлы, какой
тулчейн он установит (по умолчанию `stable`) и что он изменит ваш `PATH`. Затем он показывает
меню:

```text
1) Proceed with standard installation (default - just press enter)
2) Customize installation
3) Cancel installation
```

Нажмите **Enter** для стандартной установки. (Точные формулировки установщика могут немного меняться
между версиями; на своём компьютере, где Rust уже есть, я его повторно не запускал.) Он скачивает несколько
сотен мегабайт. В конце печатает строку вроде `Rust is installed now. Great!`.

Что установщик сделал на вашем компьютере:

- Создал `~/.rustup`: тулчейны (компилятор и стандартную библиотеку).
- Создал `~/.cargo`: инструменты, которые вы устанавливаете, и `~/.cargo/bin`, где лежат программы `rustc`, `cargo`, `rustup`, `rustfmt` и другие.
- Добавил строку `. "$HOME/.cargo/env"` в стартовый файл вашей оболочки (для zsh это `~/.zshenv`). Эта строка добавляет `~/.cargo/bin` в ваш `PATH` (список из Урока 00.4) при каждом открытии терминала.

**Теперь закройте вкладку терминала и откройте новую.** Старое окно не знает о новом
`PATH`. (Если закрывать не хочется, выполните один раз `source "$HOME/.cargo/env"`.)

### Проверьте, что всё работает

```text
% rustc --version
rustc 1.100.0 (0ef1bc386 2026-11-09)
% cargo --version
cargo 1.100.0 (3acc79c0c 2026-11-05)
% rustup --version
rustup 1.29.3 (edbc831ce 2026-11-02)
info: This is the version for the rustup toolchain manager, not the rustc compiler.
info: the currently active `rustc` version is `rustc 1.100.0 (0ef1bc386 2026-11-09)`
```

Ваши номера версий могут быть новее. Если первое число у `rustc` меньше `1.100`, выполните
`rustup update` (см. ниже). Что означает версия `1.100.0`? Три числа: старшая
`1`, младшая `100`, патч `0`. Rust 1.0 появился в 2015 году; с тех пор новая младшая версия выходит каждые
шесть недель.

Где лежат программы? Спросите у `which`:

```text
% which rustc cargo rustup
/Users/student/.cargo/bin/rustc
/Users/student/.cargo/bin/cargo
/Users/student/.cargo/bin/rustup
```

Все три находятся в `~/.cargo/bin`. Это та самая директория, которую установщик добавил в `PATH`.

Теперь спросим у компилятора о нём самом, с опцией «подробная версия»:

```text
% rustc -vV
rustc 1.100.0 (0ef1bc386 2026-11-09)
binary: rustc
commit-hash: 0ef1bc386059596dada8fb65b50425aab2ea637a
commit-date: 2026-11-09
host: aarch64-apple-darwin
release: 1.100.0
LLVM version: 23.1.5
```

Строка `host: aarch64-apple-darwin` — это **целевая тройка** вашего компьютера: `aarch64` — семейство CPU
(arm64, как в Уроке 00.3), `apple` — производитель, `darwin` — ядро ОС macOS. **Там должно быть написано
`aarch64-apple-darwin`.** Если написано `x86_64-apple-darwin`, значит установщик запускали в Терминале,
работающем под Rosetta (слой эмуляции для программ Intel). Удалите Rust (раздел 6) и установите заново в обычном терминале.

Строка `LLVM version` называет движок под компилятором, который на самом деле генерирует машинный код
(`rustc` — передняя часть; LLVM — генератор кода). Сейчас больше знать не нужно.

### Тулчейны, компоненты и каналы

```text
% rustup show
Default host: aarch64-apple-darwin
rustup home:  /Users/student/.rustup

installed toolchains
--------------------
stable-aarch64-apple-darwin (active, default)

active toolchain
----------------
name: stable-aarch64-apple-darwin
active because: it's the default toolchain
installed targets:
  aarch64-apple-darwin
```

(На моём компьютере вывод ещё содержит дополнительные тулчейны и целевые платформы, которые я установил для другой
работы; я убрал эти строки. Свежая установка выглядит так.)

```text
% rustup component list --installed
cargo-aarch64-apple-darwin
clippy-aarch64-apple-darwin
rust-docs-aarch64-apple-darwin
rust-std-aarch64-apple-darwin
rustc-aarch64-apple-darwin
rustfmt-aarch64-apple-darwin
```

Что происходит:

1. `rustup show` перечисляет установленные **тулчейны**. Имя `stable-aarch64-apple-darwin` = канал `stable` + целевая тройка.
2. `rustup component list --installed` перечисляет **компоненты** внутри тулчейна. Вы видите компилятор (`rustc`), инструмент сборки (`cargo`), форматировщик (`rustfmt`), линтер (`clippy`), стандартную библиотеку (`rust-std`) и офлайн-документацию (`rust-docs`).

У Rust три **релизных канала**:

| Канал | Что это | Используете ли вы его? |
|---|---|---|
| **stable** | Проверенный релиз, выходит каждые 6 недель. | **Да, всегда, в этом курсе.** |
| **beta** | Следующий стабильный релиз, на тестировании. | Нет. |
| **nightly** | Сборка, которая делается каждую ночь, с экспериментальными возможностями. | Только в нескольких продвинутых уроках (Этап 06 и далее). |

Поддерживайте свежесть тулчейна. Раз в несколько недель выполняйте:

```text
% rustup update
```

Он скачивает самый новый стабильный тулчейн, если он есть, и заменяет старый. Это безопасно.

Наконец, **редакция**. Rust обещает, что старый код продолжит компилироваться, но иногда нужны новые, более чистые правила.
Их объединяют в *редакцию*: 2015, 2018, 2021 и 2024. Редакция выбирается для каждого
проекта в его файле `Cargo.toml`. Cargo создаёт новые проекты с самой новой редакцией, **2024**, и этот курс везде использует
2024. Строку `edition = "2024"` вы увидите в Уроке 00.6.

### Документация уже на вашем диске

`rust-docs` означает, что официальные книги и справочник стандартной библиотеки у вас **офлайн**:

```text
% rustup doc --path
/Users/student/.rustup/toolchains/stable-aarch64-apple-darwin/share/doc/rust/html/index.html
```

`rustup doc` открывает эту страницу в браузере. Другие полезные опции: `rustup doc --book` (книга по
Rust), `rustup doc --std` (стандартная библиотека), `rustup doc --cargo` (книга о Cargo),
`rustup doc --error-codes` (список кодов ошибок компилятора, пригодится в Уроке 00.7).

## 4. Шаг 3 — Установка RustRover

**RustRover** — это IDE от JetBrains, созданная специально для Rust. Она подсвечивает ошибки по мере набора, запускает и
отлаживает ваши программы одним щелчком, и в ней встроены терминал и панель Git. Согласно
[странице RustRover](https://www.jetbrains.com/rust/), она **бесплатна для некоммерческого использования** (например, для
обучения) и платная, если вы зарабатываете с её помощью; при скачивании проверьте актуальные условия на странице.

1. Откройте [jetbrains.com/rust/download](https://www.jetbrains.com/rust/download/) в браузере.
2. Выберите macOS и версию для **Apple Silicon** (для Intel и Apple silicon есть отдельные образы дисков). Скачайте файл `.dmg`.
3. Откройте скачанный `.dmg` и перетащите **RustRover** в **Программы** (Applications).
4. Запустите его из «Программ» (или нажмите `Cmd + Space` и введите «RustRover»). В первый раз macOS может спросить «вы уверены, что хотите открыть?»: подтвердите.
5. Примите пользовательское соглашение, выберите бесплатную некоммерческую лицензию (или войдите с учётной записью JetBrains).

(JetBrains также предлагает **Toolbox App**, который устанавливает и обновляет все их IDE. Он необязателен.)

### Первая настройка

RustRover сам умеет находить установленный вами Rust в `~/.cargo/bin`. Проверьте:

1. На приветственном экране выберите **Open**, выберите папку `~/projects/rust` и доверьте проект. (Папка открывается как проект; `Cargo.toml` в ней пока нет, и это нормально.)
2. Откройте настройки: меню **RustRover → Settings** (сочетание `Cmd + ,`). Названия страниц могут немного отличаться в разных версиях; пользуйтесь строкой поиска вверху окна настроек.
3. Перейдите в **Languages & Frameworks → Rust**. Поле **Toolchain location** должно показывать путь, оканчивающийся на `.cargo/bin`, а поле под ним — путь к стандартной библиотеке. Если оно пустое, нажмите кнопку с папкой и выберите `~/.cargo/bin`.
4. В тех же настройках Rust найдите страницу **Rustfmt** и включите **Run rustfmt on Save**. Теперь ваш код форматируется автоматически при каждом сохранении.
5. Найдите страницу **External Linters**, выберите **Clippy** и включите запуск «на лету». Теперь советы Clippy появляются прямо в редакторе.
6. Файлы Markdown (как этот урок) открываются в RustRover с предпросмотром. Откройте файл `.md` и кнопками в правом верхнем углу редактора переключайтесь между исходником и предпросмотром.
7. Встроенный терминал: меню **View → Tool Windows → Terminal** (сочетание `Option + F12`). Это тот же терминал, что в Уроке 00.4, уже открытый в папке проекта.

> 📏 **Соглашение:** форматируйте код при каждом сохранении и исправляйте предупреждения Clippy. В профессиональных командах на Rust
> это обязательно; код, который не проходит `cargo fmt --check` или `cargo clippy`, не принимают.

## 5. Шаг 4 — Проверьте Git

Git входит в Command Line Tools от Apple, так что он у вас, скорее всего, уже есть. Проверьте:

```text
% git --version
git version 2.54.0 (Apple Git-157)
```

(У вас может быть другая версия; любая свежая подойдёт.) **Git** — это инструмент, который хранит историю ваших
файлов, как объяснялось в Уроках 00.1 и 00.2. Этап 01 учит ему с нуля, включая настройку
вашего имени и адреса электронной почты. Сегодня достаточно убедиться, что команда существует.

Если вы видите `command not found: git`, вернитесь к разделу 2 и установите Command Line Tools.

> 💡 **Совет:** ещё один инструмент, который устанавливают многие разработчики, — **Homebrew** (`brew`), менеджер пакетов
> для macOS. На этом этапе он не нужен. Инструкции на [brew.sh](https://brew.sh/), а
> следующие этапы подскажут, когда инструмент проще поставить через него.

## 6. Когда что-то идёт не так

| Симптом | Причина | Исправление |
|---|---|---|
| `zsh: command not found: cargo` (или `rustc`) | Терминал открыт до установки, или `~/.cargo/bin` нет в `PATH`. | Закройте вкладку и откройте новую. Если не помогло: `source "$HOME/.cargo/env"`, затем `echo $PATH` и поищите `.cargo/bin`. Проверьте, что `ls ~/.cargo/bin` показывает `cargo`. |
| `error: linker 'cc' not found` при сборке | Нет Command Line Tools. | `xcode-select --install`, затем повторите. |
| `rustc -vV` показывает `host: x86_64-apple-darwin` | Rust установлен из Терминала, работающего под Rosetta. | Выполните `rustup self uninstall`, откройте обычный терминал, установите заново. |
| `curl: (6) Could not resolve host` или другие сетевые ошибки | Нет интернета, VPN или прокси блокирует загрузку. | Проверьте соединение, отключите VPN, повторите. |
| RustRover показывает «Cargo project not found» или красные строки `use` | IDE не знает тулчейн или проект. | Укажите тулчейн в настройках (раздел 4). Для проектов: щёлкните правой кнопкой по `Cargo.toml` и выберите **Attach Cargo Project** (Урок 00.6). |

Чтобы полностью удалить Rust (сейчас это не понадобится): `rustup self uninstall`.

## Частые ошибки

1. **Установка с случайного сайта.** Поисковики показывают поддельные страницы загрузки. *Исправление:* всегда начинайте с `rust-lang.org` или `rustup.rs`.
2. **Не перезапустили терминал.** Вы установили Rust, а старый терминал говорит `command not found: cargo`. *Исправление:* закройте вкладку, откройте новую.
3. **Использование `sudo` для установщика.** `rustup` устанавливается в вашу домашнюю директорию и не требует прав администратора. С `sudo` создаются файлы, принадлежащие администратору, и позже возникают ошибки доступа. *Исправление:* никогда не ставьте `sudo` перед `curl ... | sh` здесь.
4. **Установка Rust через Homebrew *и* через rustup.** Две копии спорят за имя `rustc`. *Исправление:* используйте только rustup; если вы установили одну через `brew`, выполните `brew uninstall rust`.
5. **Пропуск проверок.** Установка казалась успешной, но целевая платформа неверна или PATH неполон. *Исправление:* выполните проверки из раздела 3 и сравните вывод.

## Упражнения

### Упражнение 1 — Что где? (легко)

Ответьте по своему компьютеру: (a) полный путь программы `cargo`, (b) папка, где лежат
все тулчейны, (c) канал вашего активного тулчейна.

<details>
<summary>Подсказка</summary>

(a) `which`. (b) Установщик создал её в вашей домашней папке; `rustup show` печатает её как «rustup home». (c) Первая часть имени тулчейна.

</details>

<details>
<summary>Ответ</summary>

(a) `which cargo` → `/Users/<you>/.cargo/bin/cargo`.
(b) `rustup show` → `rustup home: /Users/<you>/.rustup` (тулчейны внутри, в `.rustup/toolchains`).
(c) Активный тулчейн — `stable-aarch64-apple-darwin`, значит, канал — `stable`.

Почему это работает: `rustup` хранит всё в двух папках в вашей домашней директории и кладёт команды в `~/.cargo/bin`.

</details>

### Упражнение 2 — Прочитайте тройку (легко)

Разбейте `aarch64-apple-darwin` на три части и скажите, что означает каждая. Затем объясните, почему программа, собранная
для этой тройки, не запустится на ПК с процессором Intel под управлением Windows.

<details>
<summary>Подсказка</summary>

Вспомните Урок 00.3: семейство CPU определяет машинный код.

</details>

<details>
<summary>Ответ</summary>

- `aarch64` — семейство CPU (64-битный ARM, то же, что arm64).
- `apple` — производитель.
- `darwin` — ядро операционной системы (macOS).

ПК с Windows и процессором Intel нужен машинный код x86-64 и формат исполняемого файла для Windows. Программа, собранная для этой тройки, содержит машинный код arm64 в формате Mach-O, поэтому её не сможет запустить ни CPU, ни ОС.

Почему это работает: машинный код специфичен для семейства CPU, а формат файла — для ОС.

</details>

### Упражнение 3 — Найдите код ошибки (средне)

Используя офлайн-документацию, найдите объяснение кода ошибки компилятора `E0425`. Затем
найдите то же объяснение в терминале.

<details>
<summary>Подсказка</summary>

`rustup doc --error-codes` открывает указатель. Для терминала есть опция `rustc`, которая начинается с `--explain`.

</details>

<details>
<summary>Ответ</summary>

Браузер: `rustup doc --error-codes`, затем найдите E0425 в списке. Терминал: `rustc --explain E0425`.

Текст начинается с: «An unresolved name was used.» Это значит: вы использовали имя (переменной или функции), которого не существует там, где вы его использовали.

Почему это работает: у каждой ошибки компилятора есть код, и документация для каждого кода поставляется вместе с тулчейном. Урок 00.7 широко это использует.

</details>

### Упражнение 4 — Смоделируйте отсутствующий PATH (сложно)

Используя то, что вы узнали в Уроке 00.4 (раздел 10), запустите чистую оболочку, у которой `PATH` содержит только
`/usr/bin:/bin`, и спросите у неё версию Rust. Затем запустите снова, добавив `~/.cargo/bin`. Объясните оба результата.

<details>
<summary>Подсказка</summary>

Используйте `env -i PATH=... /bin/zsh -f -c '...'`. Директория с `cargo` — это `$HOME/.cargo/bin`. Этой чистой оболочке нужно передать и `HOME`.

</details>

<details>
<summary>Ответ</summary>

```text
% env -i PATH=/usr/bin:/bin /bin/zsh -f -c 'cargo --version'
zsh:1: command not found: cargo
% env -i HOME=$HOME PATH=$HOME/.cargo/bin:/usr/bin:/bin /bin/zsh -f -c 'cargo --version'
cargo 1.100.0 (3acc79c0c 2026-11-05)
```

Почему это работает: в первой команде ни в одной директории из `PATH` нет файла `cargo`, поэтому оболочка говорит «command not found». Вторая добавляет `~/.cargo/bin`, и оболочка находит программу. То же самое происходит в терминале, открытом до того, как установщик изменил ваш стартовый файл. (`rustup` также нужен `HOME`, чтобы найти `~/.rustup`, поэтому мы его передаём.)

</details>

## Вопросы для самопроверки

1. В чём разница между `rustup`, `rustc` и `cargo`?

<details>
<summary>Ответ</summary>

`rustup` устанавливает и обновляет тулчейны. `rustc` — компилятор. `cargo` — инструмент сборки и менеджер пакетов, который сам вызывает `rustc`.

</details>

2. Какой релизный канал мы используем и как часто выходит его новая версия?

<details>
<summary>Ответ</summary>

`stable`. Новая стабильная версия выходит каждые 6 недель.

</details>

3. Что должна говорить строка `host` в `rustc -vV` на вашем Mac?

<details>
<summary>Ответ</summary>

`aarch64-apple-darwin`.

</details>

4. После установки Rust `cargo` «не найден» в старом терминале. Почему и что делать?

<details>
<summary>Ответ</summary>

Старый терминал запущен до того, как установщик добавил `~/.cargo/bin` в `PATH`. Закройте его и откройте новый (или выполните `source "$HOME/.cargo/env"`).

</details>

5. Что делают Clippy и rustfmt?

<details>
<summary>Ответ</summary>

Clippy даёт советы об ошибках и плохом стиле (`cargo clippy`). rustfmt форматирует код в стандартном стиле (`cargo fmt`).

</details>

6. Где доступна документация Rust офлайн и как её открыть?

<details>
<summary>Ответ</summary>

Она устанавливается вместе с тулчейном (компонент `rust-docs`). Выполните `rustup doc` (или `rustup doc --book`, `--std`, `--cargo`).

</details>

## Итоги

- Устанавливайте в таком порядке: Command Line Tools от Apple, Rust через `rustup`, затем RustRover.
- Официальный установщик Rust — одна команда с rust-lang.org; проверяйте адрес, прежде чем запускать скрипт из интернета.
- В `~/.cargo/bin` лежат `rustc`, `cargo` и `rustup`; он должен быть в `PATH`. После установки откройте новый терминал.
- Проверьте `rustc --version`, `cargo --version` и что `host` — это `aarch64-apple-darwin`.
- Мы используем канал `stable` и редакцию 2024; обновляйте командой `rustup update` раз в несколько недель.
- Книги и справочник стандартной библиотеки доступны офлайн: `rustup doc`.
- RustRover бесплатен для некоммерческого использования; включите rustfmt при сохранении и Clippy в его настройках.
- Git приходит с инструментами Apple; Этап 01 учит ему.
