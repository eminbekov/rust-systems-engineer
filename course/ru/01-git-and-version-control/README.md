# Этап 01 — Git и контроль версий

> **Стадия 1 — Фундамент: инструменты, Git и язык Rust** · ⏱ около 2–3 недель при ~10 часах в неделю

## О чём этот этап

Любая программа со временем меняется. Вы добавляете функцию, что-то ломаете, хотите вернуть вчерашнюю версию, или коллега изменяет тот же файл, что и вы. **Контроль версий** — это инструмент, который записывает каждое изменение, чтобы вы могли увидеть, что произошло, отменять ошибки и работать вместе, не затирая работу друг друга. **Git** — система контроля версий, которой пользуются почти все; сам проект Rust, Cargo и большинство библиотек Rust живут в репозиториях Git.

В этом этапе вы изучаете Git с нуля на своём Mac, в терминале. Вы начинаете с идеи истории снимков (коммитов), затем учитесь смотреть на неё, безопасно отменять ошибки и работать параллельно с помощью веток. Вы узнаёте, что делать, когда два изменения сталкиваются (конфликт слияния). Затем вы выходите во внешний мир: GitHub и GitLab, SSH-ключи (SSH — Secure Shell) и то, как работают настоящие команды с pull request, код-ревью и автоматическими проверками.

Почему сейчас, до языка Rust? Потому что с первого урока по Rust вы будете писать код, который хотите сохранить. Хорошая привычка, выработанная сегодня, — «маленькие коммиты в ветке, никогда не терять работу» — спасёт вас много раз. В конце этапа вы создадите настоящий учебный репозиторий для всего курса: с проектом на Rust, CI (Continuous Integration, автоматические проверки при каждом push) и релизом с тегом.

Предыдущие знания Git или программирования не нужны. Всё объясняется внутри уроков, и каждая команда была запущена, чтобы получить вывод, который вы видите.

## Что вы научитесь делать

- [ ] Объяснять, что такое контроль версий и почему Git, GitHub и GitLab — три разные вещи.
- [ ] Установить и настроить Git, задать личность, безопасные настройки по умолчанию и глобальный файл игнорирования.
- [ ] Создавать репозиторий, подготавливать и коммитить изменения с хорошими сообщениями и игнорировать файлы через `.gitignore` (в том числе для проекта Cargo).
- [ ] Читать историю и изменения командами `git log`, `git diff`, `git show`, `git blame` и `git bisect`.
- [ ] Безопасно отменять ошибки с помощью `restore`, `amend`, `reset`, `revert`, `stash` и `reflog`.
- [ ] Пользоваться ветками, сливать их и вручную решать конфликт слияния.
- [ ] Работать с удалённым репозиторием: clone, fetch, pull и push по SSH, и не пускать секреты в историю.
- [ ] Следовать командному процессу: pull request, код-ревью, rebase, Conventional Commits, теги SemVer и проверка CI для проекта на Rust.

## Проекты этого этапа

- **Репозитории для практики** (Уроки 3–9): небольшие одноразовые папки в `~/projects/git-playground`, где вы повторяете каждую команду.
- **`code/p01-git-practice`** (Урок 10): ваш первый библиотечный крейт Rust внутри учебного репозитория `~/projects/rust`, с тестами, решённым конфликтом, pull request с CI и релизом с тегом `v0.1.0`.
- **`notes/git-cheatsheet.md`** (Урок 10): ваша собственная шпаргалка по Git.

## Как изучать этот этап

1. **Вводите каждую команду сами.** Git учится пальцами. Не только читайте примеры; запускайте их в `~/projects/git-playground` и сравнивайте свой вывод с уроком (ваши хеши и даты будут другими).
2. **Всё время запускайте `git status`.** Он говорит, где вы находитесь и что делать дальше. Сделайте это рефлексом до и после любой другой команды.
3. **Ломайте всё намеренно в папках для практики.** Создайте конфликт, удалите ветку, сбросьте слишком далеко — а затем восстановитесь. Ошибки в одноразовой папке — самый дешёвый способ перестать бояться.
4. **Коммитьте мелко и часто,** даже в этих папках для практики. Считайте коммиты точками сохранения.
5. **Ведите короткую шпаргалку** команд, которыми вы действительно пользуетесь. Вы напишете её в итоговом проекте, поэтому начинайте собирать её уже во время этапа.
