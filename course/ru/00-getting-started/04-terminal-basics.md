# Урок 00.4 — Терминал: первые команды

> **Этап 00 — Начало пути** · Урок 4 из 8 · ⏱ около 2,5 часа (2 занятия)

## Что вы узнаете

- Что такое терминал, командная оболочка и команда и как читать части команды.
- Как организованы папки на вашем Mac и как перемещаться по ним с помощью путей.
- Основные команды: `pwd`, `ls`, `cd`, `mkdir`, `touch`, `echo`, `cat`, `cp`, `mv`, `rm`.
- Как получить справку, соединять команды конвейером и сохранять вывод в файл.
- Что такое `PATH` и права доступа к файлам и почему из-за них возникают знаменитые ошибки «command not found» и «permission denied».

## Перед началом

- Вы прошли [Урок 00.3 — Как компьютер выполняет программу](03-how-a-computer-runs-a-program.md).
- Откройте приложение «Терминал»: нажмите `Cmd + Space`, введите `Terminal` (или «Терминал»), нажмите Enter. Держите его открытым рядом с этим уроком.
- Всё в этом уроке безопасно: мы работаем внутри папки курса и создаём и удаляем только то, что создали сами.

## Новые слова

| Слово | Значение |
|---|---|
| **терминал** (terminal) | Окно, в котором вы набираете команды и видите текстовые ответы. |
| **командная оболочка** (shell) | Программа внутри терминала, которая читает вашу команду и выполняет её. В macOS оболочка по умолчанию — **zsh**. |
| **CLI** (Command-Line Interface, интерфейс командной строки) | Способ работать с программами, набирая команды. Противоположность **GUI** (Graphical User Interface, графический интерфейс), где вы щёлкаете окна и кнопки. |
| **приглашение** (prompt) | Короткий текст в начале строки (часто оканчивается на `%`), который говорит: «я жду вашу команду». |
| **команда** (command) | Слово, которое говорит оболочке, какую программу запустить, например `ls`. |
| **аргумент** (argument) | Дополнительная информация для команды, например имя папки. |
| **опция** (option, flag) | Переключатель, который меняет работу команды; пишется с дефисом: `-l`. |
| **директория** (directory, папка) | Контейнер для файлов и других директорий. |
| **путь** (path) | «Адрес» файла или директории, например `/Users/student/projects`. |
| **абсолютный путь** (absolute path) | Путь, который начинается с самого верха файловой системы, с `/`. |
| **относительный путь** (relative path) | Путь, который начинается от директории, где вы сейчас находитесь. |
| **домашняя директория** (home directory) | Ваша личная директория, пишется `~`. Здесь лежат ваши документы, загрузки и проекты. |
| **рабочая директория** (working directory) | Директория, в которой вы сейчас находитесь в терминале. Ещё называется текущей директорией. |
| **скрытый файл** (hidden file) | Файл, имя которого начинается с точки (например, `.gitignore`). `ls` не показывает его, пока вы не попросите. |
| **конвейер** (pipe) | Символ `\|`, который передаёт вывод одной команды на вход следующей. |
| **перенаправление** (redirect) | Символы `>` и `>>`, которые отправляют вывод команды в файл вместо экрана. |
| **переменная окружения** (environment variable) | Именованная настройка, которую может прочитать любая программа, запущенная из оболочки, например `HOME` или `PATH`. |
| **PATH** | Переменная окружения: список директорий, где оболочка ищет команды. |
| **права доступа** (permission) | Отметка на файле, которая говорит, кто может его читать, менять или запускать. |
| **скрипт** (script) | Текстовый файл с командами, которые оболочка может выполнить одну за другой. |

## 1. Что такое терминал

До сих пор вы пользовались своим Mac с помощью щелчков. Терминал — это другой способ: вы **набираете**, что
хотите, нажимаете Enter, и компьютер отвечает текстом. Это называется интерфейсом
командной строки (**CLI**). Программисты пользуются им целый день: набирать быстрее, набранную команду можно повторить и
сохранить, и почти каждый инструмент программирования (Git, Cargo, компилятор Rust) управляется именно так.

Три слова часто путают:

- **Терминал** — это окно.
- **Оболочка** — программа внутри него, которая понимает то, что вы набираете. У вас это `zsh`.
- **Приглашение** — текст, который показывает оболочка, ожидая вас.

Ваше приглашение, скорее всего, выглядит как `yourname@yourmac ~ %`. В этом уроке мы пишем только `%` вместо
приглашения. **Вы никогда не набираете `%`**, только то, что идёт после него. Строки без `%` — это
ответ компьютера.

> 💡 **Совет:** терминал сам по себе не опасен. Он просто делает то, что вы говорите, буквально (помните
> строгого помощника из Урока 00.2). Опасны только команды, которые удаляют, и с ними мы обращаемся
> осторожно в разделе 6.

## 2. Устройство команды

Попробуйте первую команду. Наберите её и нажмите Enter:

```text
% echo hello
hello
```

Что происходит:

1. `%` — приглашение (не набирается).
2. `echo` — **команда**: программа, которая печатает слова, которые вы ей дали.
3. `hello` — **аргумент**: что печатать.
4. Оболочка запустила `echo`, та напечатала `hello`, после чего появилось новое приглашение.

У команды могут быть и **опции** (переключатели). Опции обычно начинаются с дефиса:

```text
% ls -l notes
        ^  ^
        |  +-- argument: which directory to list
        +----- option: "long" format
```

Общий вид: `команда [опции] [аргументы]`, разделённые пробелами. Запомните два правила:

- **Пробелы разделяют слова.** Если в имени есть пробел, его нужно взять в кавычки (см. раздел 6).
- **Регистр важен.** `Notes` и `notes` — разные имена. `LS` — это не `ls`.

## 3. Где я? Пути

Файлы на вашем Mac лежат в дереве директорий. На самом верху — `/`, **корень**. Всё находится ниже него.

```text
/                          <- корень: самый верх всего
├── Applications
├── System
└── Users
    └── student            <- ваша домашняя директория, пишется ~
        ├── Documents
        ├── Downloads
        └── projects
            └── rust       <- ~/projects/rust, папка курса
                ├── course
                ├── ru
                └── code
```

(Ваше имя пользователя — не `student`; везде, где видите его, подставляйте своё.)

Команда `pwd` (print working directory, «показать рабочую директорию») говорит, где вы находитесь:

```text
% pwd
/Users/student
```

**Путь** — это маршрут от какого-то места до файла. Бывает два вида:

| Вид | Начинается с | Пример | Значение |
|---|---|---|---|
| Абсолютный | `/` | `/Users/student/projects/rust` | Полный маршрут от корня. Работает откуда угодно. |
| Относительный | с любого другого символа | `projects/rust` | Маршрут оттуда, где вы сейчас. |

Четыре особых имени делают пути короче:

| Имя | Значение |
|---|---|
| `~` | ваша домашняя директория (`/Users/student`) |
| `.` | текущая директория |
| `..` | родительская директория (на уровень выше) |
| `/` | корень |

## 4. Осматриваемся и перемещаемся: `ls` и `cd`

`ls` показывает, что находится в директории. Без аргументов показывает текущую.

```text
% ls
Documents
Downloads
projects
```

> Настоящая команда `ls` печатает имена рядом, в колонки. В этом уроке мы показываем по одному имени в
> строке, чтобы сэкономить место.

Полезные опции:

| Команда | Значение |
|---|---|
| `ls -l` | длинный формат: права, владелец, размер, дата |
| `ls -a` | показать всё, включая скрытые файлы (имена, начинающиеся с точки) |
| `ls -la` | и то и другое вместе |
| `ls -R` | показать и вложенные директории (рекурсивно) |

```text
% ls -a
.
..
Documents
Downloads
projects
```

`.` и `..` есть всегда. Ваш Mac также скрывает файлы вроде `.zshrc` в домашней директории.
В Finder нажмите `Cmd + Shift + .`, чтобы показать или скрыть скрытые файлы.

`cd` (change directory, «сменить директорию») перемещает вас:

```text
% cd projects
% pwd
/Users/student/projects
% cd rust
% pwd
/Users/student/projects/rust
% cd ..
% pwd
/Users/student/projects
% cd ~
% pwd
/Users/student
```

Что происходит:

1. `cd projects` — относительный путь: зайти в `projects` внутри текущей директории.
2. `cd rust` — спуститься ещё на уровень.
3. `cd ..` — подняться на уровень выше, обратно в `projects`.
4. `cd ~` — прыжок домой откуда угодно. `cd` без аргумента делает то же самое. `cd -` возвращает в предыдущую директорию.

> 💡 **Совет:** нажмите **Tab**, когда набираете имя. Оболочка допишет его (`cd pro` + Tab превращается в
> `cd projects/`). Если подходит несколько имён, нажмите Tab дважды, чтобы увидеть их. Это экономит набор и предотвращает опечатки.

Теперь перейдите в папку курса и посмотрите на неё. Это ваша настоящая папка (файлы, которые вы увидите, будут немного другими):

```text
% cd ~/projects/rust
% ls
GLOSSARY.md
START-HERE.md
course
ru
```

## 5. Создаём: `mkdir`, `touch`, `echo`, `cat`

Создайте папки, которые будут нужны в курсе (см. [Урок 00.1](01-how-to-use-this-course.md)). Смотрите на каждый результат:

```text
% mkdir code
% mkdir notes
% ls
GLOSSARY.md
START-HERE.md
code
course
notes
ru
```

`mkdir` (make directory, «создать директорию») создаёт директорию. С опцией `-p` она создаёт целую цепочку и не
жалуется, если директория уже есть:

```text
% mkdir -p code/demo/src
% ls -R code
demo

code/demo:
src

code/demo/src:
```

(`code/demo` нужна только для практики. Мы удалим её в разделе 6. Настоящие папки проектов создаст Cargo в Уроке 00.6.)

`touch` создаёт пустой файл (или обновляет дату существующего). `echo` печатает текст, а с
**перенаправлением** записывает текст в файл:

```text
% touch notes/day1.md
% echo 'Day 1: I learned the terminal.' > notes/day1.md
% cat notes/day1.md
Day 1: I learned the terminal.
% echo 'Next: install Rust.' >> notes/day1.md
% cat notes/day1.md
Day 1: I learned the terminal.
Next: install Rust.
```

Что происходит:

1. `touch notes/day1.md` — создать пустой файл `day1.md` внутри `notes`.
2. `echo '...' > file` — `>` отправляет вывод `echo` в файл. **Он заменяет всё, что было в файле.**
3. `cat file` (concatenate, «соединить») — вывести содержимое файла на экран.
4. `echo '...' >> file` — `>>` **дописывает** в конец файла, а не заменяет.

> ⚠️ **Частая ошибка:** использовать `>`, когда хотели `>>`. Старое содержимое файла пропадает, вопросов не
> задаётся, и никакой Корзины, чтобы его восстановить, нет.

## 6. Копирование, перемещение, переименование, удаление

| Команда | Что делает | Пример |
|---|---|---|
| `cp source target` | копирует файл | `cp notes/day1.md notes/backup.md` |
| `cp -r source target` | копирует директорию со всем содержимым | `cp -r code code2` |
| `mv source target` | перемещает файл или переименовывает его | `mv notes/backup.md notes/old.md` |
| `rm file` | удаляет файл | `rm notes/old.md` |
| `rm -r directory` | удаляет директорию со всем содержимым | `rm -r code2` |
| `rmdir directory` | удаляет **пустую** директорию | `rmdir code2` |

```text
% cp notes/day1.md notes/day1-backup.md
% ls notes
day1-backup.md
day1.md
% mv notes/day1-backup.md notes/old.md
% ls notes
day1.md
old.md
% rm notes/old.md
% ls notes
day1.md
```

Что происходит:

1. `cp` сделала второй файл с тем же содержимым.
2. `mv` переместила его под новым именем. Перемещение под новым именем в той же директории *и есть* переименование.
3. `rm` удалила его. `ls` подтверждает, что остался только `day1.md`.

Теперь удалите учебную папку из раздела 5. Сначала посмотрите, потом удалите, потом посмотрите снова (`ls code` ничего не печатает, когда папка пуста):

```text
% ls code
demo
% rm -r code/demo
% ls code
```

### Удаление окончательно

> 🔒 **Безопасность:** `rm` **не** использует Корзину. Удалённые файлы пропадают. Привыкайте так:
> 1. Перед `rm something` выполните `ls something` с тем же аргументом и проверьте результат.
> 2. Предпочитайте `rm file`, а не `rm -r directory`, и дважды подумайте перед `rm -r`.
> 3. Никогда не запускайте команду с `rm -rf`, скопированную из интернета, не поняв каждую её часть.
> 4. Никогда не набирайте `rm -r` с `/`, `~` или `*`, если не уверены абсолютно. `rm -r ~` удалил бы всю вашу домашнюю директорию.

### Имена с пробелами

Пробелы разделяют слова, поэтому `mkdir my notes` создаёт **две** директории, `my` и `notes`. Используйте кавычки:

```text
% mkdir 'my notes'
% ls
code
my notes
notes
% rmdir 'my notes'
```

> 📏 **Соглашение:** программисты избегают пробелов в именах файлов и директорий. Используйте строчные буквы, цифры,
> дефисы и подчёркивания: `p00-hello`, `day1.md`, `my_notes`. Тогда кавычки не понадобятся.

## 7. Как получить справку

Вы не запомните все опции, и этого не требуется. Пользуйтесь так:

- **`man command`** открывает страницу руководства команды. Прокручивайте стрелками, ищите через `/слово` и **выходите клавишей `q`**. Попробуйте `man ls`.
- **`command --help`** печатает краткую сводку для программ, которые её поддерживают (например, работает `cargo --help`).
  Многие старые инструменты, встроенные в macOS, не понимают `--help`:

```text
% ls --help
ls: unrecognized option `--help'
usage: ls [-@ABCFGHILOPRSTUWXabcdefghiklmnopqrstuvwxy1%,] [--color=when] [-D format] [file ...]
```

  Это сообщение не бесполезно: вторая строка, «usage», перечисляет все опции. Объяснение ищите в `man ls`.
- **`type command`** и **`which command`** сообщают, что такое команда и где она находится:

```text
% type cd
cd is a shell builtin
% which ls
/bin/ls
```

`cd` встроена в саму оболочку, поэтому файла у неё нет. `ls` — программа в файле `/bin/ls`.

## 8. Конвейеры и поиск

Настоящая сила оболочки — в соединении маленьких команд. **Конвейер** `|` берёт вывод левой
команды и использует его как ввод правой.

```text
% cat notes/day1.md | wc -l
       2
% ls | head -2
GLOSSARY.md
START-HERE.md
% grep Rust notes/day1.md
Next: install Rust.
% find . -name '*.md'
./notes/day1.md
```

Что происходит:

1. `wc -l` (word count, lines — подсчёт строк) считает строки своего ввода. Конвейер подал ему содержимое `day1.md`: 2 строки. (`wc -w` считает слова.)
2. `head -2` показывает только первые 2 строки своего ввода (`tail` показывает последние).
3. `grep Rust file` печатает строки файла, содержащие слово `Rust`. `grep -i` игнорирует регистр, `grep -n` ещё показывает номера строк.
4. `find . -name '*.md'` ищет в текущей директории (`.`) и во всём, что ниже, имена, подходящие под `*.md`. `*` — это **шаблон-подстановка** (wildcard): он означает «любые символы». Кавычки не дают оболочке раскрыть `*` самой.

> 💡 **Совет:** шаблон-подстановку можно использовать прямо с другими командами: `ls *.md` показывает все файлы Markdown в
> текущей директории.

## 9. Сочетания клавиш, которые экономят часы

| Клавиши | Что делают |
|---|---|
| **Tab** | дописать имя |
| **↑ / ↓** | предыдущая / следующая команда из истории |
| **Ctrl + R** | поиск по истории: наберите несколько букв старой команды |
| **Ctrl + C** | **остановить** выполняющуюся команду (самая важная клавиша!) |
| **Ctrl + A / Ctrl + E** | перейти в начало / в конец строки |
| **Ctrl + L** (или `clear`) | очистить экран |
| **Cmd + T** | открыть новую вкладку терминала |

> 💡 **Совет:** если программа как будто зависла и приглашение не возвращается, нажмите **Ctrl + C**. Это
> универсальное «стоп».

## 10. Как оболочка находит команды: `PATH`

Когда вы набираете `git`, откуда оболочка знает, где находится программа `git`? Она просматривает список
директорий по порядку, пока не найдёт файл с таким именем. Список хранится в **переменной
окружения** `PATH`. Любую переменную можно напечатать с помощью `echo` и `$` перед её именем:

```text
% echo $HOME
/Users/student
% echo $SHELL
/bin/zsh
% echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

(Последняя строка — типичное значение. У вас оно будет длиннее.) `PATH` — это список директорий, разделённых
двоеточиями. Оболочка сначала смотрит в `/usr/local/bin`, затем в `/usr/bin` и так далее.

Чтобы убедиться, что это правда, запустим чистую оболочку с намеренно коротким `PATH`. Программа `git` находится в
`/usr/bin`, поэтому `PATH`, содержащий только `/bin`, не сможет её найти:

```text
% which git
/usr/bin/git
% env -i PATH=/bin /bin/zsh -f -c 'git --version'
zsh:1: command not found: git
% env -i PATH=/usr/bin:/bin /bin/zsh -f -c 'git --version'
git version 2.54.0 (Apple Git-157)
```

Что происходит:

1. `which git` — файл лежит в `/usr/bin/git`.
2. Вторая команда запускает свежую оболочку, у которой `PATH` — только `/bin`. Она не смотрит в `/usr/bin`, поэтому пишет `command not found`, хотя `git` установлен.
3. В третьей `/usr/bin` есть в `PATH`, и `git` находится.

> 💡 **Совет:** на новом Mac `/usr/bin/git` — лишь маленькая заглушка, пока не установлены инструменты разработчика от Apple. Если появится окно с предложением установить «command line developer tools», можно нажать **Install** сейчас или **Cancel** и сделать это в Уроке 00.5. Идея `PATH` от этого не меняется.

Это понадобится вам в [Уроке 00.5](05-install-rust-and-rustrover.md): установщик Rust добавляет в ваш `PATH`
директорию `~/.cargo/bin`, и самая частая проблема установки — терминал, открытый *до* этого изменения. Лекарство — закрыть вкладку терминала и открыть новую.

## 11. Файлы, которые можно запускать: права доступа

В Уроке 00.3 вы узнали, что программа — это файл. Что делает файл *запускаемым*? **Право доступа**.
`ls -l` показывает их. Вот что он показывает для небольшого файла-скрипта `hello.sh` (пока не вводите это: мы создадим файл чуть ниже):

```text
% ls -l hello.sh
-rw-r--r--  1 student  staff  38 Nov 17 16:26 hello.sh
```

Как это читать, слева направо:

| Часть | Значение |
|---|---|
| `-` | тип: `-` — файл, `d` — директория |
| `rw-` | владелец может **r**ead (читать) и **w**rite (писать), но не e**x**ecute (выполнять) |
| `r--` | группа может только читать |
| `r--` | все остальные могут только читать |
| `1` | число ссылок (игнорируйте) |
| `student` `staff` | владелец и группа |
| `38` | размер в байтах |
| `Nov 17 16:26` | дата последнего изменения |
| `hello.sh` | имя |

(Символ `@` или `+` сразу после прав на вашем экране — лишь пометка о дополнительных атрибутах. Игнорируйте его.)

Сделаем **скрипт**: текстовый файл с командами. Мы запишем его с помощью `cat` и «here-document» (текст
между двумя строками `XX` попадает в файл):

```text
% cat > hello.sh <<'XX'
#!/bin/zsh
echo "Hello from a script"
XX
% ./hello.sh
zsh: permission denied: ./hello.sh
% chmod +x hello.sh
% ls -l hello.sh
-rwxr-xr-x  1 student  staff  38 Nov 17 16:26 hello.sh
% ./hello.sh
Hello from a script
```

Что происходит:

1. Первая строка `#!/bin/zsh` («шебанг») сообщает системе, какая программа должна прочитать этот файл. Вторая строка — команда.
2. `./hello.sh` — `./` означает «в текущей директории». Без `./` оболочка искала бы в `PATH`, а не в текущей директории. Результат — **permission denied**: у файла нет права `x` (выполнение).
3. `chmod +x hello.sh` — change mode, «изменить режим»: добавить право выполнения. Теперь `ls -l` показывает `-rwxr-xr-x`: три `x`.
4. Скрипт запускается. Скомпилированная программа на Rust — тоже просто файл с правом `x`.

Закончив, удалите учебный файл: `rm hello.sh`.

## 12. Доверие, `sudo` и скопированные команды

> 🔒 **Безопасность:** каждая команда выполняется с вашими правами, поэтому может удалить или изменить всё, что можете вы.
> - Читайте команду **до** нажатия Enter. Понимайте каждую часть или не запускайте.
> - `sudo` запускает команду от имени администратора. Никогда не ставьте `sudo` перед командой, которую не понимаете, и никогда не добавляйте его лишь потому, что кто-то на форуме написал, будто так ошибка пропала. В нашем курсе `sudo` почти никогда не нужен.
> - В некоторых инструкциях по установке написано `curl ... | sh`: скачать скрипт и сразу его запустить. Это
>   настолько же безопасно, насколько безопасен сайт, откуда он приходит. Мы используем это один раз, для официального установщика Rust, и
>   внимательно проверим адрес.
> - Никогда не вставляйте в чат или на форум команду, содержащую ваши пароли или токены.

## Частые ошибки

1. **Набор приглашения.** Вы скопировали `% ls` вместе с `%`. *Исправление:* наберите только `ls`.
2. **Опечатка в команде.** Набрали `sl` вместо `ls`. Оболочка отвечает `zsh: command not found: sl`. Прочитайте имя; исправьте опечатку.
3. **Не та директория.** `cat notes/day1.md` говорит `cat: notes/day1.md: No such file or directory`, потому что вы не в `~/projects/rust`. *Исправление:* выполните `pwd`, затем `cd` в нужное место.
4. **Забыли `./`.** Скрипт лежит в текущей директории, но `hello.sh` отвечает `zsh: command not found: hello.sh`. *Исправление:* `./hello.sh`.
5. **Создание уже существующей директории.** `mkdir notes` говорит `mkdir: notes: File exists`. Не опасно; используйте `mkdir -p`.
6. **`rmdir` для непустой директории.** Отвечает `rmdir: notes: Directory not empty`. Используйте `rm -r notes` — но только после проверки через `ls notes`.
7. **Попытка сделать `cd` в файл.** `cd file.txt` говорит `cd: not a directory: file.txt`.
8. **Пробелы без кавычек.** `cat my file.txt` пытается прочитать два файла, `my` и `file.txt`:

```text
% cat my file.txt
cat: my: No such file or directory
```

   *Исправление:* `cat 'my file.txt'`.

## Попробуйте сами

Следуйте этим шагам точно. В конце у вас будет настоящий файл заметок для вашего курса.

1. Откройте Терминал. Наберите `pwd` и прочитайте ответ.
2. Наберите `cd ~/projects/rust`, затем снова `pwd`. Убедитесь, что путь заканчивается на `projects/rust`.
3. Наберите `ls`. Убедитесь, что видите `course` и `ru`.
4. Создайте папки (если их ещё нет): `mkdir -p code notes`. Затем `ls`, чтобы их увидеть.
5. Создайте первую заметку: `echo '# Day 1' > notes/day1.md`.
6. Добавьте ещё две строки с помощью `>>`: `echo 'I can use the terminal.' >> notes/day1.md` и `echo 'Next: install Rust.' >> notes/day1.md`.
7. Покажите файл: `cat notes/day1.md`. Ожидаемый результат:

```text
# Day 1
I can use the terminal.
Next: install Rust.
```

8. Посчитайте строки конвейером: `cat notes/day1.md | wc -l`. Ожидается: `3`.
9. Нажимайте клавишу **↑**, пока не вернётся команда `mkdir`. Нажмите **Ctrl + C**, чтобы отменить её, не выполняя.
10. Выполните `man ls`, прокрутите стрелками и нажмите `q`, чтобы выйти.

## Упражнения

### Упражнение 1 — Навигация (легко)

Начиная с домашней директории, напишите команды, чтобы: перейти в `~/projects/rust/code`, показать
текущую директорию, подняться на уровень выше и снова вернуться домой.

<details>
<summary>Подсказка</summary>

Нужны `cd`, `pwd`, `cd ..` и `cd ~`.

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust/code
% pwd
/Users/student/projects/rust/code
% cd ..
% cd ~
```

Почему это работает: `~` раскрывается в домашнюю директорию, поэтому первый путь абсолютный. `..` — родительская директория, а `cd ~` возвращает домой откуда угодно.

</details>

### Упражнение 2 — Небольшая структура (легко)

Внутри `~/projects/rust/notes` создайте папку `week1`. Внутри неё создайте файлы `monday.md` и
`tuesday.md`, в каждом по одной строке текста. Затем покажите содержимое папки.

<details>
<summary>Подсказка</summary>

`mkdir`, затем дважды `echo '...' > file`, затем `ls week1`.

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust/notes
% mkdir week1
% echo 'Monday: terminal basics' > week1/monday.md
% echo 'Tuesday: first program' > week1/tuesday.md
% ls week1
monday.md
tuesday.md
```

Почему это работает: `>` создаёт файл, если его нет, поэтому `touch` не нужен.

</details>

### Упражнение 3 — Копируем, переименовываем, удаляем (средне)

Скопируйте `monday.md` в `monday-copy.md`, переименуйте копию в `old.md` и удалите `old.md`. После каждого
шага показывайте папку. В конце должны остаться только `monday.md` и `tuesday.md`.

<details>
<summary>Подсказка</summary>

`cp`, `mv`, `rm` и `ls` между ними. Выполните `ls week1` перед `rm`.

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust/notes/week1
% cp monday.md monday-copy.md
% mv monday-copy.md old.md
% ls
monday.md
old.md
tuesday.md
% rm old.md
% ls
monday.md
tuesday.md
```

Почему это работает: `mv` в пределах одной директории переименовывает; `ls` перед `rm` подтверждает, что мы удаляем нужный файл.

</details>

### Упражнение 4 — Конвейеры (средне)

У вас есть файл `words.txt` со строкой `one two three`. Создайте его, затем посчитайте слова с помощью
`wc` и покажите имя каждого файла `.md` в `~/projects/rust/notes` и ниже.

<details>
<summary>Подсказка</summary>

`echo` с `>`, затем `wc -w words.txt`. Для поиска используйте `find` с `-name`.

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust/notes
% echo 'one two three' > words.txt
% wc -w words.txt
       3 words.txt
% find . -name '*.md'
./day1.md
./week1/monday.md
./week1/tuesday.md
% rm words.txt
```

Почему это работает: `wc -w` считает слова; `find` обходит все поддиректории. Порядок файлов, которые печатает `find`, на вашем компьютере может отличаться.

</details>

### Упражнение 5 — Найдите ошибку (сложно)

Друг набирает эти команды в `~/projects/rust` и получает ошибки. Объясните каждую проблему и исправьте её.

```text
% cd notes/week 1
% cat notes/day1.md | wc -l
% hello.sh
```

(Считайте, что `week 1` — директория с пробелом в имени, скрипт `hello.sh` лежит в текущей директории и у него
есть право `x`.)

<details>
<summary>Подсказка</summary>

Посмотрите на пробелы, на текущую директорию и на то, как оболочка находит скрипты.

</details>

<details>
<summary>Ответ</summary>

1. `cd notes/week 1` передаёт `cd` два аргумента. *Исправление:* `cd 'notes/week 1'` (или используйте автодополнение по Tab, которое само добавит обратную косую черту: `cd notes/week\ 1`).
2. После первой команды друг находится в `notes/week 1`, поэтому `notes/day1.md` — неверный относительный путь: здесь нет папки `notes`. *Исправление:* сначала `cd ~/projects/rust` или использовать абсолютный путь `cat ~/projects/rust/notes/day1.md | wc -l`.
3. `hello.sh` не находится, потому что текущей директории нет в `PATH`. *Исправление:* `./hello.sh`.

Почему это работает: всегда нужно спрашивать: где я (`pwd`), что именно получила оболочка (кавычки!) и ищет ли оболочка команду в нужном месте (`PATH`, `./`).

</details>

## Вопросы для самопроверки

1. В чём разница между терминалом и оболочкой?

<details>
<summary>Ответ</summary>

Терминал — это окно. Оболочка (zsh) — программа внутри него, которая читает и выполняет ваши команды.

</details>

2. Что означают `.`, `..` и `~` в пути?

<details>
<summary>Ответ</summary>

`.` — текущая директория, `..` — её родитель, `~` — ваша домашняя директория.

</details>

3. В чём разница между `>` и `>>`?

<details>
<summary>Ответ</summary>

`>` заменяет содержимое файла выводом; `>>` дописывает вывод в конец.

</details>

4. Почему перед `rm` нужно выполнить `ls`?

<details>
<summary>Ответ</summary>

`rm` необратима, Корзины нет. `ls` с тем же аргументом показывает, что именно будет удалено.

</details>

5. Что означает `command not found` и как `PATH` может его вызвать?

<details>
<summary>Ответ</summary>

Оболочка не нашла программу с таким именем ни в одной директории из `PATH`. Либо имя написано с опечаткой, либо программа не установлена, либо директория, где она лежит, не входит в `PATH`.

</details>

6. Что делает `chmod +x file` и зачем это нужно?

<details>
<summary>Ответ</summary>

Добавляет право выполнения. Без него система отказывается запускать файл («permission denied»).

</details>

7. Какое сочетание клавиш останавливает выполняющуюся команду?

<details>
<summary>Ответ</summary>

Ctrl + C.

</details>

## Итоги

- Терминал — это окно, оболочка (zsh) понимает команды, приглашение их ждёт.
- Команда имеет вид `команда [опции] [аргументы]`; пробелы разделяют слова, регистр важен.
- Пути бывают абсолютными (начинаются с `/`) и относительными; `~` — домашняя, `.` — текущая, `..` — родительская директория.
- Основные команды: `pwd`, `ls`, `cd`, `mkdir`, `touch`, `echo`, `cat`, `cp`, `mv`, `rm`.
- `>` заменяет файл, `>>` дописывает; `|` передаёт вывод одной команды следующей.
- `rm` необратима: сначала проверьте через `ls`; избегайте `rm -r`, пока не уверены.
- Для справки используйте `man`, `--help`, `type` и `which`; Tab и ↑ уменьшают набор; Ctrl + C останавливает.
- `PATH` — список директорий, где оболочка ищет команды; права доступа решают, можно ли запустить файл.
