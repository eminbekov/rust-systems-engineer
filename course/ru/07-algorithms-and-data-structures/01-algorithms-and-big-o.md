## Новые слова

| Слово | Значение |
|---|---|
| **алгоритм** (algorithm) | Точный список шагов, который решает задачу и всегда заканчивается. |
| **размер входа (`n`)** (input size) | Число, которое говорит, насколько велик вход: длина вектора, количество слов в тексте. По традиции его называют `n`. |
| **временная сложность** (time complexity) | Как растёт число шагов, когда растёт `n`. |
| **сложность по памяти** (space complexity) | Как растёт объём дополнительной памяти, когда растёт `n` (Урок 07.2). |
| **нотация «O большое»** (Big-O notation) | Короткая запись сложности: `O(n)` читается «о от эн» или «big-O от n». Остаётся только самая быстрорастущая часть. |
| **лучший / худший случай** (best case / worst case) | Вход, при котором алгоритм заканчивает быстрее всего / медленнее всего при данном `n`. |
| **линейный / квадратичный** (linear / quadratic) | `O(n)`: вход вдвое больше — работы вдвое больше / `O(n²)`: вход вдвое больше — работы в четыре раза больше. |
| **логарифм** (`log n`) | Здесь: сколько раз можно разделить `n` пополам, пока не получится 1. Для 1 000 это 9, для 1 000 000 это 19. Растёт очень медленно. |
| **экспоненциальный** (exponential) | `O(2ⁿ)`: каждый новый элемент удваивает работу. Непригоден примерно с `n = 40`. |
| **модуль** (module) | Именованная часть крейта, обычно один файл. Здесь: один модуль на тему. |
| **пример (Cargo)** (example) | Небольшая программа в папке `examples/` пакета, запускается командой `cargo run --example <имя>`. |
| **`std`** | Стандартная библиотека Rust (standard library). |

## 1. Что такое алгоритм

**Алгоритм** — это точный список шагов, который превращает **вход** в **выход**. Четыре свойства отличают
алгоритм от пожелания:

1. У него есть ясный вход и ясный выход.
2. Каждый шаг точен: компьютер может выполнить его, ничего не угадывая.
3. Он всегда заканчивается (за конечное число шагов).
4. Он даёт правильный ответ для любого допустимого входа.

Вот бытовой алгоритм: *найти самого высокого человека в комнате.* Посмотрите на первого человека и
запомните рост. Смотрите на каждого следующего. Если этот человек выше запомненного роста, запомните новый
рост. Когда людей не осталось, запомненный рост — ответ. Вы уже писали это на Стадии 1 как цикл `for`.

Одну и ту же задачу могут решать разные алгоритмы. Все они дают правильный ответ, но один потратит секунду,
а другой — год на большом входе. **Структура данных** (data structure) — это способ организовать данные в
памяти (вектор, хеш-таблица, дерево). Алгоритмы и структуры данных идут вместе: правильная структура часто
делает алгоритм намного быстрее. Этот этап учит и тому, и другому.

Значит, нужен способ сказать «этот алгоритм быстрее того». Секундомер — плохой судья: результат зависит от
компьютера, от других запущенных программ и от входа, который вам случайно попался. Нам нужна мера, одинаковая
на любом компьютере. Это **число шагов как функция размера входа `n`**.

## 3. Считаем шаги

Мы будем считать **сравнения**, потому что сравнения — основная работа в трёх алгоритмах ниже.
Создайте `src/big_o.rs` и напишите первый алгоритм — из истории про самого высокого человека:

```rust
/// Returns the largest number in the slice, or `None` if the slice is empty.
pub fn largest(numbers: &[i32]) -> Option<i32> {
    if numbers.is_empty() {
        return None;
    }
    let mut best = numbers[0];
    for &n in &numbers[1..] {
        if n > best {
            best = n;
        }
    }
    Some(best)
}
```

**Что происходит:**

1. У пустого среза нет наибольшего числа, поэтому ответ — `None`.
2. `best` помнит наибольшее число из увиденных. Сначала это первый элемент.
3. `&numbers[1..]` — срез без первого элемента. Цикл смотрит на каждый из остальных элементов один раз.
4. Для `n` элементов цикл делает `n - 1` сравнений. Если `n` вырастет вдвое, работа вырастет вдвое. Удачного
   входа нет (надо посмотреть каждый элемент), поэтому лучший и худший случай совпадают.

Теперь поиск. **Линейный поиск** (linear search) ищет значение слева направо и останавливается, когда находит.
Эта версия ещё возвращает число сделанных сравнений, чтобы мы могли её изучать:

```rust
/// Looks for `target` from left to right.
/// Returns the position (if found) and the number of comparisons made.
pub fn linear_search_counted(items: &[i32], target: i32) -> (Option<usize>, usize) {
    let mut comparisons = 0;
    for (index, &item) in items.iter().enumerate() {
        comparisons += 1;
        if item == target {
            return (Some(index), comparisons);
        }
    }
    (None, comparisons)
}
```

**Что происходит:** `items.iter().enumerate()` даёт пары `(index, item)`; образец `(index, &item)` копирует
`i32` из ссылки. Каждый проход цикла — одно сравнение. При совпадении функция сразу возвращается. Если цикл
закончился, значения нет, и ответ — `None`.

**Лучший случай** — цель стоит первой: 1 сравнение при любом `n`. **Худший случай** — цель стоит последней
или её нет: `n` сравнений. Обычно нас интересует худший случай, потому что обещание «никогда не медленнее
этого» полезнее, чем «иногда быстрее».

Третий алгоритм проверяет, встречается ли какое-нибудь значение дважды, сравнивая все пары элементов:

```rust
/// Checks whether some value appears twice, by comparing every pair.
/// Returns the answer and the number of comparisons made.
pub fn has_duplicate_counted(items: &[i32]) -> (bool, usize) {
    let mut comparisons = 0;
    for i in 0..items.len() {
        for j in (i + 1)..items.len() {
            comparisons += 1;
            if items[i] == items[j] {
                return (true, comparisons);
            }
        }
    }
    (false, comparisons)
}
```

**Что происходит:** внешний цикл выбирает позицию `i`; внутренний выбирает каждую позицию `j` *после* `i`,
так что каждая пара сравнивается один раз. Два равных элемента останавливают функцию с ответом `true`. В худшем
случае (все элементы разные) число пар равно `(n-1) + (n-2) + ... + 1 = n(n-1)/2`.

Посмотрим на числа. Файл `examples/e01_steps.rs` считает худший случай для растущих `n`:

```rust
use p07_algorithms::big_o::{has_duplicate_counted, linear_search_counted};

fn main() {
    println!(
        "{:>8} {:>16} {:>16}",
        "n", "search (worst)", "pairs (worst)"
    );
    for n in [10, 100, 1_000, 10_000] {
        let items: Vec<i32> = (0..n).collect(); // all different, 0..n
        let (_, search_steps) = linear_search_counted(&items, -1); // -1 is not there
        let (_, pair_steps) = has_duplicate_counted(&items);
        println!("{:>8} {:>16} {:>16}", n, search_steps, pair_steps);
    }
}
```

**Что происходит:** `(0..n).collect()` строит вектор `0, 1, ..., n-1` из разных элементов. Поиск `-1` никогда
не успешен, а проверка дубликатов никогда не находит дубликат, так что оба проходят весь худший случай.
`{:>8}` печатает число по правому краю в 8 символах (Урок 02.6).

Запустите командой `cargo run --example e01_steps`:

```text
       n   search (worst)    pairs (worst)
      10               10               45
     100              100             4950
    1000             1000           499500
   10000            10000         49995000
```

Посмотрите на два столбца. Когда `n` растёт в 10 раз, поиску нужно в 10 раз больше сравнений. Проверке пар
нужно примерно в 100 раз больше: от 45 до 4 950, до 499 500, до 49 995 000. В этом вся идея урока. Два
алгоритма отличаются **тем, как растёт их стоимость**.

## 4. Нотация «O большое»

**Нотация «O большое»** — это короткая запись фразы «как стоимость растёт вместе с `n`». Мы говорим:

- `largest` и `linear_search_counted` — это `O(n)` (читается «о от эн», или «линейный»).
- `has_duplicate_counted` — это `O(n²)` («о от эн в квадрате», или «квадратичный»).

Точное определение, для любопытных: *стоимость `f(n)` есть `O(g(n))`, если, начиная с некоторого размера,
`f(n)` никогда не больше, чем некоторое постоянное число, умноженное на `g(n)`.* На практике нужна только идея:
**оставьте самую быстрорастущую часть, остальное выбросьте.**

Распространённые скорости роста — от лучшей к худшей:

| Запись | Название | Пример | Если `n` вырастет вдвое |
|---|---|---|---|
| `O(1)` | константная | прочитать `v[5]` из вектора | то же самое |
| `O(log n)` | логарифмическая | двоичный поиск (Урок 07.10) | на один шаг больше |
| `O(n)` | линейная | `largest`, `linear_search` | работы вдвое больше |
| `O(n log n)` | «эн лог эн» | хорошая сортировка (Урок 07.9) | чуть больше, чем вдвое |
| `O(n²)` | квадратичная | сравнить все пары | в четыре раза больше |
| `O(2ⁿ)` | экспоненциальная | перебрать все подмножества | возводится в квадрат (очень плохо) |

`log n` требует ещё одного объяснения. Возьмём `n = 1000`. Делим пополам: 500, 250, 125, 62, 31, 15, 7, 3, 1.
Это 9 делений. Число делений и есть `log n` (точнее, `log₂ n`, но в Big-O основание не важно). Алгоритмы,
которые на каждом шаге делят задачу пополам, — это `O(log n)`. Вот функция, которая считает деления:

```rust
/// How many times can `n` be cut in half (rounding down) before it reaches 1?
pub fn halvings(mut n: u64) -> u32 {
    let mut count = 0;
    while n > 1 {
        n /= 2;
        count += 1;
    }
    count
}
```

Файл `examples/e01_growth.rs` печатает, сколько шагов нужно каждой скорости роста для нескольких размеров:

```rust
use p07_algorithms::big_o::halvings;

fn main() {
    println!(
        "{:>10} {:>4} {:>6} {:>10} {:>12} {:>16}",
        "n", "1", "log n", "n", "n log n", "n squared"
    );
    for n in [10u64, 100, 1_000, 1_000_000] {
        let log_n = halvings(n);
        println!(
            "{:>10} {:>4} {:>6} {:>10} {:>12} {:>16}",
            n,
            1,
            log_n,
            n,
            n * u64::from(log_n),
            n * n
        );
    }

    println!();
    println!("2 to the power n:");
    for n in [10u32, 20, 30, 40, 50, 60] {
        println!("{:>4} {:>22}", n, 1u64 << n);
    }
}
```

**Что происходит:** `halvings(n)` — это `log n`, а `n * u64::from(log_n)` — это `n log n` (`u64::from` безопасно
расширяет `u32`). `1u64 << n` — это 2 в степени `n`: бит `1`, сдвинутый влево на `n` позиций. При `n = 64` число
уже не поместилось бы в `u64` (Урок 02.2: переполнение). Запустите командой `cargo run --example e01_growth`:

```text
         n    1  log n          n      n log n        n squared
        10    1      3         10           30              100
       100    1      6        100          600            10000
      1000    1      9       1000         9000          1000000
   1000000    1     19    1000000     19000000    1000000000000

2 to the power n:
  10                   1024
  20                1048576
  30             1073741824
  40          1099511627776
  50       1125899906842624
  60    1152921504606846976
```

Читайте таблицу по столбцам, как будто каждый столбец — алгоритм, работающий с вектором из миллиона
элементов:

- `O(log n)` требует **19** шагов.
- `O(n)` требует 1 000 000 шагов: для компьютера это мгновение.
- `O(n log n)` требует 19 000 000 шагов: всё ещё быстро.
- `O(n²)` требует **1 000 000 000 000** шагов. При миллиарде простых шагов в секунду это около 17 минут.
- `O(2ⁿ)` при `n = 60` — это около миллиарда миллиардов (10¹⁸) шагов. Ни один компьютер этого не сделает.

Вот почему Big-O важна. При малом `n` разницы никто не замечает. При большом `n` скорость роста решает,
закончится ли программа сегодня или никогда.

## 5. Три правила Big-O

**Правило 1: отбросьте постоянные множители.** Цикл, который делает 3 сравнения на элемент, делает `3n`
шагов. Цикл с 1 сравнением делает `n` шагов. Оба — `O(n)`. Постоянные множители зависят от компьютера и
компилятора, а форма роста — нет. Два цикла подряд (`n + n = 2n`) — по-прежнему `O(n)`.

**Правило 2: отбросьте меньшие слагаемые.** Если алгоритм делает `n² + 5n + 100` шагов, то при `n = 1000` это
1 000 000 + 5 000 + 100. Слагаемое `n²` — почти всё, и чем больше `n`, тем это вернее. Значит, алгоритм — `O(n²)`.

**Правило 3: говорите, какой случай имеете в виду.** Если не сказано иное, Big-O описывает **худший случай**.
Поэтому `linear_search_counted` — это `O(n)`, хотя может закончиться после одного сравнения. Если важен лучший
или средний случай, скажите об этом: «лучший случай `O(1)`, худший случай `O(n)`».

Два предупреждения, которые часто нужны новичкам:

> ⚠️ **Частая ошибка:** `O(1)` не значит «быстро», а `O(n²)` не значит «медленно». Big-O говорит только о том,
> как стоимость *растёт*. Операция `O(1)`, которая длится секунду, медленнее цикла `O(n)` по десяти элементам.
> При малом `n` выигрывают постоянные множители; поэтому очень простые алгоритмы часто лучший выбор для
> маленьких входов. Вы увидите это на настоящих числах в Уроке 07.2.

> ⚡ **Производительность:** Big-O подсказывает, какой алгоритм *рассмотреть*. Измерение показывает, какой
> *быстрее на ваших данных* ([Урок 05.12](../05-rust-intermediate/12-benchmarking-basics.md)). Используйте
> оба.

## 6. Тесты: сравниваем со стандартной библиотекой на малых входах

Алгоритм, который быстр, но неверен, бесполезен. Хороший способ его проверить: написать ту же функцию совсем
другим, очевидно правильным способом и сравнить обе на **множестве входов**. Для крошечных входов можно
перебрать **все** (*исчерпывающий тест*, exhaustive test). Большинство ошибок видно уже на малых входах.
Добавьте это в конец `src/big_o.rs`:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use std::collections::HashSet;

    #[test]
    fn largest_of_empty_is_none() {
        assert_eq!(largest(&[]), None);
        assert_eq!(largest(&[4, 9, 2]), Some(9));
    }

    #[test]
    fn linear_search_counts_comparisons() {
        let v = [5, 8, 13, 21];
        assert_eq!(linear_search_counted(&v, 5), (Some(0), 1)); // best case
        assert_eq!(linear_search_counted(&v, 21), (Some(3), 4));
        assert_eq!(linear_search_counted(&v, 99), (None, 4)); // worst case
    }

    #[test]
    fn has_duplicate_matches_a_hash_set() {
        // every vector of length 3 with items from 0 to 3: 64 vectors
        for a in 0..4 {
            for b in 0..4 {
                for c in 0..4 {
                    let v = [a, b, c];
                    let unique: HashSet<i32> = v.iter().copied().collect();
                    let expected = unique.len() != v.len();
                    assert_eq!(has_duplicate_counted(&v).0, expected, "input {v:?}");
                }
            }
        }
    }

    #[test]
    fn duplicate_check_worst_case_is_n_times_n_minus_1_over_2() {
        let v: Vec<i32> = (0..100).collect(); // all different: no early exit
        assert_eq!(has_duplicate_counted(&v), (false, 100 * 99 / 2));
    }

    #[test]
    fn halvings_examples() {
        assert_eq!(halvings(1), 0);
        assert_eq!(halvings(8), 3);
        assert_eq!(halvings(1000), 9);
        assert_eq!(halvings(1_000_000), 19);
    }
}
```

**Что происходит:**

1. `largest_of_empty_is_none` проверяет граничный случай: пустой срез.
2. `linear_search_counts_comparisons` проверяет лучший случай (1 сравнение), средний случай и худший случай
   (4 сравнения).
3. `has_duplicate_matches_a_hash_set` обходит все 64 вектора длины 3 со значениями от 0 до 3 тремя вложенными
   циклами. Для каждого сравнивает наш ответ `O(n²)` с другим методом: положить элементы в `HashSet` (множество
   хранит каждое значение один раз) и посмотреть, меньше ли множество, чем вектор.
4. Два последних теста фиксируют формулу `n(n-1)/2` из раздела 3 (для `n = 100`) и значения `log n`.

Запустите `cargo test`:

```text
running 5 tests
test big_o::tests::halvings_examples ... ok
test big_o::tests::largest_of_empty_is_none ... ok
test big_o::tests::duplicate_check_worst_case_is_n_times_n_minus_1_over_2 ... ok
test big_o::tests::linear_search_counts_comparisons ... ok
test big_o::tests::has_duplicate_matches_a_hash_set ... ok

test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

(Порядок строк на вашем компьютере может отличаться: тесты идут параллельно.)

> 🧪 **Тестирование:** «Сравнить с медленной, но очевидно правильной версией на всех малых входах» — самый
> полезный приём тестирования на этом этапе. Вы будете применять его к сортировке, поиску, деревьям и графам.

## 7. Когда вместо этого взять стандартную библиотеку

Вы писали эти алгоритмы, чтобы понять их. В реальном коде используйте то, что предлагает `std`:

| Что нужно | Что использовать | Стоимость |
|---|---|---|
| наибольший элемент | `v.iter().max()` | `O(n)` |
| позиция значения | `v.iter().position(\|x\| *x == target)` или `v.contains(&target)` | `O(n)` |
| «есть ли в векторе дубликаты?» | положить элементы в `HashSet` и сравнить длины | `O(n)` в среднем |

Стандартная библиотека документирует стоимость своих коллекций в таблице (см. источники). Научитесь её
читать: это Big-O в повседневной работе.

## Частые ошибки

**1. Обращение к первому элементу пустого среза.** Первый элемент среза — `numbers[0]`, но только если он есть.

```rust
fn first_or_panic(numbers: &[i32]) -> i32 {
    numbers[0]
}

fn main() {
    let empty: Vec<i32> = Vec::new();
    println!("{}", first_or_panic(&empty));
}
```

Запустите командой `cargo run --example e01_panic` (если положите файл в `examples/`):

```text

thread 'main' (4624881) panicked at examples/e01_panic.rs:2:5:
index out of bounds: the len is 0 but the index is 0
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

(Число после `thread 'main'` на вашем компьютере будет другим.) Поэтому `largest` сначала проверяет
`numbers.is_empty()`. Всегда думайте о пустом входе и о входе из одного элемента.

**2. Путаница между двумя разными `n`.** Если функция принимает два вектора `a` и `b`, размеров два. Цикл по
`a` с внутренним циклом по `b` — это `O(a.len() * b.len())`, а не `O(n²)`. Называйте свои размеры.

## Упражнения

### Упражнение 1 — Классифицируйте циклы (легко)

Назовите временную сложность каждого фрагмента для вектора `v` длины `n`. (Фрагменты — части `main`; запускать
их не нужно.)

```rust
let mut total = 0;                  // (a)
for x in &v { total += x; }

let first = v[0];                   // (b)

for x in &v {                       // (c)
    for y in &v { println!("{x} {y}"); }
}

let mut k = v.len();                // (d)
while k > 1 { k /= 2; }
```

<details>
<summary>Подсказка</summary>

Посчитайте, сколько раз выполняется самый внутренний оператор как функция от `n`. Для (d) спросите себя,
сколько раз можно разделить `n` пополам.

</details>

<details>
<summary>Ответ</summary>

(a) `O(n)`: одно сложение на элемент. (b) `O(1)`: один шаг при любом `n`. (c) `O(n²)`: `n` раз по `n` печатей.
(d) `O(log n)`: `k` каждый раз делится пополам.

Почему это работает: постоянные множители отбрасываются (правило 1), а вложенные циклы перемножают свои числа.

</details>

### Упражнение 2 — Второй по величине (средне)

Напишите `pub fn second_largest(numbers: &[i32]) -> Option<i32>`, которая возвращает второй элемент по убыванию
(равные элементы считаются отдельно: для `[5, 5]` ответ `Some(5)`). Используйте **один проход** по срезу и
назовите временную сложность. Проверьте функцию тестом против версии, которая сортирует копию.

<details>
<summary>Подсказка</summary>

Держите две переменные, `first` и `second`, обе `Option<i32>`. Число, которое побеждает `first`, сдвигает
старый `first` вниз в `second`; любое другое число всё ещё может победить `second`.

</details>

<details>
<summary>Ответ</summary>

```rust
pub fn second_largest(numbers: &[i32]) -> Option<i32> {
    let mut first: Option<i32> = None;
    let mut second: Option<i32> = None;
    for &n in numbers {
        match first {
            None => first = Some(n),
            Some(f) if n > f => {
                second = first;
                first = Some(n);
            }
            Some(_) => {
                if second.is_none_or(|s| n > s) {
                    second = Some(n);
                }
            }
        }
    }
    second
}
```

Тест (внутри `mod tests`):

```rust
    #[test]
    fn second_largest_matches_sorting() {
        for a in 0..4 {
            for b in 0..4 {
                for c in 0..4 {
                    let v = [a, b, c];
                    let mut sorted = v.to_vec();
                    sorted.sort_by(|x, y| y.cmp(x)); // largest first
                    assert_eq!(second_largest(&v), sorted.get(1).copied(), "input {v:?}");
                }
            }
        }
        assert_eq!(second_largest(&[]), None);
        assert_eq!(second_largest(&[7]), None);
    }
```

Сложность — `O(n)`: один проход, постоянное число шагов на элемент и `O(1)` дополнительной памяти (две
переменные). Версия с сортировкой — `O(n log n)` (Урок 07.9).

</details>

### Упражнение 3 — Посчитайте тройки (сложно)

Напишите `pub fn count_triples(n: u64) -> u64`, которая считает, сколько раз выполняется самая внутренняя
строка в циклах `for i in 0..n`, `for j in (i + 1)..n`, `for k in (j + 1)..n`. Найдите формулу вручную,
проверьте её тестом для `n` от 0 до 29 и назовите Big-O.

<details>
<summary>Подсказка</summary>

Каждый запуск выбирает 3 разных числа из `n` без учёта порядка. Способов `n(n-1)(n-2)/6` (для `n >= 3`; при
меньших `n` ответ 0).

</details>

<details>
<summary>Ответ</summary>

```rust
pub fn count_triples(n: u64) -> u64 {
    let mut count = 0;
    for i in 0..n {
        for j in (i + 1)..n {
            for _k in (j + 1)..n {
                count += 1;
            }
        }
    }
    count
}
```

```rust
    #[test]
    fn triples_formula() {
        for n in 0..30u64 {
            let formula = if n < 3 { 0 } else { n * (n - 1) * (n - 2) / 6 };
            assert_eq!(count_triples(n), formula);
        }
    }
```

Количество — примерно `n³/6`. Отбросив постоянный множитель `1/6` и меньшие слагаемые, получаем `O(n³)`.
Каждый дополнительный вложенный цикл такого вида умножает рост ещё на `n`.

</details>

## Вопросы для самопроверки

1. Почему мы считаем шаги, а не измеряем секунды?

<details>
<summary>Ответ</summary>

Секунды зависят от компьютера, настроек компилятора и других запущенных программ. Число шагов как функция
от `n` одинаково везде и показывает, как стоимость *растёт*.

</details>

2. Чему равна Big-O для `3n² + 20n + 7`?

<details>
<summary>Ответ</summary>

`O(n²)`: отбросьте постоянный множитель 3 и меньшие слагаемые `20n` и `7`.

</details>

3. Каковы лучший и худший случаи линейного поиска среди `n` элементов?

<details>
<summary>Ответ</summary>

Лучший: цель стоит первой, 1 сравнение, `O(1)`. Худший: цель стоит последней или её нет, `n` сравнений, `O(n)`.

</details>

4. Алгоритм A делает `50n` шагов, алгоритм B делает `n²` шагов. При каких `n` B быстрее? Какой лучше для огромных `n`?

<details>
<summary>Ответ</summary>

`n² < 50n` означает `n < 50`. Для `n` меньше 50 быстрее B; больше 50 выигрывает A, и разрыв растёт без
предела. A — это `O(n)`, B — `O(n²)`. Значит, Big-O определяет победителя для больших `n`, но для крошечных
`n` «худший» алгоритм может выиграть.

</details>

## Итоги

- Алгоритм — это точный список шагов, который решает задачу и всегда заканчивается. Разные алгоритмы для одной
  задачи могут отличаться по стоимости огромно.
- Мы измеряем алгоритм, считая шаги как функцию размера входа `n`, а не засекая время.
- Big-O оставляет только самую быстрорастущую часть: `O(1)`, `O(log n)`, `O(n)`, `O(n log n)`, `O(n²)`, `O(2ⁿ)`.
- Правила: отбросить постоянные множители, отбросить меньшие слагаемые и сказать, какой случай (обычно худший)
  вы имеете в виду.
- Big-O — про рост, а не про скорость на одном входе; когда это важно, измеряйте.
- `code/p07-algorithms` содержит по модулю на тему, модульные тесты рядом с кодом, примеры в `examples/`,
  бенчмарки в `benches/`.
- Хороший тест сравнивает ваш алгоритм с очевидно правильным на всех малых входах.
