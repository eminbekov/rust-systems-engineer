## Новые слова

| Слово | Значение |
|---|---|
| **RFC** (Request for Comments, «запрос комментариев») | Нумерованные документы, которые определяют интернет-протоколы. RFC 1035 определяет формат сообщений DNS (Domain Name System, система доменных имён). |
| **спецификация** (specification) | Точное описание формата или протокола. Ваш код должен выдавать и принимать ровно то, что в ней сказано. |
| **формат на проводе** (wire format) | Точные байты, которые идут по сети, в отличие от текста, который пишут люди (`rust-lang.org`). |
| **фикстура** (fixture) | Фиксированные тестовые данные, которые лежат рядом с тестами. Здесь — настоящие DNS-ответы, перехваченные `tcpdump`. |
| **проверка границ** (bounds check) | Проверка того, что позиция находится внутри буфера, до чтения. В Rust `slice.get(i)` возвращает `None` вместо паники. |
| **цикл указателей** (pointer loop) | Вредоносный или испорченный указатель сжатия, который указывает сам на себя или вперёд, так что наивный парсер следует по нему бесконечно. |
| **UDP, IP, TCP, TTL** | User Datagram Protocol, Internet Protocol, Transmission Control Protocol, Time To Live (протокол пользовательских датаграмм, межсетевой протокол, протокол управления передачей, время жизни): транспорты и время жизни в кэше из Уроков 15.3 и 15.10. |
| **CNAME, MX, NS, SOA** | Canonical NAME, Mail eXchange, Name Server, Start Of Authority (каноническое имя, почтовый обмен, сервер имён, начало полномочий): типы записей из Урока 15.10. |
| **QR, RD, AA, TC, RCODE** | Query/Response, Recursion Desired, Authoritative Answer, TrunCated, Response CODE (запрос/ответ, нужна рекурсия, авторитативный ответ, усечено, код ответа): флаги заголовка из Урока 15.10. |
| **AAAA, AD, NXDOMAIN** | Запись IPv6-адреса (в четыре раза больше записи A); флаг Authenticated Data («данные проверены») из DNSSEC (DNS Security Extensions, расширения безопасности DNS: подписанные записи), который ставит `dig`; RCODE 3, «non-existent domain» (несуществующий домен) — всё из Урока 15.10. |
| **QDCOUNT, ANCOUNT, NSCOUNT, ARCOUNT, RDLENGTH** | Имена полей из RFC 1035: число вопросов, ответов, записей authority и записей additional в заголовке и длина данных ресурса (resource data length) перед данными записи. |
| **I/O** (input/output, ввод-вывод) | Чтение и запись данных, здесь — через сетевой сокет. |
| **код возврата** (exit code) | Число, которое программа возвращает командной оболочке при завершении: 0 при успехе, другие значения при ошибках (Урок 11.5). |

## 1. Как работает резолвер

Ваша программа — маленький **stub-резолвер**: она отправляет один вопрос рекурсивному резолверу, например `1.1.1.1`, и печатает ответ. Сама она по дереву не ходит (это дополнительная цель).

```text
 resolve rust-lang.org --type A
        │
        ▼
 build_query(id, "rust-lang.org", A) ──► 31 bytes ──► UdpSocket.send_to(1.1.1.1:53)
                                                              │
 print records ◄── parse_message(bytes) ◄── 95 bytes ◄── recv_from (3 s timeout)
                         │
                         ├─ header (12 bytes): id, flags, 4 counts
                         ├─ questions:  name, type, class
                         └─ answers / authorities / additionals: records
```

Код разделён на две части, как в Уроке 15.9: **библиотека** (`src/lib.rs`), которая только превращает имена в байты, а байты в структуры, и тонкая **программа** (`src/main.rs`), которая разбирает командную строку и работает с сетью. Библиотека не делает ввода-вывода (I/O), поэтому каждый её байт можно протестировать без сети.

> 🔒 **Безопасность:** DNS-ответ — **недоверенный ввод** из сети. Испорченный или враждебный пакет может заявить 65 535 ответов, метку длиннее самого пакета или указатель на самого себя. На каждый такой пакет ваш парсер должен отвечать `Err` — никогда паникой, зависанием или огромным выделением памяти. Используйте `get()` вместо индексации и никогда не доверяйте полям счётчиков и длин.

## Проект

### Что вы создадите

Утилиту командной строки `resolve`:

```text
$ resolve rust-lang.org
rust-lang.org.	233	A	185.199.109.153
rust-lang.org.	233	A	185.199.111.153
rust-lang.org.	233	A	185.199.108.153
rust-lang.org.	233	A	185.199.110.153
$ resolve rust-lang.org --type MX
rust-lang.org.	60	MX	10 mxa.mailgun.org.
rust-lang.org.	60	MX	10 mxb.mailgun.org.
$ resolve no-such-name.rust-lang.org
error: name does not exist (NXDOMAIN)
```

(TTL и порядок адресов меняются от запуска к запуску: кэш резолвера отсчитывает время, а записи он перемешивает.)

### Контракт

**Командная строка.**

```text
resolve <name> [--type A|AAAA|MX] [--server <ip>]
```

- `<name>`: имя хоста, с последней точкой или без неё. Недопустимые имена (пустые метки, метки длиннее 63 байт, имя длиннее 253 символов, символы кроме букв, цифр, `-` и `_`) отвергаются **до** какой-либо отправки.
- `--type`: `A` (по умолчанию), `AAAA` или `MX`, в верхнем или нижнем регистре.
- `--server`: адрес IPv4 или IPv6 рекурсивного резолвера (по умолчанию `1.1.1.1`); порт всегда 53.
- Исполняемый файл называется `resolve`. Добавьте в `Cargo.toml`:

```toml
[[bin]]
name = "resolve"
path = "src/main.rs"
```

**Вывод и коды возврата.**

| Ситуация | Стандартный вывод | Стандартный поток ошибок | Код возврата |
|---|---|---|---|
| Ответ получен | по строке на каждую запись ответа: `name<TAB>ttl<TAB>type<TAB>data` | — | 0 |
| Имя существует, но записей этого типа нет | `(no records of this type)` | — | 0 |
| RCODE 3 | — | `error: name does not exist (NXDOMAIN)` | 1 |
| Любой другой RCODE | — | `error: server answered with RCODE <n>` | 1 |
| Нет ответа за 3 секунды | — | `error: no answer from <ip>:53 within 3 s` | 1 |
| Выставлен флаг TC | — | `error: answer was truncated (TCP fallback is a stretch goal)` | 1 |
| Неверные аргументы | — | `usage: resolve <name> [--type A\|AAAA\|MX] [--server <ip>]` | 2 |
| Недопустимое имя | — | `error: invalid name: <name>` | 2 |

Имена печатаются с последней точкой. Данные `A`/`AAAA` — адрес в обычном текстовом виде, `CNAME` и `NS` — имя, `MX` — `<preference> <exchange>`. Записи других типов печатаются как `TYPE<n>` с `(<len> bytes)`.

**Сетевое поведение.** Для каждого запроса используйте **случайный** 16-битный ID и выставляйте только флаг RD (`0x0100`). После отправки игнорируйте каждую датаграмму, которая пришла не с адреса сервера, не является ответом (QR = 0) или имеет другой ID, и продолжайте ждать до тайм-аута.

**API библиотеки** (`src/lib.rs`, крейт называется `p15_dns`):

```text
pub enum RecordType { A, Ns, Cname, Mx, Aaaa, Other(u16) }
pub enum DnsError { BadName(String), TooShort, PointerLoop, LabelTooLong, BadData(&'static str) }

pub fn build_query(id: u16, name: &str, qtype: RecordType) -> Result<Vec<u8>, DnsError>;
pub fn read_name(msg: &[u8], pos: usize) -> Result<(String, usize), DnsError>;
pub fn parse_message(msg: &[u8]) -> Result<Message, DnsError>;

pub struct Header { pub id: u16, pub flags: u16, pub qdcount: u16, pub ancount: u16, pub nscount: u16, pub arcount: u16 }
pub struct Question { pub name: String, pub qtype: RecordType, pub class: u16 }
pub struct Record { pub name: String, pub rtype: RecordType, pub class: u16, pub ttl: u32, pub data: RData }
pub enum RData { A(Ipv4Addr), Aaaa(Ipv6Addr), Cname(String), Ns(String), Mx { preference: u16, exchange: String }, Unknown(Vec<u8>) }
pub struct Message { pub header: Header, pub questions: Vec<Question>, pub answers: Vec<Record>, pub authorities: Vec<Record>, pub additionals: Vec<Record> }
```

Это *форма*, а не компилируемый код: добавьте `#[derive(Debug, PartialEq)]` (и `Clone, Copy, Eq` для `RecordType`), `impl Display`, `impl std::error::Error for DnsError` и вспомогательные методы вроде `Header::rcode()` по мере надобности. `read_name` возвращает имя **с** последней точкой и позицию сразу после имени в сообщении.

**Качество.** `cargo test` проходит, `cargo clippy --all-targets` не печатает предупреждений, `cargo fmt --check` чист, в проекте есть `README.md` с примерами использования, и на каждую веху приходится один коммит Git.

### Пошаговый план

#### M1 — Сборка запроса

**Цель:** `build_query(0x7897, "rust-lang.org", RecordType::A)` возвращает ровно 31 байт запроса из Урока 15.10, за исключением флагов `01 00` (мы выставляем только RD; `dig` выставлял ещё и AD).

**Как делать:**

1. Напишите `RecordType` с методом `code()` (A = 1, NS = 2, CNAME = 5, MX = 15, AAAA = 28) и `DnsError`.
2. Напишите приватную `encode_name(name, &mut Vec<u8>)`: уберите одну последнюю точку, проверьте правила контракта (повторно используйте свою `is_valid_name` из Упражнения 3 Урока 15.10, если вы его делали, и разрешите ещё `_`: его используют настоящие имена вроде `_dmarc.example.com`, и контракт его допускает), затем для каждой метки добавьте байт длины и её байты, а в конце — `0`.
3. `build_query` добавляет 12-байтовый заголовок (`id.to_be_bytes()`, флаги `0x0100`, QDCOUNT 1, три нулевых счётчика), закодированное имя, тип и класс `1` — всё в big-endian.
4. Напишите модульный тест в `src/lib.rs`, который сравнивает с ожидаемыми байтами, и ещё один для плохих имён.

<details>
<summary>Подсказка</summary>

Запишите ожидаемые байты так, чтобы их можно было прочитать: `9, b'r', b'u', b's', b't', b'-', b'l', b'a', b'n', b'g', 3, b'o', b'r', b'g', 0`. `u16::to_be_bytes()` возвращает `[u8; 2]`, который добавляет `extend_from_slice(&…)`. Можно использовать `Vec::with_capacity(32)`, но это не обязательно.

</details>

#### M2 — Отправить и получить байты

**Цель:** `src/main.rs` собирает запрос для `rust-lang.org`, отправляет его на `1.1.1.1:53` и печатает, сколько байт вернулось.

**Как делать:**

1. `UdpSocket::bind("0.0.0.0:0")` позволяет ОС (операционной системе) выбрать свободный локальный порт; `set_read_timeout(Some(Duration::from_secs(3)))` ограничивает ожидание.
2. `send_to(&query, server)` отправляет одну датаграмму. Буфера в 512 байт достаточно: это классический предел DNS по UDP без EDNS (Extension Mechanisms for DNS, механизмы расширения DNS, Урок 15.10).
3. `recv_from(&mut buf)` возвращает длину и отправителя. Сравните отправителя с сервером, а первые два байта — со своим ID.
4. Для ID используйте что-то непредсказуемое. Без внешних крейтов `std::hash::RandomState::new().hash_one(std::time::SystemTime::now()) as u16` даёт новое значение при каждом запуске (см. замечание о безопасности в «Частых ошибках»).
5. Напечатайте временную отладочную строку. В M5 вы её замените.

<details>
<summary>Подсказка</summary>

ID — в первых двух байтах: `u16::from_be_bytes([buf[0], buf[1]])`. Если `recv_from` завершается ошибкой из-за тайм-аута, вид ошибки — `WouldBlock` или `TimedOut` в зависимости от ОС; пока просто передайте её дальше через `?`.

</details>

**Готово, когда:**

```bash
cargo run -q -- rust-lang.org
git commit -am "M2: send the query over UDP"
```

```text

```

(Ваш ID каждый раз другой; оба ID должны совпадать. Число полученных байт может измениться, если сайт поменяет свои записи.)

#### M3 — Разбор заголовка и вопроса

**Цель:** `parse_message` читает заголовок и вопросы; ответы пока могут оставаться пустыми.

**Как делать:**

1. Напишите маленький приватный `Reader { msg: &[u8], pos: usize }` с методами `u8()`, `u16()`, `u32()` и `bytes(n)`. Каждый использует `msg.get(…)` и возвращает `Err(DnsError::TooShort)` вместо паники. Все остальные части парсера читают только через него.
2. Разберите шесть полей заголовка, затем `qdcount` вопросов: имя (в этой вехе можно читать только простые метки, без указателей), тип, класс.
3. Создайте `tests/fixtures.rs` с помощником `fixture` и первым тестом на `a.hex`: ID `0x7897`, один вопрос с именем `rust-lang.org.`, `ancount` 4.

<details>
<summary>Подсказка</summary>

`bytes(n)` не должен переполняться: вычислите конец через `self.pos.checked_add(n)`, затем `self.msg.get(self.pos..end)`. Не создавайте `Vec` с ёмкостью, взятой из счётчика в пакете: враждебный `ancount` 65 535 не должен ничего стоить, пока записи реально не существуют.

</details>

**Готово, когда:**

```bash

git commit -am "M3: parse the header and the question"
```


#### M4 — Имена со сжатием

**Цель:** `read_name(msg, pos)` обрабатывает метки, указатели и завершающий байт и возвращает ошибку для любого испорченного имени.

**Как делать:**

1. Прочитайте байт в `pos`. `0` завершает имя. Значение с двумя установленными старшими битами (`b & 0xC0 == 0xC0`) — указатель: смещение равно `((b & 0x3F) << 8) | next_byte`. Значение от 1 до 63 — длина метки. Всё остальное (от 64 до 191) — ошибка.
2. После **первого** указателя запомните `pos + 2`: именно там продолжит вызывающий код, потому что имя в *этом* месте сообщения заканчивается указателем. Метки, прочитанные после прыжка, эту позицию не сдвигают.
3. Защититесь от циклов: указатель должен указывать **назад** (`target < pos`), и число прыжков ограничено (например, 32).
4. Соберите текст: каждая метка, за ней точка. Пустое имя (только байт `0`) — это корень, `"."`.
5. Используйте `read_name` для имён в вопросах и протестируйте её: указатель на себя (`c0 0c` по смещению 12) даёт `PointerLoop`; обрезанная метка даёт `TooShort`.

<details>
<summary>Подсказка</summary>

Держите две переменные: `pos` (где вы читаете сейчас) и `after: Option<usize>` (где продолжит вызывающий код). Возвращайте `after.unwrap_or(pos)`. Минимальное сообщение для теста цикла: двенадцать нулевых байтов, за ними `0xc0, 0x0c`.

</details>

**Готово, когда:**

```bash

git commit -am "M4: names with compression pointers"
```

#### M5 — Записи и командная строка

**Цель:** полный контракт: разобраны все разделы, записи печатаются, работают параметры и коды возврата.

**Как делать:**

1. Запись — это имя, тип, класс, TTL (`u32`), RDLENGTH, затем RDLENGTH байт данных. Сначала прочитайте данные через `bytes(len)`, чтобы позиция всегда была правильной, даже для типов, которых вы не понимаете.
2. Расшифруйте данные по типу: для A нужно ровно 4 байта, для AAAA — ровно 16 (`Ipv4Addr::from([u8; 4])`, `Ipv6Addr::from([u8; 16])`). Для CNAME и NS вызовите `read_name(msg, start)`, где `start` — начало данных: имена внутри данных могут содержать указатели во *всё* сообщение. Для MX — 2-байтовое предпочтение, затем имя с `start + 2`. Остальные типы становятся `Unknown`.
3. Разберите `ancount` ответов, `nscount` записей authority и `arcount` дополнительных записей.
4. `impl Display for Record` в формате контракта (`{name}\t{ttl}\t{type}\t{data}`).
5. В `main`: разберите аргументы вручную (`std::env::args()` и `match` по `"--type"` и `"--server"`), проверьте ответ, как велит контракт, напечатайте ответы и верните `std::process::ExitCode`.

<details>
<summary>Подсказка</summary>

Преобразование среза в массив само проверяет длину: `let b: [u8; 4] = raw.try_into().map_err(|_| DnsError::BadData("A needs 4 bytes"))?;`. Для кода возврата — `fn main() -> ExitCode` и `ExitCode::from(2)`. Чтобы превратить тайм-аут в сообщение из контракта: `.map_err(|_| format!("no answer from {server} within 3 s"))?`. `192.0.2.1` — адрес для документации, который никогда не отвечает, поэтому он идеально подходит для проверки тайм-аута.

</details>

### Дополнительные цели

1. **Итеративное разрешение от корня** (`--trace`). Отправляйте запросы с RD = 0 (флаги `0x0000`), начиная с `198.41.0.4` (`a.root-servers.net`). Если раздел ответов пуст, возьмите записи NS из раздела authority и запись A для одной из них из раздела additional (glue) и спросите следующим этот сервер. Остановитесь, когда получите ответ с флагом AA. Печатайте каждый шаг, как `dig +trace`. Если реферал пришёл без glue, сначала разрешите имя NS (рекурсивный вызов). Ограничьте число шагов.
2. **Переход на TCP.** Когда выставлен TC, отправьте тот же запрос по TCP на порт 53 с 2-байтовой длиной в big-endian впереди и прочитайте ответ так же (`read_exact` для длины, затем для сообщения).
3. **Больше типов записей**: TXT (одна или несколько строк с префиксом длины), SOA (два имени и пять чисел `u32`) и `--type` для них.
4. **Кэш** в долгоживущем режиме (`resolve --repl`): храните ответы в `HashMap<(String, RecordType), (Instant, Vec<Record>)>` и отдавайте их, пока не истёк TTL.
5. **Сравнение с hickory.** Напишите тест (с пометкой `#[ignore]`, потому что ему нужна сеть), который разрешает список имён вашим кодом и `hickory-resolver` (Урок 15.10) и сравнивает множества адресов.
6. **Перехватите собственную фикстуру**: перехватите в контейнере ответ для `crates.io` через `tcpdump -x`, отрежьте первые 28 байт и добавьте для него тест.

## Частые ошибки

**1. Читать следующую запись не с того места после указателя.** Если `read_name` возвращает позицию, где закончилось имя, *к которому прыгнули*, следующее поле читается из середины вопроса, и вы получаете мусорные типы и огромные длины. Позиция после сжатого имени — всегда «сразу после первого указателя», через 2 байта от его начала.

**2. Индексировать через `msg[pos]`.** Тогда один короткий пакет обрушит программу паникой, а в сервере паника на каждый пакет — это отказ в обслуживании. Используйте `get()` везде, через один маленький читатель, чтобы правильно сделать нужно было только в одном месте.

**3. Забыть, что имена внутри данных могут быть сжаты.** Данные CNAME, NS и MX содержат имена, и серверы их сжимают (фикстура MX заканчивается на `c0 16` и `c0 31`). Разбирайте их через `read_name` по **всему сообщению**, а не только по срезу данных: указатель — это смещение от начала сообщения.

**4. Принимать любой ответ.** Если не проверять адрес источника и ID, запоздалый ответ на предыдущий запрос или поддельный ответ будет напечатан как правда. Именно так и работает DNS-спуфинг.

> 🔒 **Безопасность:** ID из `RandomState` годится для учёбы, но это не криптографически случайное число. Настоящий резолвер использует криптографически стойкий генератор (например, крейт `getrandom`) для ID **и** отправляет каждый запрос со случайного порта источника (это вам уже даёт `bind("0.0.0.0:0")`). Вместе они делают подделку ответа очень трудной для угадывания.

## Вопросы для самопроверки

1. Почему библиотека вообще не делает сетевого ввода-вывода?

<details>
<summary>Ответ</summary>

Чтобы вся логика протокола (сборка и разбор байтов) тестировалась без сети, быстро и воспроизводимо на фикстурах. Программа вокруг неё только соединяет библиотеку с сокетом.

</details>

2. Имя в разделе ответов — `c0 0c`. Где начинается следующее поле (тип)?

<details>
<summary>Ответ</summary>

Через два байта после начала имени, сразу после указателя. То, куда ведёт указатель (смещение 12), позицию в ответе не меняет.

</details>

3. Как ваш парсер гарантирует, что цикл указателей не может его повесить?

<details>
<summary>Ответ</summary>

Каждый указатель должен указывать на более раннюю позицию, чем читаемая сейчас, а число прыжков ограничено. Указатель на себя или вперёд отвергается с `PointerLoop`.

</details>

4. Почему в фикстуре CNAME есть `c0 2f` и что находится по смещению `0x2f`?

<details>
<summary>Ответ</summary>

`c0 2f` — указатель на смещение 47, где начинаются данные CNAME: имя `rust-lang.github.io.`. Четыре записи A используют его как своё имя вместо повторения меток.

</details>

5. Почему программе стоит прочитать RDLENGTH байт до расшифровки данных?

<details>
<summary>Ответ</summary>

Чтобы позиция следующей записи всегда была верной (начало данных + RDLENGTH), даже для типов записей, которых программа не понимает, и чтобы слишком большой RDLENGTH был пойман как `TooShort` до расшифровки.

</details>

6. Какой код возврата `resolve` даёт при NXDOMAIN и почему не 0?

<details>
<summary>Ответ</summary>

1. Программа не получила того, о чём её просили, поэтому скрипт, который её использует (`resolve name && connect`), должен увидеть неудачу. Неверное использование возвращает 2 — другой код, чтобы скрипты могли различать эти случаи.

</details>

## Итоги

- Stub-резолвер мал: собрать 12 байт заголовка и вопрос, отправить одну UDP-датаграмму, ждать с тайм-аутом, проверить источник и ID, разобрать.
- Имена на проводе — метки с префиксом длины, заканчивающиеся `0`; байт `0xC0` и выше начинает 2-байтовый указатель сжатия на смещение во всём сообщении.
- После сжатого имени разбор продолжается сразу после первого указателя; указатели должны вести назад, а число прыжков ограничено.
- Каждое чтение идёт через помощников с проверкой границ, поэтому любой испорченный пакет даёт `Err`, а не панику или зависание.
- Настоящие перехваченные пакеты в роли фикстур позволяют тестировать парсер без сети; обрезка их на каждой длине — дешёвая проверка надёжности.
- Разделение на библиотеку и программу, коды возврата и контракт делают утилиту простой для тестирования и использования из скриптов.

## Источники и что почитать

- [RFC 3596 — DNS Extensions to Support IP Version 6](https://www.rfc-editor.org/rfc/rfc3596) — определяет запись AAAA (тип 28).
- [IANA — DNS Parameters](https://www.iana.org/assignments/dns-parameters/dns-parameters.xhtml) — официальный список типов записей, классов и RCODE.
- [std::net::UdpSocket](https://doc.rust-lang.org/std/net/struct.UdpSocket.html) — `bind`, `send_to`, `recv_from` и `set_read_timeout`.
- [Emil Hernvall — Building a DNS server in Rust](https://github.com/EmilHernvall/dnsguide) — бесплатное пошаговое руководство, которое доходит до рекурсивного резолвера и сервера.
