## Новые слова

| Слово | Значение |
|---|---|
| **контрольная точка** (checkpoint) | Остановка в пути, где вы проверяете, что действительно знаете материал, прежде чем идти дальше. |
| **самопроверка** (self-test) | Тест, который вы даёте себе сами, без учителя. |
| **активное воспроизведение** (active recall) | Вспоминание ответа из головы вместо перечитывания. Один из самых сильных способов учиться. |
| **интервальное повторение** (spaced repetition) | Повторение материала снова через растущие промежутки времени (день, неделя, месяц), чтобы он оставался в долговременной памяти. |

1. Чем отличается `let x = 5;` от `let mut x = 5;`? Какую ошибку вы получите, если позже изменить первый `x`?

<details>
<summary>Ответ</summary>

`let x` неизменяема: значение нельзя менять после того, как оно задано. `let mut x` позволяет менять. Изменение неизменяемой переменной даёт `error[E0384]: cannot assign twice to immutable variable`. (Урок 02.1)

</details>

2. Чем отличается затенение (`let x = x + 1;`) от изменения (`x += 1;`)? Что из них позволяет сменить тип?

<details>
<summary>Ответ</summary>

Затенение создаёт **новую** переменную с тем же именем; у неё может быть другой тип (`let spaces = spaces.len();`). Изменение меняет значение **той же** переменной, которая должна быть `mut`, и её тип измениться не может. (Урок 02.1)

</details>

3. Чем `const` отличается от `let`? Напишите константу для числа секунд в сутках.

<details>
<summary>Ответ</summary>

У `const` тип должен быть записан, она вычисляется при компиляции, её можно объявлять вне функций, она никогда не бывает `mut`, а её имя пишется в `SCREAMING_SNAKE_CASE`. Например, `const SECONDS_PER_DAY: u32 = 24 * 60 * 60;`. (Урок 02.1)

</details>

</details>

5. Что напечатают `7 / 2 * 2`, `7 % 4` и `-7 / 2`?

<details>
<summary>Ответ</summary>

`6`, `3` и `-3`. Целочисленное деление отбрасывает дробную часть: `7 / 2 = 3`, затем `3 * 2 = 6`. `7 % 4` — остаток, `3`. `-7 / 2` отбрасывается в сторону нуля, `-3`. (Урок 02.3)

</details>

6. Каковы диапазоны `u8` и `i8`? Что даёт `250_u8.wrapping_add(10)` и что даёт `250_u8.checked_add(10)`?

<details>
<summary>Ответ</summary>

`u8`: от 0 до 255. `i8`: от −128 до 127. `wrapping_add` даёт `4` (заворачивается по кругу). `checked_add` даёт `None` (вместо результата сообщается о переполнении). В отладочной сборке обычное `250_u8 + 10` во время работы паникует с `attempt to add with overflow`; в релизной сборке оно заворачивается в `4`. (Урок 02.2)

</details>

7. Какой тип у `let t = (1, "a", 2.5);` и как прочитать `2.5`? Как получить первый элемент массива `arr`?

<details>
<summary>Ответ</summary>

Это кортеж `(i32, &str, f64)`. `t.2` читает `2.5`. В массиве `arr[0]` — первый элемент. И кортежи, и массивы нумеруются с 0. (Урок 02.2)

</details>

8. Что напечатает `for i in (1..=10).step_by(3) { print!("{i} "); }`? Что изменится, если написать `1..10`?

17. Что такое фича-ветка в Git и зачем делать один коммит на веху? Что делает `git merge --no-ff`?

<details>
<summary>Ответ</summary>

Фича-ветка — это ветка для одной части работы, которая сливается в `main`, когда закончена. Коммит на каждую веху даёт ясную, небольшую историю, которую легко проверять, искать `bisect`-ом и откатывать. `--no-ff` всегда создаёт коммит слияния, поэтому история показывает функцию как единое целое. 18. Чем отличаются `Cargo.toml` и `Cargo.lock` и почему `target/` должна быть в `.gitignore`?

<details>

### Задание 1 — Таблица температур

Напишите `celsius_to_fahrenheit(c: f64) -> f64` и программу, которая печатает таблицу для значений Цельсия −10, 0, 10, 20, 30 и 40, с обоими столбцами, выровненными вправо, и одним знаком после точки. Напишите три теста: 0 °C — это 32 °F, 100 °C — это 212 °F, а −40 одинаково в обеих шкалах.

Ожидаемый вывод:

```text
 Celsius | Fahrenheit
---------+-----------
   -10.0 |       14.0
     0.0 |       32.0
    10.0 |       50.0
    20.0 |       68.0
    30.0 |       86.0
    40.0 |      104.0
```

<details>
<summary>Подсказка</summary>

`for c in (-10..=40).step_by(10)` даёт целые числа; преобразуйте каждое через `as f64`. Заголовки используют `{:>8}` и `{:>10}`; значения используют `{:>8.1}` и `{:>10.1}`. Разделитель можно получить как `{:-<8}-+-{:-<10}`, применённый к двум пустым текстам.

</details>

<details>
<summary>Ответ</summary>

```rust
fn celsius_to_fahrenheit(c: f64) -> f64 {
    c * 9.0 / 5.0 + 32.0
}

fn main() {
    println!("{:>8} | {:>10}", "Celsius", "Fahrenheit");
    println!("{:-<8}-+-{:-<10}", "", "");
    for c in (-10..=40).step_by(10) {
        let c = c as f64;
        println!("{:>8.1} | {:>10.1}", c, celsius_to_fahrenheit(c));
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn freezing_point() {
        assert_eq!(celsius_to_fahrenheit(0.0), 32.0);
    }

    #[test]
    fn boiling_point() {
        assert_eq!(celsius_to_fahrenheit(100.0), 212.0);
    }

    #[test]
    fn minus_forty_is_the_same_in_both_scales() {
        assert_eq!(celsius_to_fahrenheit(-40.0), -40.0);
    }
}
```

Почему это работает: затенение (`let c = c as f64;`) меняет тип `c` без нового имени; спецификаторы формата выравнивают столбцы; а три теста используют значения, которые числа с плавающей точкой хранят точно, поэтому `assert_eq!` безопасен. `cargo test` печатает `test result: ok. 3 passed`.

</details>

### Задание 2 — FizzBuzz как протестированная функция

Напишите `fn fizzbuzz(n: u32) -> String`, которая возвращает `"Fizz"` для кратных 3, `"Buzz"` для кратных 5, `"FizzBuzz"` для кратных обоим и число в виде текста в остальных случаях. `main` печатает результаты для 1–15, по одному на строку. Напишите четыре теста (обычные числа, Fizz, Buzz, FizzBuzz), в каждом по два примера.

<details>
<summary>Подсказка</summary>

Сначала проверяйте кратные 15. Число становится текстом через `n.to_string()` (метод, дающий `String`) или через `format!("{n}")`. Для фиксированных слов возвращайте `String::from("Fizz")`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn fizzbuzz(n: u32) -> String {

        String::from("FizzBuzz")
    } else if n % 3 == 0 {

        String::from("Buzz")

        n.to_string()
    }

fn main() {
    for n in 1..=15 {
        println!("{}", fizzbuzz(n));
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn plain_numbers_stay_numbers() {
        assert_eq!(fizzbuzz(1), "1");
        assert_eq!(fizzbuzz(7), "7");
    }

    #[test]
    fn multiples_of_three_are_fizz() {
        assert_eq!(fizzbuzz(3), "Fizz");
        assert_eq!(fizzbuzz(9), "Fizz");
    }

    #[test]
    fn multiples_of_five_are_buzz() {
        assert_eq!(fizzbuzz(5), "Buzz");
        assert_eq!(fizzbuzz(10), "Buzz");
    }

    #[test]
    fn multiples_of_fifteen_are_fizzbuzz() {
        assert_eq!(fizzbuzz(15), "FizzBuzz");

}
```

Вывод `cargo run` для 1–15: `1`, `2`, `Fizz`, `4`, `Buzz`, `Fizz`, `7`, `8`, `Fizz`, `Buzz`, `11`, `Fizz`, `13`, `14`, `FizzBuzz`, по одному на строку, а `cargo test` печатает `test result: ok. 4 passed`.

Почему это работает: поскольку `fizzbuzz` возвращает текст, а не печатает его, тесты могут его проверить. Цепочка `if` — выражение, поэтому её значение — результат функции.

### Задание 3 — Калькулятор суммы для терминала

Напишите программу, которая читает строки из стандартного ввода до строки `done` или до конца ввода. Каждое корректное целое число (`i64`) добавляется к сумме. О некорректных строках сообщается в **stderr** в виде `skipped "<text>": <reason>`, и они подсчитываются. В конце печатается `accepted N, skipped M, sum = S`. Вынесите разбор в `fn parse_number(text: &str) -> Result<i64, String>` и напишите два теста: один для корректных входных данных (`"42"`, `"  -7\n"`, `"+5"`) и один для некорректных (`"abc"`, `""`, `"1.5"`, `"99999999999999999999"`).

Проверьте так:

```bash
printf '10\nabc\n5\n\n-3\n1.5\ndone\n99\n' | cargo run -q --bin <name>
```

Ожидаемый вывод (первые три строки — в stderr):

```text
skipped "abc": invalid digit found in string
skipped "": cannot parse integer from empty string
skipped "1.5": invalid digit found in string
accepted 3, skipped 3, sum = 12
```

<details>
<summary>Подсказка</summary>

Используйте `loop`, новый `String` на каждой итерации, `bytes == 0` для конца ввода и `line.trim() == "done"` для остановки. `parse_number` может использовать `match text.trim().parse::<i64>()` и собирать текст для `Err` через `format!("{:?}: {e}", text.trim())`.

</details>

<details>
<summary>Ответ</summary>

```rust
use std::io;

fn parse_number(text: &str) -> Result<i64, String> {
    match text.trim().parse::<i64>() {
        Ok(n) => Ok(n),
        Err(e) => Err(format!("{:?}: {e}", text.trim())),
    }
}

fn main() {
    let mut sum = 0i64;
    let mut good = 0;
    let mut bad = 0;
    loop {
        let mut line = String::new();
        let bytes = io::stdin().read_line(&mut line).expect("failed to read a line");
        if bytes == 0 || line.trim() == "done" {
            break;
        }
        match parse_number(&line) {
            Ok(n) => {
                sum += n;
                good += 1;
            }
            Err(message) => {
                eprintln!("skipped {message}");
                bad += 1;
            }
        }
    }
    println!("accepted {good}, skipped {bad}, sum = {sum}");
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn accepts_numbers_with_spaces_and_signs() {
        assert_eq!(parse_number("42"), Ok(42));
        assert_eq!(parse_number("  -7\n"), Ok(-7));
        assert_eq!(parse_number("+5"), Ok(5));
    }

    #[test]
    fn rejects_bad_text() {
        assert!(parse_number("abc").is_err());
        assert!(parse_number("").is_err());
        assert!(parse_number("1.5").is_err());
        assert!(parse_number("99999999999999999999").is_err());
    }
}
```

Почему это работает: `10 + 5 - 3 = 12`; строка `99` после `done` никогда не читается; три плохие строки сообщаются в stderr и подсчитываются; никакой ввод не может заставить программу паниковать. Последний тест показывает число, которое является корректным текстом, но не помещается в `i64`.

</details>

### Задание 4 — Найдите две ошибки

Эта функция должна вычислять `n!` (`5! = 120`, `12! = 479 001 600`). Её тесты падают. (a) Запустите тесты и прочитайте сообщение о падении. (b) Найдите первую ошибку и исправьте её. (c) Добавьте тест `assert_eq!(factorial(13), 6_227_020_800)` и посмотрите, что скажет компилятор. (d) Исправьте вторую ошибку и добавьте тест для `20! = 2_432_902_008_176_640_000`. (e) Сделайте коммит с сообщением `fix(p02): …`.

```rust
fn factorial(n: u32) -> u32 {
    let mut result = 1;
    for i in 1..n {
        result *= i;
    }
    result
}

fn main() {
    println!("5! = {}", factorial(5));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn small_factorials() {
        assert_eq!(factorial(0), 1);
        assert_eq!(factorial(1), 1);
        assert_eq!(factorial(5), 120);
    }

    #[test]
    fn twelve_factorial() {
        assert_eq!(factorial(12), 479_001_600);
    }
}
```

<details>
<summary>Подсказка</summary>

Первое падение показывает `left: 24`, `right: 120`: не хватает последнего множителя, значит, диапазон неверен (Урок 02.5). После этого посмотрите на сообщение компилятора про литерал `6_227_020_800` и подумайте о диапазоне `u32` (Урок 02.2).

</details>

<details>
<summary>Ответ</summary>

(a) Падение:

```text
thread 'tests::small_factorials' panicked at src/main.rs:21:9:
assertion `left == right` failed
  left: 24
 right: 120

thread 'tests::twelve_factorial' panicked at src/main.rs:26:9:
assertion `left == right` failed
  left: 39916800
 right: 479001600
```

(b) Ошибка 1: `1..n` не включает `n` (ошибка на единицу). Используйте `1..=n`; оба теста проходят.

(c) С новым тестом компилятор говорит:

```text
error: literal out of range for `u32`
   = note: the literal `6_227_020_800` does not fit into the type `u32` whose range is `0..=4294967295`
   = note: `#[deny(overflowing_literals)]` on by default
```

(d) Ошибка 2: `u32` слишком мал для `13!`. (Даже без ошибки литерала умножение в отладочной сборке запаниковало бы с `attempt to multiply with overflow`.) Используйте `u64` для параметра и результата. `20!` — наибольший факториал, помещающийся в `u64`.

```rust
fn factorial(n: u64) -> u64 {
    let mut result = 1;
    for i in 1..=n {
        result *= i;
    }
    result
}
```

Тесты (малые, `12!`, `13!` и `20!`) теперь проходят: `test result: ok. 4 passed`.

(e) `git add code/p02-basics && git commit -m "fix(p02): include n in factorial and widen it to u64"`.

Почему это работает: первая ошибка — неверный диапазон, вторая — слишком маленький тип; тесты и компилятор нашли обе, а новые тесты не дадут им вернуться.

</details>

## Что дальше

Теперь вы можете писать настоящие небольшие программы на Rust. Но остался вопрос, которого вы лишь коснулись: почему `read_line` нужен `&mut input` и почему одни функции принимают `&str`, а другие `String`? На него отвечает следующий этап. Он учит **владению и заимствованию** — идее, которая отличает Rust от других языков: кто владеет каждым значением, как значения перемещаются и как безопасно их одалживать. Это самый важный этап стадии 1, и именно здесь многим ученикам нужно немного больше времени. Не торопитесь.

- Дальше: [Этап 03 — Владение и заимствование](../03-ownership-and-borrowing/01-memory-stack-and-heap.md), начиная с Урока 03.1 «Память: стек и куча».
- Необязательная практика перед продолжением (бесплатная): упражнения по первым темам [Rustlings](https://github.com/rust-lang/rustlings) (переменные, функции, `if`, примитивные типы) и упражнения для начинающих трека Rust на [Exercism](https://exercism.org/tracks/rust). Они маленькие, дают автоматическую обратную связь и повторяют то, что вы выучили на этом этапе.
