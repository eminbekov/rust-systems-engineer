# Start here

Welcome! This is a complete, step-by-step course that takes you from **your first line of code**
to working as a **systems engineer**, using the Rust programming language.

You do not need to know anything about programming to start. Every lesson explains its topic from
zero, in simple words. Every abbreviation is written in full and explained. All the content is
here, in these files, so you can study **offline**. Links to the real, official sources are at the
end of each lesson, if you want to check something or go deeper.

---

## What is a systems engineer?

A **systems engineer** builds the software that other software runs on: operating systems,
databases, web servers, networks, containers, cloud platforms and tools for developers. This work
needs three things:

1. a language that is **fast** and gives you **control** over memory — Rust;
2. knowledge of **how computers really work** — memory, processors, operating systems, networks;
3. **engineering habits** — version control, testing, measuring performance, security, clean
   design.

This course teaches all three, in that order.

## How to study

**Follow the links.** At the top and the bottom of every page there is a navigation line:

```
🏠 Start · ← Previous · 📋 Phase · Next → · 📖 Glossary
```

Open a lesson, study it, do the exercises, then click **Next →**. That is all. The order of the
lessons is planned so that each lesson uses only what you learned before.

**Every lesson has the same parts:**

| Part | What it is for |
|---|---|
| What you will learn | The goal of the lesson |
| New words | Every new term and abbreviation, explained |
| Explanation sections | The topic, step by step, with small examples and their output |
| Common mistakes | Typical errors and how to fix them |
| Try it yourself | A guided mini task: type it, run it, see the result |
| Exercises | Tasks from easy to hard. Hints and answers are hidden — click to open them |
| Quiz | Questions to check that you understood |
| Summary | The key ideas to remember |
| Sources and further reading | Links to the official sources |

**Projects** are bigger tasks at the end of most phases. They have a contract (what the program
must do), a step-by-step plan and acceptance tests ("Done when"), but no full solution: you build
them yourself, and you can ask Claude to review your code.

**Checkpoints** close each phase: a self-test, practical tasks and a list of lessons to review if
something was hard.

## Rules that make you learn faster

1. **Type the code yourself.** Do not copy and paste. Typing makes you notice details.
2. **Run everything.** Change the examples and see what happens.
3. **Try for 20–30 minutes before you open a hint.** Open the answer only after you have a
   solution or are really stuck. Struggling a little is part of learning.
4. **Read error messages fully.** They tell you what is wrong and often how to fix it.
5. **Write short notes** after each study session (Lesson 00.8 shows how).
6. **Do not skip checkpoints.** Going back to an earlier lesson is normal and smart.
7. **Ask for help the right way.** Ask Claude for a hint, an explanation or a review, not for the
   finished answer (Lesson 00.7 shows how).

## What you need

- Your Mac and about **10 hours per week** (for example, three evenings of 2 hours and one
  weekend session of 4 hours).
- Internet only for installing tools and downloading libraries. The lessons themselves work
  offline.
- A place for your code: `~/projects/rust/code/`. Every exercise and project gets its own folder,
  for example `code/p02-guessing-game` (`p02` = phase 02). Lesson 00.6 explains this.

**How long does it take?** At about 10 hours per week:

| Stage | Study time | At 10 hours per week |
|---|---|---|
| 1. Foundations | about 230 hours | about 5–6 months |
| 2. Engineering fundamentals | about 210 hours | about 5 months |
| 3. How computers really work | about 135 hours | about 3 months |
| 4. Build real systems | about 200 hours | about 4–5 months |
| 5. Mastery and career | about 260 hours (one specialization track, two capstone projects) | about 6 months |
| **Whole course** | **about 1,040 hours** | **about 2 years** |

At 15–20 hours per week it goes faster. Do not hurry: understanding is more important than speed.
