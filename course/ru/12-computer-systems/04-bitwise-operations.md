## Новые слова

| Слово | Значение |
|---|---|
| **маска** (mask) | Целое число, биты `1` которого отмечают интересующие вас биты. `x & mask` оставляет только их. |
| **установить / сбросить / переключить бит** (set / clear / toggle) | Сделать бит `1` / сделать его `0` / перевернуть его. |
| **флаг** (flag) | Бит, означающий «да» или «нет» для одной настройки, например «владелец может писать». В одно целое число помещается несколько флагов. |
| **битовое поле** (bit field) | Группа соседних битов внутри целого числа, хранящая одно небольшое значение, например красную составляющую цвета. |
| **логический сдвиг** (logical shift) | Сдвиг вправо, который заполняет новые старшие биты нулями. Rust использует его для беззнаковых типов. |
| **арифметический сдвиг** (arithmetic shift) | Сдвиг вправо, который заполняет новые старшие биты копиями знакового бита. Rust использует его для знаковых типов. |
| **циклический сдвиг** (rotation) | Сдвиг, при котором биты, выпавшие с одной стороны, возвращаются с другой. |
| **степень двойки** (power of two) | Число ровно с одним битом `1`: 1, 2, 4, 8, 16 … |
| **выравнивание** (alignment) | Правило, по которому адрес должен быть кратен некоторой степени двойки, например 8. Урок 12.11 объясняет, зачем оно нужно типам. |
| **битовое множество** (bit set) | Множество небольших чисел, хранящееся как биты целого: бит *n* равен `1`, если *n* входит в множество. |

## 1. Маски: работа с отдельными битами

**Маска** — это число, у которого биты `1` стоят ровно там, где вы хотите действовать. Биту с номером *n* (считая с 0 справа) соответствует маска `1 << n`. Вспомните побитовые операторы из Урока 02.3: `&` (AND, «И») даёт бит `1` там, где оба бита равны 1, `|` (OR, «ИЛИ») — где хотя бы один равен 1, `^` (XOR, *exclusive OR*, исключающее ИЛИ) — где ровно один равен 1, а `!` (NOT, «НЕ») переворачивает каждый бит. С маской четыре операции покрывают почти всё:

| Цель | Код | Почему работает |
|---|---|---|
| установить бит *n* | `x \| (1 << n)` | ИЛИ с 1 делает бит единицей; ИЛИ с 0 ничего не меняет |
| сбросить бит *n* | `x & !(1 << n)` | `!` даёт маску с 0 только на месте *n*; И с 0 делает бит нулём |
| переключить бит *n* | `x ^ (1 << n)` | исключающее ИЛИ с 1 переворачивает бит; с 0 ничего не меняет |
| проверить бит *n* | `x & (1 << n) != 0` | И оставляет только этот бит; результат либо 0, либо нет |

```rust
fn main() {
    let mut x: u8 = 0b0000_0101;
    println!("start      {x:08b}");
    x |= 1 << 3;
    println!("set bit 3  {x:08b}");
    x &= !(1 << 0);
    println!("clear 0    {x:08b}");
    x ^= 1 << 7;
    println!("toggle 7   {x:08b}");
    x ^= 1 << 7;
    println!("toggle 7   {x:08b}");
    println!("bit 2 set? {}", x & (1 << 2) != 0);
    println!("bit 1 set? {}", x & (1 << 1) != 0);
    let low_nibble = x & 0x0f;
    let high_nibble = x >> 4;
    println!("nibbles    {high_nibble:04b} {low_nibble:04b}");
}
```

**Что происходит:**

1. `x |= 1 << 3` — короткая форма `x = x | (1 << 3)`. Составные операторы `|=`, `&=` и `^=` работают как `+=`.
2. Двойное переключение бита 7 возвращает его обратно: исключающее ИЛИ отменяет само себя.
3. `x & 0x0f` — маска четырёх младших битов (`0x0f` = `0000_1111`); `x >> 4` опускает вниз четыре старших бита. Вместе они делят байт на два полубайта.
4. В Rust `&` связывает **сильнее**, чем `!=`, поэтому `x & (1 << 2) != 0` означает `(x & (1 << 2)) != 0`. Многие всё равно ставят скобки, чтобы это было очевидно.

```text
start      00000101
set bit 3  00001101
clear 0    00001100
toggle 7   10001100
toggle 7   00001100
bit 2 set? true
bit 1 set? false
nibbles    0000 1100
```

### Флаги: много ответов «да/нет» в одном числе

Права доступа Unix вы знаете по Этапу 11: `rwxr-xr-x` — это восьмеричное число `755`. Каждая восьмеричная цифра — три **флага**: чтение (4 = `100`), запись (2 = `010`) и выполнение (1 = `001`). Три группы (владелец, группа, остальные) стоят рядом, по 3 бита каждая:

```text
mode 0o755:    owner  group  others
bits:           111    101    101
meaning:        rwx    r-x    r-x
bit numbers:   8 7 6  5 4 3  2 1 0
```

```rust
const READ: u32 = 0b100;
const WRITE: u32 = 0b010;
const EXECUTE: u32 = 0b001;

fn describe(mode: u32) {
    let owner = (mode >> 6) & 0b111;
    let group = (mode >> 3) & 0b111;
    let others = mode & 0b111;
    println!(
        "{mode:o}: owner {owner:03b}, group {group:03b}, others {others:03b}; owner can write: {}",
        owner & WRITE != 0
    );
}

fn main() {
    describe(0o755);
    describe(0o640);
    let mode = (READ | WRITE) << 6 | READ << 3;
    println!("built mode = {mode:o}");
    let without_group_read = mode & !(READ << 3);
    println!("without group read = {without_group_read:o}");
    println!("everyone may execute 0o755? {}", 0o755 & (EXECUTE << 6 | EXECUTE << 3 | EXECUTE) == 0o111);
}
```

**Что происходит:**

1. Чтобы прочитать одну группу, сдвиньте её вниз к трём младшим битам и наложите маску `0b111`. Этот приём «сдвиг, затем маска» — способ прочитать любое битовое поле.
2. Чтобы собрать режим, объедините флаги через `|` и сдвиньте каждую группу на её место. `<<` связывает сильнее, чем `|`, поэтому выражение означает `((READ | WRITE) << 6) | (READ << 3)` = `rw-r-----` = `640`.
3. Чтобы убрать одно право, примените И с инвертированной маской этого флага.
4. Чтобы проверить, что установлены **все** из нескольких флагов, наложите маску со всеми ними и сравните с полной маской. (`!= 0` сказало бы только, что установлен **хотя бы один**.)

```text
755: owner 111, group 101, others 101; owner can write: true
640: owner 110, group 100, others 000; owner can write: true
built mode = 640
without group read = 600
everyone may execute 0o755? true
```

> 📏 **Соглашение:** давайте каждому флагу именованную константу (`const WRITE: u32 = 0b010;`), а не пишите в коде магические числа вроде `2`. Для большого числа флагов популярный крейт `bitflags` сгенерирует вам типобезопасный тип флагов.

## 2. Битовые поля: упаковка небольших значений

Тот же приём «сдвиг и маска» работает для значений шире одного бита. Цвет на веб-странице, например `#ff8800`, — это три байта (красный, зелёный и синий), упакованные в одно 24-битное число:

```rust
fn pack(r: u8, g: u8, b: u8) -> u32 {
    (r as u32) << 16 | (g as u32) << 8 | b as u32
}

fn unpack(color: u32) -> (u8, u8, u8) {
    let r = (color >> 16) & 0xff;
    let g = (color >> 8) & 0xff;
    let b = color & 0xff;
    (r as u8, g as u8, b as u8)
}

fn main() {
    let orange = pack(255, 136, 0);
    println!("packed:   {orange:#08x}");
    println!("unpacked: {:?}", unpack(orange));
    println!("unpacked: {:?}", unpack(0x1e90ff));
}
```

**Что происходит:**

1. `pack` сначала расширяет каждый байт до `u32` (`u8`, сдвинутый на 16, переполнился бы), затем ставит его на место: красный — в биты 16–23, зелёный — в биты 8–15, синий остаётся в битах 0–7. Поля не пересекаются, поэтому `|` просто ставит их рядом.
2. `unpack` сдвигает каждое поле вниз и накладывает маску `0xff`, чтобы отрезать всё, что выше.

```text
packed:   0xff8800
unpacked: (255, 136, 0)
unpacked: (30, 144, 255)
```

Битовые поля в системной работе повсюду: заголовки сетевых пакетов (Этап 15), кодирование инструкций процессора (Урок 12.7) и части числа с плавающей точкой, которые вы вырезали в Уроке 12.3.

## 3. Сдвиги подробно

### Логический и арифметический сдвиг вправо

Сдвиг влево всегда заполняет нулями. У сдвига **вправо** два варианта, и Rust выбирает один по типу:

```rust
fn main() {
    let u: u8 = 0b1001_0110;
    let i: i8 = u as i8;
    println!("u8 {u:08b} >> 2 = {:08b}", u >> 2);
    println!("i8 {:08b} >> 2 = {:08b} ({} >> 2 = {})", i, i >> 2, i, i >> 2);
    println!("-7 >> 1 = {}, -7 / 2 = {}", -7i32 >> 1, -7i32 / 2);
    println!("13 << 3 = {} (13 * 8)", 13u32 << 3);
    println!("rotate_left(3):  {:08b}", u.rotate_left(3));
    println!("checked_shl(8):  {:?}", 1u8.checked_shl(8));
    println!("wrapping_shl(9): {}", 1u8.wrapping_shl(9));
}
```

**Что происходит:**

1. Для беззнакового `u8` оператор `>>` — это **логический сдвиг**: слева входят нули.
2. Для знакового `i8` с теми же битами `>>` — это **арифметический сдвиг**: входят копии знакового бита, поэтому отрицательное число остаётся отрицательным. −106 >> 2 — это −27.
3. Сдвиг вправо на *n* делит на 2ⁿ, но для отрицательных чисел округляет **вниз** (к минус бесконечности): −7 >> 1 — это −4, а деление −7 / 2 округляет к нулю и даёт −3.
4. Сдвиг влево на *n* умножает на 2ⁿ (пока биты не выпадают).
5. `rotate_left(3)` переносит три старших бита `100` в правый конец, а не теряет их.
6. Сдвиг `u8` на 8 и больше — переполнение. `checked_shl` возвращает `None`; `wrapping_shl(9)` берёт величину сдвига по модулю 8, поэтому сдвигает на 1.

```text
u8 10010110 >> 2 = 00100101
i8 10010110 >> 2 = 11100101 (-106 >> 2 = -27)
-7 >> 1 = -4, -7 / 2 = -3
13 << 3 = 104 (13 * 8)
rotate_left(3):  10110100
checked_shl(8):  None
wrapping_shl(9): 2
```

> ⚡ **Производительность:** не нужно писать `x << 3` вместо `x * 8` ради скорости: компилятор сам делает эту замену (Урок 12.8 покажет это в ассемблере). Пишите `* 8`, когда имеете в виду умножение, и `<< 3`, когда имеете в виду перемещение битов.

## 4. Встроенные битовые методы и классические приёмы

У каждого целочисленного типа есть методы, которые считают и находят биты. Большинство из них компилируется в одну инструкцию процессора.

```rust
fn main() {
    let x: u32 = 0b0010_1100;
    println!("x                   = {x:032b}");
    println!("count_ones          = {}", x.count_ones());
    println!("leading_zeros       = {}", x.leading_zeros());
    println!("trailing_zeros      = {}", x.trailing_zeros());
    println!("x & (x - 1)         = {:08b}  (lowest 1 cleared)", x & (x - 1));
    println!("x & x.wrapping_neg()= {:08b}  (lowest 1 kept)", x & x.wrapping_neg());
    for n in [1u32, 6, 64, 100] {
        println!("{n:>3}: power of two? {:<5} next power of two: {}", n.is_power_of_two(), n.next_power_of_two());
    }
    println!("swap_bytes(0x12345678) = {:#x}", 0x1234_5678u32.swap_bytes());
}
```

**Что происходит:**

1. `count_ones` считает биты `1` (это называют ещё *population count*). `leading_zeros` считает нули сверху, `trailing_zeros` — снизу. `trailing_zeros` — это номер младшей `1`.
2. `x & (x - 1)` **сбрасывает младший бит `1`**. Вычитание 1 превращает младшую `1` в `0`, а все нули под ней — в единицы; затем И убирает их все. У степени двойки только одна `1`, поэтому для неё результат — 0: так и может работать `is_power_of_two`.
3. `x & x.wrapping_neg()` оставляет **только** младший бит `1` (потому что −x = !x + 1, Урок 12.2).
4. `next_power_of_two` округляет вверх до степени двойки. `Vec` и хеш-таблицы наращивают память степенями двойки.
5. `swap_bytes` переставляет байты в обратном порядке: так число переводят между little-endian и big-endian (Урок 12.1).

```text
x                   = 00000000000000000000000000101100
count_ones          = 3
leading_zeros       = 26
trailing_zeros      = 2
x & (x - 1)         = 00101000  (lowest 1 cleared)
x & x.wrapping_neg()= 00000100  (lowest 1 kept)
  1: power of two? true  next power of two: 1
  6: power of two? false next power of two: 8
 64: power of two? true  next power of two: 64
100: power of two? false next power of two: 128
swap_bytes(0x12345678) = 0x78563412
```

### Округление вверх до кратного степени двойки

Аллокаторам памяти (Урок 12.13) часто нужно округлить адрес вверх до ближайшего кратного 8, 16 или 4096. Когда `align` — степень двойки, `align - 1` — это маска всех младших битов (для 8: `0b111`). Адрес кратен `align` ровно тогда, когда эти младшие биты равны 0. Чтобы округлить вверх:

```text
align_up(addr, align) = (addr + align - 1) & !(align - 1)

example: addr = 13, align = 8
  13 + 7       = 20  = 0b1_0100
  !(8 - 1)     =       ...1_1000   (all bits except the lowest three)
  20 & !7      = 16  = 0b1_0000
```

Прибавление `align - 1` переносит адрес за следующую границу (если он не стоял на ней), а маска срезает его обратно до границы. Вы напишете эту функцию в Упражнении 4.

> 🧪 **Тестирование:** битовые приёмы легко написать «почти правильно». Проверяйте их против медленной очевидной версии: для `align_up` проверьте на тысячах входов, что результат выровнен, не меньше входа и отстоит от него меньше чем на `align`. Проверка таких *свойств* — идея тестирования на основе свойств (Этап 09).

## Частые ошибки

> ⚠️ **Частая ошибка: сдвиг на полную ширину.** Маска из `width` младших битов выглядит простой:

```rust
fn mask_of(width: u32) -> u32 {
    (1 << width) - 1
}

fn main() {
    println!("{:b}", mask_of(4));
    println!("{:b}", mask_of(32));
}
```

```text
1111

thread 'main' (5578658) panicked at src/main.rs:2:5:
attempt to shift left with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

В отладочной сборке сдвиг `u32` на 32 вызывает панику. В релизной сборке программа печатает `1111`, а затем `0`: величина сдвига берётся по модулю 32, поэтому `1 << 32` становится `1 << 0`, и маска «все единицы» молча превращается в ноль. Исправление: обработайте полную ширину отдельно (`if width == 32 { u32::MAX } else { (1 << width) - 1 }`) или используйте `u32::MAX.checked_shr(32 - width).unwrap_or(0)`. Если величина сдвига — константа, компилятор даже остановит вас: `1u32 << 32` даёт `error: this arithmetic operation will overflow`.

> ⚠️ **Частая ошибка: сдвиг до расширения.** `(r << 16) as u32` при `r: u8` сначала сдвигает `u8`, а это переполнение. Сначала расширьте: `(r as u32) << 16`.

> ⚠️ **Частая ошибка: `!` вместо `-`.** `!mask` переворачивает биты; `-mask` — отрицательное число. Для беззнаковых типов `-` даже не компилируется, а для знаковых они отличаются на единицу (`!x == -x - 1`).

## Попробуйте сами

Напечатайте номера всех битов `1` числа с помощью двух приёмов из раздела 4: `trailing_zeros` находит младшую `1`, а `x &= x - 1` убирает её.

```rust
fn main() {
    let mut x: u64 = 0b1010_0110;
    print!("set bits of {x:#b}:");
    while x != 0 {
        print!(" {}", x.trailing_zeros());
        x &= x - 1;
    }
    println!();
}
```

**Что происходит:**

1. Пока осталась хотя бы одна `1`, печатаем номер младшей.
2. Убираем её через `x &= x - 1`. Цикл выполняется один раз на каждый бит `1`, а не на каждую позицию, поэтому он быстр для чисел с небольшим количеством единиц.

```text
set bits of 0b10100110: 1 2 5 7
```

Затем поменяйте число и предскажите вывод до запуска.

## Упражнения

### Упражнение 1 — Предскажите биты (легко)

При `let a: u8 = 0b1100;` предскажите `a | 0b0011`, `a & 0b1010`, `a ^ a`, `!0u8` и `0b1u8 << 4 >> 2` в десятичном виде. Затем проверьте одним `println!`.

<details>
<summary>Подсказка</summary>

Запишите биты друг под другом и примените правило каждого оператора столбец за столбцом. Сдвиги вычисляются слева направо.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let a: u8 = 0b1100;
    println!("{} {} {} {} {}", a | 0b0011, a & 0b1010, a ^ a, !0u8, 0b1u8 << 4 >> 2);
}
```

```text
15 8 0 255 4
```

Почему это работает: `1100 | 0011 = 1111` (15); `1100 & 1010 = 1000` (8); любое значение XOR самого себя — 0; `!0u8` — восемь единиц (255); `1 << 4` — это 16, а `>> 2` даёт 4.

</details>

### Упражнение 2 — Права доступа текстом (средне)

В `src/lib.rs` напишите `pub fn permissions_string(mode: u32) -> String`, которая превращает 9 младших битов режима Unix в текст вида `rwxr-xr-x`. Старшие биты игнорируйте (полный режим из `stat` может быть `0o100644`, где `100` означает «обычный файл»). Напишите тест с `0o755`, `0o640`, `0o000`, `0o777` и `0o100644`.

<details>
<summary>Подсказка</summary>

Пройдите циклом по сдвигам `[6, 3, 0]`. Для каждой группы получите её 3 бита приёмом «сдвиг, затем маска `0b111`» и добавьте `'r'` или `'-'`, `'w'` или `'-'`, `'x'` или `'-'` в зависимости от битов `0b100`, `0b010`, `0b001`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Turns the lowest 9 bits of a Unix mode into text like "rwxr-xr-x".
pub fn permissions_string(mode: u32) -> String {
    let mut text = String::new();
    for shift in [6, 3, 0] {
        let part = (mode >> shift) & 0b111;
        text.push(if part & 0b100 != 0 { 'r' } else { '-' });
        text.push(if part & 0b010 != 0 { 'w' } else { '-' });
        text.push(if part & 0b001 != 0 { 'x' } else { '-' });
    }
    text
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn known_modes() {
        assert_eq!(permissions_string(0o755), "rwxr-xr-x");
        assert_eq!(permissions_string(0o640), "rw-r-----");
        assert_eq!(permissions_string(0o000), "---------");
        assert_eq!(permissions_string(0o777), "rwxrwxrwx");
        assert_eq!(permissions_string(0o100644), "rw-r--r--");
    }
}
```

Почему это работает: каждый сдвиг приводит одну группу к трём младшим битам, а маска `0b111` отрезает всё выше, включая биты типа файла в `0o100644`.

</details>

### Упражнение 3 — Битовое множество (средне)

Напишите тип `pub struct BitSet64(u64)`, хранящий множество чисел от 0 до 63. Дайте ему `new`, `insert`, `remove`, `contains`, `len`, `is_empty`, `union` и `intersection`. `insert(64)` должен паниковать с понятным сообщением. Напишите тесты для insert/contains/remove (включая повторную вставку того же числа), для объединения и пересечения и тест с `#[should_panic]`.

<details>
<summary>Подсказка</summary>

`insert` устанавливает бит *n*, `remove` сбрасывает его, `contains` проверяет, `len` — это `count_ones`. Объединение — `|` двух чисел, пересечение — `&`. Пусть `contains` для `n >= 64` возвращает `false`, а не паникует (и не сдвигает слишком далеко).

</details>

<details>
<summary>Ответ</summary>

```rust
/// A set of the numbers 0 to 63, stored as the bits of one u64.
#[derive(Debug, Default, Clone, Copy, PartialEq, Eq)]
pub struct BitSet64(u64);

impl BitSet64 {
    pub fn new() -> Self {
        BitSet64(0)
    }

    pub fn insert(&mut self, n: u32) {
        assert!(n < 64, "only 0 to 63 fit");
        self.0 |= 1 << n;
    }

    pub fn remove(&mut self, n: u32) {
        assert!(n < 64, "only 0 to 63 fit");
        self.0 &= !(1 << n);
    }

    pub fn contains(&self, n: u32) -> bool {
        n < 64 && self.0 & (1 << n) != 0
    }

    pub fn len(&self) -> u32 {
        self.0.count_ones()
    }

    pub fn is_empty(&self) -> bool {
        self.0 == 0
    }

    pub fn union(self, other: BitSet64) -> BitSet64 {
        BitSet64(self.0 | other.0)
    }

    pub fn intersection(self, other: BitSet64) -> BitSet64 {
        BitSet64(self.0 & other.0)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn insert_contains_remove() {
        let mut set = BitSet64::new();
        assert!(set.is_empty());
        set.insert(0);
        set.insert(5);
        set.insert(63);
        set.insert(5);
        assert_eq!(set.len(), 3);
        assert!(set.contains(5) && set.contains(63) && !set.contains(4));
        assert!(!set.contains(100));
        set.remove(5);
        assert!(!set.contains(5));
        assert_eq!(set.len(), 2);
    }

    #[test]
    fn union_and_intersection() {
        let mut a = BitSet64::new();
        let mut b = BitSet64::new();
        for n in [1, 2, 3] {
            a.insert(n);
        }
        for n in [3, 4] {
            b.insert(n);
        }
        assert_eq!(a.union(b).len(), 4);
        let both = a.intersection(b);
        assert_eq!(both.len(), 1);
        assert!(both.contains(3));
    }

    #[test]
    #[should_panic(expected = "only 0 to 63 fit")]
    fn rejects_64() {
        BitSet64::new().insert(64);
    }
}
```

Почему это работает: один `u64` хранит 64 ответа «да/нет», по одному на число. Операции над множествами становятся одиночными инструкциями: `|` для объединения, `&` для пересечения. В `contains` оператор `&&` останавливается до сдвига, когда `n >= 64`, поэтому сдвиг никогда не переполняется. Clippy требует `is_empty`, когда у типа есть `len`, поэтому он здесь есть.

</details>

### Упражнение 4 — Выравнивание вверх (сложно)

Напишите `pub fn align_up(addr: usize, align: usize) -> usize` и `pub fn is_aligned(addr: usize, align: usize) -> bool` для `align`, являющегося степенью двойки (иначе — паника). Тесты: `align_up(13, 16)` = 16, `align_up(8, 8)` = 8, `align_up(0, 8)` = 0, `align_up(4097, 4096)` = 8192; тест свойств на множестве входов; тест с `#[should_panic]` для `align = 12`.

<details>
<summary>Подсказка</summary>

Используйте формулу из раздела 4. Для `is_aligned` младшие биты `addr & (align - 1)` должны быть нулями. Для теста свойств пройдите циклом по нескольким выравниваниям и адресам `0..10_000` и проверьте три вещи: результат выровнен, он не меньше `addr` и отстоит от него меньше чем на `align`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Rounds `addr` up to the next multiple of `align` (a power of two).
pub fn align_up(addr: usize, align: usize) -> usize {
    assert!(align.is_power_of_two(), "align must be a power of two");
    (addr + align - 1) & !(align - 1)
}

/// True if `addr` is a multiple of `align` (a power of two).
pub fn is_aligned(addr: usize, align: usize) -> bool {
    assert!(align.is_power_of_two(), "align must be a power of two");
    addr & (align - 1) == 0
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn align_examples() {
        assert_eq!(align_up(0, 8), 0);
        assert_eq!(align_up(1, 8), 8);
        assert_eq!(align_up(8, 8), 8);
        assert_eq!(align_up(13, 16), 16);
        assert_eq!(align_up(4097, 4096), 8192);
        assert!(is_aligned(4096, 4096));
        assert!(!is_aligned(4100, 8));
    }

    #[test]
    fn align_up_properties() {
        for align in [1usize, 2, 4, 8, 64, 4096] {
            for addr in 0..10_000 {
                let up = align_up(addr, align);
                assert!(up >= addr && up - addr < align && is_aligned(up, align));
            }
        }
    }

    #[test]
    #[should_panic(expected = "power of two")]
    fn align_must_be_power_of_two() {
        align_up(10, 12);
    }
}
```

```text

test tests::align_examples ... ok
test tests::align_must_be_power_of_two - should panic ... ok
test tests::align_up_properties ... ok

test result: ok. 3 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

Почему это работает: для степени двойки `align - 1` — маска младших битов, а `!(align - 1)` их сбрасывает, что округляет вниз до кратного; предварительное прибавление `align - 1` превращает «вниз» во «вверх». При `align = 12` приём с маской был бы неверен (12 — это `1100`, поэтому `11` — не маска младших битов), и функция его отвергает. Одно ограничение остаётся: `addr + align - 1` может переполниться для адресов около `usize::MAX`; настоящие аллокаторы используют там `checked_add`.

</details>

## Вопросы для самопроверки

1. Как сбросить бит 5 в `x`?

<details>
<summary>Ответ</summary>

`x & !(1 << 5)` (или `x &= !(1 << 5)`).

</details>

2. Что даёт `(x >> 8) & 0xff` при `x = 0x00ab_cdef`?

<details>
<summary>Ответ</summary>

`0xcd`: сдвиг опускает второй байт вниз, маска оставляет только этот байт.

</details>

3. Чем отличаются `0b1000_0000u8 >> 1` и `0b1000_0000u8 as i8 >> 1`?

<details>
<summary>Ответ</summary>

Сдвиг `u8` логический и даёт `0b0100_0000` (64). Сдвиг `i8` арифметический, копирует знаковый бит и даёт `0b1100_0000` (−64).

</details>

4. Почему `x & (x - 1) == 0` верно для степеней двойки?

<details>
<summary>Ответ</summary>

У степени двойки ровно один бит `1`, а `x & (x - 1)` сбрасывает младший бит `1`, и ничего не остаётся. (Это верно и для `x = 0`, который степенью двойки не является; `is_power_of_two` обрабатывает этот случай.)

</details>

5. Что происходит с `1u32 << n` при `n`, равном 32, в отладочной и в релизной сборке?

<details>
<summary>Ответ</summary>

Отладка: паника «attempt to shift left with overflow». Релиз: величина сдвига берётся по модулю 32, поэтому результат — `1 << 0` = 1, молча.

</details>

6. Почему `align_up` работает, только когда `align` — степень двойки?

<details>
<summary>Ответ</summary>

Только тогда `align - 1` — маска всех младших битов (например, `0b111` для 8), и сброс этих битов даёт число, кратное `align`.

</details>

## Итоги

- Маска отмечает нужные биты: `| mask` устанавливает, `& !mask` сбрасывает, `^ mask` переключает, `& mask != 0` проверяет.
- Много флагов или небольших значений помещается в одно целое число. Поле читают приёмом «сдвиг, затем маска», записывают — «сдвиг на место, затем ИЛИ».
- `>>` логический для беззнаковых типов и арифметический для знаковых. Сдвиг на полную ширину и больше — переполнение: в отладке паника, в релизе молча используется величина по модулю ширины.
- Встроенные методы (`count_ones`, `leading_zeros`, `trailing_zeros`, `is_power_of_two`, `next_power_of_two`, `rotate_left`, `swap_bytes`) быстрые и понятные; используйте их вместо самописных циклов.
- `x & (x - 1)` сбрасывает младшую `1`; `(addr + align - 1) & !(align - 1)` округляет вверх до выравнивания по степени двойки.
- Проверяйте битовые приёмы очевидными свойствами на множестве входов.
