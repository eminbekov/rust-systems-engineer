## Новые слова

| Слово | Значение |
|---|---|
| **основание** (base, radix) | Сколько разных цифр использует система счисления. У десятичной основание 10, у двоичной 2, у шестнадцатеричной 16, у восьмеричной 8. |
| **позиционная система счисления** (positional number system) | Система, в которой значение цифры зависит от её места. В числе 352 тройка означает 3 сотни. |
| **шестнадцатеричная система** (hexadecimal, hex) | Основание 16. Цифры `0`–`9` и `a`–`f` (a = 10 … f = 15). Одна шестнадцатеричная цифра — ровно 4 бита. |
| **восьмеричная система** (octal) | Основание 8. Цифры `0`–`7`. Одна восьмеричная цифра — ровно 3 бита. Используется для прав доступа к файлам в Unix. |
| **полубайт** (nibble) | Половина байта: 4 бита, одна шестнадцатеричная цифра. |
| **старший / младший бит** (most / least significant bit) | Бит с наибольшим весом разряда (слева) / с наименьшим (справа, вес 1). Биты нумеруются с 0 справа. |
| **машинное слово** (word) | Естественный размер числа для CPU (Central Processing Unit, центральный процессор). У 64-битного процессора слово — 64 бита; такой размер у `usize`. |
| **KiB, MiB, GiB** | Двоичные единицы размера от IEC (International Electrotechnical Commission, Международная электротехническая комиссия): 1 KiB = 1024 байта, 1 MiB = 1024 KiB, 1 GiB = 1024 MiB. |
| **KB, MB, GB** | Десятичные единицы размера из SI (International System of Units, Международная система единиц): 1 KB = 1000 байт, 1 MB = 1000 KB. |
| **порядок байтов** (byte order, endianness) | Порядок, в котором байты многобайтового числа лежат в памяти или в файле. |
| **little-endian** (от младшего к старшему) | Младший байт идёт первым (по наименьшему адресу). Так работают ваш Mac и компьютеры x86-64. |
| **big-endian** (от старшего к младшему) | Старший байт идёт первым. Его используют сетевые протоколы и многие форматы файлов, поэтому его называют ещё *сетевым порядком байтов*. |
| **магическое число** (magic number) | Несколько фиксированных байтов в начале файла, которые говорят, какой это формат. |

## 1. Одна идея, много оснований

В Уроке 00.3 вы уже читали двоичные числа, складывая веса разрядов. Вот общее правило, которое за этим стоит.

В **позиционной системе счисления** с основанием *b* каждый разряд весит в *b* раз больше разряда справа. Самый правый разряд весит 1. Поэтому число — это сумма «цифра × вес разряда»:

```text
base 10:   352      = 3×100 + 5×10 + 2×1                    = 352
base 2:    11001010 = 1×128 + 1×64 + 0×32 + 0×16
                    + 1×8   + 0×4  + 1×2  + 0×1             = 202
base 16:   ca       = 12×16 + 10×1                          = 202
base 8:    312      = 3×64  + 1×8  + 2×1                    = 202
```

У одного и того же числа 202 четыре разных записи. Число не меняется, меняется только способ его записать. Компьютер всегда хранит биты. «Десятичное» или «шестнадцатеричное» — это лишь вопрос того, как человек их читает или пишет.

### Из десятичной в любую систему: делим и запоминаем остатки

Урок 00.3 показал способ «возьмите самый большой вес разряда, который помещается». Второй способ работает для любого основания и легко превращается в код: **делите на основание снова и снова и записывайте остатки**. Остатки, прочитанные от последнего к первому, и есть цифры.

```text
202 in binary:                    202 in hex:
202 / 2 = 101  remainder 0        202 / 16 = 12  remainder 10 → a
101 / 2 =  50  remainder 1         12 / 16 =  0  remainder 12 → c
 50 / 2 =  25  remainder 0        read upwards:  ca
 25 / 2 =  12  remainder 1
 12 / 2 =   6  remainder 0
  6 / 2 =   3  remainder 0
  3 / 2 =   1  remainder 1
  1 / 2 =   0  remainder 1
read upwards: 11001010
```

Почему это работает? Остаток от деления на 2 — это значение последней двоичной цифры (нечётное ли число?). Деление на 2 отбрасывает эту цифру и сдвигает остальные на один разряд вправо. Затем всё повторяется.

### Из двоичной в шестнадцатеричную и обратно: группы по четыре

Поскольку 16 = 2⁴, одна шестнадцатеричная цифра — это ровно четыре бита (**полубайт**). Чтобы перевести число, разрежьте двоичную запись на группы по четыре бита справа и замените каждую группу:

```text
binary:  1100 1010        hex digit table (memorise the first and last rows):
hex:        c    a        0000=0 0001=1 0010=2 0011=3 0100=4 0101=5 0110=6 0111=7
                          1000=8 1001=9 1010=a 1011=b 1100=c 1101=d 1110=e 1111=f
```

Тот же приём работает для восьмеричной системы с группами по **три** бита, потому что 8 = 2³: `011 001 010` — это `3 1 2`, восьмеричное 312.

Вот почему системные инженеры любят шестнадцатеричную запись: байт — это всегда ровно две шестнадцатеричные цифры (от `00` до `ff`), 32-битное число — восемь цифр, и при этом при необходимости видно каждый бит.

Восьмеричная система сегодня встречается редко, с одним важным исключением, знакомым вам по Этапу 11: права доступа к файлам в Unix. В `chmod 755` каждая восьмеричная цифра — это три бита `rwx` (read, write, execute — чтение, запись, выполнение): `7` = `111` = `rwx`, `5` = `101` = `r-x`.

## 2. Системы счисления в Rust

Вы умеете *записывать* литералы в других системах (`0b…`, `0o…`, `0xff`). Теперь научимся их *печатать* и *разбирать*. Поместите это в `src/main.rs` пакета `code/p12-bits`:

```rust
fn main() {
    let n: u32 = 202;
    println!("decimal: {n}");
    println!("binary:  {n:b}");
    println!("octal:   {n:o}");
    println!("hex:     {n:x}  {n:X}");
    println!("with prefixes: {n:#b} {n:#o} {n:#x}");
    println!("padded:  {n:#010b} {n:08b} {n:04x}");

    let from_bin = u32::from_str_radix("11001010", 2).unwrap();
    let from_hex = u32::from_str_radix("ca", 16).unwrap();
    let from_oct = u32::from_str_radix("312", 8).unwrap();
    println!("parsed:  {from_bin} {from_hex} {from_oct}");

    println!("digit 'c' in base 16 = {:?}", 'c'.to_digit(16));
    println!("digit 'c' in base 10 = {:?}", 'c'.to_digit(10));
    println!("number 11 as a base-16 digit = {:?}", char::from_digit(11, 16));
}
```

**Что происходит:**

1. `{n:b}`, `{n:o}`, `{n:x}` и `{n:X}` печатают число в двоичной, восьмеричной и шестнадцатеричной системе (строчными или заглавными буквами). Это работает для всех целочисленных типов.
2. `#` добавляет префикс `0b`, `0o` или `0x` — те же префиксы, что у литералов Rust.
3. `{n:#010b}` означает: префикс, ширина 10 **вместе с префиксом**, заполнение нулями. `{n:08b}` — 8 цифр без префикса, обычный способ показать один байт. `{n:04x}` — 4 шестнадцатеричные цифры.
4. `u32::from_str_radix(text, base)` разбирает текст, записанный в заданной системе (от 2 до 36). Он возвращает `Result`, потому что текст может быть неправильным; здесь мы знаем, что он правильный, поэтому `unwrap` допустим.
5. `char::to_digit(base)` превращает один символ-цифру в её значение или возвращает `None`, если это не цифра данной системы. `char::from_digit(value, base)` делает обратное.

```text
decimal: 202
binary:  11001010
octal:   312
hex:     ca  CA
with prefixes: 0b11001010 0o312 0xca
padded:  0b11001010 11001010 00ca
parsed:  202 202 202
digit 'c' in base 16 = Some(12)
digit 'c' in base 10 = None
number 11 as a base-16 digit = Some('b')
```

> 📏 **Соглашение:** печатайте байты двумя шестнадцатеричными цифрами (`{:02x}`), а целый срез байтов — через `{:02x?}`, который вы используете ниже. В длинных двоичных литералах группируйте биты по четыре через `_`: `0b1100_1010`.

## 3. Степени двойки и размеры

Из *n* битов можно составить 2ⁿ разных комбинаций. Некоторые степени двойки встречаются так часто, что их стоит знать наизусть:

```rust
fn main() {
    for p in [8, 10, 16, 20, 30, 32, 40] {
        println!("2^{p:<2} = {}", 1u64 << p);
    }
    println!("u32 has {} bits, u64 has {} bits", u32::BITS, u64::BITS);
    println!("usize has {} bits on this computer", usize::BITS);
    for n in [1u32, 255, 256, 1000, 1_000_000] {
        let bits_needed = n.ilog2() + 1;
        println!("{n:>9} needs {bits_needed:>2} bits: {n:b}");
    }
}
```

**Что происходит:**

1. `1u64 << p` сдвигает бит `1` влево на `p` разрядов. Каждый разряд влево удваивает значение, поэтому получается 2ᵖ (сдвиги появились в Уроке 02.3; Урок 12.4 использует их очень много).
2. `u32::BITS` — константа: число битов в типе. `usize::BITS` на вашем Mac равно 64, потому что `usize` имеет размер **машинного слова** 64-битного процессора.
3. `n.ilog2()` — целочисленный логарифм по основанию 2: номер старшего бита `1`, считая с 0. Прибавив 1, получаем число битов, нужных для записи `n`. (Для 0 он паникует, потому что у 0 нет ни одного бита `1`.)

```text
2^8  = 256
2^10 = 1024
2^16 = 65536
2^20 = 1048576
2^30 = 1073741824
2^32 = 4294967296
2^40 = 1099511627776
u32 has 32 bits, u64 has 64 bits
usize has 64 bits on this computer
        1 needs  1 bits: 1
      255 needs  8 bits: 11111111
      256 needs  9 bits: 100000000
     1000 needs 10 bits: 1111101000
  1000000 needs 20 bits: 11110100001001000000
```

### KiB или KB?

2¹⁰ = 1024 очень близко к 1000. Долгое время словом «килобайт» называли и то и другое, и это путало людей. Сегодня есть два набора единиц:

| Двоичная единица (IEC) | Байтов | Десятичная единица (SI) | Байтов |
|---|---|---|---|
| 1 KiB (кибибайт) | 2¹⁰ = 1 024 | 1 KB (килобайт) | 10³ = 1 000 |
| 1 MiB (мебибайт) | 2²⁰ = 1 048 576 | 1 MB (мегабайт) | 10⁶ = 1 000 000 |
| 1 GiB (гибибайт) | 2³⁰ = 1 073 741 824 | 1 GB (гигабайт) | 10⁹ = 1 000 000 000 |
| 1 TiB (тебибайт) | 2⁴⁰ ≈ 1,10 × 10¹² | 1 TB (терабайт) | 10¹² |

Разница растёт с размером: 1 TiB примерно на 10% больше, чем 1 TB. Размеры памяти почти всегда — степени двойки (страница памяти, кэш), поэтому на этом этапе мы используем KiB и MiB. Например, `sysctl hw.l1dcachesize` на Apple M4 Pro печатает `65536` — ровно 64 KiB (это кэш данных первого уровня одного энергоэффективного ядра; `sysctl hw.perflevel0.l1dcachesize` показывает `131072`, 128 KiB, у производительных ядер — эти кэши объясняет Урок 12.9). Производители дисков обычно используют десятичные единицы, поэтому диск на «1 TB» показывается как примерно 931 GiB.

> 💡 **Совет:** некоторые инструменты пишут «K» или «KB», а имеют в виду 1024. Kubernetes здесь аккуратен: `128Mi` означает 128 MiB, а `128M` — 128 MB. Когда число важно, проверьте, какую единицу использует инструмент.

## 4. Порядок байтов: какой байт идёт первым?

Память — это ряд пронумерованных байтов (Урок 03.1). `u32` занимает 4 байта, и вопрос в том, **в каком порядке эти 4 байта кладутся в 4 ячейки?** Ответов два, и используются оба.

```text
the number 0x12345678 (four bytes: 12 34 56 78)

address:        100  101  102  103
little-endian:   78   56   34   12     ← least significant byte first (your Mac, x86-64)
big-endian:      12   34   56   78     ← most significant byte first (networks, many file formats)
```

Внутри одной работающей программы порядок байтов незаметен: процессор правильно читает свои собственные числа. Он важен на **границах**: когда вы записываете числа в файл или сетевой пакет или читаете байты, созданные другой программой. Тогда обе стороны должны договориться о порядке. Rust делает порядок явным:

```rust
fn main() {
    let n: u32 = 0x1234_5678;
    println!("number:        {n:#010x}");
    println!("little-endian: {:02x?}", n.to_le_bytes());
    println!("big-endian:    {:02x?}", n.to_be_bytes());
    println!("native:        {:02x?}", n.to_ne_bytes());
    println!("this computer is little-endian: {}", cfg!(target_endian = "little"));

    let bytes = [0x00, 0x00, 0x01, 0x2c];
    let as_big = u32::from_be_bytes(bytes);
    let as_little = u32::from_le_bytes(bytes);
    println!("{bytes:02x?} read as big-endian    = {as_big}");
    println!("{bytes:02x?} read as little-endian = {as_little}");
}
```

**Что происходит:**

1. `to_le_bytes` возвращает массив `[u8; 4]` в порядке little-endian, `to_be_bytes` — в порядке big-endian. `to_ne_bytes` использует **родной** (native) порядок компьютера, на котором работает программа.
2. `cfg!(target_endian = "little")` равно `true`, когда программа скомпилирована для целевой платформы с порядком little-endian. Это известно во время компиляции.
3. `from_be_bytes` и `from_le_bytes` собирают число из 4 байтов. **Одни и те же четыре байта** дают 300 или 738 263 040 в зависимости от того, какой порядок вы предполагаете. Неправильный порядок не роняет программу — он молча даёт неверное число.

```text
number:        0x12345678
little-endian: [78, 56, 34, 12]
big-endian:    [12, 34, 56, 78]
native:        [78, 56, 34, 12]
this computer is little-endian: true
[00, 00, 01, 2c] read as big-endian    = 300
[00, 00, 01, 2c] read as little-endian = 738263040
```

Это та самая деталь, которую Урок 00.3 отложил на потом: инструкция `add w0, w1, w0` — это 32-битное число `0x0b000020`, а в файле программы она хранится как байты `20 00 00 0b`. Это little-endian.

> 🔒 **Безопасность:** байты из файла или из сети — это ввод извне. Проверяйте длину, прежде чем читать из них число: `u32::from_be_bytes` нужно ровно 4 байта, а превращение среза в `[u8; 4]` через `try_into()` вернёт ошибку, если срез короче. Никогда не считайте, что поле длины в пакете честное.

> 🧪 **Тестирование:** для кода, который читает или пишет байты, напишите **тест туда-обратно** (round-trip): превратите значение в байты и обратно и проверьте, что получилось то же значение (`assert_eq!(u32::from_be_bytes(n.to_be_bytes()), n)`). Добавьте один тест с фиксированными байтами, записанными вручную, — тогда неправильный порядок байтов провалит тест.

## Частые ошибки

> ⚠️ **Частая ошибка: префикс в `from_str_radix`.** Текст должен содержать только цифры. Префикс `0x` — не шестнадцатеричная цифра:

```rust
fn main() {
    println!("{:?}", u32::from_str_radix("0xff", 16));
    println!("{:?}", u32::from_str_radix("ff", 16));
    println!("{:?}", u8::from_str_radix("100000000", 2));
}
```

```text
Err(ParseIntError { kind: InvalidDigit })
Ok(255)
Err(ParseIntError { kind: PosOverflow })
```

Сначала уберите префикс, например через `text.trim_start_matches("0x")`. Третья строка показывает другую частую ошибку: девять битов не помещаются в `u8`, поэтому результат — `PosOverflow` (positive overflow, переполнение в положительную сторону).

> ⚠️ **Частая ошибка: родной порядок в файлах.** `to_ne_bytes` годится для данных, которые остаются внутри одной программы, но файл, записанный так на вашем Mac, компьютер с порядком big-endian правильно не прочитает. Для файлов и сетевых данных всегда выбирайте `to_le_bytes` или `to_be_bytes` сознательно и записывайте этот выбор в описание формата.

> ⚠️ **Частая ошибка: путать KB и KiB.** «Кэш — 64 KB» может означать 64 000 или 65 536 байт. В коде записывайте размеры как `64 * 1024` или `1 << 16`, но никогда как `64000`.

## Попробуйте сами

Соберите маленький шестнадцатеричный дамп, как инструмент `xxd` из Урока 00.3. Поместите это в `src/main.rs`:

```rust
fn hexdump(data: &[u8]) {
    for (line, chunk) in data.chunks(8).enumerate() {
        let offset = line * 8;
        print!("{offset:08x}: ");
        for byte in chunk {
            print!("{byte:02x} ");
        }
        for _ in chunk.len()..8 {
            print!("   ");
        }
        let text: String = chunk
            .iter()
            .map(|&b| if b.is_ascii_graphic() || b == b' ' { b as char } else { '.' })
            .collect();
        println!(" {text}");
    }
}

fn main() {
    hexdump("Hi, bytes!\n".as_bytes());
    hexdump(&0x1234_5678_u32.to_le_bytes());
}
```

**Что происходит:**

1. `data.chunks(8)` режет байты на куски не длиннее 8; `enumerate` нумерует куски, поэтому смещение строки равно `line * 8` и печатается восемью шестнадцатеричными цифрами.
2. Каждый байт печатается двумя шестнадцатеричными цифрами. Короткая последняя строка дополняется пробелами, чтобы текстовая колонка оставалась ровной.
3. Текстовая колонка показывает байт как символ, если это видимый символ ASCII или пробел, и как `.` в остальных случаях (например, перевод строки `0a`). ASCII (American Standard Code for Information Interchange, американский стандартный код для обмена информацией) — старая таблица, которая даёт каждой английской букве, цифре и знаку препинания номер от 0 до 127; Урок 12.5 подробно объясняет её.

Запустите `cargo run`:

```text
00000000: 48 69 2c 20 62 79 74 65  Hi, byte
00000008: 73 21 0a                 s!.
00000000: 78 56 34 12              xV4.
```

Теперь замените `to_le_bytes` на `to_be_bytes` и предскажите последнюю строку до запуска.

## Упражнения

### Упражнение 1 — Перевод вручную (легко)

Без компьютера переведите: 45 в двоичную и шестнадцатеричную системы; `0x3f` в десятичную; `0b1011_0110` в шестнадцатеричную; `0b111_101_101` в восьмеричную. Затем проверьте ответы маленькой программой, которая их печатает.

<details>
<summary>Подсказка</summary>

Для 45 используйте способ «делим на 2». Из двоичной в шестнадцатеричную — режьте на группы по четыре бита справа; в восьмеричную — на группы по три.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("{:b} {:x}", 45, 45);
    println!("{}", 0x3f);
    println!("{:x}", 0b1011_0110);
    println!("{:o}", 0b111_101_101);
}
```

```text
101101 2d
63
b6
755
```

Почему это работает: 45 = 32 + 8 + 4 + 1 = `101101`; группами по четыре `0010 1101` = `2d`. `0x3f` = 3×16 + 15 = 63. `1011 0110` = `b6`. `111 101 101` = `7 5 5`, права `rwxr-xr-x`.

</details>

### Упражнение 2 — Свой конвертер систем счисления (средне)

В `src/lib.rs` напишите `pub fn to_base(n: u64, base: u32) -> String` для оснований от 2 до 36 (цифры `0`–`9`, затем `a`–`z`). Напишите тест, который сравнивает вашу функцию со встроенным форматированием Rust (`{:b}`, `{:o}`, `{:x}`, `to_string`) на нескольких числах, включая `0` и `u64::MAX`, и тест для основания 36.

<details>
<summary>Подсказка</summary>

Используйте способ «делим и запоминаем остатки» из раздела 1. `char::from_digit(rest, base)` даёт символ цифры. Цифры получаются в обратном порядке; соберите их и разверните. Обработайте `0` отдельно.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Writes `n` in the given base (2 to 36), using digits 0-9 and then a-z.
pub fn to_base(mut n: u64, base: u32) -> String {
    assert!((2..=36).contains(&base), "base must be from 2 to 36");
    if n == 0 {
        return "0".to_string();
    }
    let mut digits = Vec::new();
    while n > 0 {
        let rest = (n % base as u64) as u32;
        digits.push(char::from_digit(rest, base).unwrap());
        n /= base as u64;
    }
    digits.iter().rev().collect()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn matches_rust_formatting() {
        for n in [0u64, 1, 2, 7, 255, 256, 1000, u64::MAX] {
            assert_eq!(to_base(n, 2), format!("{n:b}"));
            assert_eq!(to_base(n, 8), format!("{n:o}"));
            assert_eq!(to_base(n, 16), format!("{n:x}"));
            assert_eq!(to_base(n, 10), n.to_string());
        }
    }

    #[test]
    fn base_36_round_trip() {
        let text = to_base(1_000_000, 36);
        assert_eq!(text, "lfls");
        assert_eq!(u64::from_str_radix(&text, 36), Ok(1_000_000));
    }
}
```

```text
running 2 tests
test tests::base_36_round_trip ... ok
test tests::matches_rust_formatting ... ok

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

Почему это работает: каждое `n % base` — это младшая цифра, а каждое `n /= base` её убирает, в точности как в таблице деления из раздела 1. Тест использует стандартную библиотеку как надёжный «оракул» (заведомо правильный ответ для сравнения), а `from_str_radix` проверяет путь туда и обратно.

</details>

### Упражнение 3 — Читаем заголовок файла (средне)

Выдуманный формат файла начинается с 6 байтов: версия `u16` в порядке big-endian, затем длина `u32` в порядке big-endian. Напишите `pub fn parse_header(bytes: &[u8; 6]) -> (u16, u32)` и тест с байтами `00 02 00 00 01 2c`, которые должны дать версию 2 и длину 300.

<details>
<summary>Подсказка</summary>

Соберите маленькие массивы из нужных байтов: `[bytes[0], bytes[1]]` для версии. Затем используйте `u16::from_be_bytes` и `u32::from_be_bytes`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Reads a 6-byte header: a big-endian u16 version, then a big-endian u32 length.
pub fn parse_header(bytes: &[u8; 6]) -> (u16, u32) {
    let version = u16::from_be_bytes([bytes[0], bytes[1]]);
    let length = u32::from_be_bytes([bytes[2], bytes[3], bytes[4], bytes[5]]);
    (version, length)
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn header_is_big_endian() {
        let bytes = [0x00, 0x02, 0x00, 0x00, 0x01, 0x2c];
        assert_eq!(parse_header(&bytes), (2, 300));
    }
}
```

Почему это работает: тип `&[u8; 6]` гарантирует ровно шесть байтов, поэтому индексы не могут выйти за границы. `0x012c` = 1×256 + 2×16 + 12 = 300. Если бы вы по ошибке использовали `from_le_bytes`, тест упал бы с огромной длиной — именно для этого он и нужен.

</details>

### Упражнение 4 — Размеры для людей (сложно)

Напишите `pub fn human_size(bytes: u64) -> String`, которая печатает размеры в двоичных единицах с одним знаком после точки: `0 B`, `1023 B`, `1.0 KiB`, `1.5 KiB`, `16.0 MiB`, `5.0 TiB`. TiB — самая большая единица (`3000.0 TiB` допустимо). Напишите тесты для всех этих случаев.

<details>
<summary>Подсказка</summary>

Храните единицы в массиве `["B", "KiB", "MiB", "GiB", "TiB"]`. Меньше 1024 печатайте целое число с `B`. Иначе делите `f64` на 1024, пока оно не меньше 1024 и есть единица крупнее. Форматируйте через `{value:.1}`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Formats a byte count with binary units: B, KiB, MiB, GiB, TiB.
pub fn human_size(bytes: u64) -> String {
    const UNITS: [&str; 5] = ["B", "KiB", "MiB", "GiB", "TiB"];
    if bytes < 1024 {
        return format!("{bytes} B");
    }
    let mut value = bytes as f64;
    let mut unit = 0;
    while value >= 1024.0 && unit < UNITS.len() - 1 {
        value /= 1024.0;
        unit += 1;
    }
    format!("{value:.1} {}", UNITS[unit])
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn sizes() {
        assert_eq!(human_size(0), "0 B");
        assert_eq!(human_size(1023), "1023 B");
        assert_eq!(human_size(1024), "1.0 KiB");
        assert_eq!(human_size(1536), "1.5 KiB");
        assert_eq!(human_size(16 * 1024 * 1024), "16.0 MiB");
        assert_eq!(human_size(5 * 1024u64.pow(4)), "5.0 TiB");
        assert_eq!(human_size(3000 * 1024u64.pow(4)), "3000.0 TiB");
    }
}
```

Почему это работает: каждое деление на 1024 переводит на одну единицу выше. Условие `unit < UNITS.len() - 1` останавливается на TiB, поэтому очень большой размер остаётся в TiB, а не выходит за конец массива. Тесты покрывают граничные случаи 1023 и 1024, где живут ошибки «на единицу».

</details>

## Вопросы для самопроверки

1. Сколько разных значений можно хранить в 12 битах?

<details>
<summary>Ответ</summary>

2¹² = 4096 (от 0 до 4095 для беззнакового числа).

</details>

2. Почему одна шестнадцатеричная цифра — это ровно 4 бита?

<details>
<summary>Ответ</summary>

Потому что 16 = 2⁴: четыре бита дают 16 комбинаций, по одной на каждую цифру `0`–`f`. Поэтому две шестнадцатеричные цифры — ровно один байт.

</details>

3. Сколько байтов в 1 MiB и в 1 MB?

<details>
<summary>Ответ</summary>

1 MiB = 2²⁰ = 1 048 576 байт; 1 MB = 10⁶ = 1 000 000 байт.

</details>

4. Значение `u32` `0xAABBCCDD` хранится на вашем Mac. Какой байт лежит по наименьшему адресу?

<details>
<summary>Ответ</summary>

`0xDD`. Ваш Mac использует little-endian: младший байт идёт первым (`to_le_bytes()` даёт `[dd, cc, bb, aa]`).

</details>

5. Почему `u32::from_str_radix("0x1f", 16)` возвращает ошибку?

<details>
<summary>Ответ</summary>

`from_str_radix` ожидает только цифры данной системы. `x` — не шестнадцатеричная цифра, поэтому возвращается `InvalidDigit`. Сначала уберите префикс.

</details>

6. Какой порядок байтов обычно используют сетевые протоколы и как ещё его называют?

<details>
<summary>Ответ</summary>

Big-endian, его называют ещё сетевым порядком байтов.

</details>

7. Что напечатает `println!("{:#06x}", 255)`?

<details>
<summary>Ответ</summary>

`0x00ff`. Ширина 6 включает два символа префикса, поэтому остаётся четыре шестнадцатеричные цифры.

</details>

## Итоги

- Число остаётся тем же, как бы его ни записали; системы с основанием 2, 8, 10 и 16 — лишь разные записи одних и тех же битов.
- Из десятичной системы переводят делением на основание, читая остатки в обратном порядке; между двоичной и шестнадцатеричной — группами по четыре бита, между двоичной и восьмеричной — группами по три.
- В Rust печатают через `{:b}`, `{:o}`, `{:x}` (`#` добавляет префикс, `0N` — заполнение нулями), а разбирают через `from_str_radix`.
- 2¹⁰ = 1024: двоичные единицы (KiB, MiB, GiB) — степени 1024, десятичные (KB, MB, GB) — степени 1000.
- Порядок байтов определяет, какой байт числа идёт в памяти первым. Ваш Mac и x86-64 используют little-endian; сети и многие форматы файлов — big-endian.
- На границах программы (файлы, сеть) выбирайте порядок байтов сознательно через `to_le_bytes`/`to_be_bytes` и `from_le_bytes`/`from_be_bytes` и проверяйте его тестами с фиксированными байтами.
