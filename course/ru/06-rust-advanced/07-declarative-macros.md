## Новые слова

| Слово | Значение |
|---|---|
| **макрос** (macro) | Код, который пишет код. Компилятор запускает макрос во время компиляции и заменяет вызов макроса на код, который макрос создал. Вы уже пользуетесь макросами: `println!`, `vec!`, `assert_eq!`. |
| **декларативный макрос** (declarative macro) | Макрос, написанный через `macro_rules!`. Вы описываете образцы входных данных и код, который нужно создать для каждого образца. |
| **процедурный макрос** (procedural macro) | Макрос, написанный как функция Rust, которая работает с кодом как с данными. Вы напишете такой макрос в [Уроке 06.8](08-procedural-macros.md). |
| **раскрытие макроса** (macro expansion) | Шаг, на котором компилятор заменяет вызов макроса на код, который создал макрос. |
| **токен** (token) | Самый маленький кусочек исходного кода, который понимает компилятор: имя, число, символ вроде `+` или `,`. |
| **дерево токенов** (token tree, `tt`) | Один токен или группа токенов внутри парных скобок `()`, `[]` или `{}`. |
| **спецификатор фрагмента** (fragment specifier) | Часть после двоеточия в `$x:expr`. Она говорит, какой вид кода должна принимать переменная макроса (выражение, имя, тип, …). |
| **повторение** (repetition) | Синтаксис `$( ... ),*`, который сопоставляет или создаёт кусок кода много раз. |
| **гигиена** (hygiene) | Правило: имена, созданные внутри макроса, не могут столкнуться с именами в коде, который вызывает макрос. |
| **AST** (Abstract Syntax Tree, абстрактное синтаксическое дерево) | Дерево, которое компилятор строит из вашего исходного кода, например «сумма двух чисел». |
| **DSL** (Domain-Specific Language, предметно-ориентированный язык) | Крошечный язык, сделанный для одной задачи, например `calc!(add 2, 3)` в этом уроке. |
| **DRY** (Don't Repeat Yourself, «не повторяйся») | Принцип: одно и то же знание должно быть записано только в одном месте. |

## 1. Что такое макрос

**Функция** работает, когда работает ваша программа. Она получает значения и возвращает значение.

**Макрос** работает раньше — пока компилятор компилирует вашу программу. Он получает *куски исходного кода* и возвращает *новый исходный код*. Затем компилятор компилирует этот новый код так, будто вы сами его набрали.

Вы пользуетесь макросами с первой программы. Знак `!` после имени говорит, что это вызов макроса, а не функции:

```rust
fn main() {
    let numbers = vec![1, 2, 3];
    println!("{:?}", numbers);
}
```

`vec![1, 2, 3]` — это макрос. Функция не может сделать то, что делает он, потому что у функции в Rust фиксированное число параметров. Макрос может принять любое число элементов, а `println!` может проверить строку формата ещё до запуска вашей программы.

Макросы полезны для трёх задач:

1. **Переменное число аргументов** (`vec!`, `println!`).
2. **Устранение повторяющегося кода**, который не убрать функциями и обобщениями, например один и тот же `impl` для десяти типов (DRY).
3. **Небольшой собственный синтаксис** (мини-язык, DSL).

В Rust есть два семейства макросов. Этот урок учит первому.

| Семейство | Как пишется | Урок |
|---|---|---|
| Декларативные | `macro_rules! name { ... }` с образцами | этот урок |
| Процедурные | функция Rust, которая получает и возвращает токены | [Урок 06.8](08-procedural-macros.md) |

> 📏 **Соглашение:** сначала подумайте о функции. Если нужны разные типы — используйте обобщения и трейты. Макрос берите только тогда, когда функция не справляется. Макросы тяжелее читать и отлаживать, и сообщения об ошибках у них хуже.

## 2. Ваш первый макрос

Декларативный макрос похож на `match`. У каждой *ветки* слева образец, а справа код, который нужно создать.

```rust
macro_rules! say_hello {
    () => {
        println!("Hello from a macro!");
    };
}

fn main() {
    say_hello!();
    say_hello!();
}
```

**Что происходит:**

1. `macro_rules! say_hello { ... }` определяет макрос с именем `say_hello`. Вызывается он как `say_hello!`.
2. У макроса одна ветка. Образец `()` слева означает: «между скобками вызова ничего нет».
3. Код в `{ ... }` справа — это то, что компилятор вставит вместо каждого вызова.
4. Компилятор заменяет оба вызова `say_hello!();` на `println!("Hello from a macro!");` и компилирует результат.

```text
Hello from a macro!
Hello from a macro!
```

> 💡 **Совет:** макрос можно вызывать с `()`, `[]` или `{}`. `say_hello!()`, `say_hello![]` и `say_hello!{}` означают одно и то же. По привычке `vec![...]` пишут с квадратными скобками, всё остальное — с круглыми.

## 3. Образцы и фрагменты

Чтобы принять входные данные, вы пишете **переменные макроса**. Переменная макроса начинается с `$` и после двоеточия имеет *спецификатор фрагмента*: `$x:expr` означает «сопоставь любое выражение и назови его `$x`».

```rust
macro_rules! square {
    ($x:expr) => {
        $x * $x
    };
}

fn main() {
    println!("{}", square!(7));
    println!("{}", square!(1 + 2));
}
```

**Что происходит:**

1. Образец `($x:expr)` сопоставляет одно выражение. Для `square!(7)` переменная `$x` равна `7`. Макрос создаёт `7 * 7`.
2. Для `square!(1 + 2)` компилятор сначала разбирает `1 + 2` как **одно** выражение. Поэтому получается `(1 + 2) * (1 + 2)`, а не `1 + 2 * 1 + 2`. Макрос в Rust работает с *деревом* кода, а не с обычным текстом, поэтому лишние скобки не нужны.

```text
49
9
```

Вот спецификаторы фрагментов, которые вы будете использовать чаще всего:

| Спецификатор | Что сопоставляет | Пример входных данных |
|---|---|---|
| `expr` | выражение | `1 + 2`, `foo(x)`, `"text"` |
| `ident` | имя (идентификатор) | `my_var`, `Point` |
| `ty` | тип | `i32`, `Vec<String>` |
| `literal` | литерал | `5`, `"hi"`, `true` |
| `pat` | образец | `Some(x)`, `1..=5` |
| `stmt` | инструкцию | `let a = 1` |
| `block` | блок в фигурных скобках | `{ a + b }` |
| `item` | элемент: функцию, структуру, `impl`… | `fn f() {}` |
| `path` | путь | `std::collections::HashMap` |
| `vis` | видимость (может быть пустой) | `pub`, `pub(crate)` |
| `lifetime` | время жизни | `'a` |
| `tt` | одно дерево токенов: фрагмент «что угодно» | `+`, `foo`, `( a, b )` |

> ⚠️ **Частая ошибка:** после `$x:expr` компилятор разрешает только `=>`, `,` или `;`. Это правило не даёт макросу стать неоднозначным. Поэтому между фрагментами пишут запятую: `$a:expr, $b:expr`. Запись `$a:expr $b:expr` — ошибка компиляции.

### Несколько веток и фиксированные слова

У макроса может быть много веток. Компилятор пробует их сверху вниз и берёт первую подходящую. В ветках могут быть фиксированные слова, так что можно построить крошечный язык:

```rust
macro_rules! calc {
    (add $a:expr, $b:expr) => {
        $a + $b
    };
    (mul $a:expr, $b:expr) => {
        $a * $b
    };
    (neg $a:expr) => {
        -$a
    };
}

fn main() {
    println!("{}", calc!(add 2, 3));
    println!("{}", calc!(mul 4, 5));
    println!("{}", calc!(neg 6));
}
```

**Что происходит:**

1. `calc!(add 2, 3)` не подходит ни к ветке `mul`, ни к ветке `neg`. Он подходит к первой ветке: фиксированное слово `add`, затем выражение `2`, запятая и выражение `3`.
2. Макрос создаёт `2 + 3`. Остальные два вызова работают так же.

```text
5
20
-6
```

## 4. Повторения

Как `vec![1, 2, 3]` принимает любое число элементов? Через **повторение**: `$( ... ) разделитель квантификатор`.

- Часть внутри `$( ... )` повторяется.
- *Разделитель* необязателен: обычно `,` или `;`.
- *Квантификатор* говорит, сколько раз: `*` — ноль или больше, `+` — один или больше, `?` — ноль или один.

Напишем собственный `vec!`:

```rust
macro_rules! my_vec {
    () => {
        Vec::new()
    };
    ($($item:expr),+ $(,)?) => {{
        let mut v = Vec::new();
        $( v.push($item); )+
        v
    }};
}

fn main() {
    let empty: Vec<i32> = my_vec![];
    let numbers = my_vec![1, 2, 3];
    let words = my_vec!["a", "b", "c",];
    println!("{:?}", empty);
    println!("{:?}", numbers);
    println!("{:?}", words);
}
```

**Что происходит:**

1. Первая ветка `()` обрабатывает пустой вызов и создаёт `Vec::new()`.
2. Во второй ветке `$($item:expr),+` означает «одно или больше выражений через запятую». Каждое совпадение сохраняется в `$item`.
3. `$(,)?` означает «необязательная запятая в конце», поэтому `my_vec!["a", "b", "c",]` допустим.
4. В правой части `$( v.push($item); )+` повторяет код в скобках по одному разу для каждого найденного элемента.
5. Тело обёрнуто в **двойные** фигурные скобки `{{ ... }}`. Внешняя пара — синтаксис макроса. Внутренняя пара создаёт блок, поэтому макрос может содержать несколько инструкций (`let`, `push` и итоговое `v`) и всё равно быть одним выражением.

```text
[]
[1, 2, 3]
["a", "b", "c"]
```

### Повторение с двумя переменными

Повторения работают сразу с несколькими переменными. Вот макрос `hashmap!`:

```rust
use std::collections::HashMap;

macro_rules! hashmap {
    ($($key:expr => $value:expr),* $(,)?) => {{
        let mut map = HashMap::new();
        $( map.insert($key, $value); )*
        map
    }};
}

fn main() {
    let ages = hashmap! {
        "Aziza" => 31,
        "Bobur" => 27,
    };
    let mut names: Vec<_> = ages.iter().collect();
    names.sort();
    println!("{:?}", names);
}
```

**Что происходит:**

1. Каждое повторение сопоставляет `key => value`. Знак `=>` — фиксированный токен, который выбрали вы; это просто украшение.
2. Для каждой пары компилятор пишет один `map.insert(key, value);`. Переменные, которые повторяются вместе (`$key` и `$value`), должны повторяться одинаковое число раз.
3. Мы собираем пары в `Vec` и сортируем его, потому что у `HashMap` нет фиксированного порядка, а нам нужен стабильный вывод.

```text
[("Aziza", 31), ("Bobur", 27)]
```

## 5. Макросы, которые вызывают сами себя

Макрос может вызывать сам себя. Так обрабатывают схему «первый элемент, потом остальные». Вот макрос `max!` для любого числа значений:

```rust
macro_rules! max {
    ($x:expr) => {
        $x
    };
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = max!($($rest),+);
        if a > b { a } else { b }
    }};
}

fn main() {
    println!("{}", max!(4));
    println!("{}", max!(3, 9, 5));
    println!("{}", max!(1.5, 0.5));
}
```

**Что происходит:**

1. `max!(4)` подходит к первой ветке (одно выражение, после него ничего нет) и создаёт `4`.
2. `max!(3, 9, 5)` подходит ко второй ветке: `$x` равен `3`, а `$rest` содержит `9` и `5`.
3. Макрос создаёт код, который вызывает `max!(9, 5)`. Компилятор раскрывает и его, пока не останется одно значение.
4. Компилятор раскрывает всё до проверки типов, поэтому один и тот же макрос работает и для целых чисел, и для чисел с плавающей точкой.

```text
4
9
1.5
```

Порядок веток важен. Более короткий образец стоит первым, потому что второй ветке нужна запятая и хотя бы ещё одно значение.

> ⚡ **Производительность:** у макроса нет затрат во время выполнения: созданный код — обычный код. Цена — время компиляции и размер кода. У глубокой рекурсии есть предел (по умолчанию `recursion_limit` равен 128 уровням).

Чтобы увидеть код, который компилятор строит на самом деле, используйте `cargo expand` (раздел 8). Раскрытие `max!(3, 9, 5)` выглядит так:

```rust
{
    let a = 3;
    let b = {
        let a = 9;
        let b = 5;
        if a > b { a } else { b }
    };
    if a > b { a } else { b }
}
```

Обратите внимание: здесь две переменные с именем `a`. Почему это работает? Об этом — следующий раздел.

## 6. Гигиена

Во многих языках макросы ломаются, когда имя внутри макроса совпадает с именем снаружи. Макросы Rust **гигиеничны** для локальных переменных: переменная, которую создаёт макрос, невидима для вызывающего кода, а переменные вызывающего кода невидимы для собственного кода макроса.

```rust
macro_rules! double_it {
    ($e:expr) => {{
        let x = 2;
        $e * x
    }};
}

fn main() {
    let x = 10;
    println!("{}", double_it!(x + 1));
}
```

**Что происходит:**

1. У вызывающего кода `x = 10`. Макрос тоже создаёт свой `x = 2`.
2. Выражение `x + 1`, которое вы написали, принадлежит вызывающему коду, поэтому его `x` — это `x` вызывающего, то есть `10`.
3. `x` макроса — другая переменная. Результат: `(10 + 1) * 2 = 22`.

```text
22
```

Гигиена работает и в обратную сторону. `let` внутри макроса наружу не «утекает»:

```rust
macro_rules! make_var {
    () => {
        let secret = 5;
    };
}

fn main() {
    make_var!();
    println!("{}", secret);
}
```

```text
error[E0425]: cannot find value `secret` in this scope
 --> src/main.rs:9:20
  |
9 |     println!("{}", secret);
  |                    ^^^^^^ not found in this scope
  |
help: an identifier with the same name is defined here, but is not accessible due to macro hygiene
```

Компилятор даже называет причину: «macro hygiene» (гигиена макросов). Исправление: пусть вызывающий код выбирает имя и передаёт его как `ident`: `make_var!(secret)` с образцом `($name:ident) => { let $name = 5; }`.

Гигиена касается локальных переменных и меток циклов. **Элементы** (функции, структуры, трейты), которые определяет макрос, вызывающему коду *видны*. На этом построен следующий раздел.

## 7. Создание элементов

Макрос может создавать целые элементы. Классический случай: один и тот же `impl` для многих типов.

```rust
trait Describe {
    fn describe(&self) -> String;
}

macro_rules! impl_describe {
    ($($t:ty),+ $(,)?) => {
        $(
            impl Describe for $t {
                fn describe(&self) -> String {
                    format!("{} of type {}", self, stringify!($t))
                }
            }
        )+
    };
}

impl_describe!(i32, u8, f64, bool);

fn main() {
    println!("{}", 42_i32.describe());
    println!("{}", 7_u8.describe());
    println!("{}", 2.5_f64.describe());
    println!("{}", true.describe());
}
```

**Что происходит:**

1. `$t:ty` сопоставляет тип. Макрос повторяет весь блок `impl` по разу для каждого типа: четыре блока `impl` из одной строки (DRY).
2. `stringify!($t)` — встроенный макрос, который превращает код в строковый литерал. `stringify!(i32)` — это `"i32"`.
3. `format!("{} ...", self, ...)` требует, чтобы `self` реализовывал `Display`. Все четыре типа его реализуют, поэтому макрос компилируется для всех.

```text
42 of type i32
7 of type u8
2.5 of type f64
true of type bool
```

Можно создать и структуру, взяв её имя как `ident`:

```rust
macro_rules! make_struct {
    ($name:ident { $($field:ident : $ty:ty),* $(,)? }) => {
        #[derive(Debug)]
        struct $name {
            $($field: $ty),*
        }

        impl $name {
            fn field_names() -> &'static [&'static str] {
                &[$(stringify!($field)),*]
            }
        }
    };
}

make_struct!(Point { x: i32, y: i32 });

fn main() {
    let p = Point { x: 3, y: 4 };
    println!("{:?}", p);
    println!("sum = {}", p.x + p.y);
    println!("{:?}", Point::field_names());
}
```

**Что происходит:**

1. `$name:ident` сопоставляет `Point`. Каждое повторение `$field:ident : $ty:ty` сопоставляет `x: i32` и `y: i32`.
2. Макрос пишет `struct Point { x: i32, y: i32 }` и блок `impl` с функцией, которая перечисляет имена полей как строки.
3. Поскольку элементы не гигиеничны, `main` может использовать `Point`, хотя его создал макрос.

```text
Point { x: 3, y: 4 }
sum = 7
["x", "y"]
```

## 8. Заглянуть внутрь: `cargo expand`

Когда макрос ведёт себя не так, как вы ждёте, посмотрите на код, который он создаёт. `cargo expand` печатает ваш крейт после раскрытия всех макросов.

Установите его один раз (тулчейн `nightly` нужен только для печати раскрытия; ваш проект по-прежнему собирается стабильным Rust):

```sh
rustup toolchain install nightly --profile minimal
cargo install cargo-expand
```

Затем внутри вашего проекта:

## 9. Использование макроса в других местах

У `macro_rules!` есть два правила видимости, которые удивляют новичков.

**Правило 1 — определяйте до использования.** Макрос должен стоять в файле *выше* кода, который его вызывает:

```rust
fn main() {
    greet!();
}

macro_rules! greet {
    () => {
        println!("hi");
    };
}
```

```text
error: cannot find macro `greet` in this scope
 --> src/main.rs:2:5
  |
2 |     greet!();
  |     ^^^^^ consider moving the definition of `greet` before this call
```

Исправление: переместите `macro_rules! greet` выше `main`.

**Правило 2 — экспортируйте через `#[macro_export]`.** Обычный макрос приватен для своего файла или модуля. Чтобы использовать его из других крейтов, пометьте его `#[macro_export]`. Тогда он окажется в корне крейта. Внутри макроса перед собственными элементами крейта пишите `$crate::`, чтобы они находились везде, где используется макрос:

```rust
/// Превращает текст в верхний регистр и добавляет восклицательный знак.
pub fn yell(text: &str) -> String {
    format!("{}!", text.to_uppercase())
}

/// Вызывает `yell` за вас. `$crate` всегда означает «этот крейт»,
/// даже если макрос используется из другого крейта.
#[macro_export]
macro_rules! shout {
    ($text:expr) => {
        $crate::yell($text)
    };
}
```

Если этот код — библиотека `macros07`, то другой крейт (или бинарный файл в том же пакете) пишет:

```rust
use macros07::shout;

fn main() {
    println!("{}", shout!("hello"));
}
```

```text
HELLO!
```

> 🔒 **Безопасность:** макрос может скрывать опасный код, в том числе блоки `unsafe`. Прежде чем использовать макрос из незнакомого крейта, прочитайте, во что он раскрывается (`cargo expand`). К этому мы вернёмся на этапе о безопасности.

## 10. Сообщения об ошибках и `compile_error!`

Ошибки макросов говорят «no rules expected» (ни одно правило не ожидало). Они возникают, когда вызов не подходит ни к одной ветке:

```rust
macro_rules! square {
    ($x:expr) => {
        $x * $x
    };
}

fn main() {
    println!("{}", square!(1, 2));
}
```

```text
error: no rules expected `,`
 --> src/main.rs:8:29
  |
1 | macro_rules! square {
  | ------------------- when calling this macro
...
8 |     println!("{}", square!(1, 2));
  |                             ^ no rules expected this token in macro call
  |
note: while trying to match meta-variable `$x:expr`
```

**Что это значит:** макрос сопоставил `1` с `$x`, затем нашёл запятую, но образец закончился после `$x`. Вызов со слишком малым числом аргументов даёт похожее сообщение: `unexpected end of macro invocation`.

Пользователям можно дать сообщение получше с помощью последней «универсальной» ветки, которая вызывает встроенный `compile_error!`:

```rust
macro_rules! only_number {
    ($x:literal) => {
        $x
    };
    ($($t:tt)*) => {
        compile_error!("only_number! takes exactly one literal, like only_number!(5)")
    };
}

fn main() {
    println!("{}", only_number!(5));
    println!("{}", only_number!(1 + 2));
}
```

```text
error: only_number! takes exactly one literal, like only_number!(5)
  --> src/main.rs:6:9
   |
 6 |         compile_error!("only_number! takes exactly one literal, like only_number!(5)")
   |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
...
12 |     println!("{}", only_number!(1 + 2));
   |                    ------------------- in this macro invocation
```

**Что происходит:** `5` подходит к первой ветке. `1 + 2` — не один литерал, поэтому компилятор пробует следующую ветку. `$($t:tt)*` сопоставляет *что угодно*, поэтому эта ветка срабатывает всегда и останавливает сборку с вашим сообщением. Держите такую «универсальную» ветку последней.

> 🧪 **Тестирование:** тестируйте макрос как любой другой код: вызовите его в `#[test]` и используйте `assert_eq!`. Проверяйте крайние случаи *образцов*: пустой вызов, один элемент, много элементов, запятая в конце. Для проверки «этот вызов не должен компилироваться» можно написать документационный тест с пометкой `compile_fail` (документационные тесты объяснены в [Уроке 05.7 — Документация](../05-rust-intermediate/07-documentation.md)).

## Частые ошибки

**1. Вызов макроса без `!`.** `say_hello()` ищет функцию. Всегда пишите `!`: `say_hello!()`.

**2. Нет запятой между фрагментами.** `($a:expr $b:expr)` отвергается уже при определении макроса:

```text
error: `$a:expr` is followed by `$b:expr`, which is not allowed for `expr` fragments
  = note: allowed there are: `=>`, `,` or `;`
```

Поставьте между ними фиксированный токен: `($a:expr, $b:expr)`. Это же правило объясняет, почему вызов вроде `my_vec![1 2 3]` (без запятых) даёт ошибку «no rules expected» с токеном `2`.

**3. Забыли двойные скобки.** Если в теле макроса несколько инструкций и вы написали `=> { let a = 1; a + $x }`, макрос пытается создать *инструкции*, а это не работает там, где нужно выражение:

```text
error: expected expression, found `let` statement
error: macro expansion ignores `a` and any tokens following
  = note: the usage of `one_plus!` is likely invalid in expression context
```

Используйте `=> {{ let a = 1; a + $x }}`: внутренние скобки превращают всё тело в один блок, а блок — это выражение.

**4. Общая ветка поставлена первой.** Компилятор берёт первую подходящую ветку. Если первой стоит `($($t:tt)*)`, никакая другая ветка не будет использована. Располагайте ветки от самой конкретной к самой общей.

**5. Использование макроса до его определения** (раздел 9). Поднимите определение выше.

**6. Ожидание, что `let` макроса виден снаружи** (раздел 6). Передавайте имя как `ident`.

**7. Макрос там, где хватило бы функции.** Если можно написать обычную или обобщённую функцию — напишите её. Сравните: `fn square<T: std::ops::Mul<Output = T> + Copy>(x: T) -> T { x * x }` делает то же, что `square!`, но с более понятными сообщениями об ошибках.

## Упражнения

### Упражнение 1 — `min!` (легко)

Напишите макрос `min!`, который возвращает наименьшее из одного или нескольких значений. `min!(8, 3, 5)` равно `3`. `min!(2.5, 7.0)` равно `2.5`. Возьмите за образец макрос `max!` из раздела 5.

<details>
<summary>Подсказка</summary>

Скопируйте `max!`. Нужно изменить только одно: сравнение в `if`.

</details>

<details>
<summary>Ответ</summary>

```rust
macro_rules! min {
    ($x:expr) => {
        $x
    };
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = min!($($rest),+);
        if a < b { a } else { b }
    }};
}

fn main() {
    println!("{}", min!(8));
    println!("{}", min!(8, 3, 5));
    println!("{}", min!(2.5, 7.0));
}
```

```text
8
3
2.5
```

Почему это работает: первая ветка останавливает рекурсию, когда остаётся одно значение. Вторая ветка берёт первое значение и просит `min!` найти наименьшее из остальных.

</details>

### Упражнение 2 — `set!` с тестами (средне)

Напишите макрос `set!`, который строит `HashSet` из списка выражений, как `hashmap!` делает это для словаря. Он должен допускать запятую в конце. Напишите два теста: один проверяет, что дубликаты удаляются, второй — что запятая в конце допустима.

<details>
<summary>Подсказка</summary>

Начните с `hashmap!` из раздела 4. У множества нет значений, поэтому используйте `s.insert($item)`. Положите тесты в `#[cfg(test)] mod tests` и напишите `use super::*;` в начале модуля, чтобы тесты видели `HashSet`.

</details>

<details>
<summary>Ответ</summary>

```rust
use std::collections::HashSet;

macro_rules! set {
    ($($item:expr),* $(,)?) => {{
        let mut s = HashSet::new();
        $( s.insert($item); )*
        s
    }};
}

fn main() {
    let s = set![3, 1, 3, 2, 1];
    let mut sorted: Vec<_> = s.into_iter().collect();
    sorted.sort();
    println!("{:?}", sorted);
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn set_removes_duplicates() {
        let s = set![1, 1, 2];
        assert_eq!(s.len(), 2);
        assert!(s.contains(&1));
        assert!(s.contains(&2));
    }

    #[test]
    fn trailing_comma_is_allowed() {
        let one = set![5,];
        assert_eq!(one.len(), 1);
    }
}
```

`cargo run` печатает `[1, 2, 3]`. `cargo test` печатает `test result: ok. 2 passed`.

Почему это работает: `$(,)?` принимает одну необязательную запятую в конце. `HashSet` игнорирует `insert` значения, которое у него уже есть, поэтому дубликаты исчезают.

</details>

### Упражнение 3 — `string_enum!` (средне)

Напишите макрос `string_enum!` так, чтобы `string_enum!(Color { Red, Green, Blue });` создавал `enum Color` с методом `as_str(&self) -> &'static str` (возвращает `"Red"`, …) и функцией `all() -> &'static [Color]`. Выведите каждый цвет и его текст.

<details>
<summary>Подсказка</summary>

Имя перечисления — это `ident`. Варианты — `$($variant:ident),+`. Внутри `match self` пишите `$name::$variant => stringify!($variant)` по разу на каждый вариант. Ссылка на массив вариантов без данных, например `&[Color::Red, Color::Green]`, может быть `'static`, потому что компилятор хранит такие константные данные внутри самой программы.

</details>

<details>
<summary>Ответ</summary>

```rust
macro_rules! string_enum {
    ($name:ident { $($variant:ident),+ $(,)? }) => {
        #[derive(Debug, Clone, Copy, PartialEq)]
        enum $name {
            $($variant),+
        }

        impl $name {
            fn as_str(&self) -> &'static str {
                match self {
                    $($name::$variant => stringify!($variant)),+
                }
            }

            fn all() -> &'static [$name] {
                &[$($name::$variant),+]
            }
        }
    };
}

string_enum!(Color { Red, Green, Blue });

fn main() {
    for color in Color::all() {
        println!("{:?} -> {}", color, color.as_str());
    }
}
```

```text
Red -> Red
Green -> Green
Blue -> Blue
```

Почему это работает: макрос повторяет `$variant` в трёх местах: в теле перечисления, в ветках `match` и в срезе. Один список имён даёт все три, это и есть идея DRY.

</details>

### Упражнение 4 — `ensure!` с тестами (сложно)

Напишите `ensure!(condition, "message {}", value)`. Если условие ложно, макрос должен сделать `return Err(String)` из *вызывающей функции* с сообщением, отформатированным как в `format!`. Используйте его в `fn check_age(age: i32) -> Result<i32, String>`, которая отвергает отрицательный возраст и возраст 150 и больше. Напишите тест для успешного случая и для одного сообщения об ошибке.

<details>
<summary>Подсказка</summary>

После условия нужно «всё остальное, любое число токенов», чтобы передать это в `format!`. Для этого подходит фрагмент `$($arg:tt)+`. Затем напишите `format!($($arg)+)`. `return` внутри макроса выходит из функции, где этот макрос вызван.

</details>

<details>
<summary>Ответ</summary>

```rust
macro_rules! ensure {
    ($cond:expr, $($arg:tt)+) => {
        if !$cond {
            return Err(format!($($arg)+));
        }
    };
}

fn check_age(age: i32) -> Result<i32, String> {
    ensure!(age >= 0, "age {} is negative", age);
    ensure!(age < 150, "age {} is too large", age);
    Ok(age)
}

fn main() {
    println!("{:?}", check_age(30));
    println!("{:?}", check_age(-4));
    println!("{:?}", check_age(200));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn valid_age_passes() {
        assert_eq!(check_age(30), Ok(30));
    }

    #[test]
    fn negative_age_fails_with_message() {
        assert_eq!(check_age(-4), Err("age -4 is negative".to_string()));
    }
}
```

```text
Ok(30)
Err("age -4 is negative")
Err("age 200 is too large")
```

Почему это работает: макрос вставляется в вызывающую функцию, поэтому `return` выходит из `check_age`. Функция так не умеет. Это одна из настоящих причин выбрать макрос.

</details>

### Упражнение 5 — посчитать токены (сложно)

Напишите макрос `count!`, который возвращает, сколько деревьев токенов он получил: `count!()` равно `0`, `count!(a b c)` равно `3`, `count!(+ - * / %)` равно `5`. Используйте рекурсию и `tt`.

<details>
<summary>Подсказка</summary>

Две ветки. Первая ничего не сопоставляет и даёт `0usize`. Вторая сопоставляет `$head:tt $($tail:tt)*` и даёт `1usize + count!($($tail)*)`.

</details>

<details>
<summary>Ответ</summary>

```rust
macro_rules! count {
    () => { 0usize };
    ($head:tt $($tail:tt)*) => { 1usize + count!($($tail)*) };
}

fn main() {
    println!("{}", count!());
    println!("{}", count!(a b c));
    println!("{}", count!(+ - * / %));
}
```

```text
0
3
5
```

Почему это работает: каждый шаг убирает одно дерево токенов (`$head`), прибавляет `1` и считает хвост. Пустой вызов заканчивает рекурсию. На очень длинном входе здесь упрётся предел рекурсии, поэтому настоящий код использует другие приёмы, но идея та же.

</details>

## Вопросы для самопроверки

1. Чем функция отличается от макроса?

<details>
<summary>Ответ</summary>

Функция работает, когда работает программа, и получает значения. Макрос работает во время компиляции, получает куски исходного кода и возвращает новый исходный код, который заменяет вызов макроса.

</details>

2. Что означает `$x:expr`? Что часть `expr` сообщает компилятору?

<details>
<summary>Ответ</summary>

`$x` — переменная макроса. `expr` — спецификатор фрагмента: он говорит, что `$x` должна сопоставляться с целым выражением. Компилятор сначала разбирает выражение, поэтому `1 + 2` остаётся одним целым.

</details>

3. Что означают `*`, `+` и `?` после `$( ... )`?

<details>
<summary>Ответ</summary>

`*` — ноль или больше повторений, `+` — одно или больше, `?` — ноль или одно.

</details>

4. Почему `double_it!(x + 1)` использует `x` вызывающего кода, хотя макрос тоже объявляет `let x = 2`?

<details>
<summary>Ответ</summary>

Из-за гигиены. Локальные переменные, созданные внутри макроса, живут в своём «пространстве имён». `x` в `x + 1` написал вызывающий код, поэтому он означает `x` вызывающего. `x` макроса — другая переменная.

</details>

5. Где должно стоять определение `macro_rules!` и что делает его доступным из другого крейта?

<details>
<summary>Ответ</summary>

Оно должно быть написано выше кода, который его использует. Чтобы использовать макрос из другого крейта, поставьте на него `#[macro_export]`. Внутри обращайтесь к элементам самого крейта через `$crate::`.

</details>

6. Вызов падает с ошибкой «no rules expected `,`». Что это значит?

<details>
<summary>Ответ</summary>

Вызов не подошёл ни к одной ветке макроса: компилятор нашёл запятую там, где ни одна ветка её не допускает. Сверьте вызов с образцами или добавьте ветку для такой формы.

</details>

7. Назовите одну задачу, которую может решить макрос, а функция — нет.

<details>
<summary>Ответ</summary>

Примеры: принять переменное число аргументов (`vec!`), создать несколько блоков `impl` или целую `struct`, выполнить `return` из вызывающей функции (`ensure!`).

</details>

## Итоги

- Макрос — это код, который пишет код. Он работает во время компиляции, и компилятор компилирует то, что он создал.
- `macro_rules!` работает как `match`: ветки вида `образец => код`, которые пробуются сверху вниз.
- У переменных макроса есть спецификаторы фрагментов: `expr`, `ident`, `ty`, `literal`, `tt` и другие.
- `$( ... ),*` и `$( ... ),+` повторяют код. `$(,)?` разрешает запятую в конце.
- Макросы могут вызывать сами себя, так обрабатывают схему «первый элемент, потом остальные».
- Гигиена разделяет локальные имена макроса и вызывающего кода. Элементы, которые определяет макрос, вызывающему коду видны.
- `#[macro_export]` и `$crate` позволяют делиться макросом между крейтами. `cargo expand` показывает, что создал макрос.
- Предпочитайте функции и обобщения. Макрос нужен для переменных аргументов, создаваемых элементов или управления потоком вроде `return`.
