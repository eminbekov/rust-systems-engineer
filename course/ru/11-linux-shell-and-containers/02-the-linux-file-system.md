# Урок 11.2 — Файловая система Linux

> **Этап 11 — Linux, командная оболочка и контейнеры** · Урок 2 из 16 · ⏱ около 120 минут

## Что вы узнаете

- Как файловая система Linux устроена в виде одного дерева, которое начинается с `/`, и для чего нужны главные каталоги верхнего уровня.
- Почему в Linux «всё — файл» и как читать сведения о системе из `/proc` и `/dev`.
- Как изучать файлы (`ls -l`, `stat`, `file`, `du`, `df`) и понимать жёсткие и символические ссылки.
- Как безопасно копировать, перемещать и удалять и как искать файлы командой `find`.
- Где программы хранят настройки, журналы и данные и как скопировать проект с Mac в ВМ (виртуальную машину `dev` из Урока 11.1).

## Новые слова

| Слово | Значение |
|---|---|
| **корневой каталог** (root directory) | Вершина дерева, обозначается `/`. Все остальные файлы и каталоги находятся под ним. (Не путайте с пользователем `root`, то есть администратором.) |
| **FHS** (Filesystem Hierarchy Standard, стандарт иерархии файловой системы) | Соглашение о том, для чего служат каталоги верхнего уровня (`/etc`, `/var`, `/usr` …). |
| **inode** (индексный дескриптор) | Запись внутри файловой системы, в которой хранится всё о файле, кроме его имени: размер, владелец, права, времена и где лежат данные. |
| **жёсткая ссылка** (hard link) | Второе *имя* того же файла (того же inode). |
| **символическая ссылка** (symbolic link, symlink) | Крошечный файл, содержащий *путь* к другому файлу, как ярлык. |
| **виртуальная файловая система** (virtual file system) | Файлы, которые не лежат на диске: ядро создаёт их на лету, например `/proc` и `/dev/null`. |
| **точка монтирования** (mount point) | Каталог, в котором к дереву подключён диск или другая файловая система. |
| **скрытый файл** (hidden file) | Файл, имя которого начинается с точки, например `.bashrc`. `ls` не показывает его, пока вы не попросите. |
| **МиБ / КиБ** (MiB / KiB) | Кибибайт и мебибайт: 1024 байта и 1024 × 1024 байта. Утилиты печатают их как `K`, `M`, `G`. |

## 1. Одно дерево, которое начинается с `/`

На Mac у вас есть `/Users`, `/Applications`, `/Volumes`. В Linux одно дерево с одной вершиной — **корневым
каталогом** `/`. Даже второй диск не получает буквы; он *монтируется* в какой-нибудь каталог внутри дерева.

Посмотрите на верх дерева:

```bash
ls /
ls -ld /bin /sbin /lib
```

```text
bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
lrwxrwxrwx 1 root root 7 Apr 20  2026 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 Apr 20  2026 /lib -> usr/lib
lrwxrwxrwx 1 root root 8 Apr 20  2026 /sbin -> usr/sbin
```

Даты у вас будут другими, а в ВМ может быть ещё несколько записей (например, `lost+found`). Стрелки `->`
обозначают символические ссылки (раздел 5). У каждого каталога верхнего уровня своя задача, её определяет
**FHS** (Filesystem Hierarchy Standard):

| Каталог | Что там лежит | Пример |
|---|---|---|
| `/home` | Домашние каталоги обычных пользователей | `/home/student` |
| `/root` | Домашний каталог администратора `root` | |
| `/etc` | **Настройки** всей системы (текстовые файлы) | `/etc/hostname`, `/etc/passwd` |
| `/usr` | Установленные программы, библиотеки и общие данные | `/usr/bin/ls`, `/usr/share` |
| `/usr/local` | Программы, которые вы ставите сами, вне менеджера пакетов | `/usr/local/bin` |
| `/bin`, `/sbin`, `/lib` | Старые имена; в Ubuntu это символические ссылки на `/usr/bin`, `/usr/sbin`, `/usr/lib` (см. `->` выше) | |
| `/var` | Данные, которые **меняются во время работы системы**: журналы, кэши, базы данных | `/var/log`, `/var/lib` |
| `/tmp` | Временные файлы, писать может любой пользователь, при перезагрузке может очищаться | |
| `/opt` | Крупное дополнительное ПО, упакованное производителями | |
| `/srv` | Данные, которые отдаёт эта машина (сайты, файлы) | |
| `/mnt`, `/media` | Места для монтирования дисков и флешек | |
| `/dev` | **Устройства** в виде файлов | `/dev/null` |
| `/proc`, `/sys` | Живая информация от **ядра** | `/proc/meminfo` |
| `/run` | Данные работающих служб (сокеты, PID-файлы: файлы с идентификатором процесса, process ID — номером процесса) | |
| `/boot` | Файлы для запуска системы (образ ядра) | |

> 💡 **Совет:** короткое правило для памяти: `/etc` — настройки (**E**ditable **T**ext **C**onfig, редактируемый
> текстовый конфиг), `/var` — то, что **var**ies (меняется), `/usr` — программы, `/home` — ваше.

Два факта, которые удивляют тех, кто пришёл из macOS:

1. **Имена чувствительны к регистру.** `Notes.txt` и `notes.txt` — два разных файла. (По умолчанию macOS считает их одним файлом.)
2. **Нет букв дисков и нет `/Users`.** Папка вашего Mac появляется как `/Users/...` в ВМ только потому, что Lima монтирует её туда ([Урок 11.1](01-linux-and-a-virtual-machine.md)).

> 💡 **Совет:** в Ubuntu 26.04 многие базовые команды, такие как `ls`, `cp` и `cat`, берутся из *uutils coreutils* —
> переписанных на Rust классических утилит. Проверьте: `ls --version`. Команды ведут себя как классические;
> только некоторые сообщения об ошибках сформулированы иначе.

## 2. Всё — файл

Идея Unix: программы читают и пишут **файлы**, а система предлагает *в виде файлов* многое — оборудование,
процессы, настройки ядра. Тогда одни и те же инструменты (`cat`, `grep`, `>`) работают со всем.

**Устройства в `/dev`.** Два особых файла, которыми вы будете пользоваться постоянно:

```bash
echo "this text disappears" > /dev/null
head -c 8 /dev/zero | od -An -tx1
```

```text
 00 00 00 00 00 00 00 00
```

**Что происходит:**

1. `/dev/null` — «чёрная дыра»: всё, что в него записано, выбрасывается. Его используют, чтобы заглушить вывод ([Урок 11.3](03-text-tools-pipes-and-redirection.md)).
2. `/dev/zero` выдаёт бесконечный поток нулевых байтов. `head -c 8` берёт первые 8 байтов, а `od -An -tx1` («octal dump», без адресов, байты в шестнадцатеричном виде) их печатает. Есть и другие: `/dev/urandom` выдаёт случайные байты.

**Сведения ядра в `/proc`.** `/proc` — **виртуальная файловая система**: на диске ничего не хранится, ядро
создаёт содержимое, когда вы его читаете.

```bash
head -3 /proc/meminfo
cat /proc/loadavg
cat /proc/self/comm
readlink /proc/self/cwd
```

```text
MemTotal:        8124192 kB
MemFree:          272820 kB
MemAvailable:    7099324 kB
0.00 0.10 0.09 1/459 2512
cat
/home/student
```

**Что происходит:**

1. `/proc/meminfo` описывает память. Команда `free`, которой вы пользовались в Уроке 11.1, лишь читает его и форматирует.
2. В `/proc/loadavg` лежит *средняя нагрузка* (load average): сколько процессов хотели процессор за последние 1, 5 и 15 минут (первые три числа), затем число работающих/всех процессов и последний выданный PID.
3. `/proc/self` всегда означает *процесс, который его читает*. Здесь это сам `cat`, поэтому `comm` (имя команды) содержит `cat`. `readlink /proc/self/cwd` печатает рабочий каталог процесса `readlink` — то есть ваш текущий каталог.
4. У каждого работающего процесса есть своя папка `/proc/<PID>/`. [Урок 11.5](05-processes-and-signals.md) использует их.

> ⚠️ **Частая ошибка:** пытаться редактировать файлы в `/proc` редактором или «освобождать место», удаляя их.
> Они не на диске. Читайте их; записывайте в них, только если руководство точно говорит что, потому что это меняет работающее ядро.

## 3. Пути, скрытые файлы, пробелы

Вы знаете абсолютные пути (начинаются с `/`) и относительные. Потренируйтесь в учебной папке; все файлы
останутся в домашней папке ВМ, так что в конце всё можно удалить:

```bash
cd ~
mkdir lab
cd lab
mkdir -p projects/demo/src
touch Notes.txt notes.txt .hidden
ls
```

```text
Notes.txt
notes.txt
projects
```

**Что происходит:**

1. `mkdir -p projects/demo/src` создаёт цепочку каталогов за раз. `-p` означает «parents» (родители): недостающие каталоги по пути создаются, и ошибки нет, если они уже есть.
2. `touch` создаёт пустые файлы. `Notes.txt` и `notes.txt` лежат рядом, потому что имена чувствительны к регистру.
3. `ls` не показывает `.hidden`. Имена, начинающиеся с точки, — это **скрытые файлы**. Порядок имён зависит от локали (языковых настроек); при `C.UTF-8` по умолчанию сначала идут заглавные буквы.

```bash
ls -a
```

```text
.
..
.hidden
Notes.txt
notes.txt
projects
```

**Что происходит:** `ls -a` («all», все) показывает скрытые файлы и две особые записи: `.` — «этот каталог», а
`..` — «родительский каталог». Со скрытыми файлами вы встречаетесь каждый день: `~/.bashrc` (настройки
оболочки), `~/.cargo` (Cargo), `~/.ssh` (ключи, [Урок 11.10](10-ssh-and-remote-servers.md)), `~/.config` (настройки многих программ).

`~` — сокращение для вашего домашнего каталога, `cd -` возвращает в предыдущий каталог, а просто `cd` ведёт
домой. Имя с **пробелом** — это одно имя, но оболочка делит слова по пробелам. `rm my file.txt` заставляет `rm` искать два
файла, `my` и `file.txt`, и завершаться ошибкой `No such file or directory`. Возьмите имя в кавычки (`rm "my file.txt"`) или поставьте
обратную косую черту перед пробелом (`my\ file.txt`).

> 📏 **Соглашение:** избегайте пробелов и заглавных букв в именах, которые вы создаёте для программ: используйте
> `lowercase-with-dashes` или `snake_case`. Так делает Cargo, и это избавляет от кавычек.

## 4. Смотрим на файл: размер, тип, владелец

`ls -l` показывает подробности из Урока 00.4. Ещё три инструмента отвечают на другие вопросы:

```bash
cd ~/lab
echo "line one" > a.txt
stat a.txt
file a.txt /etc
```

```text
  File: a.txt
  Size: 9         	Blocks: 8          IO Block: 4096   regular file
Device: 0,69	Inode: 959145      Links: 1
Access: (0664/-rw-rw-r--)  Uid: ( 1000/ student)   Gid: ( 1000/ student)
Access: 2026-11-18 06:33:34.239697004 +0000
Modify: 2026-11-18 06:33:34.239697004 +0000
Change: 2026-11-18 06:33:34.239697004 +0000
 Birth: 2026-11-18 06:33:34.239697004 +0000
a.txt: ASCII text
/etc:  directory
```

**Что происходит:**

1. `stat` печатает всё, что файловая система знает о файле: размер в байтах (9 = `line one` плюс перевод строки), номер **inode**, число ссылок, права в виде восьмеричного числа `0664` (Урок 11.4), числа владельца и группы и четыре времени: *Access* (последнее чтение), *Modify* (изменение содержимого), *Change* (изменение метаданных), *Birth* (создание).
2. `file` смотрит на **содержимое** (а не на имя) и говорит, что это: текст, изображение, программа. Linux не полагается на окончания `.txt` или `.rs`.

Размеры множества файлов и свободное место на дисках:

```bash
du -sh ~/lab
du -sh /usr/bin
df -h /
```

```text
20K	/home/student/lab
57M	/usr/bin
Filesystem      Size  Used Avail Use% Mounted on
overlay         453G   88G  343G  21% /
```

**Что происходит:** `du` («disk usage», использование диска) суммирует место, занятое деревом каталогов; `-s` даёт один итог, `-h` использует
`K`, `M`, `G`. `df` («disk free», свободное место на диске) показывает каждую файловую систему. Ваши числа будут другими. В вашей ВМ в столбце `Filesystem` будет устройство, например
`/dev/vda1` (как в Уроке 11.1). Когда появляется «no space left on device», сначала выполните `df -h` (диск полон?),
затем `du -sh *` в подозрительном каталоге (какая папка большая?). Папка `target/` у Rust — классический ответ.

> ⚡ **Производительность:** `target/` проекта на Rust может занимать несколько ГиБ. Удалите её командой `cargo clean`,
> когда нужно место; следующая сборка создаст её заново.

## 5. Жёсткие и символические ссылки

Имя файла — это только **метка**, которая указывает на **inode**. *Жёсткая ссылка* — вторая метка на тот же inode.
*Символическая ссылка* — другое: маленький файл, который хранит путь.

```text
  hard link                           symbolic link
  a.txt ---+                          soft.txt --> "a.txt" (a path in text)
           +--> inode 959145 -> data                |
  hard.txt-+                                        v
                                      a.txt --> inode 959145 -> data
```

Попробуйте обе:

```bash
cd ~/lab
ln a.txt hard.txt
ln -s a.txt soft.txt
ls -li a.txt hard.txt soft.txt
```

```text
959145 -rw-rw-r-- 2 student student 9 Nov 18 06:33 a.txt
959145 -rw-rw-r-- 2 student student 9 Nov 18 06:33 hard.txt
959142 lrwxrwxrwx 1 student student 5 Nov 18 06:33 soft.txt -> a.txt
```

**Что происходит:**

1. `ln a.txt hard.txt` создаёт жёсткую ссылку. `ls -i` печатает номер inode первым: у `a.txt` и `hard.txt` **один и тот же** inode, а счётчик ссылок (число после прав) равен 2.
2. `ln -s a.txt soft.txt` создаёт символическую ссылку (`-s`). У неё свой inode и тип `l`; `ls -l` показывает `-> a.txt`, то есть путь, хранящийся внутри.

Теперь удалите исходное имя и посмотрите на разницу:

```bash
echo "line two" >> hard.txt
cat a.txt
rm a.txt
cat hard.txt
cat soft.txt
```

```text
line one
line two
line one
line two
cat: soft.txt: No such file or directory
```

**Что происходит:**

1. Запись через `hard.txt` изменила те же данные, поэтому `cat a.txt` видит обе строки.
2. `rm a.txt` удаляет одно *имя*. Данные остаются, пока остаётся хотя бы одно имя: `hard.txt` по-прежнему работает.
3. `soft.txt` указывает на путь `a.txt`, которого больше нет: это **битая ссылка**. `cat` идёт по пути и терпит неудачу.

Символические ссылки встречаются гораздо чаще. Ещё раз посмотрите на вывод `ls -ld` в разделе 1: `/bin -> usr/bin`. `readlink -f /bin` печатает
конечную настоящую цель: `/usr/bin`. Символические ссылки дают постоянное имя тому, что меняется, например
`current -> release-2026-11-18`. Уберите за собой:

```bash
rm soft.txt hard.txt
```

## 6. Копирование, перемещение, удаление — осторожно

Вы знаете `cp`, `mv`, `rm`. Ловушки появляются с каталогами:

```bash
cd ~/lab
mkdir -p projects/demo/src projects/other
echo "fn main() {}" > projects/demo/src/main.rs
cp -r projects projects-copy
ls projects-copy
cp -r projects projects-copy
ls projects-copy
```

```text
demo
other
demo
other
projects
```

**Что происходит:**

1. `cp -r` («recursive», рекурсивно) копирует каталог со всем содержимым. Без `-r` `cp` отказывается копировать каталог.
2. Первое копирование создало `projects-copy` как копию `projects`. **Во второй раз** `projects-copy` уже существовал, поэтому `cp` положил источник *внутрь* него: `projects-copy/projects`. Поведение зависит от того, существует ли цель. Проверяйте через `ls` перед копированием.
3. `cp -a` («archive», архив) сохраняет ещё права и даты; это правильный выбор для резервных копий.

`mv` работает с каталогами без `-r`. `rmdir` удаляет только **пустые** каталоги — это страховка
(`rmdir: failed to remove 'projects/other': Directory not empty`). `rm -r` удаляет каталог со всем
внутри, а `rm -f` («force», принудительно) скрывает ошибки «нет такого файла» и никогда не спрашивает.

> 🔒 **Безопасность:** в командной строке **нет корзины**. `rm` удаляет сразу и навсегда.
> - `rm -rf` плюс ошибка — так люди теряют работу. Классика: `rm -rf $DIR/`, когда переменная `DIR` пуста, превращается в `rm -rf /`.
> - Сначала выполните `ls` с тем же шаблоном, потом `rm`. Используйте `rm -i` («interactive», интерактивно), чтобы вас спрашивали про каждый файл, когда не уверены.
> - Берите переменные в кавычки (`"$DIR"`) и не используйте `sudo rm -rf`, если не можете вслух сказать, что именно это удалит.

## 7. Поиск файлов: `find`, `which`, `type`

`find` обходит дерево каталогов и печатает пути, подходящие под условия. Подготовьте файлы и попробуйте:

```bash
cd ~/lab
echo "[package]" > projects/demo/Cargo.toml
head -c 3000 /dev/zero > big.bin
find . -name "*.rs"
find . -type d
find . -type f -size +1k
find . -name "*.md" -o -name "*.toml"
```

```text
./projects/demo/src/main.rs
.
./projects
./projects/other
./projects/demo
./projects/demo/src
./big.bin
./projects/other/notes.md
./projects/demo/Cargo.toml
```

**Что происходит:**

1. `find . -name "*.rs"`: начать в `.` (здесь) и печатать каждый путь, имя которого подходит. Берите шаблон в кавычки, чтобы оболочка не раскрыла `*` первой ([Урок 00.4](../00-getting-started/04-terminal-basics.md)). Шаблон чувствителен к регистру; `-iname` регистр игнорирует.
2. `-type d` — каталоги, `-type f` — обычные файлы, `-type l` — символические ссылки.
3. `-size +1k` подходит для файлов больше 1 КиБ (`-size -1k` — меньше).
4. `-o` означает *или*. Два условия подряд означают *и*.

Другие полезные условия: `-maxdepth 1` (не спускаться глубже), `-mtime -1` (изменён за последние сутки), `-newer file`
(изменён позже, чем `file`). `find` может также запустить команду для каждого найденного:

```bash
find . -name "*.rs" -exec wc -l {} \;
```

```text
1 ./projects/demo/src/main.rs
```

**Что происходит:** для каждого найденного `find` подставляет вместо `{}` путь и запускает `wc -l` (подсчёт строк). Символы
`\;` завершают команду; обратная косая черта не даёт оболочке использовать `;` самой. В следующем уроке вы
познакомитесь с `xargs` — способом сделать то же самое через конвейер.

Чтобы найти *программы*, спросите оболочку:

```bash
type cd
type bash
command -v bash
```

```text
cd is a shell builtin
bash is /usr/bin/bash
/usr/bin/bash
```

**Что происходит:** `type` говорит, как оболочка запустит имя: как **встроенную команду** (часть самой оболочки, как `cd`),
как файл программы по некоторому пути, как псевдоним или функцию. `which` и `command -v` печатают путь. Этими
инструментами отвечают на вопрос «какой именно `cargo` я запускаю?», когда их несколько.

## 8. Где программы хранят свои вещи

Когда что-то не работает, нужно знать, где искать. Практические правила для Ubuntu:

| Что | Где | Пример |
|---|---|---|
| Настройки всей системы | `/etc/<program>/` или `/etc/<program>.conf` | `/etc/ssh/sshd_config` |
| Ваши собственные настройки | `~/.config/<program>/` или файл с точкой `~/.<program>` | `~/.config/git/config`, `~/.bashrc` |
| Программы системы | `/usr/bin` | `/usr/bin/ls` |
| Программы, которые вы ставите сами | `/usr/local/bin`, или `~/.local/bin`, или `~/.cargo/bin` | `~/.cargo/bin/cargo` |
| Меняющиеся данные служб | `/var/lib/<program>/` | базы данных |
| Журналы | `/var/log/` (и *журнал* journal, Урок 11.6) | `/var/log/dpkg.log` |
| Кэши | `/var/cache`, `~/.cache` | |
| Сокеты и PID-файлы во время работы | `/run` | |

Из этой таблицы следуют два правила. **Настройки — это текст**, поэтому их можно читать, искать и копировать. И
**код и данные разделены**: программа лежит в `/usr/bin`, а её данные — в `/var/lib`, поэтому программу можно обновлять,
не трогая данные. Программы на Rust следуют той же схеме, когда вы разворачиваете их в [Уроке 11.6](06-services-with-systemd.md).

### Перенесите проект на Rust с Mac в ВМ

Файлы вашего Mac видны по пути `/Users/<your-mac-name>/`, но только для чтения. Чтобы собрать проект в Linux, скопируйте его
в домашнюю папку ВМ (в примере имя `student`; подставьте своё, его покажет `ls /Users`):

```bash
mkdir -p ~/code
cp -r /Users/student/projects/rust/code/p11-heartbeat ~/code/
```

Если источника ещё нет, сначала создайте любую папку на Mac (Урок 11.5 создаёт `p11-heartbeat`).
Чтобы перенести результат **обратно** на Mac, помните, что монтирование только для чтения: копируйте через `scp` или
используйте `limactl copy`. Точный синтаксис проверьте командой `limactl copy --help`; `scp` вы изучите в Уроке 11.10.

Удалите учебную папку из разделов 3–7, когда закончите:

```bash
rm -r ~/lab
```

## Частые ошибки

1. **Привычки Mac в вопросе регистра.** Вы создали `Cargo.toml`, а набрали `cargo.toml`: `No such file or directory`. *Исправление:* имена чувствительны к регистру; проверьте через `ls`.
2. **`cp -r` в уже существующий каталог** даёт `target/source/...` вместо копии. *Исправление:* проверьте, существует ли цель; используйте `cp -a source/. target/`, чтобы скопировать *содержимое*.
3. **Имена с пробелами без кавычек** делают так, что команда видит несколько аргументов. *Исправление:* берите их в кавычки или избегайте пробелов.
4. **Удаление не того через `rm -rf`.** *Исправление:* сначала выполните `ls` с теми же аргументами; не используйте `-f` по привычке.
5. **Битая символическая ссылка.** `cat link` пишет `No such file or directory`, хотя `ls -l` показывает ссылку. *Исправление:* `readlink link` показывает путь, хранящийся в ссылке; проверьте, что такая цель существует.
6. **Попытка менять файлы Mac из ВМ.** `Read-only file system`. *Исправление:* работайте в `~` внутри ВМ.

## Упражнения

### Упражнение 1 — Исследуйте дерево (легко)

Без подсказок выясните, что находится в `/etc/hostname`, в каком каталоге лежат настройки вашего входа и
какой файл содержит список всех пользователей системы. Используйте `cat`, `ls -a ~` и таблицу из раздела 1.

<details>
<summary>Подсказка</summary>

Пользователи перечислены в текстовом файле в `/etc`, имя которого начинается с `pass`. Настройки вашей оболочки — скрытые файлы в `~`.

</details>

<details>
<summary>Ответ</summary>

```bash
cat /etc/hostname
ls -a ~
cat /etc/passwd
```

В `/etc/hostname` лежит имя машины (`lima-dev`). Скрытые файлы вроде `.bashrc` и `.profile` в `~`
хранят настройки вашей оболочки. `/etc/passwd` перечисляет пользователей (вы прочитаете его в Уроке 11.4).

Почему это работает: настройки — простой текст в `/etc`, а пользовательские настройки — файлы с точкой в домашнем каталоге.

</details>

### Упражнение 2 — Жёсткая ссылка выживает (средне)

Создайте `x.txt`, жёсткую ссылку `y.txt` и символическую ссылку `z.txt` на `x.txt`. Удалите `x.txt`. Какой из файлов
`y.txt` и `z.txt` вы ещё можете прочитать и почему? Подкрепите ответ выводом `ls -li`.

<details>
<summary>Подсказка</summary>

Сравните номера inode и счётчики ссылок до удаления.

</details>

<details>
<summary>Ответ</summary>

```bash
cd ~
echo data > x.txt
ln x.txt y.txt
ln -s x.txt z.txt
ls -li x.txt y.txt z.txt
rm x.txt
cat y.txt
cat z.txt
rm y.txt z.txt
```

`y.txt` по-прежнему читается (`data`); `z.txt` даёт `No such file or directory`.

Почему это работает: `x.txt` и `y.txt` — два имени одного inode, и данные остаются, пока остаётся имя. `z.txt`
хранит только текст `x.txt` — путь, который больше никуда не ведёт.

</details>

### Упражнение 3 — Напишите проверку структуры каталогов (средне)

**Тест** — это команда, которая отвечает «да» или «нет» через код возврата. Команда `[ -d path ]` успешна, если `path`
— каталог; `[ -f path ]` — если обычный файл; `[ -L path ]` — если символическая ссылка. Напишите три проверки:
`/etc` — каталог; `/bin` — символическая ссылка; `/etc/hostname` — обычный файл. Для каждой напечатайте `ok` или `FAIL` через `&&` и `||`.

<details>
<summary>Подсказка</summary>

`cmd1 && echo ok || echo FAIL` печатает `ok`, если `cmd1` успешна, и `FAIL` в противном случае. Следите за пробелами внутри `[ ... ]`.

</details>

<details>
<summary>Ответ</summary>

```bash
[ -d /etc ] && echo ok || echo FAIL
[ -L /bin ] && echo ok || echo FAIL
[ -f /etc/hostname ] && echo ok || echo FAIL
[ -f /etc ] && echo ok || echo FAIL
```

```text
ok
ok
ok
FAIL
```

Последняя строка — намеренная неудача: `/etc` — каталог, а не обычный файл.

Почему это работает: `[` — команда bash (см. `type [`), которая проверяет условие и задаёт код возврата; `&&` запускает следующую команду только
после успеха, `||` — только после неудачи. Урок 11.8 собирает из этих частей скрипты.

</details>

## Вопросы для самопроверки

1. Сколько «корней» у файловой системы Linux и как подключить второй диск?

<details>
<summary>Ответ</summary>

Один корень, `/`. Второй диск *монтируется* в каталог дерева.

</details>

2. Где искать настройки системы для программы? А её журналы?

<details>
<summary>Ответ</summary>

Настройки: `/etc`. Журналы: `/var/log` (и journal, Урок 11.6).

</details>

3. Чем жёсткая ссылка отличается от символической?

<details>
<summary>Ответ</summary>

Жёсткая ссылка — ещё одно имя того же inode, поэтому данные живут, пока остаётся хотя бы одно имя. Символическая ссылка — маленький файл с путём; она ломается, если цель исчезает.

</details>

4. Что делает `/dev/null`?

<details>
<summary>Ответ</summary>

Выбрасывает всё, что в него записано, а при чтении выглядит пустым. Его используют, чтобы скрыть вывод.

</details>

5. Почему `rm my file.txt` не работает для файла с именем `my file.txt`?

<details>
<summary>Ответ</summary>

Оболочка делит слова по пробелам, поэтому `rm` получила два имени (`my` и `file.txt`). Возьмите имя в кавычки: `rm "my file.txt"`.

</details>

## Итоги

- Файловая система — одно дерево, которое начинается с `/`. В `/etc` лежат настройки, в `/var` меняющиеся данные и журналы, в `/usr` программы, в `/home` файлы пользователей, в `/tmp` временные файлы.
- Имена чувствительны к регистру; точка в начале скрывает файл; имена с пробелами берите в кавычки.
- Всё — файл: `/dev/null` поглощает данные, `/proc` показывает живую информацию ядра.
- `stat`, `file`, `du`, `df` рассказывают о файлах, содержимом, размерах и свободном месте.
- Жёсткая ссылка — ещё одно имя того же inode; символическая ссылка хранит путь и может «сломаться».
- `cp -r`, `mv`, `rm -r` требуют осторожности; корзины нет. `find` с `-name`, `-type`, `-size` находит файлы.
- Файлы вашего Mac в ВМ доступны только для чтения; скопируйте проект в `~`, чтобы собрать его там.
