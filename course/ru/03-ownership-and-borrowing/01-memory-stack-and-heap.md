# Урок 03.1 — Память: стек и куча

> **Этап 03 — Владение и заимствование** · Урок 1 из 8 · ⏱ около 2,5 часа (2 занятия)

## Что вы узнаете

- Как программа «видит» память: байты, адреса и указатели.
- Что такое **стек** (stack), почему он быстрый и что происходит, когда он заканчивается.

## Новые слова

| Слово | Значение |
|---|---|
| **память** (memory) | Место, где работающая программа хранит свои данные. Представьте очень длинный ряд пронумерованных ячеек. |
| **RAM** (Random Access Memory, оперативная память) | Быстрые временные микросхемы памяти в компьютере. Всё, что использует работающая программа, находится здесь. Память очищается, когда программа завершается или компьютер выключается. |
| **CPU** (Central Processing Unit, центральный процессор) | Микросхема, которая выполняет инструкции программы, читает и записывает память. |
| **байт** (byte) | Одна ячейка памяти. В ней хранится число от 0 до 255. Всё остальное (текст, большие числа) собирается из нескольких байтов. |
| **адрес** (address) | Номер ячейки памяти, как номер дома на улице. |
| **указатель** (pointer) | Значение, которое содержит адрес. Оно «указывает» на место, где лежат другие данные. |
| **стек** (stack) | Область памяти для локальных переменных. Работает как стопка тарелок: последним положили — первым взяли. |
| **LIFO** (Last In, First Out, «последним пришёл — первым вышел») | Правило стопки: последний положенный элемент снимается первым. |
| **кадр стека** (stack frame) | Блок стека, принадлежащий одному вызову функции. В нём лежат локальные переменные этого вызова. |
| **куча** (heap) | Большая область памяти для данных, размер которых заранее неизвестен или которые должны жить дольше одного вызова функции. |
| **выделить** (allocate) / **освободить** (free) | Выделить — значит попросить кусок памяти в куче. Освободить (также *deallocate*) — значит вернуть его обратно. |
| **аллокатор** (allocator) | Часть системы, которая выдаёт и забирает обратно куски памяти в куче. |
| **ёмкость** (capacity) | Сколько байтов (или элементов) может вместить растущее значение, такое как `String` или `Vec`, прежде чем ему понадобится кусок кучи побольше. |
| **переполнение стека** (stack overflow) | Аварийное завершение, когда на стеке кончилось место, обычно из-за функции, которая бесконечно вызывает саму себя. |
| **утечка памяти** (memory leak) | Память в куче, которую выделили, но так и не освободили, поэтому программа занимает всё больше и больше памяти. |
| **висячий указатель** (dangling pointer) | Указатель на память, которая уже освобождена. Использовать его — серьёзная ошибка. |
| **cache** (кэш) | Небольшая очень быстрая память внутри CPU, которая хранит недавно использованные данные рядом с микросхемой. |
| **OS** (Operating System, операционная система) | Программа (macOS на вашем Mac), которая управляет компьютером и выдаёт память другим программам. |

## 1. Память — это длинный ряд пронумерованных ячеек

В вашем Mac есть гигабайты RAM. Представьте её как одну очень длинную улицу. Каждый дом на улице — это один **байт**, и у каждого дома есть номер: его **адрес**.

```text
address:   ...  1000   1001   1002   1003   1004   1005  ...
content:   ...  [ 42 ] [ 7  ] [ 0  ] [ 255] [ 18 ] [ 9  ] ...
```

Когда ваша программа выполняет `let number = 42;`, Rust выбирает несколько ячеек, записывает в них число и запоминает адрес. Значение, которому нужно больше 255, занимает несколько соседних байтов. Поэтому у разных типов разные **размеры**. Узнать размер типа можно с помощью `size_of`:

```rust
fn main() {
    println!("i32:        {} bytes", size_of::<i32>());
    println!("i64:        {} bytes", size_of::<i64>());
    println!("f64:        {} bytes", size_of::<f64>());
    println!("bool:       {} byte", size_of::<bool>());
    println!("char:       {} bytes", size_of::<char>());
    println!("(i32, i32): {} bytes", size_of::<(i32, i32)>());
    println!("[i32; 4]:   {} bytes", size_of::<[i32; 4]>());
    println!("String:     {} bytes", size_of::<String>());
    println!("&str:       {} bytes", size_of::<&str>());
    println!("&i32:       {} bytes", size_of::<&i32>());
}
```

**Что происходит:**

1. `size_of::<i32>()` — это функция, которая отвечает на вопрос «сколько байтов занимает одно значение этого типа?». Часть `::<i32>` сообщает функции, какой тип измерять. (Этот синтаксис относится к *обобщениям* (generics), которые вы изучите в Уроке 05.1. Пока просто копируйте его.)
2. Каждый `println!` выводит ответ для одного типа.
3. Размер определяется только типом. Он одинаков для любого значения этого типа.

```text
i32:        4 bytes
i64:        8 bytes
f64:        8 bytes
bool:       1 byte
char:       4 bytes
(i32, i32): 8 bytes
[i32; 4]:   16 bytes
String:     24 bytes
&str:       16 bytes
&i32:       8 bytes
```

Обратите внимание на три вещи:

- `i32` всегда занимает 4 байта. Кортеж из двух `i32` занимает 8, а массив из четырёх — 16. Размеры просто складываются.
- `String` занимает **24 байта** — независимо от того, хранит ли он «hi» или весь текст романа. Очевидно, что `String` не может держать свои буквы внутри этих 24 байтов. Где же буквы? Это главный вопрос урока.
- Ссылка вроде `&i32` занимает **8 байтов**. Это просто адрес. (Ваш Mac — *64-битный* компьютер, поэтому адрес — это 64 бита = 8 байтов.)

> 💡 **Совет:** `size_of` входит в *прелюдию* Rust (prelude — небольшой набор имён, доступных любой программе без строки `use`). Когда захотите узнать «насколько велик этот тип?», просто выведите его размер.

## 2. Стек: быстрый, аккуратный и ограниченный

**Стек** — это часть памяти, где живут ваши локальные переменные. Он работает как стопка тарелок в столовой. Тарелку можно положить только сверху и взять тоже только сверху. Это правило называется **LIFO** (Last In, First Out — «последним пришёл — первым вышел»).

Каждый раз, когда вызывается функция, программа кладёт на вершину стопки новый блок. Это **кадр стека** функции. В нём лежат параметры и локальные переменные функции. Когда функция возвращает управление, её кадр снимается, и всё, что в нём было, исчезает сразу.

```rust
fn main() {
    let a = 1;
    println!("main:   a is at {:p}", &a);
    first();
}

fn first() {
    let b = 2;
    println!("first:  b is at {:p}", &b);
    second();
}

fn second() {
    let c = 3;
    println!("second: c is at {:p}", &c);
}
```

**Что происходит:**

1. Запускается `main`. Её кадр кладётся на стек. Переменная `a` живёт внутри него.
2. `&a` означает «адрес `a`». Это *ссылка*; про ссылки вы узнаете в Уроке 03.4. Формат `{:p}` выводит адрес (`p` — от *pointer*, указатель).
3. `main` вызывает `first`. Новый кадр для `first` кладётся сверху, в нём лежит `b`. Затем `first` вызывает `second`, и третий кадр хранит `c`.
4. Когда `second` завершается, её кадр снимается. Затем кадр `first`, затем кадр `main`.

```text
main:   a is at 0x16bc51e64
first:  b is at 0x16bc51e14
second: c is at 0x16bc51dc4
```

У вас числа будут другими. Операционная система сама выбирает, где начинается стек, и это место меняется от запуска к запуску. Но закономерность та же: **чем глубже вызов, тем меньше адрес**. На вашем Mac стек растёт в сторону меньших адресов.

```text
 high addresses
 ┌──────────────────┐
 │ frame of main    │  a = 1
 ├──────────────────┤
 │ frame of first   │  b = 2
 ├──────────────────┤
 │ frame of second  │  c = 3      ← the top of the stack (newest)
 └──────────────────┘
 low addresses
```

Почему стек быстрый? Потому что «выделить» кадр — это лишь сдвинуть одно число (*указатель стека*, stack pointer) вверх или вниз. Ничего не нужно искать и ничего не нужно чистить. Вершина стека к тому же используется постоянно, поэтому CPU держит её в своей небольшой очень быстрой внутренней памяти (она называется *кэш*, cache).

У стека два правила и одно ограничение:

- **Правило 1:** размер каждого значения должен быть известен при компиляции программы. Rust должен знать, насколько велик кадр, ещё до запуска функции.
- **Правило 2:** кадр живёт ровно столько, сколько длится вызов его функции. Нельзя сохранить значение со стека после возврата из функции.
- **Ограничение:** стек небольшой. У главного потока на вашем Mac около 8 MiB (мебибайт, примерно 8 миллионов байтов).

Что будет, если использовать больше? Посмотрите на функцию, которая вызывает саму себя без конца:

```rust
fn count_down_forever(n: u64) -> u64 {
    count_down_forever(n + 1) + 1
}

fn main() {
    println!("starting");
    let result = count_down_forever(0);
    println!("result = {}", result);
}
```

Каждый вызов добавляет кадр, и ни один вызов не возвращается. Компилятор даже предупреждает об этом («function cannot return without recursing»). Запустите:

```text
starting

thread 'main' (3866480) has overflowed its stack
fatal runtime error: stack overflow, aborting
```

Это **переполнение стека** (stack overflow). Программу останавливает операционная система, а ваш последний `println!` не выполняется. Код завершения программы — 134 (сигнал, а не обычное завершение).

> ⚠️ **Частая ошибка:** обычная причина переполнения стека — глубокая *рекурсия* (функция, вызывающая саму себя). Цикл не добавляет кадров, поэтому цикл в десять миллионов шагов — это нормально, а десять миллионов вложенных вызовов — нет. Вы потренируетесь на этом в Упражнении 5.

## 3. Куча: гибкая, но не бесплатная

Некоторые данные не подходят под правила стека:

- Их размер **неизвестен**, когда вы пишете программу. Строка, введённая пользователем, может содержать 3 буквы, а может 3000.
- Они должны **расти или уменьшаться** во время работы программы.
- Они должны **жить дольше**, чем функция, которая их создала.

Для этого программы используют **кучу**. Куча — это большой пул памяти, которым управляет **аллокатор**. Разговор происходит так:

1. Ваша программа говорит: «Мне нужно 100 байтов».
2. Аллокатор находит где-то в куче 100 свободных байтов, помечает их занятыми и отвечает их **адресом**.
3. Ваша программа хранит этот адрес в **указателе** и пользуется памятью.
4. Когда программа закончила, она обязана сказать: «Эти 100 байтов мне больше не нужны». Аллокатор снова помечает их свободными, и их можно использовать повторно.

Просьба называется **выделением** (allocate). Возврат называется **освобождением** (free). Между этими двумя моментами память принадлежит вашей программе.

Теперь вы можете ответить на вопрос из раздела 1. `String` — это **три числа на стеке** — указатель на буквы, *длина* (сколько байтов используется) и *ёмкость* (сколько байтов зарезервировано) — и **сами буквы в куче**. 3 числа × 8 байтов = 24 байта. Именно это и показал `size_of::<String>()`.

```text
  STACK                              HEAP
 ┌─────────────────────┐            ┌───┬───┬───┬───┬───┐
 │ s: String           │            │ h │ e │ l │ l │ o │
 │   ptr ──────────────┼──────────► └───┴───┴───┴───┴───┘
 │   len = 5           │             5 bytes reserved, 5 used
 │   cap = 5           │
 └─────────────────────┘
```

Посмотрим на эти части на настоящем коде:

```rust
fn main() {
    let number = 42;
    let text = String::from("hello");
    println!("number lives at {:p}", &number);
    println!("text (the three-part value) lives at {:p}", &text);
    println!("the letters of text live at {:p}", text.as_ptr());
}
```

**Что происходит:**

1. `number` — обычный `i32`, поэтому он целиком живёт на стеке.
2. `String::from("hello")` просит у аллокатора место и копирует туда буквы. Трёхчастное значение `text` лежит на стеке.
3. `&text` — адрес этого трёхчастного значения. `text.as_ptr()` — указатель, **хранящийся внутри** него, то есть адрес букв.

```text
number lives at 0x16dab1dac
text (the three-part value) lives at 0x16dab1db0
the letters of text live at 0x102a912d0
```

Первые два адреса близки друг к другу (оба находятся в одном кадре стека). Третий сильно отличается. Он находится в другой области памяти — в куче. Точные числа меняются при каждом запуске программы, но *разница* между адресами стека и кучи остаётся.

### Как растущая String использует кучу

`String` может расти. Когда места не остаётся, она просит у аллокатора кусок побольше, копирует буквы и освобождает старый кусок. Посмотрим на ёмкость:

```rust
fn main() {
    let mut s = String::with_capacity(5);
    println!("start:  len = {}, capacity = {}, letters at {:p}", s.len(), s.capacity(), s.as_ptr());

    s.push_str("hello");
    println!("hello:  len = {}, capacity = {}, letters at {:p}", s.len(), s.capacity(), s.as_ptr());

    s.push('!');
    println!("hello!: len = {}, capacity = {}, letters at {:p}", s.len(), s.capacity(), s.as_ptr());

    let empty = String::new();
    println!("new():  len = {}, capacity = {}", empty.len(), empty.capacity());
}
```

**Что происходит:**

1. `String::with_capacity(5)` создаёт пустую строку, но уже резервирует 5 байтов в куче. Поэтому `len` равна 0, а `capacity` равна 5.
2. `push_str("hello")` добавляет 5 байтов. Они помещаются точно. Ёмкость не меняется.
3. `push('!')` нужен 6-й байт. Места нет, поэтому `String` просит больше. Она просит не один лишний байт, а удваивает ёмкость (5 → 10), чтобы следующие добавления были дешёвыми.
4. `String::new()` пуста и имеет ёмкость 0: она вообще не обращалась к куче.

```text
start:  len = 0, capacity = 5, letters at 0x1025352d0
hello:  len = 5, capacity = 5, letters at 0x1025352d0
hello!: len = 6, capacity = 10, letters at 0x1025352d0
new():  len = 0, capacity = 0
```

(Адрес здесь остался тем же, а значит, аллокатор, вероятно, смог увеличить кусок на месте. При других запусках или на других машинах адрес может измениться; когда он меняется, старый кусок освобождается. Rust не позволит вам по ошибке продолжать использовать старый адрес — почему, вы увидите в Уроке 03.5.)

`Vec<T>` (растущий список элементов типа `T`; вы изучите его в Уроке 04.7) работает так же. Посмотрите на его ёмкость, пока мы добавляем числа:

```rust
fn main() {
    let mut numbers = Vec::new();
    println!("start: len = {}, capacity = {}", numbers.len(), numbers.capacity());
    for i in 1..=9 {
        numbers.push(i);
        println!("push {}: len = {}, capacity = {}", i, numbers.len(), numbers.capacity());
    }
}
```

```text
start: len = 0, capacity = 0
push 1: len = 1, capacity = 4
push 2: len = 2, capacity = 4
push 3: len = 3, capacity = 4
push 4: len = 4, capacity = 4
push 5: len = 5, capacity = 8
push 6: len = 6, capacity = 8
push 7: len = 7, capacity = 8
push 8: len = 8, capacity = 8
push 9: len = 9, capacity = 16
```

Закономерность такая: 0 → 4 → 8 → 16. Каждый раз, когда место заполнено, ёмкость удваивается, а элементы копируются в новый кусок кучи.

### Box: одно значение в куче

Rust также позволяет положить одно значение в кучу с помощью `Box::new`. `Box` — это просто указатель на значение в куче (полностью вы изучите его в Уроке 05.9):

```rust
fn main() {
    let on_stack = 42;
    let on_heap = Box::new(42);
    println!("on_stack = {}, on_heap = {}", on_stack, on_heap);
    println!("the Box itself is {} bytes", size_of::<Box<i32>>());
    println!("on_stack is at {:p}", &on_stack);
    println!("the heap number is at {:p}", on_heap);
}
```

```text
on_stack = 42, on_heap = 42
the Box itself is 8 bytes
on_stack is at 0x16b04dd84
the heap number is at 0x1056592d0
```

Сам `Box` (8 байтов: адрес) лежит на стеке. Число `42`, на которое он указывает, лежит в куче. Пользоваться `on_heap` можно почти как обычным числом.

## 4. Что где лежит

| Значение | Часть на стеке | Часть в куче |
|---|---|---|
| `let n: i32 = 5` | 4 байта `n` | — |
| `let x: f64`, `bool`, `char` | само значение | — |
| `let t = (1, true)` | весь кортеж | — |
| `let a = [0u8; 16]` | все 16 байтов | — |
| `let s = String::from("hi")` | указатель, длина, ёмкость (24 байта) | буквы |
| `let v = vec![1, 2, 3]` | указатель, длина, ёмкость (24 байта) | три числа |
| `let b = Box::new(7)` | указатель (8 байтов) | число `7` |
| `let r = "hello"` (`&str`) | указатель и длина (16 байтов) | — (буквы хранятся внутри самого файла программы) |

Практическое правило: **значения фиксированного размера живут на стеке; значения, которые могут расти или чей размер неизвестен, живут (хотя бы частично) в куче, а на стеке лежит небольшой «дескриптор», указывающий на них.**

> ⚡ **Производительность:** стек быстрее кучи, потому что там нечего искать, а память уже «тёплая» в кэше CPU. Выделение стоит времени, а переход по указателю в кучу может стоить ещё одного обращения к памяти. Не делайте вывод «никогда не использовать кучу» — большинству настоящих программ она нужна. Вывод такой: не выделяйте больше, чем необходимо, и **измеряйте, прежде чем оптимизировать** (как это делать, расскажет Этап 09).

## 5. Кто освобождает кучу? Три вида ошибок

Память в куче нужно вернуть ровно один раз. Это самая трудная часть ручного управления памятью. Есть три классические ошибки:

```text
1. Memory leak       — you forget to free.
   The memory stays reserved for nothing. A long-running server grows
   bigger and bigger until the operating system kills it.

2. Dangling pointer  — you free, but keep using the pointer.
   It is like a hotel key card for a room that was given to another guest.
   You read or write data that now belongs to someone else.
   (This is also called "use after free".)

3. Double free       — you free the same memory twice.
   The allocator's bookkeeping is corrupted. The program may crash,
   or worse, an attacker can use it.
```

Языки решают эту проблему по-разному. В одних программист должен вызвать «free» вручную и ни разу не ошибиться. В других часть среды выполнения, называемая *сборщиком мусора* (garbage collector), время от времени ищет неиспользуемую память; это стоит скорости и делает время работы менее предсказуемым. Rust использует третий путь:

> Компилятор решает во время компиляции, где именно нужно освободить каждый кусок памяти в куче, опираясь на набор правил, который называется **владение** (ownership). Проверки происходят до запуска программы, и во время выполнения нет сборщика мусора.

Если правила нарушены, программа не компилируется. Если они соблюдены, в безопасном коде на Rust не бывает утечек обычного вида, висячих указателей и двойных освобождений. Правила вы изучите в следующих уроках, начиная с [Урока 03.2 — Правила владения](02-ownership-rules.md).

> 🔒 **Безопасность:** ошибки использования после освобождения и двойного освобождения — одни из самых частых причин серьёзных дыр в безопасности программ на языках, где освобождать память должен сам программист. Значительная часть ценности Rust для системного инженера в том, что компилятор отклоняет эти классы ошибок.

> 📏 **Соглашение:** в коде на Rust вам редко нужно самим писать «выделить» или «освободить». Вы создаёте значения `String`, `Vec` и `Box`, и они сами освобождают свою память в куче в нужный момент. Этот приём называется **RAII** (Resource Acquisition Is Initialization, «получение ресурса есть инициализация»): значение, которое владеет ресурсом, освобождает его автоматически, когда исчезает. Урок 03.2 покажет это в действии.

## Частые ошибки

**1. Думать, что `String` хранит буквы на стеке.** `size_of::<String>()` всегда равно 24 байтам. Буквы лежат в куче. Это важно в следующих уроках: копировать `String` — это не то же самое, что копировать `i32`.

**2. Пытаться вывести адрес обычного значения.** Формату `{:p}` нужен указатель или ссылка, а не само значение:

```rust
fn main() {
    let x = 5;
    println!("{:p}", x);
}
```

```text
error[E0277]: the trait bound `{integer}: std::fmt::Pointer` is not satisfied
 --> src/main.rs:3:22
  |
3 |     println!("{:p}", x);
  |               ----   ^ the trait `std::fmt::Pointer` is not implemented for `{integer}`
  |               |
  |               required by this formatting parameter
```

Это означает: «целое число — не указатель, поэтому `{:p}` не может его вывести». Исправление: выводите адрес через `&x`: `println!("{:p}", &x);`.

**3. Писать бесконечную или очень глубокую рекурсию.** Результат — переполнение стека, как в разделе 2. Если число шагов может быть большим, предпочитайте цикл.

**4. Считать, что кучу надо избегать, потому что она «медленная».** Куча — обычный необходимый инструмент. Избегайте *лишних* выделений в горячем коде, но свободно используйте `String` и `Vec`, когда они нужны.

## Упражнения

### Упражнение 1 — Стек или куча? (легко)

Для каждого объявления скажите, что лежит на стеке, а что в куче:

1. `let a: i32 = 7;`
2. `let b = String::from("rust");`
3. `let c = [0u8; 16];`
4. `let d = Box::new(7);`
5. `let e = vec![1, 2, 3];`
6. `let f = (1, true);`
7. `let g = "hello";`

<details>
<summary>Подсказка</summary>

Задайте два вопроса: «Размер фиксирован и известен при компиляции?» и «Может ли значение расти?». Растущее значение хранит небольшой дескриптор на стеке, а данные — в куче.

</details>

<details>
<summary>Ответ</summary>

1. `a`: только стек (4 байта).
2. `b`: три числа (указатель, длина, ёмкость) на стеке; буквы `rust` в куче.
3. `c`: только стек (16 байтов). У массива фиксированный размер.
4. `d`: указатель (8 байтов) на стеке; число `7` в куче.
5. `e`: указатель, длина, ёмкость на стеке; три числа в куче.
6. `f`: только стек (кортеж из двух небольших значений).
7. `g`: `&str` — это указатель и длина (16 байтов) на стеке. Буквы не в куче: они часть файла программы и только читаются.

Почему это работает: значения фиксированного размера, которые не растут, помещаются прямо в кадр стека. Всё, что может расти, нуждается в куче.

</details>

### Упражнение 2 — Предскажите размеры (легко)

Сначала предскажите вывод этой программы на бумаге, затем запустите её.

```rust
fn main() {
    println!("[u8; 100]: {}", size_of::<[u8; 100]>());
    println!("(u8, u32): {}", size_of::<(u8, u32)>());
    println!("[char; 3]: {}", size_of::<[char; 3]>());
    println!("&[u8]:     {}", size_of::<&[u8]>());
    println!("Vec<i32>:  {}", size_of::<Vec<i32>>());
}
```

<details>
<summary>Подсказка</summary>

`u8` — 1 байт, `u32` и `char` — 4 байта. Ссылка на срез (`&[u8]`) — это указатель плюс длина, как у `&str`. `Vec` — дескриптор, как `String`. Неожиданность — кортеж `(u8, u32)`: CPU любит, когда числа начинаются с адреса, кратного их размеру, поэтому Rust добавляет пустые байты-заполнители (padding).

</details>

<details>
<summary>Ответ</summary>

```text
[u8; 100]: 100
(u8, u32): 8
[char; 3]: 12
&[u8]:     16
Vec<i32>:  24
```

Почему это работает: 100 × 1 = 100; `(u8, u32)` — это 1 байт + 3 байта заполнителя + 4 байта = 8, а не 5; 3 × 4 = 12; ссылка на срез — это указатель (8) + длина (8) = 16; `Vec` — это указатель + длина + ёмкость = 24.

</details>

### Упражнение 3 — Протестируйте размеры (средне)

Напишите три теста (используйте `#[test]`, см. [Урок 02.8](../02-programming-basics/08-your-first-tests.md)), которые проверяют: `String` — это три машинных слова, `&str` — два машинных слова, а `[i32; 4]` — в четыре раза больше `i32`. «Машинное слово» здесь — это `size_of::<usize>()`. Запустите `cargo test`.

<details>
<summary>Подсказка</summary>

Поместите тесты в блок `#[cfg(test)] mod tests { ... }`. Используйте `assert_eq!(size_of::<String>(), 3 * size_of::<usize>());`. Строка `use` для `size_of` не нужна.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("run `cargo test`");
}

#[cfg(test)]
mod tests {
    #[test]
    fn string_is_three_machine_words() {
        assert_eq!(size_of::<String>(), 3 * size_of::<usize>());
    }

    #[test]
    fn str_reference_is_pointer_plus_length() {
        assert_eq!(size_of::<&str>(), 2 * size_of::<usize>());
    }

    #[test]
    fn array_size_is_count_times_item_size() {
        assert_eq!(size_of::<[i32; 4]>(), 4 * size_of::<i32>());
    }
}
```

```text
running 3 tests
...
test result: ok. 3 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

Почему это работает: тест говорит то же, что и раздел 1, но теперь компьютер перепроверяет это при каждом запуске `cargo test`.

</details>

### Упражнение 4 — Понаблюдайте, как растёт ёмкость (средне)

Напишите программу, которая начинает с `String::new()`, добавляет символ `'x'` сто раз и выводит строку **только** тогда, когда меняется ёмкость.

<details>
<summary>Подсказка</summary>

Заведите `let mut last_capacity = s.capacity();`. После каждого `push` сравнивайте `s.capacity()` с `last_capacity`. Если они различаются, выведите строку и обновите `last_capacity`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let mut s = String::new();
    let mut last_capacity = s.capacity();
    println!("len = 0, capacity = {last_capacity}");
    for i in 1..=100 {
        s.push('x');
        if s.capacity() != last_capacity {
            last_capacity = s.capacity();
            println!("len = {i}, capacity grew to {last_capacity}");
        }
    }
}
```

```text
len = 0, capacity = 0
len = 1, capacity grew to 8
len = 9, capacity grew to 16
len = 17, capacity grew to 32
len = 33, capacity grew to 64
len = 65, capacity grew to 128
```

Почему это работает: первое добавление выделяет 8 байтов, а затем ёмкость удваивается всякий раз, когда место заполнено. Точные числа — деталь реализации стандартной библиотеки, поэтому никогда не пишите код, который от них зависит.

</details>

### Упражнение 5 — Рекурсия против цикла (сложно)

Напишите две функции, вычисляющие `1 + 2 + … + n`: `sum_to_recursive(n: u64) -> u64` (функция вызывает саму себя с `n - 1`) и `sum_to_loop(n: u64) -> u64` (цикл `for`). Напишите тест, проверяющий, что обе дают 55 при `n = 10`. Затем вызовите обе с `n = 10_000_000` в `main` и посмотрите, что произойдёт.

<details>
<summary>Подсказка</summary>

Рекурсивная версия: если `n == 0`, вернуть `0`, иначе вернуть `n + sum_to_recursive(n - 1)`. Десять миллионов вложенных вызовов требуют десяти миллионов кадров стека.

</details>

<details>
<summary>Ответ</summary>

```rust
fn sum_to_recursive(n: u64) -> u64 {
    if n == 0 { 0 } else { n + sum_to_recursive(n - 1) }
}

fn sum_to_loop(n: u64) -> u64 {
    let mut total = 0;
    for i in 1..=n {
        total += i;
    }
    total
}

fn main() {
    println!("recursive 100 = {}", sum_to_recursive(100));
    println!("loop 10_000_000 = {}", sum_to_loop(10_000_000));
    println!("recursive 10_000_000 = {}", sum_to_recursive(10_000_000));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn both_versions_agree() {
        assert_eq!(sum_to_recursive(10), 55);
        assert_eq!(sum_to_loop(10), 55);
    }
}
```

Вывод `cargo run`:

```text
recursive 100 = 5050
loop 10_000_000 = 50000005000000

thread 'main' (3895331) has overflowed its stack
fatal runtime error: stack overflow, aborting
```

Почему это работает: 100 вложенных вызовов легко помещаются в стек размером 8 MiB, а цикл использует один кадр при любом `n`. Десять миллионов кадров не помещаются, поэтому последняя строка роняет программу. Тест проходит, потому что использует только `n = 10`.

</details>

## Вопросы для самопроверки

1. Что такое адрес и что такое указатель?

<details>
<summary>Ответ</summary>

Адрес — это номер одного байта в памяти. Указатель — это значение, хранящее адрес, то есть оно «указывает» на данные, которые там лежат.

</details>

2. Почему стек быстрый?

<details>
<summary>Ответ</summary>

Чтобы положить кадр на стек или снять его, достаточно сдвинуть одно число (указатель стека). Не нужно искать свободное место и не нужно очищать отдельные значения.

</details>

3. `String` занимает на стеке 24 байта. Что это за 24 байта?

<details>
<summary>Ответ</summary>

Три 8-байтовых числа: указатель на буквы в куче, длина (используемые байты) и ёмкость (зарезервированные байты).

</details>

4. Назовите две причины использовать кучу вместо стека.

<details>
<summary>Ответ</summary>

Размер неизвестен при написании программы, или данные должны расти либо уменьшаться во время работы, или данные должны жить дольше функции, которая их создала. (Любые две из них.)

</details>

5. Что такое висячий указатель?

<details>
<summary>Ответ</summary>

Указатель на память, которая уже освобождена. Чтение или запись через него затрагивает память, которая теперь может принадлежать чему-то другому.

</details>

6. Что вызывает переполнение стека и как его избежать?

<details>
<summary>Ответ</summary>

Использование большего объёма стека, чем доступно, чаще всего из-за функции, которая слишком много раз вызывает саму себя. Избежать можно, используя цикл вместо глубокой рекурсии или сохраняя небольшую глубину.

</details>

7. Как Rust избегает утечек, висячих указателей и двойных освобождений без сборщика мусора?

<details>
<summary>Ответ</summary>

Компилятор применяет правила владения, чтобы точно определить, где освобождается каждое значение, и отклоняет программы, нарушающие правила. Правила разобраны в Уроке 03.2.

</details>

## Итоги

- Память — это ряд пронумерованных байтов; адрес — номер байта; указатель хранит адрес.
- Стек хранит локальные переменные в кадрах, которые появляются и исчезают вместе с вызовами функций (LIFO). Он быстрый, но небольшой, и значения на нём должны иметь размер, известный при компиляции.
- Куча — гибкий пул памяти, который выдаёт аллокатор. Данным в куче нужен указатель, их нужно освободить ровно один раз, и они обходятся дороже данных на стеке.
- `String` или `Vec` — это небольшой дескриптор на стеке (указатель, длина, ёмкость) плюс данные в куче. `Box::new(x)` кладёт одно значение в кучу.
- Рост `String` или `Vec` сверх ёмкости выделяет кусок побольше, копирует данные и освобождает старый кусок.
- Классические ошибки — утечка, висячий указатель, двойное освобождение — возникают от освобождения памяти в неподходящий момент. Правила владения Rust, проверяемые при компиляции, их предотвращают.
