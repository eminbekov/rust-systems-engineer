# Этап 02 — Основы программирования на Rust

> **Стадия 1 — Фундамент: инструменты, Git и язык Rust** · ⏱ около 3 недель при ~10 часах в неделю

## О чём этот этап

Любая программа на любом языке строится из одних и тех же нескольких блоков: она хранит данные в **переменных**, задаёт данным **типы**, считает с помощью **операторов**, группирует код в **функции**, принимает решения с помощью **условий**, повторяет работу в **циклах** и общается с пользователем через **ввод и вывод**. Этот этап учит этим блокам на Rust, по одному, и показывает настоящие сообщения компилятора, которые вы будете видеть каждый день.

Вы также усвоите две привычки, которые отличают любителя от инженера. Первая — **тестирование**: написание небольших проверок, которые доказывают, что код работает, и которые запускаются снова после каждого изменения. Вторая — **отладка**: поиск причины ошибки по методу, а не наугад, с помощью печати, `dbg!`, backtrace и отладчика RustRover. Git проходит через весь этап: вы делаете коммит после каждого урока, а в проекте работаете на фича-ветке, делаете по одному коммиту на веху, сливаете и ставите тег на результат.

В конце вы соберёте всё вместе в проекте: игра «Угадай число» для терминала с внешним крейтом (`rand`), модульными тестами, README и чистой историей Git. Этот этап — основа для всего, что следует дальше. Следующий этап (владение и заимствование) объясняет идею, которая делает Rust особенным, и он гораздо проще, когда эти основы кажутся естественными.

## Что вы научитесь делать

- [ ] Создавать переменные с помощью `let`, `mut` и `const` и объяснять затенение и область видимости.
- [ ] Выбирать между целочисленными типами, числами с плавающей точкой, `bool` и `char` и объяснять переполнение и преобразования через `as`.
- [ ] Писать функции с параметрами и возвращаемыми значениями и использовать кортежи и массивы.
- [ ] Управлять потоком выполнения программы с помощью `if`, `match`, `loop`, `while` и `for`.
- [ ] Форматировать вывод с помощью `println!`, `format!`, `{:?}` и спецификаторов формата и хорошо комментировать код.
- [ ] Читать ввод из терминала, разбирать его и обрабатывать неверный ввод без аварийного завершения.
- [ ] Писать модульные тесты (`#[test]`, `assert_eq!`, `should_panic`) и применять разработку через тестирование.
- [ ] Находить ошибки с помощью `dbg!`, backtrace, отладчика, Clippy и `git bisect` и создавать небольшую протестированную программу с фича-веткой в Git, одним коммитом на веху, слиянием и тегом.

## Как изучать этот этап

1. **Набирайте код сами.** Не копируйте и не вставляйте. Набор заставляет заметить каждый символ, а ошибки компилятора учат вас больше, чем работающий код.
2. **Ломайте намеренно.** Уберите `mut`, добавьте точку с запятой, используйте неверный тип и прочитайте ошибку. К концу этапа сообщения об ошибках должны казаться друзьями.
3. **Запускайте примеры, затем меняйте их.** Измените число, тип, условие и предскажите результат до запуска. Именно предсказание создаёт понимание.
4. **Делайте коммит после каждого урока** с понятным сообщением (`feat(p02): …`, `test(p02): …`). Хорошая история Git — это дневник вашего прогресса и страховочная сетка.
5. **Выполняйте контрольную точку без конспектов**, затем повторяйте только пропущенные темы. Если тема остаётся непонятной, вернитесь к ней через день и через неделю.
