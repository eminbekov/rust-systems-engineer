# Урок 03.2 — Правила владения

> **Этап 03 — Владение и заимствование** · Урок 2 из 8 · ⏱ около 2,5 часа (2 занятия)

## Что вы узнаете

- Три правила владения простыми словами.
- Что такое **область видимости** (scope) и как Rust освобождает значение, когда его владелец покидает область видимости.
- В каком порядке значения уничтожаются (drop) и как *увидеть* это своими глазами.
- Что происходит с владением, когда вы передаёте значение в функцию или возвращаете его из неё.
- Почему эти правила устраняют утечки, висячие указатели и двойные освобождения.

## Перед началом

- Вы прошли [Урок 03.1 — Память: стек и куча](01-memory-stack-and-heap.md). Вы знаете, что `String` — это небольшой дескриптор на стеке плюс буквы в куче, и что память в куче нужно освободить ровно один раз.
- Вы умеете писать функции ([Урок 02.4](../02-programming-basics/04-functions.md)) и знаете, как работают переменные и блоки `{ }` ([Урок 02.1](../02-programming-basics/01-variables-and-mutability.md)).
- Создайте проект: `cargo new code/p03-ownership` (из `~/projects/rust`). Каждый пример ниже можно вставить в `src/main.rs`.

## Новые слова

| Слово | Значение |
|---|---|
| **значение** (value) | Кусок данных в памяти, например число `42` или текст `"hello"`. |
| **владелец** (owner) | Переменная, которая отвечает за значение. Только владелец может его освободить. |
| **владение** (ownership) | Набор правил, который говорит, кто владеет каждым значением и когда оно освобождается. |
| **область видимости** (scope) | Часть кода, где существует переменная. В Rust она начинается с `let` и заканчивается закрывающей `}` блока, который её содержит. |
| **drop** (уничтожение значения) | Освободить значение (и вернуть всё, чем оно владеет). Rust *уничтожает* (drops) значение, когда его владелец выходит из области видимости. |
| **перемещение** (move) | Передача владения от одной переменной другой. После перемещения старую переменную больше нельзя использовать. (Подробно перемещения разбираются в Уроке 03.3.) |
| **RAII** (Resource Acquisition Is Initialization, «получение ресурса есть инициализация») | Идея, что значение владеет ресурсом (памятью, файлом, блокировкой) и автоматически освобождает его, когда значение уничтожается. |
| **структура** (struct) | Способ создать собственный тип, объединяющий несколько значений. Здесь она используется только внутри маленького помощника; как следует структуры изучаются в Уроке 04.1. |
| **трейт** (trait) | Набор возможностей, которые может иметь тип. `Drop` — это трейт «что делать, когда меня уничтожают». Трейты изучаются в Уроке 05.2. |

## 1. Три правила

Вот правила владения. Они короткие, и вы должны уметь произнести их по памяти:

> 1. **У каждого значения есть ровно один владелец** — переменная.
> 2. **В каждый момент времени владелец может быть только один.**
> 3. **Когда владелец выходит из области видимости, значение уничтожается** (освобождается).

Бытовая картинка: значение — это **номер в гостинице**, а владелец держит **единственную карточку-ключ**. Вы можете отдать карточку другому (тогда сами войти уже не сможете), а когда владелец карточки выезжает, номер убирают, и он снова свободен. Два человека никогда не держат единственный мастер-ключ одновременно, поэтому никто не может убирать номер, пока в нём ещё спит другой.

Сравните с Уроком 03.1: три ошибки памяти возникали из-за освобождения в неподходящее время или дважды. Правило 3 говорит, *когда* освобождать (ровно один раз, когда владелец уходит), а правило 2 — *кто* это делает (владелец один, значит, и освобождение одно).

## 2. Область видимости: где живёт переменная

**Область видимости** — это участок кода, в котором переменная действительна. В Rust блок `{ ... }` создаёт область видимости. Переменная действительна от строки, где она создана, до закрывающей `}`.

```rust
fn main() {
    {
        let s = String::from("hello");
        println!("inside: {s}");
    } // s goes out of scope here

    println!("outside: {s}");
}
```

**Что происходит:**

1. Начинается внутренний блок. `let s = String::from("hello");` создаёт `String` (три числа на стеке, буквы в куче). `s` — её владелец.
2. `println!` использует `s`. Это нормально, потому что мы всё ещё в области видимости.
3. Закрывающая `}` завершает область видимости. `s` исчезает, поэтому Rust **уничтожает** `String`: память в куче освобождается.
4. Последний `println!` пытается использовать `s` за пределами области видимости. Компилятор отказывается:

```text
error[E0425]: cannot find value `s` in this scope
 --> src/main.rs:7:25
  |
7 |     println!("outside: {s}");
  |                         ^
  |
help: the binding `s` is available in a different scope in the same function
 --> src/main.rs:3:13
  |
3 |         let s = String::from("hello");
  |             ^
```

Эта ошибка говорит, что имени `s` здесь не существует. Исправление: используйте `s` только внутри блока или создайте переменную снаружи.

## 3. Как увидеть уничтожение

Обычно уничтожение невидимо. Чтобы *увидеть* его, мы используем маленький вспомогательный тип, который печатает сообщение, когда его уничтожают. Понимать этот помощник пока не нужно. Считайте его чёрным ящиком и просто скопируйте:

```rust
struct Noisy(String);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("  drop: {}", self.0);
    }
}

fn noisy(name: &str) -> Noisy {
    Noisy(name.to_string())
}
```

Коротко, по одному предложению:

- `struct Noisy(String);` создаёт новый тип `Noisy`, который хранит одну `String` (своё имя). Структуры — Урок 04.1.
- `impl Drop for Noisy { ... }` говорит: «когда `Noisy` уничтожается, выполни этот код». `Drop` — это *трейт* (Урок 05.2). Запись `self.0` — это имя, хранящееся внутри.
- `noisy("a")` — небольшая вспомогательная функция, которая создаёт `Noisy` с именем `"a"`. (`&str` в её сигнатуре — это текст, заимствованный откуда-то; это объясняется в Уроке 03.6.)

Теперь мы можем наблюдать за областями видимости:

```rust
fn main() {
    println!("start of main");
    let _first = noisy("first");
    {
        println!("  entering inner block");
        let _inner = noisy("inner");
        println!("  leaving inner block");
    }
    let _second = noisy("second");
    println!("end of main");
}
```

**Что происходит:**

1. `let _first = ...` создаёт `Noisy`. Имя, начинающееся с `_`, сообщает Rust: «я знаю, что эта переменная не используется; не предупреждай меня».
2. Внутренний блок создаёт `_inner`. Когда блок заканчивается, `_inner` выходит из области видимости, и его `drop` выполняется **на закрывающей скобке**.
3. После этого создаётся `_second`.
4. Когда `main` завершается, `_second` и `_first` выходят из области видимости и уничтожаются.

```text
start of main
  entering inner block
  leaving inner block
  drop: inner
end of main
  drop: second
  drop: first
```

Посмотрите на порядок в конце `main`: **`second` был уничтожен раньше `first`**. Переменные уничтожаются в **обратном порядке** создания, как тарелки, снимаемые с вершины стопки. С тремя переменными это ещё нагляднее:

```rust
fn main() {
    let _a = noisy("a");
    let _b = noisy("b");
    let _c = noisy("c");
    println!("end of main");
}
```

```text
end of main
  drop: c
  drop: b
  drop: a
```

Обратный порядок полезен. Если `b` было построено с использованием чего-то из `a`, то `b` уничтожается первым, пока `a` ещё существует.

> 📏 **Соглашение:** такое поведение — «владелец вышел из области видимости, значение автоматически убирается» — называется **RAII**. Оно не только для памяти: файл закрывается, блокировка отпускается, сетевое соединение разрывается точно так же, когда их владельцы уничтожаются. В обычном коде на Rust вы никогда не пишете `free` или `close` вручную.

## 4. Передача значения в функцию перемещает владение

Что происходит, когда вы передаёте `String` в функцию? У функции появляется **новый владелец**: её параметр. Старая переменная отказывается от владения. Мы говорим, что значение **перемещено** (moved).

```rust
fn takes_ownership(item: Noisy) {
    println!("  inside takes_ownership: {}", item.0);
} // item is dropped here

fn gives_ownership() -> Noisy {
    println!("  inside gives_ownership");
    noisy("made-by-function")
}

fn takes_and_gives_back(item: Noisy) -> Noisy {
    println!("  inside takes_and_gives_back: {}", item.0);
    item
}

fn main() {
    let x = noisy("x");
    println!("calling takes_ownership");
    takes_ownership(x);
    println!("back in main");

    let y = gives_ownership();
    println!("main now owns {}", y.0);

    let z = takes_and_gives_back(y);
    println!("main owns {} again", z.0);
    println!("end of main");
}
```

**Что происходит:**

1. `x` владеет `Noisy` по имени "x".
2. `takes_ownership(x)` перемещает значение в параметр `item`. Теперь владелец — `item`, а `x` пуста. Когда функция заканчивается, `item` выходит из области видимости, поэтому значение уничтожается **в конце функции**, а не в `main`.
3. `gives_ownership()` создаёт значение и возвращает его. Возвращённое значение перемещается наружу к вызывающему коду: `y` становится его владельцем. Здесь ничего не уничтожается.
4. `takes_and_gives_back(y)` перемещает значение внутрь и сразу возвращает его. Последняя строка `item` (без точки с запятой) — это возвращаемое значение, поэтому значение снова перемещается наружу, в `z`.
5. В конце `main` значением владеет `z`, и он его уничтожает. Переменные `x` и `y` ничем не владеют, поэтому ничего не уничтожают.

```text
calling takes_ownership
  inside takes_ownership: x
  drop: x
back in main
  inside gives_ownership
main now owns made-by-function
  inside takes_and_gives_back: made-by-function
main owns made-by-function again
end of main
  drop: made-by-function
```

Каждое значение было уничтожено ровно один раз. Ничего не утекло, ничего не освобождено дважды.

### Что говорит компилятор, если использовать перемещённое значение

Старая переменная больше не владелец, поэтому её нельзя использовать. Rust проверяет это при компиляции:

```rust
fn print_it(s: String) {
    println!("{s}");
}

fn main() {
    let name = String::from("Ada");
    print_it(name);
    println!("{name}");
}
```

```text
error[E0382]: borrow of moved value: `name`
 --> src/main.rs:8:16
  |
6 |     let name = String::from("Ada");
  |         ---- move occurs because `name` has type `String`, which does not implement the `Copy` trait
7 |     print_it(name);
  |              ---- value moved here
8 |     println!("{name}");
  |                ^^^^ value borrowed here after move
  |
note: consider changing this parameter type in function `print_it` to borrow instead if owning the value isn't necessary
 --> src/main.rs:1:16
  |
1 | fn print_it(s: String) {
  |    --------    ^^^^^^ this parameter takes ownership of the value
  |    |
  |    in this function
help: consider cloning the value if the performance cost is acceptable
  |
7 |     print_it(name.clone());
  |                  ++++++++
```

Как это читать:

- `error[E0382]` — код ошибки. `E0382` означает «использование перемещённого значения». Запустив `rustc --explain E0382`, вы прочтёте длинное объяснение.
- Подписи указывают на три места: где значение было создано (`move occurs because ...`), где оно было перемещено (`value moved here`) и где вы попытались его использовать (`value borrowed here after move`).
- `note` предлагает, чтобы функция *заимствовала* значение вместо того, чтобы забирать владение. Это настоящее исправление, и ему учит Урок 03.4.
- `help` предлагает `.clone()` (сделать полную копию). Это работает, но стоит времени и памяти. Урок 03.3 объясняет, когда это уместно.

### Перемещение внутри цикла

Перемещение может случиться и в месте, которое вы сначала не замечаете. Цикл выполняет своё тело много раз, а значение можно переместить только один раз:

```rust
fn print_it(s: String) {
    println!("{s}");
}

fn main() {
    let name = String::from("Ada");
    for _ in 0..2 {
        print_it(name);
    }
}
```

```text
error[E0382]: use of moved value: `name`
 --> src/main.rs:8:18
  |
6 |     let name = String::from("Ada");
  |         ---- move occurs because `name` has type `String`, which does not implement the `Copy` trait
7 |     for _ in 0..2 {
  |     ------------- inside of this loop
8 |         print_it(name);
  |                  ^^^^ value moved here, in previous iteration of loop
```

Первый проход перемещает `name` в `print_it`. На втором проходе у `name` нет значения. Rust видит это *до* запуска программы.

## 5. Возвращать значение обратно утомительно

До Урока 03.4 у нас есть только один инструмент: отдать значение и забрать его обратно, если оно ещё нужно. Это работает:

```rust
fn add_exclamation(mut s: String) -> String {
    s.push('!');
    s
}

fn text_and_length(s: String) -> (String, usize) {
    let length = s.len();
    (s, length)
}

fn main() {
    let greeting = String::from("hello");
    let greeting = add_exclamation(greeting);
    println!("{greeting}");

    let (greeting, length) = text_and_length(greeting);
    println!("{greeting} has {length} bytes");
}
```

**Что происходит:**

1. `add_exclamation` забирает владение, изменяет строку (`mut s` означает, что параметр можно менять) и возвращает её. В `main` строка `let greeting = ...` создаёт новую переменную, которая затеняет старую (Урок 02.1).
2. `text_and_length` хочет вернуть две вещи, поэтому возвращает кортеж: строку и её длину. Кортеж мы распаковываем с помощью `let (greeting, length) = ...`.

```text
hello!
hello! has 6 bytes
```

Это правильно, но неуклюже: каждая функция, которой нужно только *посмотреть* на значение, обязана вернуть его обратно. Rust решает это с помощью **ссылок**, и им посвящены Уроки 03.4 и 03.5.

## 6. Ещё факты об уничтожении

**Присваивание нового значения немедленно уничтожает старое.** Переменная остаётся, но значение, которым она владела, больше не нужно:

```rust
fn main() {
    let mut item = noisy("old");
    println!("item is {}", item.0);
    println!("assigning a new value");
    item = noisy("new");
    println!("assigned; item is {}", item.0);
    println!("end of main");
}
```

```text
item is old
assigning a new value
  drop: old
assigned; item is new
end of main
  drop: new
```

**Коллекция владеет своими элементами.** Когда уничтожается владелец `Vec` (растущего списка, Урок 04.7), все элементы внутри него тоже уничтожаются, по порядку:

```rust
fn main() {
    let mut list = Vec::new();
    list.push(noisy("one"));
    list.push(noisy("two"));
    list.push(noisy("three"));
    println!("the list has {} items", list.len());
    println!("end of main");
}
```

```text
the list has 3 items
end of main
  drop: one
  drop: two
  drop: three
```

Владение образует дерево:

```text
list (owner on the stack)
 └── heap buffer of the Vec
      ├── Noisy "one"   └── String "one"   (heap)
      ├── Noisy "two"   └── String "two"   (heap)
      └── Noisy "three" └── String "three" (heap)
```

Уничтожение корня уничтожает каждую ветку. Поэтому в Rust вы редко думаете об освобождении: освободите владельца, и всё, что под ним, уйдёт вместе с ним.

**Жизнь значения можно закончить раньше с помощью `drop`.** Функция `drop(x)` забирает владение `x` и ничего с ним не делает. Параметр сразу выходит из области видимости, поэтому значение убирается немедленно:

```rust
fn main() {
    let big = noisy("big-resource");
    println!("using {}", big.0);
    drop(big);
    println!("the resource is already gone");
    println!("end of main");
}
```

```text
using big-resource
  drop: big-resource
the resource is already gone
end of main
```

После `drop(big)` имя `big` — «перемещено из», поэтому его использование является ошибкой (`E0382`, «borrow of moved value»). `drop` нужен нечасто. Он полезен, когда значение держит что-то ценное, например большой буфер, файл или блокировку, и вы хотите освободить это до конца области видимости.

> 🔒 **Безопасность:** автоматическая очистка — это ещё и средство безопасности. Секреты, такие как пароли и ключи, не должны оставаться в памяти дольше необходимого. Поскольку значение уничтожается в известной, предсказуемой точке, легко рассуждать о том, сколько оно живёт. (Настоящие библиотеки для работы с секретами идут дальше и затирают память; об этом пойдёт речь на Этапе 10.)

> 🧪 **Тестирование:** тест может проверить, что функция правильно возвращает владение: достаточно вызвать её и использовать результат. Если бы функция «проглотила» значение, тест бы не скомпилировался. Ошибки компиляции — самые дешёвые тесты.

## Частые ошибки

**1. Использование переменной после передачи её в функцию по значению.** Это `E0382`, показанная выше. Спросите себя: «Нужно ли этой функции *владеть* значением или только смотреть на него?» Если только смотреть — заимствуйте (Урок 03.4).

**2. Перемещение значения внутри цикла.** Тоже `E0382`, показано выше. Вынесите вызов из цикла или сделайте так, чтобы функция заимствовала значение.

**3. Мысль, что значение уничтожается после своего *последнего использования*.** Это не так. Значение уничтожается, когда **заканчивается область видимости** владельца, даже если вы давно перестали его использовать. (Только *заимствования* из следующих уроков заканчиваются на последнем использовании.)

**4. Мысль, что затенение уничтожает старое значение.** Когда вы пишете `let x = ...;` дважды, первое значение остаётся живым до конца области видимости; просто имя скрыто. Упражнение 4 показывает это.

**5. Чтение `drop(x)` как «забыть `x`» и последующее использование `x`.**

```rust
fn main() {
    let s = String::from("hello");
    drop(s);
    println!("{s}");
}
```

```text
error[E0382]: borrow of moved value: `s`
 --> src/main.rs:4:16
  |
2 |     let s = String::from("hello");
  |         - move occurs because `s` has type `String`, which does not implement the `Copy` trait
3 |     drop(s);
  |          - value moved here
4 |     println!("{s}");
  |                ^ value borrowed here after move
```

`drop` — обычная функция. Она забирает владение, поэтому `s` перемещена. Исправление: не используйте `s` после `drop(s)`.

fn main() {
    let _a = noisy("a");

<details>
<summary>Подсказка</summary>

Переменные области видимости уничтожаются в обратном порядке на её закрывающей скобке. Сначала разберите внутренний блок, потом `main`.

<details>

### Упражнение 2 — Исправьте перемещённое значение (легко)

Эта программа не компилируется. Исправьте её, **используя только то, что вы знаете из этого урока** (не клонируйте):

```rust
fn print_twice(s: String) {
    println!("{s}");
    println!("{s}");
}

fn main() {
    let message = String::from("ownership");
    print_twice(message);
    println!("length: {}", message.len());
}
```

<details>
<summary>Подсказка</summary>

Если функции нужно отдать значение обратно, она может его вернуть. Измените тип возвращаемого значения и используйте возвращённое значение в `main`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn print_twice(s: String) -> String {
    println!("{s}");
    println!("{s}");
    s
}

fn main() {
    let message = String::from("ownership");
    let message = print_twice(message);
    println!("length: {}", message.len());
}
```

```text

ownership

```

Почему это работает: владение входит в `print_twice` и выходит обратно как возвращаемое значение. Новая `message` (она затеняет старую) снова владелец. В Уроке 03.4 вы увидите более простое исправление: заимствовать строку вместо того, чтобы забирать её.

</details>

### Упражнение 3 — Напишите функцию и тесты (средне)

Напишите `fn longer(a: String, b: String) -> String`, которая забирает владение обеими строками и возвращает более длинную (первую, если длины равны). Другая строка уничтожается, когда функция заканчивается. Напишите два теста: один для явного победителя и один для ничьей.

<details>
<summary>Подсказка</summary>

Сравните `b.len() > a.len()`. Используйте `if ... { b } else { a }` как последнее выражение функции. В тестах создавайте строки через `String::from(...)` и сравнивайте результат через `assert_eq!(result, "hello")` (`String` можно сравнивать с текстом).

</details>

<details>
<summary>Ответ</summary>

```rust
fn longer(a: String, b: String) -> String {
    if b.len() > a.len() { b } else { a }
}

fn main() {
    let result = longer(String::from("short"), String::from("much longer"));
    println!("{result}");
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn returns_the_longer_one() {
        let result = longer(String::from("hi"), String::from("hello"));
        assert_eq!(result, "hello");
    }

    #[test]
    fn tie_returns_the_first() {
        let result = longer(String::from("aa"), String::from("bb"));
        assert_eq!(result, "aa");
    }
}
```

```text
running 2 tests
..
test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

Почему это работает: оба параметра принадлежат функции. Она возвращает один из них (перемещая его наружу), а другой уничтожается на закрывающей скобке функции.

</details>

### Упражнение 4 — Затенение не уничтожает (сложно)

Предскажите вывод. В каком порядке и когда уничтожаются четыре значения?

```rust
fn main() {
    let x = noisy("first x");
    println!("the first x is {}", x.0);
    let x = noisy("second x");
    println!("shadowed; the current x is {}", x.0);

    let list = vec![noisy("p"), noisy("q")];
    println!("made the list");
    drop(list);
    println!("main ends");
}
```

<details>
<summary>Подсказка</summary>

Затенение лишь скрывает имя. Оба значения `Noisy` живы до конца `main`. `drop(list)` выполняется раньше и уничтожает `p`, затем `q` (по порядку).

</details>

<details>
<summary>Ответ</summary>

```text
the first x is first x
shadowed; the current x is second x
made the list
  drop: p
  drop: q
main ends
  drop: second x
  drop: first x
```

Почему это работает: `drop(list)` завершает жизнь списка раньше срока и уничтожает его элементы по порядку. Два значения `x` уничтожаются в конце `main` в обратном порядке создания: сначала «second x», затем «first x». Затенённое значение не было уничтожено раньше.

</details>

## Вопросы для самопроверки

1. Сформулируйте три правила владения.

<details>
<summary>Ответ</summary>

У каждого значения есть владелец; в каждый момент владелец может быть только один; когда владелец выходит из области видимости, значение уничтожается.

</details>

2. Когда именно уничтожается локальная переменная?

<details>
<summary>Ответ</summary>

На закрывающей скобке блока, где она была объявлена (в конце её области видимости), если только её значение не было перемещено куда-то раньше.

</details>

3. В каком порядке уничтожаются локальные переменные?

<details>
<summary>Ответ</summary>

В обратном порядке объявления: последняя созданная переменная уничтожается первой.

</details>

4. Что происходит со старой переменной, когда вы передаёте `String` в функцию по значению?

<details>
<summary>Ответ</summary>

Владение перемещается в параметр функции. Старая переменная больше ничем не владеет, и её использование — ошибка компиляции (`E0382`).

</details>

5. Почему в безопасном коде Rust никогда не освободит одну и ту же память в куче дважды?

<details>
<summary>Ответ</summary>

Потому что у значения в каждый момент только один владелец, и только владелец уничтожает значение. После перемещения старая переменная не может его уничтожить.

</details>

6. Что делает `drop(x)` и почему `x` после этого нельзя использовать?

<details>
<summary>Ответ</summary>

`drop` — обычная функция, которая забирает владение `x`. Её параметр сразу выходит из области видимости, поэтому значение убирается. Поскольку значение было перемещено в функцию, `x` больше использовать нельзя.

</details>

## Итоги

- У владения три правила: один владелец у значения, один владелец в каждый момент, уничтожение при выходе владельца из области видимости.
- Область видимости — это блок между фигурными скобками. Переменные уничтожаются в конце своей области видимости, в обратном порядке.
- Передача значения в функцию по значению **перемещает** владение; возврат значения перемещает его обратно наружу.
- Использование переменной после перемещения её значения — ошибка компиляции `E0382`.
- Присваивание переменной нового значения сразу уничтожает старое; уничтожение владельца уничтожает всё, чем он владеет.
- Отдавать значения и забирать их обратно можно, но это неуклюже. Заимствование (следующие уроки) — чистое решение.
