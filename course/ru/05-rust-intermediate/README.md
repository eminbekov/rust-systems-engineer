# Этап 05 — Rust: средний уровень

> **Стадия 1 — Фундамент: инструменты, Git и язык Rust** · ⏱ около 5 недель при ~10 часах в неделю

## О чём этот этап

После Этапа 04 вы умеете описывать данные структурами и перечислениями, хранить их в векторах и хеш-таблицах и обрабатывать
ошибки. Этот этап учит инструментам, которые превращают такие программы в **переиспользуемый, протестированный и задокументированный
код**. Вы напишете одну функцию, которая работает с многими типами (обобщения), опишете общие умения (трейты) и расскажете
компилятору, как долго живут заимствованные данные (времена жизни). Вы будете передавать маленькие кусочки поведения (замыкания) и
обрабатывать последовательности данных в ясном и быстром стиле (итераторы).

Вторая половина этапа посвящена повседневной работе инженера. Вы научитесь как следует тестировать и документировать свой код,
подключать чужой код через Cargo и крейты, пользоваться умными указателями, делить работу между потоками и измерять скорость
бенчмарками. Вы познакомитесь с `serde`, `clap`, `thiserror` и `anyhow` — крейтами, которые используют почти все настоящие программы на Rust.

На протяжении всего этапа вы также тренируете инженерные привычки вокруг кода: одна ветка Git на урок, маленькие коммиты со
значимыми сообщениями, `git add -p`, `git stash`, `git bisect`, хук pre-commit, запускающий `cargo fmt`, `cargo clippy` и `cargo test`,
а также помеченные тегами релизы с журналом изменений. Хороший код, который никто не может понять, протестировать или выпустить, — это ещё не инженерия.

Этап заканчивается настоящим консольным инструментом `minigrep` и контрольной точкой. После этого вы готовы к продвинутым возможностям Rust на Этапе 06.

## Что вы научитесь делать

- [ ] Писать обобщённые функции и типы с ограничениями трейтов и объяснять, почему обобщённый код так же быстр, как написанный вручную.
- [ ] Определять трейты, реализовывать стандартные трейты (`Display`, `From`, `Add`, `Default`, `Iterator`) и выводить самые частые через derive.
- [ ] Читать и писать аннотации времён жизни и возвращать заимствованные данные из функции без копирования.
- [ ] Использовать замыкания и конвейеры итераторов (`map`, `filter`, `fold`, `collect`) и выбирать между циклом и конвейером.
- [ ] Тестировать код «тест вперёд», покрывать ошибки и граничные случаи и организовывать модульные, интеграционные и документационные тесты.
- [ ] Документировать публичный API (функции и типы, которые может использовать другой код) примерами, которые запускаются как тесты, генерировать документацию через `cargo doc` и вести README и журнал изменений.
- [ ] Добавлять зависимости через Cargo, пользоваться умными указателями, делить состояние между потоками и измерять скорость бенчмарком.
- [ ] Использовать Git как инженерный инструмент: ветки, частичная подготовка к коммиту, хуки, bisect, теги.

## Проекты этого этапа

- **Учебные пакеты** (`code/p05-lessons`, `code/p05-textkit`): небольшие примеры из Уроков 05.1–05.7, каждый урок в своей ветке Git.
  `p05-textkit` вырастает из первого падающего теста в задокументированную, протестированную и помеченную тегом библиотеку (версия 0.1.0).
- **`minigrep`** (Урок 05.13): консольный инструмент поиска в духе `grep`, построенный с тестами, обработкой ошибок, библиотекой и тонким `main`,
  документацией и коммитом Git на каждую веху.
- **Контрольная точка** (Урок 05.14): тест для самопроверки и практические задания, которые покажут, готовы ли вы к Этапу 06.

## Как изучать этот этап

- **Набирайте каждый пример сами** в `code/p05-lessons` и запускайте его. Затем меняйте его нарочно и читайте сообщение компилятора.
  На этом этапе сообщения об ошибках — учитель: ошибки обобщений, трейтов и времён жизни лучше всего объясняют правила.
- **Выполняйте шаги с Git в каждом уроке.** Одна ветка на урок, коммит после каждого работающего примера и сообщение вида `feat(p05): …`.
  К концу этапа ваша история должна читаться как дневник того, чему вы научились.
- **Не нарушайте порядок.** Уроки 05.1–05.3 (обобщения, трейты, времена жизни) связаны между собой, а замыкания и итераторы опираются на них. Если
  урок кажется трудным, перечитайте предыдущий и повторите его упражнения.
- **Пишите тесты раньше кода**, когда упражнение просит написать и то, и другое. Сначала смотрите, как тест падает; именно эта привычка делает
  проекты безопасными для изменений.
- **Планируйте около 10 часов в неделю.** Два-три урока в неделю — хороший темп; выделите целый день на проект `minigrep` и не торопитесь.
