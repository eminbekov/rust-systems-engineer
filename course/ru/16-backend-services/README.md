# Этап 16 — Бэкенд-сервисы

> **Стадия 4 — Построить настоящие системы** · ⏱ около 4–5 недель при ~10 часах в неделю

## О чём этот этап

Бэкенд-сервис — программа, которая долго работает на сервере, ждёт запросов по сети и отвечает многим клиентам
одновременно: та часть, что стоит за каждым приложением и веб-страницей. На этом этапе вы шаг за шагом строите такие
сервисы на Rust — от эндпоинта «hello» до сервиса с базой данных, входом пользователей, кэшем, сообщениями, логами,
метриками и трассировками, упакованного в контейнеры.

Вы начинаете с HTTP API: как спроектировать аккуратный REST API и как построить его на `axum` с правильными ошибками,
проверкой ввода и middleware. Затем вы с нуля изучаете SQL и PostgreSQL и подключаете сервис к базе данных через
`sqlx`, запросы которого компилятор проверяет на настоящей базе. Миграции держат схему под контролем, транзакции
сохраняют данные корректными, а аутентификация позволяет пользователям безопасно входить.

Вторая половина добавляет то, что нужно настоящим системам вокруг этого ядра: gRPC на `tonic` для вызовов между
сервисами, Redis как кэш, NATS для сообщений, OpenTelemetry для наблюдаемости, конфигурацию и проверки
работоспособности для контейнеров, а также тесты с настоящими сервисами. В конце вы соберёте всё вместе в собственном
сервисе коротких ссылок.

## Что вы научитесь делать

- [ ] Объяснять, что такое бэкенд-сервис, почему он должен быть без состояния и из каких частей состоит бэкенд-система.
- [ ] Проектировать REST API с правильными методами, кодами статуса и единым JSON-форматом ошибок.
- [ ] Строить HTTP-сервис на `axum`: маршруты, экстракторы, общее состояние, проверка ввода, middleware и тесты маршрутизатора.
- [ ] Писать SQL для PostgreSQL и использовать его из Rust через `sqlx`, включая запросы, проверяемые при компиляции, и офлайн-режим.
- [ ] Развивать схему базы данных миграциями и сохранять корректность многошаговых изменений транзакциями.
- [ ] Добавлять регистрацию, вход и защищённые эндпоинты с Argon2 и токенами сессий.
- [ ] Использовать gRPC, Redis и NATS и делать сервис наблюдаемым с помощью логов, метрик и трассировок.
- [ ] Настраивать, упаковывать в контейнер и тестировать полный сервис вместе с его зависимостями.

## Проекты этого этапа

- `code/p16-hello`: ваш первый сервис на `axum` (Уроки 16.1 и 16.2).
- `code/p16-tasks`: API задач, который растёт от урока к уроку: сначала в памяти, затем в PostgreSQL с миграциями,
  транзакциями и входом пользователей (Уроки 16.3–16.8).
- **Проект 16.15 — сервис коротких ссылок:** REST API с PostgreSQL, кэш в Redis, аутентификация для
  административных эндпоинтов, ограничение частоты запросов, трассировки OpenTelemetry, Docker Compose и
  интеграционные тесты.

## Как изучать этот этап

- Держите открытыми два терминала: в одном работает сервис, в другом — `curl`. Читайте каждый ответ, включая
  заголовки (`curl -i`).
- Начиная с Урока 16.5 должен работать Docker Desktop. Держите контейнер PostgreSQL запущенным, пока работаете, потому
  что макросы `sqlx` проверяют по нему ваши запросы при сборке.
- Проходите уроки по порядку: `p16-tasks` меняется в каждом уроке, и каждый урок начинается с того состояния, в котором
  его оставил предыдущий. Делайте коммит после каждого урока, чтобы всегда можно было вернуться.
- Запускайте `cargo test` и `cargo clippy` перед каждым коммитом. Большинство тестов этого этапа общаются с настоящей
  базой данных; это медленнее, и в этом весь смысл.
- Никогда не кладите настоящие пароли и токены в код, команды или Git. `dev-password` этого этапа — только для вашего
  ноутбука, а `.env` должен быть в `.gitignore`.
