## Новые слова

| Слово | Значение |
|---|---|
| **функция** (function) | Именованный блок кода, который выполняет одну задачу. Его можно запускать много раз, вызывая. |
| **вызов** (call) | Запуск функции: `add(3, 4)`. |
| **параметр** (parameter) | Переменная в определении функции, которая получает значение: `a` в `fn add(a: i32)`. |
| **аргумент** (argument) | Фактическое значение, которое вы передаёте при вызове: `3` в `add(3, 4)`. |
| **возвращаемое значение** (return value) | Значение, которое функция отдаёт вызывающему коду. |
| **возвращаемый тип** (return type) | Тип возвращаемого значения, записывается после `->`. |
| **сигнатура** (signature) | Первая строка функции: имя, параметры и возвращаемый тип. |
| **завершающее выражение** (tail expression) | Последнее выражение тела функции, записанное без `;`. Это и есть возвращаемое значение. |
| **рекурсия** (recursion) | Функция, которая вызывает саму себя. |
| **базовый случай** (base case) | Простой случай, в котором рекурсивная функция перестаёт вызывать себя. |
| **стек вызовов** (call stack) | Область памяти, где компьютер хранит данные функций, работающих прямо сейчас. |
| **кадр стека** (stack frame) | Часть стека вызовов, которая принадлежит одному вызову функции. |
| **переполнение стека** (stack overflow) | Аварийное завершение, которое происходит, когда стек вызовов заполняется, обычно из-за бесконечной рекурсии. |
| **DRY** (Don't Repeat Yourself, «не повторяйся») | Принцип: не копируйте один и тот же код в несколько мест; вынесите его в одну функцию. |
| **KISS** (Keep It Simple, Stupid, «делай проще») | Принцип: предпочитайте самое простое решение, которое работает. |
| **предикат** (predicate) | Функция, которая отвечает на вопрос «да/нет» и возвращает `bool`, например `is_even`. |

## 1. Зачем нужны функции?

Представьте, что вам нужно переводить минуты в секунды в десяти местах. Можно написать `minutes * 60` десять раз. А если правило изменится? Придётся искать десять мест. **Функция** даёт вычислению имя и один дом:

```text
          +----------------------+
 inputs   |                      |  output
 -------> |   function "area"    | -------> 
 (3, 4)   |   width * height     |   12
          +----------------------+
```

Функции дают три вещи:

1. **Повторное использование** — пишете один раз, вызываете много раз (принцип **DRY**: Don't Repeat Yourself).
2. **Имена** — `is_leap_year(2024)` объясняет себя лучше, чем длинное логическое выражение.
3. **Маленькие части** — маленькую функцию можно проверить и понять, не читая всю программу.

Одну функцию вы уже постоянно используете: `fn main()`, начальную точку любой программы.

## 2. Определение и вызов функции

```rust
fn main() {
    say_hello();
    let total = add(3, 4);
    println!("3 + 4 = {total}");
    println!("10 + 20 = {}", add(10, 20));
    print_square(7);
}

fn say_hello() {
    println!("Hello from a function!");
}

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn print_square(n: i32) {
    println!("{n} squared is {}", n * n);
}
```

Что происходит:

1. Программа стартует в `main`. У `main` нет параметров, и она ничего не возвращает.
2. `say_hello();` **вызывает** функцию `say_hello`. Компьютер переходит в её тело, выполняет `println!` и возвращается.
3. `fn add(a: i32, b: i32) -> i32` — это **сигнатура**. Ключевое слово `fn` начинает функцию. Затем идут имя `add`, **параметры** в скобках (`a` и `b`, оба `i32`), стрелка `->` и **возвращаемый тип** `i32`.
4. `add(3, 4)` — вызов с двумя **аргументами**: `3` попадает в `a`, `4` — в `b`. У тела `a + b` нет точки с запятой, поэтому оно — **завершающее выражение** и становится возвращаемым значением `7`. Оно сохраняется в `total`.
5. Вызов — это выражение, поэтому его можно использовать везде, где подходит значение: `add(10, 20)` внутри `println!`.
6. У `print_square` нет `->`: она ничего не возвращает (точнее, возвращает `()`, значение unit из Урока 02.2).
7. Функции определены **после** `main`. В Rust порядок не важен: функцию можно использовать раньше строки, где она написана.

```text
Hello from a function!
3 + 4 = 7
10 + 20 = 30
7 squared is 49
```

Правила сигнатуры:

- **У каждого параметра должен быть тип.** Rust никогда не угадывает типы параметров. (Типы локальных переменных внутри функции по-прежнему выводятся.)
- Возвращаемый тип пишется после `->`. Если `->` нет, функция возвращает `()`.
- Параметры сопоставляются по **позиции**: первый аргумент идёт в первый параметр.

> 📏 **Соглашение:** имена функций пишутся в `snake_case` и начинаются с глагола или описывают результат: `calculate_tax`, `is_valid`, `to_celsius`. Функция, возвращающая `bool`, часто начинается с `is_`, `has_` или `can_`. Такая функция называется **предикатом**.

## 3. Возврат значений

Значение функции — это значение блока её тела, то есть **завершающее выражение**. Это в точности правило из Урока 02.3. Можно также использовать ключевое слово `return`, чтобы выйти из функции раньше:

```rust
fn double(x: i32) -> i32 {
    x * 2
}

fn double_explicit(x: i32) -> i32 {
    return x * 2;
}

fn clamp_to_100(x: i32) -> i32 {
    if x > 100 {
        return 100;
    }
    x
}

fn main() {
    println!("{}", double(21));
    println!("{}", double_explicit(21));
    println!("{}", clamp_to_100(250));
    println!("{}", clamp_to_100(42));
}
```

Что происходит:

1. `double` использует завершающее выражение: обычный стиль Rust.
2. `double_explicit` использует `return x * 2;` с точкой с запятой. Делает то же самое.
3. У `clamp_to_100` есть **ранний возврат**: `if x > 100 { return 100; }` значит «только когда `x` больше 100, сразу выйти из функции со значением `100`». (`if` объясняется в следующем уроке. Пока читайте его как «когда».) Если `if` не сработал, результатом будет последняя строка `x`.

```text
42
42
100
42
```

> 📏 **Соглашение:** для обычного результата используйте завершающее выражение. `return` используйте для ранних выходов, например чтобы обработать необычный случай в начале функции.

### Возврат нескольких значений: кортеж

Функция возвращает одно значение. Чтобы вернуть несколько, верните кортеж (Урок 02.2) и разберите его:

```rust
fn divide_with_remainder(a: i32, b: i32) -> (i32, i32) {
    (a / b, a % b)
}

fn main() {
    let (quotient, remainder) = divide_with_remainder(17, 5);
    println!("17 = 5 * {quotient} + {remainder}");
    let pair = divide_with_remainder(20, 6);
    println!("{:?}", pair);
}
```

```text
17 = 5 * 3 + 2
(3, 2)
```

Возвращаемый тип `(i32, i32)` — кортеж из двух чисел, а `(a / b, a % b)` создаёт этот кортеж.

## 4. Функции вызывают функции

Функции — строительные блоки. Маленькие функции объединяются в большие:

```rust
fn area(width: u32, height: u32) -> u32 {
    width * height
}

fn is_big_room(width: u32, height: u32) -> bool {
    area(width, height) > 20
}

fn main() {
    println!("area of 4x6 = {}", area(4, 6));
    println!("4x6 is big? {}", is_big_room(4, 6));
    println!("3x5 is big? {}", is_big_room(3, 5));
}
```

```text
area of 4x6 = 24
4x6 is big? true
3x5 is big? false
```

`is_big_room` не повторяет умножение; она спрашивает `area`. Если формула площади когда-нибудь изменится, поменяется только одна функция.

> 📏 **Соглашение:** хорошая функция выполняет **одну задачу**, и её имя говорит, какую. Если для описания нужно слово «и» («читает файл и считает слова и печатает»), разделите её. Если функция не помещается на один экран (примерно 20–30 строк), она, вероятно, делает слишком много. Это принцип **KISS**: Keep It Simple, Stupid.

## 5. Параметры — это копии

Когда вы вызываете `bump(a)`, функция получает собственную переменную `x` со **значением** `a`. Для простых типов этого этапа (числа, `bool`, `char`) значение копируется. Параметры по умолчанию неизменяемы, как и переменные `let`:

```rust
fn bump(x: i32) -> i32 {
    x += 1;
    x
}

fn main() {
    println!("{}", bump(1));
}
```

```text
error[E0384]: cannot assign to immutable argument `x`
 --> src/main.rs:2:5
  |
2 |     x += 1;
  |     ^^^^^^ cannot assign to immutable argument
  |
help: consider making this binding mutable
  |
1 | fn bump(mut x: i32) -> i32 {
  |         +++
```

Исправление — `mut x`. Оно делает изменяемой **собственную копию** функции; переменная вызывающего кода остаётся нетронутой:

```rust
fn bump(mut x: i32) -> i32 {
    x += 1;
    x
}

fn main() {
    let a = 1;
    let b = bump(a);
    println!("a = {a}, b = {b}");
}
```

```text
a = 1, b = 2
```

`a` по-прежнему `1`. (Что происходит со значениями, которые не являются простыми копиями, например с текстом, — главная тема Этапа 03: владение и заимствование. Пока ваши функции будут принимать числа, `bool` и `char`, а текст — в виде `&str`.)

Переменные, созданные внутри функции, существуют только внутри неё (правило области видимости из Урока 02.1):

```rust
fn compute() -> i32 {
    let secret = 42;
    secret
}

fn main() {
    let result = compute();
    println!("{result}");
    println!("{secret}");
}
```

```text
error[E0425]: cannot find value `secret` in this scope
 --> src/main.rs:9:16
  |
9 |     println!("{secret}");
  |                ^^^^^^ not found in this scope
```

Единственный выход из функции — её возвращаемое значение.

## 6. Рекурсия и стек вызовов

Функция может вызывать **саму себя**. Это **рекурсия**. Она работает, когда задачу можно описать через меньшую копию такой же задачи. Факториал `n!` равен `n * (n-1)!`, а `1!` равен `1`:

```rust
fn factorial(n: u64) -> u64 {
    if n <= 1 {
        1
    } else {
        n * factorial(n - 1)
    }
}

fn main() {
    println!("5! = {}", factorial(5));
    println!("10! = {}", factorial(10));
    println!("20! = {}", factorial(20));
}
```

Что происходит:

1. `if condition { A } else { B }` выбирает одно из двух значений: `A`, когда условие истинно, и `B` в противном случае. (`if` полностью объясняет Урок 02.5. Обратите внимание: здесь `if` — выражение, и его значение является завершающим выражением функции.)
2. `factorial(5)` нужен `factorial(4)`, которому нужен `factorial(3)`, и так далее до `factorial(1)`. Это **базовый случай**: он возвращает `1`, не вызывая себя. У любой рекурсии должен быть базовый случай.
3. Затем ответы возвращаются: `1`, потом `2 * 1`, `3 * 2`, `4 * 6`, `5 * 24 = 120`.

```text
5! = 120
10! = 3628800
20! = 2432902008176640000
```

Каждому вызову нужна память для параметров и локальных переменных. Эта память — **кадр стека** в **стеке вызовов**. Каждый новый вызов кладёт кадр сверху, а каждый возврат убирает верхний кадр:

```text
 factorial(1)   <- top: runs now, returns 1
 factorial(2)   waiting for factorial(1)
 factorial(3)   waiting for factorial(2)
 factorial(4)   waiting for factorial(3)
 factorial(5)   waiting for factorial(4)
 main           waiting for factorial(5)
```

Стек ограничен (несколько мегабайтов). Рекурсия без базового случая заполняет его:

```rust
fn forever(n: u64) -> u64 {
    forever(n + 1) + 1
}

fn main() {
    println!("{}", forever(0));
}
```

```text
warning: function cannot return without recursing
 --> src/main.rs:1:1
  |
1 | fn forever(n: u64) -> u64 {
  | ^^^^^^^^^^^^^^^^^^^^^^^^^ cannot return without recursing

thread 'main' (3970470) has overflowed its stack
fatal runtime error: stack overflow, aborting
```

Компилятор даже предупреждает вас. Программу убивает операционная система. Это **переполнение стека**. (Стек и кучу подробно объясняет Этап 03, урок 1.) Когда задачу можно решить циклом (следующий урок), цикл часто лучше; рекурсия лучше всего подходит, когда задача естественно вложенная.

## Частые ошибки

**1. Точка с запятой после завершающего выражения.**

```rust
fn add_one(x: i32) -> i32 {
    x + 1;
}
```

```text
error[E0308]: mismatched types
 --> src/main.rs:1:23
  |
1 | fn add_one(x: i32) -> i32 {
  |    -------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     x + 1;
  |          - help: remove this semicolon to return this value
```

Сигнатура обещает `i32`, но из-за точки с запятой тело возвращает `()`. Уберите `;`.

**2. Параметр без типа.** `fn add(a, b) -> i32` даёт `error: expected one of ':', '@', or '|', found ','` и подсказку `give it a type`. Пишите `fn add(a: i32, b: i32)`.

**3. Неверное число аргументов.**

```text
error[E0061]: this function takes 2 arguments but 1 argument was supplied
 --> src/main.rs:6:20
  |
6 |     println!("{}", add(1));
  |                    ^^^--- argument #2 of type `i32` is missing
```

**4. Неверный тип аргумента.**

```text
error[E0308]: mismatched types
 --> src/main.rs:6:27
  |
6 |     println!("{}", add(1, 2.5));
  |                    ---    ^^^ expected `i32`, found floating-point number
  |                    |
  |                    arguments to this function are incorrect
```

Преобразуйте через `as` или измените функцию.

**5. Слишком много работы в одной функции.** Разделите её. Назовите части.

**6. Рекурсия без базового случая.** Заканчивается переполнением стека.

> 🧪 **Тестирование:** функции легко тестировать, потому что у них есть чёткие входы и выходы. Вызовите функцию с несколькими входами, включая крайние случаи, и сравните с ожидаемым ответом:
>
> ```rust
> fn is_even(n: i32) -> bool {
>     n % 2 == 0
> }
>
> fn main() {
>     assert_eq!(is_even(4), true);
>     assert_eq!(is_even(7), false);
>     assert_eq!(is_even(0), true);
>     assert_eq!(is_even(-2), true);
>     println!("is_even: all checks passed");
> }
> ```
>
> ```text
> is_even: all checks passed
> ```
>
> Хорошие тестовые входы: обычный случай, ноль, отрицательное число, наибольшее значение. В Уроке 02.8 вы перенесёте такие проверки в настоящие тесты, которые за вас запускает `cargo test`.

> 💡 **Совет:** RustRover умеет **выделять функцию** за вас: выделите код, затем выберите *Refactor → Extract Method* (пункт может называться *Extract Function*; сочетание клавиш в macOS — `⌥⌘M`). Он создаст функцию с правильными параметрами. Рефакторинг — это улучшение структуры кода без изменения того, что он делает.

## Упражнения

### Упражнение 1 — square (легко)

Напишите `fn square(n: i32) -> i32`. Проверьте её для `0`, `5` и `-4` с помощью `assert_eq!` и напечатайте `square: all checks passed`.

<details>
<summary>Подсказка</summary>

Тело — одно выражение: `n * n`, без точки с запятой.

</details>

<details>
<summary>Ответ</summary>

```rust
fn square(n: i32) -> i32 {
    n * n
}

fn main() {
    assert_eq!(square(0), 0);
    assert_eq!(square(5), 25);
    assert_eq!(square(-4), 16);
    println!("square: all checks passed");
}
```

Почему это работает: квадрат отрицательного числа положителен, поэтому `square(-4)` равно `16`. Вывод: `square: all checks passed`.

</details>

### Упражнение 2 — Исправьте сигнатуру (легко)

В этой программе три ошибки. Найдите и исправьте их с помощью компилятора. Программа должна напечатать `7`.

```rust
fn add(a, b: i32) -> i32 {
    a + b;
}

fn main() {
    println!("{}", add(3, 4.0));
}
```

<details>
<summary>Подсказка</summary>

Читайте ошибки по одной: параметр без типа, точка с запятой в конце тела и аргумент неверного типа.

</details>

<details>
<summary>Ответ</summary>

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", add(3, 4));
}
```

Почему это работает: у каждого параметра есть тип; у завершающего выражения нет `;`, поэтому тело возвращает `i32`; а `4` — целое число, а не дробное. Вывод: `7`.

</details>

### Упражнение 3 — Функции температуры (средне)

Напишите `celsius_to_fahrenheit(c: f64) -> f64` и `fahrenheit_to_celsius(f: f64) -> f64`. Проверьте, что 100 °C — это 212 °F, что 32 °F — это 0 °C и что перевод 36.6 °C в Фаренгейты и обратно снова даёт 36.6 (сравнивайте с допуском `1e-9`).

<details>
<summary>Подсказка</summary>

`F = C * 9 / 5 + 32` и `C = (F - 32) * 5 / 9`. Используйте литералы с плавающей точкой (`9.0`, а не `9`).

</details>

<details>
<summary>Ответ</summary>

```rust
fn celsius_to_fahrenheit(c: f64) -> f64 {
    c * 9.0 / 5.0 + 32.0
}

fn fahrenheit_to_celsius(f: f64) -> f64 {
    (f - 32.0) * 5.0 / 9.0
}

fn main() {
    assert_eq!(celsius_to_fahrenheit(100.0), 212.0);
    assert_eq!(fahrenheit_to_celsius(32.0), 0.0);
    let round_trip = fahrenheit_to_celsius(celsius_to_fahrenheit(36.6));
    assert!((round_trip - 36.6).abs() < 1e-9);
    println!("round trip of 36.6 C = {round_trip}");
    println!("temperature: all checks passed");
}
```

```text
round trip of 36.6 C = 36.6
temperature: all checks passed
```

Почему это работает: вызов функции — выражение, поэтому один вызов может быть аргументом другого. Точно представимые значения (100, 212, 32, 0) можно сравнивать через `assert_eq!`; у круговой проверки может быть крошечная ошибка, поэтому там используется допуск.

</details>

### Упражнение 4 — Два результата (средне)

Напишите `fn min_max(a: i32, b: i32) -> (i32, i32)`, которая возвращает сначала меньшее число, затем большее. Используйте методы `a.min(b)` и `a.max(b)`. Разберите результат `min_max(9, 4)` и напечатайте его. Добавьте три проверки `assert_eq!`, одна из них — с равными числами.

<details>
<summary>Подсказка</summary>

Завершающее выражение — кортеж `(a.min(b), a.max(b))`. Кортеж можно сравнивать через `assert_eq!`: `assert_eq!(min_max(9, 4), (4, 9));`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn min_max(a: i32, b: i32) -> (i32, i32) {
    (a.min(b), a.max(b))
}

fn main() {
    let (small, big) = min_max(9, 4);
    println!("small = {small}, big = {big}");
    assert_eq!(min_max(9, 4), (4, 9));
    assert_eq!(min_max(-1, 3), (-1, 3));
    assert_eq!(min_max(5, 5), (5, 5));
    println!("min_max: all checks passed");
}
```

```text
small = 4, big = 9
min_max: all checks passed
```

Почему это работает: функция возвращает одно значение — кортеж, который содержит оба результата.

</details>

### Упражнение 5 — Рекурсия (сложно)

Напишите две рекурсивные функции: `digit_sum(n: u32) -> u32` (сумма цифр числа `n`) и `gcd(a: u32, b: u32) -> u32` (наибольший общий делитель по алгоритму Евклида: `gcd(a, 0)` равно `a`, иначе `gcd(b, a % b)`). Для каждой назовите базовый случай. Добавьте утверждения: `digit_sum(4721) == 14`, `digit_sum(1000) == 1`, `gcd(12, 18) == 6`, `gcd(17, 5) == 1`, `gcd(0, 9) == 9`.

<details>
<summary>Подсказка</summary>

Для `digit_sum`: если `n < 10`, ответ — сам `n` (базовый случай); иначе это последняя цифра `n % 10` плюс `digit_sum(n / 10)`. Используйте `if … { … } else { … }` как завершающее выражение.

</details>

<details>
<summary>Ответ</summary>

```rust
fn digit_sum(n: u32) -> u32 {
    if n < 10 {
        n
    } else {
        n % 10 + digit_sum(n / 10)
    }
}

fn gcd(a: u32, b: u32) -> u32 {
    if b == 0 {
        a
    } else {
        gcd(b, a % b)
    }
}

fn main() {
    assert_eq!(digit_sum(7), 7);
    assert_eq!(digit_sum(4721), 14);
    assert_eq!(digit_sum(1000), 1);
    assert_eq!(gcd(12, 18), 6);
    assert_eq!(gcd(17, 5), 1);
    assert_eq!(gcd(0, 9), 9);
    println!("digit_sum and gcd: all checks passed");
}
```

Почему это работает: базовые случаи — `n < 10` и `b == 0`. Во всех остальных случаях аргумент уменьшается (`n / 10` меньше `n`; у пары `(b, a % b)` второе число меньше), поэтому рекурсия заканчивается. Вывод: `digit_sum and gcd: all checks passed`.

</details>

## Вопросы для самопроверки

1. Чем отличается параметр от аргумента?

<details>
<summary>Ответ</summary>

Параметр — переменная в определении функции (`a` в `fn add(a: i32)`). Аргумент — фактическое значение, которое вы передаёте при вызове (`3` в `add(3)`).

</details>

2. Какая часть сигнатуры говорит, что возвращает функция?

<details>
<summary>Ответ</summary>

Возвращаемый тип после стрелки `->`. Без неё функция возвращает `()`.

</details>

3. Что не так с `fn f(x: i32) -> i32 { x * 2; }`?

<details>
<summary>Ответ</summary>

Точка с запятой отбрасывает значение, поэтому тело возвращает `()`, а не `i32`. Ошибка `E0308`. Уберите `;`.

</details>

4. Нужно ли определять функцию до того, как её вызывать?

<details>
<summary>Ответ</summary>

Нет. В Rust порядок определений функций в файле не важен.

</details>

5. Как функция может вернуть два значения?

<details>
<summary>Ответ</summary>

Вернуть кортеж, например `-> (i32, i32)`, и разобрать его в вызывающем коде.

</details>

6. Что такое базовый случай и что происходит без него?

<details>
<summary>Ответ</summary>

Простой случай, в котором рекурсивная функция возвращает результат, не вызывая себя. Без него функция вызывает себя бесконечно, стек вызовов заполняется, и программа аварийно завершается с переполнением стека.

</details>

7. Почему `fn is_even(n: i32) -> bool` — хорошее имя и сигнатура?

<details>
<summary>Ответ</summary>

Имя начинается с `is_` и задаёт вопрос «да/нет»; возвращаемый тип `bool` ему соответствует. Функция выполняет одну задачу и легко тестируется.

</details>

## Итоги

- У функции есть имя, параметры с типами и необязательный возвращаемый тип: `fn name(a: T) -> R { … }`.
- У каждого параметра должен быть тип; возвращаемый тип пишется после `->`.
- Завершающее выражение (последнее выражение без `;`) — это результат. `return` нужен для ранних выходов.
- Функция может вернуть несколько значений в виде кортежа.
- Параметры — неизменяемые копии; добавьте `mut`, чтобы менять собственную копию функции.
- Переменные внутри функции не видны снаружи.
- Рекурсии нужен базовый случай, иначе стек переполнится.
- Делайте функции маленькими, с одной задачей и ясным именем (DRY, KISS). Проверяйте их с помощью `assert_eq!`.
