## 1. Режим учёбы, который работает

### Как работает память, в четырёх строках

1. Перечитывание кажется продуктивным, но работает плохо. **Активное вспоминание** (закрыть страницу и попробовать
   записать или сказать то, что помните) работает гораздо лучше.
2. Повторение через увеличивающиеся промежутки (**интервальное повторение**) переносит знания в долговременную память.
3. **Сон** закрепляет то, что вы изучили. Ночной марафон хуже, чем два коротких занятия в разные дни.
4. **Делание** учит больше, чем чтение. Поэтому в каждом уроке есть код для набора и упражнения для решения.

### Ваша неделя (около 10 часов)

| Блок | Время | Что | Правило |
|---|---|---|---|
| 4 занятия по новому материалу | 4 × 2 ч | новые уроки и «Попробуйте сами» | одно постоянное время суток |
| 1 занятие-практика | 1 × 1,5 ч | упражнения и небольшие программы без открытого урока | никаких подсказок первые 15 минут |
| 1 занятие-повторение | 1 × 0,5 ч | журнал, вопросы из прошлых недель | активное вспоминание |

### Одно занятие на 2 часа

| Минуты | Деятельность |
|---|---|
| 0–10 | **Разминка:** ответьте по памяти на 3 вопроса прошлого урока (вопросы в конце урока). |
| 10–55 | **Блок концентрации 1:** прочитайте и наберите новый урок. |
| 55–65 | **Перерыв:** встаньте, выпейте воды, без телефона. |
| 65–105 | **Блок концентрации 2:** остаток урока; начните упражнения. |
| 105–120 | **Журнал:** напишите запись в журнал (раздел 2). Решите, каков следующий шаг. |

Если вам нравится **метод Помодоро**, используйте вместо этого 25 минут работы и 5 минут отдыха.

### Правила, которые вас выручат

- **То же время, то же место.** Привычка сильнее мотивации.
- **Телефон убрать** на время блоков концентрации.
- **Останавливайтесь на середине чего-то.** Заканчивайте занятие в момент, когда точно знаете, каков
  следующий шаг, и запишите этот шаг в журнал. Следующее занятие начнётся без трения.
- **Пользуйтесь лестницей «я застрял»** из Урока 00.1 (сообщение об ошибке, 15 минут, подсказка, ответ, вопрос).
- **Не пропускайте вопросы.** Это самое дешёвое активное вспоминание.
- **Пропущенный день — не беда; пропущенная неделя — беда.** Если пропустили занятие, проведите короткое, на 30 минут, на следующий
  день, а не молча бросайте план.
- **Будьте добры к себе.** Раздражение — нормальное чувство, когда учишь что-то трудное. Прогуляйтесь; ответ часто приходит во время прогулки.

## 2. Журнал обучения и интервальное повторение

После каждого урока пишите 5 коротких строк в `~/projects/rust/notes/`. Используйте один файл на этап, например
`phase-00.md`. Шаблон:

```text
## Lesson 00.4 — The terminal (2026-11-18)
- Learned: cd, ls, mkdir, redirect (> and >>), pipe (|).
- Confusing: the difference between ~ and /.
- Remember: rm has no Trash. ls first!
- Question: what does the "@" mean in ls -l?
- Next: install Rust.
```

Строка «Question» важна. На следующем занятии найдите ответ (документация, урок, форум,
помощник) и запишите его. Список вопросов с ответами — очень ценный личный справочник.

### График повторений

Отметьте в календаре короткое повторение через **1 день, 3 дня, 1 неделю и 1 месяц** после каждого урока. В каждом повторении
потратьте 5 минут:

1. Закройте урок. Прочитайте только список заголовков вашего журнала.
2. Попробуйте ответить на вопросы урока по памяти.
3. Откройте ответы и отметьте, что вы забыли.
4. Заново наберите одну команду или одну небольшую программу, не подглядывая.

Для словаря (слова, команды, коды ошибок) можно также использовать **карточки**: бумажные или бесплатное приложение вроде
[Anki](https://apps.ankiweb.net/), которое само планирует повторения. У хорошей карточки на лицевой стороне один вопрос
(«Что делает `cargo check`?»), а на обороте короткий ответ.

> 💡 **Совет:** после месяца Этапа 00 у вас будет около 8 записей в журнале. Посмотрите на
> вопросы, которые вы записали в первых уроках. На большинство вы теперь сможете ответить. Это лучшее доказательство прогресса.

## 3. Заметки в Markdown

Все уроки — файлы Markdown, и ваши заметки тоже должны быть такими. Markdown — это обычный текст с несколькими знаками, поэтому любой редактор может его открыть,
а Git (Этап 01) покажет, что именно изменилось. Вот полный пример:

~~~markdown
# Phase 00 notes

## Commands I use every day

- `pwd` shows where I am
- `ls -la` lists files, including hidden ones
- `cargo run` builds and runs

### Steps to create a project

1. `cd ~/projects/rust`
2. `cargo new code/p00-hello`
3. `cargo run`

**Important:** `rm` has *no* Trash.

| Command | What it does |
|---|---|
| `cargo check` | checks the code, no executable |
| `cargo fmt` | formats the code |

```rust
fn main() {
    println!("Hello, Rust!");
}
```

See [the Rust book](https://doc.rust-lang.org/book/) for more.

> Note to self: ask what `@` means in `ls -l`.
~~~

Знаки, которые вам нужны:

| Вы пишете | Вы получаете |
|---|---|
| `# Title` | заголовок уровня 1 (название файла; используйте только один на файл) |
| `## Section`, `### Part` | заголовки уровней 2 и 3 |
| `- item` | пункт маркированного списка |
| `1. step` | пункт нумерованного списка |
| `` `code` `` | код в строке (команды, имена файлов, ключевые слова) |
| три обратные кавычки, затем необязательное имя языка (`rust`, `text`), строки кода и три обратные кавычки | блок кода с языком |
| `**bold**`, `*italic*` | **полужирный**, *курсив* |
| `[text](https://example.com)` | ссылка |
| `> note` | цитата или заметка |
| `\| a \| b \|` строки и линия `\|---\|---\|` под первой строкой | таблица |

Правила, которые предотвращают большинство проблем:

1. Ставьте **пустую строку** до и после заголовков, списков, таблиц и блоков кода.
2. Ставьте имя языка после открывающих трёх обратных кавычек (` ```rust `): редактор раскрасит код.
3. В нумерованном списке можно писать `1.` у каждого пункта; просмотрщик посчитает сам.
4. Чтобы показать три обратные кавычки внутри блока кода (как выше), открывайте и закрывайте внешний блок знаками `~~~`.
5. Делайте строки короткими и пишите одну мысль в абзаце. Пустая строка начинает новый абзац.

Чтобы увидеть результат: откройте файл `.md` в RustRover, где есть встроенный предпросмотр (кнопки в правом верхнем углу редактора
переключают исходник, разделённый вид и предпросмотр). В браузере GitHub и GitLab показывают Markdown автоматически.

> 📏 **Соглашение:** один файл на тему, описательное имя строчными буквами с дефисами (`phase-00-notes.md`,
> `terminal-cheatsheet.md`) и один заголовок `#` в начале. Через несколько недель вы захотите искать по своим заметкам.

## 4. Как сохранить свою работу

Скоро у вас будет много кода и заметок. Потерять их было бы больно, поэтому постройте три уровня защиты.

| Уровень | От чего защищает | Инструмент | Когда |
|---|---|---|---|
| **1. Контроль версий** | ошибки, «как это выглядело вчера?» | **Git** | Этап 01 |
| **2. Локальная резервная копия** | сломанный или украденный ноутбук | **Time Machine** | сегодня |
| **3. Удалённая копия** | то же, плюс потерянный внешний диск | GitHub или GitLab | Этап 01 (Урок 01.8) |

**Контроль версий** (Git) хранит каждый сохранённый снимок (**коммит**) вашего проекта в **репозитории**. Вы можете
смотреть историю, сравнивать версии, возвращаться к старой и пробовать рискованные идеи без страха. Этап 01 начинается
с нуля. С этого момента каждый проект курса заканчивает каждую веху коммитом. В конце
Этапа 01 вы превратите `~/projects/rust` в свой **учебный репозиторий** (Урок 01.10).

> ⚠️ **Частая ошибка:** думать, что один Git — это резервная копия. Репозиторий живёт на *вашем* диске, рядом с
> вашими файлами. Если диск умрёт, умрёт и история. Защитит только **удалённый репозиторий** (копия на GitHub или GitLab) или отдельная резервная копия. Нужно и то и другое: Git для истории, резервная копия на случай катастрофы.

**Time Machine** встроена в macOS и требует внешнего диска. Откройте **Системные настройки → Основные →
Time Machine**, добавьте диск и включите её; тогда macOS делает автоматические почасовые копии. Страница Apple о ней есть в
источниках ниже. Она защищает не только папку курса, но и всё остальное на вашем Mac.

Несколько правил для папок, которые заодно готовят вас к Git:

- **Код в `code/`, заметки в `notes/`.** Не смешивайте их с папками курса.
- **Никаких секретов в заметках или коде:** паролей, токенов, закрытых ключей. Всё, что попадает в репозиторий на GitHub, могут прочитать другие, а история хранит это, даже если вы удалите строку.
- **Не храните результаты сборки.** Папки `target/` у Cargo можно пересоздать; Cargo уже даёт каждому новому проекту `.gitignore` для этого (Урок 00.6).
- **Называйте файлы понятно.** `notes-final-2-new.md` — признак того, что вам нужен контроль версий. (Вот почему Этап 01 идёт первым.)

Проверьте, что уже готово:

```text
% git --version
git version 2.54.0 (Apple Git-157)
```

Если это работает (Урок 00.5), Этап 01 только попросит вас указать своё имя и адрес электронной почты в Git (Урок 01.2).

## 5. Шпаргалка этапа 00

Терминал (Урок 00.4):

| Команда | Значение |
|---|---|
| `pwd` | где я |
| `ls`, `ls -la` | показать файлы (подробно, со скрытыми) |
| `cd dir`, `cd ..`, `cd ~` | войти, подняться, домой |
| `mkdir -p a/b` | создать папки |
| `touch f`, `echo text > f`, `echo text >> f`, `cat f` | создать, записать, дописать, прочитать |
| `cp a b`, `mv a b`, `rm f`, `rm -r d` | копировать, переместить/переименовать, удалить (окончательно!) |
| `man x`, `which x`, `type x` | справка, где команда |
| `a \| b`, `grep`, `wc -l`, `head`, `find` | конвейер и фильтры |
| Ctrl + C, Tab, ↑ | остановить, дополнить, история |

Rust и Cargo (Уроки 00.5 и 00.6):

| Команда | Значение |
|---|---|
| `rustc --version`, `cargo --version` | версии |
| `rustup update`, `rustup doc` | обновить; открыть офлайн-документацию |
| `cargo new code/pNN-name` | новый проект |
| `cargo run`, `cargo build`, `cargo check` | запустить, собрать, быстро проверить |
| `cargo build --release` | оптимизированная сборка |
| `cargo fmt`, `cargo clippy` | форматировать, проверять линтером |

Ошибки (Урок 00.7):

1. Читайте **первую** ошибку. 2. `file:line:column` показывает, где. 3. Исправьте одно, запустите снова.
4. `rustc --explain E....` объясняет код. 5. Предупреждения нужно исправлять. 6. Паника даёт код завершения 101.
7. Хороший вопрос: цель, минимальный код, точная ошибка, версия. Никогда не вставляйте секреты.

## Частые ошибки

1. **Копирование чужих заметок вместо написания своих.** Вы не запоминаете то, что не облекли в слова. *Исправление:* пишите журнал своими словами, пусть даже коротко.
2. **Пропуск повторений.** Тема кажется ясной в тот же день и пропадает через две недели. *Исправление:* внесите повторения через 1-3-7-30 дней в календарь.
3. **Заметки в разных местах** (бумага, телефон, пять файлов). *Исправление:* одна папка, `notes/`, в Markdown.
4. **Нет пустой строки перед списком или таблицей в Markdown.** Получится один некрасивый абзац. *Исправление:* добавьте пустую строку.
5. **Забыли про резервную копию.** «Со мной такого не случится» — так теряют данные. *Исправление:* включите Time Machine на этой неделе.

## Контрольная точка — готовы ли вы к этапу 01?

### Вопросы для самопроверки

Сначала отвечайте на каждый вопрос по памяти, потом открывайте ответ. Если вы ошиблись в вопросе, таблица в конце
подскажет, какой урок повторить.

1. Кто такой системный инженер, одним предложением?

<details>
<summary>Ответ</summary>

Программист, который создаёт и поддерживает нижние слои программ (серверы, базы данных, инструменты, части операционных систем), где важны скорость, расход памяти и надёжность.

</details>

2. Почему курс учит Git (Этап 01) раньше языка Rust?

<details>
<summary>Ответ</summary>

Начиная с Этапа 01 каждый проект сохраняется коммитом на каждой вехе. Контроль версий хранит историю ваших файлов и защищает вашу работу.

</details>

3. Назовите шесть строительных блоков программы.

<details>
<summary>Ответ</summary>

Ввод, вывод, хранение (переменные), решения (условия), повторение (циклы), повторное использование (функции).

</details>

4. В чём разница между ошибкой компиляции и логическим багом?

<details>
<summary>Ответ</summary>

Ошибка компиляции останавливает сборку, и компилятор объясняет, где проблема. Логический баг позволяет программе работать, но результат неверный, и никакого сообщения нет.

</details>

5. Какая часть компьютера выполняет инструкции, какая хранит работающую программу и какая хранит файлы при выключенном питании?

<details>
<summary>Ответ</summary>

CPU выполняет инструкции, RAM хранит работающую программу и её данные, накопитель (SSD) постоянно хранит файлы.

</details>

6. Переведите `00101010` в десятичное число.

<details>
<summary>Ответ</summary>

32 + 8 + 2 = 42.

</details>

7. Что такое машинный код и почему программа, собранная на вашем Mac с M4, не запускается на ПК с x86-64?

<details>
<summary>Ответ</summary>

Машинный код — инструкции в виде чисел, которые CPU читает напрямую. У каждого семейства CPU (arm64, x86-64) свой набор инструкций, поэтому числа различаются.

</details>

8. Каковы шаги от исходного файла до вывода на экран?

<details>
<summary>Ответ</summary>

Компилятор (`rustc`) переводит исходный код в исполняемый файл; ОС загружает его в RAM как процесс; CPU выполняет его инструкции; появляется вывод.

</details>

9. В чём разница между `>` и `>>` и между `rm` и `rmdir`?

<details>
<summary>Ответ</summary>

`>` заменяет содержимое файла выводом; `>>` дописывает. `rm` удаляет файлы (и директории с `-r`); `rmdir` удаляет только пустую директорию.

</details>

10. Что такое `PATH`?

<details>
<summary>Ответ</summary>

Переменная окружения со списком директорий, где оболочка ищет команды. Установщик Rust добавляет в неё `~/.cargo/bin`.

</details>

11. Что должна показывать строка `host` в `rustc -vV` на вашем Mac?

<details>
<summary>Ответ</summary>

`host: aarch64-apple-darwin`.

</details>

12. Для чего нужны файлы `Cargo.toml`, `Cargo.lock`, `src/main.rs` и папка `target`?

<details>
<summary>Ответ</summary>

`Cargo.toml` хранит настройки проекта; `Cargo.lock` записывает точные использованные версии (его пишет Cargo); `src/main.rs` — исходный код, с которого начинается программа; `target` хранит результаты сборки (Git её игнорирует).

</details>

13. В чём разница между `cargo run`, `cargo build`, `cargo check` и `cargo build --release`?

<details>
<summary>Ответ</summary>

`run` собирает и запускает; `build` только собирает (профиль debug); `check` только анализирует код, без исполняемого файла; `build --release` собирает оптимизированную версию.

</details>

14. Что означает `!` в `println!`?

<details>
<summary>Ответ</summary>

`println` — макрос, а не обычная функция.

</details>

15. У вас семь ошибок. С чего вы начнёте и как?

<details>
<summary>Ответ</summary>

С первой ошибки. Исправьте одно, запустите снова и повторяйте; поздние ошибки часто вызваны ранними.

</details>

16. Какой код завершения даёт паника и как его увидеть?

<details>
<summary>Ответ</summary>

101; выполните `echo $?` сразу после программы.

</details>

17. Почему 1, 3, 7 и 30 дней — хороший график повторений?

<details>
<summary>Ответ</summary>

Повторение как раз тогда, когда вы начинаете забывать (интервальное повторение), укрепляет память намного сильнее, чем перечитывание всего сразу.

</details>

18. Является ли репозиторий Git на вашем ноутбуке резервной копией? Почему?

<details>
<summary>Ответ</summary>

Нет. Он живёт на том же диске, что и ваши файлы. Нужна ещё удалённая копия (GitHub/GitLab) или отдельная резервная копия, например Time Machine.

</details>

### Практические задания

Выполняйте их на своём Mac. У каждого есть подсказка и ответ.

#### Задание 1 — Постройте структуру папок (терминал)

Только с помощью терминала, из `~/projects/rust`: убедитесь, что `code` и `notes` существуют, создайте
`notes/checkpoint/` и в ней файл `a.md` со строкой `Checkpoint 00`, покажите файл, посчитайте его строки и в конце
удалите папку `notes/checkpoint` вместе с файлом.

<details>
<summary>Подсказка</summary>

`mkdir -p`, `echo ... >`, `cat`, `wc -l` и `rm -r` (сначала проверьте через `ls`).

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust
% mkdir -p code notes/checkpoint
% echo 'Checkpoint 00' > notes/checkpoint/a.md
% cat notes/checkpoint/a.md
Checkpoint 00
% wc -l notes/checkpoint/a.md
       1 notes/checkpoint/a.md
% ls notes/checkpoint
a.md
% rm -r notes/checkpoint
```

Почему это работает: `-p` создаёт недостающую цепочку папок; `>` записывает файл; `ls` перед `rm -r` подтверждает, что будет удалено.

</details>

#### Задание 2 — Отчёт о тулчейне

Создайте `notes/phase-00-report.md`, в котором есть заголовок, пустая строка и вывод `rustc --version`,
`cargo --version`, строка `host` из `rustc -vV` и `git --version`, используя перенаправления.

<details>
<summary>Подсказка</summary>

Первая команда использует `>` (она создаёт файл), следующие — `>>` (они дописывают). Конвейер с `grep host` выбирает нужную строку.

</details>

<details>
<summary>Ответ</summary>

```text
% cd ~/projects/rust
% echo '# Phase 00 report' > notes/phase-00-report.md
% echo '' >> notes/phase-00-report.md
% rustc --version >> notes/phase-00-report.md
% cargo --version >> notes/phase-00-report.md
% rustc -vV | grep host >> notes/phase-00-report.md
% git --version >> notes/phase-00-report.md
% cat notes/phase-00-report.md
# Phase 00 report

rustc 1.100.0 (0ef1bc386 2026-11-09)
cargo 1.100.0 (3acc79c0c 2026-11-05)
host: aarch64-apple-darwin
git version 2.54.0 (Apple Git-157)
```

Почему это работает: каждая команда печатает на экран, а `>>` отправляет этот вывод в конец файла. Номера ваших версий могут быть новее.

</details>

#### Задание 3 — Новый проект с форматированием и линтером

Создайте `code/p00-checkpoint`. Он должен печатать эту карточку, а `cargo fmt --check` и `cargo clippy` не должны показывать
проблем:

```text
Phase 00 study card
-------------------
Compiler: rustc
Build tool: cargo
Shell: zsh
```

<details>
<summary>Подсказка</summary>

`cargo new code/p00-checkpoint`, затем пять строк `println!` в `src/main.rs`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("Phase 00 study card");
    println!("-------------------");
    println!("Compiler: rustc");
    println!("Build tool: cargo");
    println!("Shell: zsh");
}
```

Затем `cargo run`, `cargo fmt --check` и `cargo clippy`: первая печатает карточку, две другие ничего не сообщают о проблемах.

Почему это работает: каждая строка — отдельный `println!` с текстом в двойных кавычках и `;` в конце.

</details>

#### Задание 4 — Починить программу шаг за шагом

В этой программе три ошибки. Следуйте порядку из Урока 00.7 и записывайте, сколько ошибок вы увидели в каждом раунде.

```rust
fn main() {
    let tool = "cargo"
    println("Tool: {}", tol);
}
```

<details>
<summary>Подсказка</summary>

Исправляйте ту ошибку, о которой сообщено первой. Ошибки такие: пропущенный символ в конце строки, пропущенный символ в имени макроса и неверно написанное имя переменной.

</details>

<details>
<summary>Ответ</summary>

Раунд 1: 3 ошибки (`expected ;`, `cannot find value tol`, `cannot find function println`). Исправление: добавить `;` после `"cargo"`.
Раунд 2: 2 ошибки. Исправление: `println` → `println!`.
Раунд 3: 1 ошибка (`E0425`, `cannot find value tol`). Исправление: `tol` → `tool`.

```rust
fn main() {
    let tool = "cargo";
    println!("Tool: {}", tool);
}
```

Вывод:

```text
Tool: cargo
```

Почему это работает: каждый раунд убирает одну причину, а следующий запуск показывает, что осталось. Подсказка компилятора для `tol` (использовать `tool`) здесь была верной, потому что опечатка была в *использовании*, а не в объявлении.

</details>

#### Задание 5 — Ваши заметки (Markdown)

В `notes/phase-00.md` напишите краткое изложение Этапа 00 с: заголовком `#`, как минимум двумя разделами `##`, маркированным списком, нумерованным
списком, таблицей, блоком кода с языком и ссылкой. Откройте предпросмотр и проверьте.

<details>
<summary>Подсказка</summary>

Используйте пример из раздела 3 как образец. Не забывайте пустые строки вокруг блоков.

</details>

<details>
<summary>Ответ</summary>

Единственно верного ответа нет. Сверьте файл с этим списком: один заголовок `#`; два или больше заголовка `##`; список с `-`; список с `1.`; таблица с линией `|---|---|` под первой строкой; блок кода, начинающийся тремя обратными кавычками и `rust` или `text`; ссылка вида `[text](https://...)`; пустые строки вокруг всех блоков; в предпросмотре нет «сырых» символов `#` или `|`.

Почему это работает: Markdown — это просто набор знаков, и предпросмотр сразу показывает, если один из них неверен.

</details>
