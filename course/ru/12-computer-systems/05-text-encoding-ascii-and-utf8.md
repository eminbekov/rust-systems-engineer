# Урок 12.5 — Кодировка текста: ASCII, Unicode и UTF-8

> **Этап 12 — Компьютерные системы** · Урок 5 из 15 · ⏱ около 120 минут

## Что вы узнаете

- Как устроена таблица ASCII и какие битовые приёмы стоят за цифрами и регистром букв.
- Что такое кодовая точка Unicode, какие числа допустимы и почему `char` занимает 4 байта.
- Точные битовые шаблоны UTF-8 — чтобы кодировать и декодировать символ вручную и в коде.
- Что происходит с недопустимыми байтами: ошибки, `from_utf8_lossy` и символ замены.
- Почему одна «буква» на экране может быть несколькими `char` (графемные кластеры) и где ещё встречается UTF-16.

## Новые слова

| Слово | Значение |
|---|---|
| **кодировка символов** (character encoding) | Правило, которое превращает символы в байты и обратно. ASCII и UTF-8 — кодировки. |
| **ASCII** (American Standard Code for Information Interchange, американский стандартный код для обмена информацией) | Таблица 1960-х годов из 128 символов (английские буквы, цифры, знаки препинания, управляющие коды) с номерами от 0 до 127, по 7 битов каждый. |
| **управляющий символ** (control character) | Код ASCII, который не является видимым знаком, а служит командой, например перевод строки (`0x0a`) или табуляция (`0x09`). |
| **Unicode** | Всемирная таблица символов. Она даёт каждому символу номер — его *кодовую точку*. |
| **кодовая точка** (code point) | Номер символа в Unicode, записывается как `U+` и шестнадцатеричные цифры: `U+044F` — это `я`. |
| **скалярное значение Unicode** (Unicode scalar value) | Кодовая точка, которая может встречаться в тексте: от 0 до `0x10FFFF`, кроме суррогатного диапазона `0xD800`–`0xDFFF`. `char` в Rust — ровно одно такое значение. |
| **суррогат** (surrogate) | Кодовая точка от `0xD800` до `0xDFFF`, зарезервированная для UTF-16; сама по себе символом не бывает. |
| **UTF-8** (Unicode Transformation Format, 8-bit, формат преобразования Unicode, 8-битный) | Кодировка, которая хранит кодовую точку в 1–4 байтах. `str` и `String` в Rust всегда содержат корректный UTF-8. |
| **UTF-16** | Кодировка из 16-битных единиц: одна единица для большинства символов, две (*суррогатная пара*) для остальных. Её используют Windows и некоторые форматы файлов. |
| **байт продолжения** (continuation byte) | Байт многобайтового символа UTF-8 после первого. Он всегда имеет вид `10xxxxxx`. |
| **избыточная кодировка** (overlong encoding) | Запрещённый способ записать символ большим числом байтов, чем нужно. Корректный UTF-8 её никогда не содержит. |
| **символ замены** (replacement character) | `U+FFFD`, отображается как `�`. Заменяет байты, которые не удалось декодировать. |
| **графемный кластер** (grapheme cluster) | То, что читатель видит как один символ. Может состоять из нескольких кодовых точек, например буквы и знака ударения. |

## 1. ASCII: первые 128 чисел

ASCII использует 7 битов, поэтому кодов в нём 128. Таблица устроена не случайно: она составлена так, чтобы простые битовые операции делали полезные вещи.

```rust
fn main() {
    for b in [b'\0', b'\t', b'\n', b'\r', b' ', b'0', b'9', b'A', b'Z', b'a', b'z', b'~'] {
        println!("{:>3} = {b:#04x} = {b:07b}  {:?}", b, b as char);
    }
    let digit = b'7' - b'0';
    println!("'7' - '0' = {digit}");
    println!("'a' ^ 0x20 = {}", (b'a' ^ 0x20) as char);
    println!("'Q' | 0x20 = {}", (b'Q' | 0x20) as char);
    println!("{}", "Hello, World".to_ascii_uppercase());
    println!("{}", "OK".eq_ignore_ascii_case("ok"));
}
```

**Что происходит:**

1. `b'A'` — байтовый литерал: код ASCII буквы `A` в виде `u8` (Урок 02.2). Цикл печатает каждый код в десятичном, шестнадцатеричном и 7-битном двоичном виде, а `{:?}` показывает символ, заменяя невидимые экранированными последовательностями.
2. Коды от 0 до 31 — **управляющие символы**: `\0` (нулевой байт), `\t` (табуляция), `\n` (перевод строки, «line feed»), `\r` (возврат каретки). Код 32 — пробел, 127 — ещё один управляющий код; всё, что между ними, видимо.
3. Цифры начинаются с `0x30`, поэтому значение цифры — её код минус `b'0'`. Так поступает любой парсер чисел.
4. Заглавные буквы начинаются с `0x41`, строчные — с `0x61`. Они отличаются только **битом 5** (`0x20`). Исключающее ИЛИ (XOR, exclusive OR, Урок 12.4) с `0x20` меняет регистр, ИЛИ делает букву строчной, И с `!0x20` — заглавной. Разумеется, только для букв ASCII.
5. В стандартной библиотеке это есть в виде методов: `to_ascii_uppercase`, `eq_ignore_ascii_case`, `is_ascii_digit` и другие. Символы вне ASCII они оставляют без изменений.

```text
  0 = 0x00 = 0000000  '\0'
  9 = 0x09 = 0001001  '\t'
 10 = 0x0a = 0001010  '\n'
 13 = 0x0d = 0001101  '\r'
 32 = 0x20 = 0100000  ' '
 48 = 0x30 = 0110000  '0'
 57 = 0x39 = 0111001  '9'
 65 = 0x41 = 1000001  'A'
 90 = 0x5a = 1011010  'Z'
 97 = 0x61 = 1100001  'a'
122 = 0x7a = 1111010  'z'
126 = 0x7e = 1111110  '~'
'7' - '0' = 7
'a' ^ 0x20 = A
'Q' | 0x20 = q
HELLO, WORLD
true
```

> 💡 **Совет:** строки в файлах Linux и macOS заканчиваются на `\n`. Файлы из Windows часто заканчивают строки на `\r\n`. Если в конце разобранных строк вы видите лишний `\r`, причина в этом; `str::lines()` убирает оба варианта.

## 2. Кодовые точки Unicode и `char`

Unicode даёт каждому символу номер — **кодовую точку**. Диапазон — от 0 до `0x10FFFF` (около 1,1 миллиона чисел). Первые 128 в точности совпадают с ASCII. `char` в Rust хранит одну кодовую точку в 4 байтах, потому что самой большой нужно 21 бит:

```rust
fn main() {
    for c in ['A', 'я', '€', '世', '😀'] {
        println!("{c}  U+{:04X}  as u32 = {:>6}  utf-8 bytes = {}", c as u32, c as u32, c.len_utf8());
    }
    println!("{:?}", char::from_u32(0x44F));
    println!("{:?}", char::from_u32(0xD800));
    println!("{:?}", char::from_u32(0x110000));
    println!("{}", '\u{1F600}');
    println!("char is {} bytes", std::mem::size_of::<char>());
}
```

**Что происходит:**

1. `c as u32` даёт кодовую точку. Она печатается в привычном виде `U+` минимум с четырьмя шестнадцатеричными цифрами.
2. `len_utf8()` говорит, сколько байтов нужно этому символу в UTF-8.
3. `char::from_u32` строит `char` из числа, но только если число — **скалярное значение Unicode**. `0xD800` — **суррогат** (зарезервирован для UTF-16), а `0x110000` слишком велико, поэтому оба дают `None`. Вот почему `char` никогда не может хранить недопустимое значение.
4. `'\u{1F600}'` записывает символ по его кодовой точке прямо в литерале.

```text
A  U+0041  as u32 =     65  utf-8 bytes = 1
я  U+044F  as u32 =   1103  utf-8 bytes = 2
€  U+20AC  as u32 =   8364  utf-8 bytes = 3
世  U+4E16  as u32 =  19990  utf-8 bytes = 3
😀  U+1F600  as u32 = 128512  utf-8 bytes = 4
Some('я')
None
None
😀
char is 4 bytes
```

Хранить каждый символ в 4 байтах было бы просто, но расточительно: английский текст стал бы вчетверо больше. UTF-8 — удачный компромисс.

## 3. UTF-8 бит за битом

UTF-8 режет биты кодовой точки на части и раскладывает их по байтам с фиксированными «заголовками». Заголовок первого байта говорит, сколько байтов у символа:

```text
code points          bits   byte 1     byte 2     byte 3     byte 4
U+0000  .. U+007F      7    0xxxxxxx
U+0080  .. U+07FF     11    110xxxxx   10xxxxxx
U+0800  .. U+FFFF     16    1110xxxx   10xxxxxx   10xxxxxx
U+10000 .. U+10FFFF   21    11110xxx   10xxxxxx   10xxxxxx   10xxxxxx
```

Закодируем `я` (U+044F) вручную. `0x44F` в двоичном виде — `100 0100 1111`: 11 битов, значит, 2 байта. Заполняем места `x` справа: младшие 6 битов `001111` идут во второй байт, оставшиеся 5 битов `10001` — в первый:

```text
code point 0x44F:          10001 001111
byte 1:   110 + 10001  =   11010001  = 0xd1
byte 2:    10 + 001111 =   10001111  = 0x8f
```

Это ровно `d1 8f` — байты, которые вы видели в Уроке 04.8. Пусть компьютер покажет шаблоны для других символов:

```rust
fn main() {
    for c in ['a', 'я', '€', '😀'] {
        let mut buf = [0u8; 4];
        let bytes = c.encode_utf8(&mut buf).as_bytes();
        let bits: Vec<String> = bytes.iter().map(|b| format!("{b:08b}")).collect();
        println!("{c} U+{:05X} {:>21b} -> {}", c as u32, c as u32, bits.join(" "));
    }
}
```

**Что происходит:**

1. `encode_utf8` записывает байты UTF-8 символа `char` в маленький буфер (четырёх байтов всегда достаточно) и возвращает их как `&str`; `as_bytes()` даёт байты.
2. Каждый байт печатается в двоичном виде. Сравните заголовки (`0`, `110`, `1110`, `11110`, `10`) с таблицей выше и найдите биты кодовой точки на местах `x`.

```text
a U+00061               1100001 -> 01100001
я U+0044F           10001001111 -> 11010001 10001111
€ U+020AC        10000010101100 -> 11100010 10000010 10101100
😀 U+1F600     11111011000000000 -> 11110000 10011111 10011000 10000000
```

У такого устройства четыре очень полезных свойства:

- **ASCII остаётся ASCII.** Любой текст ASCII уже является корректным UTF-8, байт в байт.
- **Нет путаницы с ASCII.** Все байты многобайтового символа ≥ `0x80`, поэтому побайтовый поиск `/` или `\n` в тексте UTF-8 никогда не найдёт ложное совпадение внутри другого символа.
- **Самосинхронизация.** Байты продолжения всегда начинаются с `10`. С любой позиции можно найти начало текущего символа, отступив назад не больше чем на три байта вида `10xxxxxx`. Именно это проверяет `str::is_char_boundary`, и поэтому срез `&str` посреди символа вызывает панику (Урок 04.8).
- **Сортировка байтов сортирует кодовые точки.** Сравнение байтов UTF-8 даёт тот же порядок, что и сравнение кодовых точек.

> ⚡ **Производительность:** благодаря этим свойствам многие строковые операции работают с байтами, не декодируя символы. Например, `str::find` с образцом из ASCII может использовать быстрый побайтовый поиск. Когда ваш ввод — чистый ASCII (лог-файлы, заголовки HTTP — HyperText Transfer Protocol, протокола передачи гипертекста, на котором работает веб), работа с `&[u8]` и методами `u8::is_ascii_*` позволяет вообще не декодировать.

## 4. Недопустимые байты

Не всякая последовательность байтов — корректный UTF-8. `&str` в Rust **гарантированно** корректен, поэтому преобразование из байтов обязано проверять:

```rust
fn main() {
    let good = vec![0x68, 0x69, 0xd1, 0x8f];
    let cut = vec![0x68, 0x69, 0xd1];
    let overlong = vec![0xc0, 0xaf];
    let surrogate = vec![0xed, 0xa0, 0x80];
    for bytes in [&good, &cut, &overlong, &surrogate] {
        match std::str::from_utf8(bytes) {
            Ok(text) => println!("{bytes:02x?} ok: {text:?}"),
            Err(e) => println!("{bytes:02x?} error: {e} (valid up to {})", e.valid_up_to()),
        }
    }
    println!("lossy: {}", String::from_utf8_lossy(&cut));
}
```

**Что происходит:**

1. `std::str::from_utf8` проверяет байты и возвращает `Ok(&str)` без копирования либо ошибку, которая говорит, где кончается корректная часть (`valid_up_to`).
2. `cut` обрывается посреди `я`: первый байт `d1` обещает байт продолжения, который так и не приходит.
3. `c0 af` — **избыточная кодировка** символа `/` (U+002F) в двух байтах. Она запрещена: у каждого символа ровно одна допустимая кодировка.
4. `ed a0 80` был бы суррогатом U+D800, который не является символом, поэтому он тоже отвергается.
5. `String::from_utf8_lossy` никогда не завершается ошибкой: каждую плохую часть он заменяет **символом замены** `U+FFFD` (`�`).

```text
[68, 69, d1, 8f] ok: "hiя"
[68, 69, d1] error: incomplete utf-8 byte sequence from index 2 (valid up to 2)
[c0, af] error: invalid utf-8 sequence of 1 bytes from index 0 (valid up to 0)
[ed, a0, 80] error: invalid utf-8 sequence of 1 bytes from index 0 (valid up to 0)
lossy: hi�
```

> 🔒 **Безопасность:** избыточные кодировки когда-то были настоящей атакой: старые программы проверяли путь на `../`, а затем декодировали `c0 af` в ещё один `/`, и `..` + `c0 af` проскальзывало мимо проверки. Строгая проверка Rust отвергает такие байты. Два других текстовых трюка по-прежнему важны: **похожие символы** (кириллическая `а` U+0430 выглядит как латинская `a` U+0061, поэтому `pаypal` может оказаться не `paypal`) и **невидимые символы** (U+200B — пробел нулевой ширины). Сравнивайте идентификаторы побайтово и не доверяйте тому, как текст *выглядит*.

## 5. Больше одного `char` на букву

`char` — это одна кодовая точка, но то, что человек видит как одну букву (**графемный кластер**), может состоять из нескольких:

```rust
fn main() {
    let composed = "\u{e9}";
    let decomposed = "e\u{301}";
    let flag = "\u{1F1EF}\u{1F1F5}";
    for (name, s) in [("composed", composed), ("decomposed", decomposed), ("flag", flag)] {
        println!("{name:<10} {s}  chars = {}  bytes = {}  utf-16 units = {}", s.chars().count(), s.len(), s.encode_utf16().count());
    }
    println!("same text? {}", composed == decomposed);
    let reversed: String = decomposed.chars().rev().collect();
    println!("reversed by chars: {reversed:?}");
}
```

**Что происходит:**

1. `é` может быть одной кодовой точкой (U+00E9) или двумя: `e` плюс U+0301, *комбинируемый знак ударения*, который присоединяется к предыдущей букве. На экране оба варианта выглядят одинаково.
2. Флаг — это две кодовые точки «региональных индикаторов» (здесь J и P — Япония). Терминал рисует их как одну картинку.
3. `encode_utf16()` превращает текст в 16-битные единицы **UTF-16**. Символам выше U+FFFF, как каждому региональному индикатору, нужно по две единицы (суррогатная пара), поэтому флаг — это 4 единицы.
4. Две формы `é` **не равны** как строки: `==` сравнивает байты. Приведение их к одному виду называется *нормализацией* (две формы называются NFC, Normalization Form C — «составная», и NFD, Normalization Form D — «разложенная»), и это делает крейт `unicode-normalization`.
5. Разворот по `char` ставит знак ударения перед `e` и ломает букву. Крейт `unicode-segmentation` делит текст на графемные кластеры, когда вам нужны «буквы, как их видят люди».

```text
composed   é  chars = 1  bytes = 2  utf-16 units = 1
decomposed é  chars = 2  bytes = 3  utf-16 units = 2
flag       🇯🇵  chars = 2  bytes = 8  utf-16 units = 4
same text? false
reversed by chars: "\u{301}e"
```

Итак, у «длины строки» как минимум четыре ответа: байты (`len`), кодовые точки (`chars().count()`), единицы UTF-16 (их считают некоторые другие системы) и графемные кластеры (их считают люди). Выбирайте то, что действительно нужно вашей задаче. Для ограничений размера ввода обычно правильны байты: именно их измеряют память, файлы и сети.

> 🧪 **Тестирование:** каждая текстовая функция заслуживает тестов с пустой строкой, чистым ASCII, кириллицей или другим 2-байтовым письмом, 3-байтовым символом (`€`), 4-байтовым эмодзи, комбинируемым знаком и недопустимыми байтами (для функций, принимающих `&[u8]`). Упражнение 2 проверяет даже все 1,1 миллиона символов.

## Частые ошибки

> ⚠️ **Частая ошибка: читать файл не в UTF-8 через `read_to_string`.** Старые текстовые файлы часто записаны в другой кодировке, например Latin-1, где `é` — один байт `0xe9`:

```rust
use std::fs;

fn main() {
    fs::write("latin1.txt", [b'c', b'a', b'f', 0xe9]).unwrap();
    match fs::read_to_string("latin1.txt") {
        Ok(text) => println!("text: {text}"),
        Err(e) => println!("error: {e}"),
    }
    let bytes = fs::read("latin1.txt").unwrap();
    println!("bytes: {bytes:02x?}");
    println!("lossy: {}", String::from_utf8_lossy(&bytes));
}
```

```text
error: stream did not contain valid UTF-8
bytes: [63, 61, 66, e9]
lossy: caf�
```

`read_to_string` отказывается читать некорректный UTF-8. Когда вы не управляете вводом, читайте байты через `fs::read`, а затем решайте: отвергнуть, использовать `from_utf8_lossy` или перекодировать из настоящей кодировки крейтом вроде `encoding_rs`. (Потом удалите `latin1.txt`.)

> ⚠️ **Частая ошибка: приёмы ASCII на тексте не из ASCII.** `b ^ 0x20` меняет регистр только у `a`–`z` и `A`–`Z`. Применённый к байтам `я`, он разрушает UTF-8. Используйте `to_ascii_uppercase` (пропускает байты вне ASCII) или `to_uppercase` (знает весь Unicode).

> ⚠️ **Частая ошибка: `chars().count()` как «число букв».** Он считает кодовые точки, поэтому `"e\u{301}"` даёт 2. Используйте графемные кластеры, когда важна видимая длина (например, при выравнивании текста в терминале).

## Попробуйте сами

1. Напечатайте `"Ünïcödé".to_uppercase()` и `"Ünïcödé".to_ascii_uppercase()` и объясните разницу.
2. Возьмите строку `"aя€😀"` и для каждого байта напечатайте его индекс, шестнадцатеричное значение и равно ли `is_char_boundary(index)` значению `true`. Убедитесь, что строки с `true` — ровно те байты, которые **не** начинаются с `10`.
3. Напечатайте `"\u{FEFF}hi".as_bytes()`. Первые три байта `ef bb bf` — это **BOM** (Byte Order Mark, метка порядка байтов), которую некоторые редакторы в Windows ставят в начало файлов UTF-8. Если парсер спотыкается на первом слове такого файла, уберите её через `trim_start_matches('\u{FEFF}')`.

## Упражнения

### Упражнение 1 — Кодирование вручную (легко)

Закодируйте `é` (U+00E9) и `€` (U+20AC) в UTF-8 на бумаге по таблице из раздела 3. Затем проверьте через `as_bytes()`.

<details>
<summary>Подсказка</summary>

`0xE9` = `1110 1001` требует 8 битов → 2-байтовая форма `110xxxxx 10xxxxxx` с 11 местами; дополните нулями слева: `000 1110 1001`. `0x20AC` требует 14 битов → 3-байтовая форма с 16 местами.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("{:02x?} {:02x?}", "é".as_bytes(), "€".as_bytes());
}
```

```text
[c3, a9] [e2, 82, ac]
```

Почему это работает: `00011 101001` → `110 00011` = `c3`, `10 101001` = `a9`. Для `€`: `0010 000010 101100` → `1110 0010` = `e2`, `10 000010` = `82`, `10 101100` = `ac`.

</details>

### Упражнение 2 — Свой кодировщик UTF-8 (средне)

В `src/lib.rs` пакета `code/p12-text` напишите `pub fn encode_utf8(cp: u32) -> Option<Vec<u8>>`, которая возвращает байты UTF-8 кодовой точки или `None` для суррогатов и значений больше `0x10FFFF`. Напишите тест, который сравнивает вашу функцию с `char::encode_utf8` для **каждого** `char` (по диапазону `char::MIN..=char::MAX` можно пройти циклом), и тест для недопустимых значений.

<details>
<summary>Подсказка</summary>

Используйте `match` с диапазонами: `0..=0x7f`, `0x80..=0x7ff`, `0xd800..=0xdfff` (→ `None`; поставьте его перед 3-байтовым диапазоном), `0x800..=0xffff`, `0x1_0000..=0x10_ffff`, `_`. Для каждого байта возьмите нужный 6-битный кусок приёмом «сдвиг, затем маска `0x3f`» и объедините через ИЛИ с заголовком, например `0b1000_0000 | (cp & 0x3f) as u8`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Encodes one Unicode code point as UTF-8, or returns None if it is not a valid scalar value.
pub fn encode_utf8(cp: u32) -> Option<Vec<u8>> {
    match cp {
        0..=0x7f => Some(vec![cp as u8]),
        0x80..=0x7ff => Some(vec![0b1100_0000 | (cp >> 6) as u8, 0b1000_0000 | (cp & 0x3f) as u8]),
        0xd800..=0xdfff => None,
        0x800..=0xffff => Some(vec![
            0b1110_0000 | (cp >> 12) as u8,
            0b1000_0000 | ((cp >> 6) & 0x3f) as u8,
            0b1000_0000 | (cp & 0x3f) as u8,
        ]),
        0x1_0000..=0x10_ffff => Some(vec![
            0b1111_0000 | (cp >> 18) as u8,
            0b1000_0000 | ((cp >> 12) & 0x3f) as u8,
            0b1000_0000 | ((cp >> 6) & 0x3f) as u8,
            0b1000_0000 | (cp & 0x3f) as u8,
        ]),
        _ => None,
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn matches_std_for_every_char() {
        for c in char::MIN..=char::MAX {
            let mut buf = [0u8; 4];
            let expected = c.encode_utf8(&mut buf).as_bytes().to_vec();
            assert_eq!(encode_utf8(c as u32), Some(expected), "char U+{:04X}", c as u32);
        }
    }

    #[test]
    fn rejects_invalid_code_points() {
        assert_eq!(encode_utf8(0xd800), None);
        assert_eq!(encode_utf8(0xdfff), None);
        assert_eq!(encode_utf8(0x11_0000), None);
    }
}
```

Почему это работает: первый байт берёт старшие биты (`cp >> 6`, `>> 12` или `>> 18`); его заголовок оставляет ровно нужное число мест, поэтому маска там не нужна. Каждый байт продолжения берёт следующие 6 битов. Ветки `match` выбираются сверху вниз, поэтому суррогатная ветка побеждает 3-байтовую. Диапазон `char::MIN..=char::MAX` сам пропускает суррогаты, поэтому тест проверяет все 1 112 064 допустимых символа за доли секунды.

</details>

### Упражнение 3 — Считаем символы без декодирования (средне)

Напишите `pub fn count_chars(text: &str) -> usize`, которая считает символы, глядя только на байты: считайте каждый байт, который **не** является байтом продолжения. Проверьте её против `text.chars().count()` на `""`, `"hello"`, `"привет"`, `"a€😀"` и `"e\u{301}"`.

<details>
<summary>Подсказка</summary>

Байт продолжения соответствует `10xxxxxx`: `b & 0b1100_0000 == 0b1000_0000`. Используйте `text.bytes().filter(…).count()`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Counts the characters of UTF-8 text by counting the bytes that are not continuation bytes.
pub fn count_chars(text: &str) -> usize {
    text.bytes().filter(|&b| b & 0b1100_0000 != 0b1000_0000).count()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn counts_like_chars() {
        for text in ["", "hello", "привет", "a€😀", "e\u{301}"] {
            assert_eq!(count_chars(text), text.chars().count(), "text {text:?}");
        }
    }
}
```

Почему это работает: у каждого символа ровно один первый байт, и только первые байты не имеют вид `10xxxxxx`. Функция верна лишь потому, что `&str` гарантированно содержит корректный UTF-8; на произвольных байтах она считала бы мусор.

</details>

### Упражнение 4 — Строгий декодер UTF-8 (сложно)

Напишите `pub fn decode_first(bytes: &[u8]) -> Option<(char, usize)>`, которая декодирует первый символ `bytes` и возвращает его вместе с длиной или `None`, если байты не начинаются с корректного UTF-8. Она должна отвергать: пустой срез, одинокий байт продолжения, оборванную последовательность, избыточные кодировки, суррогаты и значения больше `0x10FFFF`. Тесты: декодировать каждый `char` из его собственной кодировки; и плохие входы `[]`, `[80]`, `[d1]`, `[c0 af]`, `[e0 80 af]`, `[ed a0 80]`, `[f4 90 80 80]`.

<details>
<summary>Подсказка</summary>

По первому байту найдите длину (1–4), биты полезной нагрузки первого байта (маски `0x1f`, `0x0f`, `0x07`) и наименьшую кодовую точку, которой действительно нужна такая длина (`0x80`, `0x800`, `0x1_0000`). Проверьте, что следом идёт достаточно байтов и что каждый из них имеет вид `10xxxxxx`; собирайте биты через `cp = (cp << 6) | (b & 0x3f) as u32`. Результат ниже минимума — избыточная кодировка. Остальное отвергнет `char::from_u32`.

</details>

<details>
<summary>Ответ</summary>

```rust
/// Decodes the first character of `bytes`. Returns the char and its length in bytes,
/// or None if the bytes do not start with a valid UTF-8 sequence.
pub fn decode_first(bytes: &[u8]) -> Option<(char, usize)> {
    let first = *bytes.first()?;
    let (len, mut cp, min) = match first {
        0x00..=0x7f => return Some((first as char, 1)),
        0xc0..=0xdf => (2, (first & 0x1f) as u32, 0x80),
        0xe0..=0xef => (3, (first & 0x0f) as u32, 0x800),
        0xf0..=0xf7 => (4, (first & 0x07) as u32, 0x1_0000),
        _ => return None,
    };
    if bytes.len() < len {
        return None;
    }
    for &b in &bytes[1..len] {
        if b & 0b1100_0000 != 0b1000_0000 {
            return None;
        }
        cp = (cp << 6) | (b & 0x3f) as u32;
    }
    if cp < min {
        return None; // overlong encoding
    }
    char::from_u32(cp).map(|c| (c, len)) // rejects surrogates and values above 0x10FFFF
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn decodes_every_char() {
        for c in char::MIN..=char::MAX {
            let mut buf = [0u8; 4];
            let bytes = c.encode_utf8(&mut buf).as_bytes();
            assert_eq!(decode_first(bytes), Some((c, bytes.len())));
        }
    }

    #[test]
    fn rejects_bad_sequences() {
        let bad: [&[u8]; 7] = [
            &[],
            &[0x80],
            &[0xd1],
            &[0xc0, 0xaf],
            &[0xe0, 0x80, 0xaf],
            &[0xed, 0xa0, 0x80],
            &[0xf4, 0x90, 0x80, 0x80],
        ];
        for bytes in bad {
            assert_eq!(decode_first(bytes), None, "bytes {bytes:02x?}");
            assert!(std::str::from_utf8(bytes).is_err() || bytes.is_empty());
        }
    }
}
```

Почему это работает: длину определяет один первый байт; байты `0x80`–`0xbf` (продолжения) и `0xf8`–`0xff` (не используются) отвергаются сразу. Проверка минимума ловит избыточные формы вроде `c0 af` (они декодировались бы в `0x2f`, что меньше `0x80`). `f4 90 80 80` декодируется в `0x110000`, которое `char::from_u32` отвергает. Второе утверждение использует стандартную библиотеку как оракул: она должна согласиться, что эти входы некорректны.

</details>

## Вопросы для самопроверки

1. Почему значение цифры ASCII `b` равно `b - b'0'`?

<details>
<summary>Ответ</summary>

У цифр от `'0'` до `'9'` подряд идущие коды от `0x30` до `0x39`, поэтому вычитание кода `'0'` даёт от 0 до 9.

</details>

2. Какой один бит отличает `'A'` от `'a'` в ASCII?

<details>
<summary>Ответ</summary>

Бит 5 (`0x20`): `'A'` — это `0x41`, `'a'` — `0x61`.

</details>

3. Почему `char::from_u32(0xD800)` возвращает `None`?

<details>
<summary>Ответ</summary>

`0xD800` — суррогатная кодовая точка, зарезервированная для пар UTF-16. Это не скалярное значение Unicode, а `char` может хранить только скалярные значения.

</details>

4. Сколько байтов занимает U+20AC (`€`) в UTF-8 и с чего начинается первый байт?

<details>
<summary>Ответ</summary>

Три байта; первый начинается с `1110` (`e2`).

</details>

5. Почему в тексте UTF-8 можно искать байт `b'/'` без декодирования?

<details>
<summary>Ответ</summary>

Все байты многобайтовых символов не меньше `0x80`, поэтому байт ASCII `0x2f` может встретиться только как сам символ `/`.

</details>

6. Что делает `String::from_utf8_lossy` с недопустимыми байтами?

<details>
<summary>Ответ</summary>

Заменяет каждую недопустимую часть символом замены U+FFFD (`�`) и никогда не завершается ошибкой.

</details>

7. `"e\u{301}"` и `"\u{e9}"` выглядят одинаково. Почему `==` даёт false?

<details>
<summary>Ответ</summary>

Это разные кодовые точки и, значит, разные байты (`65 cc 81` против `c3 a9`). Равенство строк сравнивает байты; нормализация сделала бы их равными.

</details>

## Итоги

- ASCII — это 7 битов: управляющие коды 0–31, цифры с `0x30`, заглавные с `0x41`, строчные с `0x61`; регистры различает бит 5.
- Unicode нумерует символы кодовыми точками от 0 до `0x10FFFF`; `char` — скалярное значение (без суррогатов) в 4 байтах.
- UTF-8 использует заголовки `0`, `110`, `1110`, `11110` для первых байтов и `10` для байтов продолжения. Он совместим с ASCII и самосинхронизируется.
- `&str` всегда содержит корректный UTF-8. Преобразование байтов требует проверки: `str::from_utf8` (ошибка), `String::from_utf8_lossy` (`�`); избыточные формы и суррогаты отвергаются.
- Одна видимая буква может состоять из нескольких кодовых точек; длина может означать байты, кодовые точки, единицы UTF-16 или графемные кластеры.
- Тестируйте текстовый код на ASCII, многобайтовых символах, эмодзи, комбинируемых знаках и недопустимых байтах; не доверяйте тому, как текст выглядит.
