# Урок 02.1 — Переменные и изменяемость

- Что такое переменная и как создать её с помощью `let`.

## Новые слова

| Слово | Значение |
|---|---|
| **переменная** (variable) | Имя, которое указывает на значение, хранящееся в памяти компьютера. |
| **значение** (value) | Порция данных, например число `10` или текст `"hello"`. |
| **привязка** (binding) | Связь между именем и значением. В Rust `let` создаёт привязку. Обычно её просто называют «переменной». |
| **неизменяемый** (immutable) | Такой, который нельзя изменить после того, как он задан. В Rust переменные по умолчанию неизменяемые. |
| **изменяемый** (mutable) | Такой, который можно менять. Это включается ключевым словом `mut`. |
| **ключевое слово** (keyword) | Слово, имеющее в языке особый смысл (`let`, `fn`, `mut`, `const`). Использовать его как имя нельзя. |
| **константа** (constant) | Значение, которое никогда не меняется и известно уже при компиляции программы. Создаётся с помощью `const`. |
| **затенение** (shadowing) | Создание новой переменной с тем же именем, что у старой. Новая скрывает («затеняет») старую. |
| **область видимости** (scope) | Часть кода, в которой имя можно использовать. |
| **блок** (block) | Код между `{` и `}`. Блок создаёт новую область видимости. |
| **тип** (type) | Вид значения (целое число, дробное число, текст…). Подробно типы разбирает Урок 02.2. |
| **компилятор** (compiler) | Программа (`rustc`), которая переводит ваш код на Rust в программу, понятную компьютеру, и проверяет его на ошибки. |
| **предупреждение** (warning) | Сообщение компилятора о коде, который допустим, но, скорее всего, ошибочен. Программа при этом собирается. |
| **паника** (panic) | Контролируемая аварийная остановка: программа останавливается и печатает сообщение. |
| **макрос** (macro) | Нечто похожее на функцию, но с `!` на конце, например `println!` или `assert_eq!`. Макросы объясняются на Этапе 06. |
| **утверждение** (assertion) | Проверка в коде, которая говорит «это должно быть истинно». Если это ложно, программа паникует. |
| **RAM** (Random Access Memory, оперативная память) | Быстрая временная память, в которой работающая программа хранит свои данные. |
| **snake_case** | Стиль имён: все буквы строчные, слова разделены `_` (`total_price`). |
| **`.gitignore`** | Файл, который сообщает Git, какие файлы никогда не отслеживать (например, результаты сборки). |

## 1. Ваш учебный проект

Весь Этап 02 вы будете пробовать много маленьких программ. Вместо того чтобы создавать новый проект для каждой, вы создадите **один учебный проект** и будете хранить каждый эксперимент в отдельном файле.

Сначала убедитесь, что Git не отслеживает папку сборки. Когда вы запускаете `cargo build`, Cargo создаёт папку `target/` со скомпилированными файлами. Она большая, её можно пересобрать в любой момент, и в Git она попадать не должна. Обычно Cargo сам пишет `.gitignore`, но **только когда создаёт новый репозиторий Git**. Ваша папка `~/projects/rust` уже является репозиторием, поэтому Cargo пропускает этот шаг. Правило вы добавляете сами.

```bash
cd ~/projects/rust
echo "target/" >> .gitignore
cargo new code/p02-basics
cd code/p02-basics
mkdir src/bin
```

Что происходит:

1. `cd ~/projects/rust` переходит в корень вашего учебного репозитория.
2. `echo "target/" >> .gitignore` дописывает строку `target/` в файл `.gitignore` (и создаёт файл, если его нет). Шаблон `target/` подходит для папки `target` на любой глубине, поэтому он покрывает все будущие проекты.
3. `cargo new code/p02-basics` создаёт новый проект на Rust. Имя `p02-basics` значит «Этап 02, основы». Соглашение курса: `code/pNN-<name>`.
4. `mkdir src/bin` создаёт папку. **Каждый файл `.rs` в `src/bin/` становится отдельной маленькой программой.**

Теперь создайте файл `src/bin/01_variables.rs` и наберите в нём:

```rust
fn main() {
    let mut score = 10;
    println!("score = {score}");
    score = 11;
    println!("score = {score}");
    score += 5;
    println!("score = {score}");
}
```

Запустите. Программ несколько, поэтому нужно указать, какую именно. Имя — это имя файла без `.rs`:

```bash
cargo run --bin 01_variables
```

```text
   Compiling p02-basics v0.1.0 (/Users/you/projects/rust/code/p02-basics)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/01_variables`
score = 10
score = 11
score = 16
```

(Путь в первой строке у вас будет другой. В следующих примерах этого урока показан только вывод программы, без строк `Compiling`.)

> 💡 **Совет:** если набрать просто `cargo run` в проекте с несколькими программами, Cargo ответит `could not determine which binary to run` и перечислит известные ему имена. Добавьте `--bin <name>`.

Наконец, проверьте, что видит Git:

```bash
cd ~/projects/rust
git status --short
```

```text
?? .gitignore
?? code/
```

Видны только `.gitignore` и ваша новая папка `code/`. `target/` скрыта, как и должно быть. Коммит вы сделаете в конце урока.

## 2. Что такое переменная

Представьте полку с подписанными коробками. В каждой коробке лежит одна вещь, а подпись говорит, какая это коробка. **Переменная** работает так же: память компьютера (RAM, Random Access Memory) — это полка, значение — вещь в коробке, а имя — подпись.

```text
   name        value in memory
 +-------+    +------+
 | score | -> |  10  |
 +-------+    +------+
```

Переменную создаёт ключевое слово `let`:

```rust
let score = 10;
```

Читайте так: «пусть имя `score` означает значение `10`». Части записи:

```text
let score = 10;
│   │       │ └─ the end of the statement
│   │       └─── the value
│   └─────────── the name you choose
└─────────────── the keyword that creates a variable
```

Чтобы использовать переменную, напишите её имя. Внутри `println!` имя можно поставить в фигурные скобки: `println!("score = {score}")` напечатает `score = 10`. (`!` показывает, что `println!` — макрос. Вывод подробно разбирает Урок 02.6.)

## 3. Переменные по умолчанию не меняются

Во многих языках переменную можно изменить в любой момент. В Rust — нельзя. Это сделано намеренно. Попробуйте:

```rust
fn main() {
    let score = 10;
    println!("score = {score}");
    score = 11;
    println!("score = {score}");
}
```

Компилятор отказывается собирать программу:

```text
error[E0384]: cannot assign twice to immutable variable `score`
 --> src/main.rs:4:5
  |
2 |     let score = 10;
  |         ----- first assignment to `score`
3 |     println!("score = {score}");
4 |     score = 11;
  |     ^^^^^^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut score = 10;
  |         +++

For more information about this error, try `rustc --explain E0384`.
```

Как читать это сообщение:

1. `error[E0384]` — у ошибки есть код `E0384`. У каждой ошибки Rust есть такой код, и его можно искать.
2. `cannot assign twice to immutable variable` — суть проблемы простыми словами. «Assign» значит «присвоить», то есть положить значение в переменную. «Immutable» значит «неизменяемая».
3. Стрелки `-->` дают файл, строку и столбец: строка 4, столбец 5. Имя файла — это файл, который вы компилировали. В выводах этого курса показан `src/main.rs`; если вы поместите пример в файл в `src/bin/`, вы увидите имя этого файла, а всё остальное останется таким же.
4. Пометки `-----` и `^^^^` указывают на два места: первое присваивание и второе, которое запрещено.
5. `help:` — компилятор предлагает исправление: написать `let mut score`.

Последняя строка подсказывает полезный приём. Выполните `rustc --explain E0384` в терминале, чтобы прочитать длинное объяснение любого кода ошибки — без интернета, с примерами.

**Зачем Rust так делает?** Если значение никогда не меняется, код можно читать и доверять ему: число, которое вы видите вверху, остаётся тем же внизу. Многие ошибки возникают из-за того, что «что-то изменило эту переменную, а я не заметил». Позже, когда несколько потоков работают одновременно, неизменяемые значения безопасно делить между ними. Rust заставляет вас явно сказать, что изменение задумано.

> 📏 **Соглашение:** начинайте с обычного `let`. Добавляйте `mut` только тогда, когда значение действительно нужно менять.

## 4. `mut` — переменные, которые можно менять

Поставьте ключевое слово `mut` (сокращение от *mutable*, «изменяемый») после `let`:

```rust
fn main() {
    let mut score = 10;
    println!("score = {score}");
    score = 11;
    println!("score = {score}");
    score += 5;
    println!("score = {score}");
}
```

Что происходит:

1. `let mut score = 10;` создаёт переменную, которую разрешено менять. Сначала она равна `10`.
2. Первый `println!` печатает `score = 10`.
3. `score = 11;` кладёт новое значение в ту же коробку. Заметьте: на этот раз `let` нет — мы не создаём переменную, а только присваиваем существующей.
4. `score += 5;` значит «прибавить 5 к `score`» — это короткая запись `score = score + 5;`. Все такие операторы показывает Урок 02.3.
5. Последний `println!` печатает новое значение.

```text
score = 10
score = 11
score = 16
```

`mut` позволяет менять **значение**. Менять **тип** переменной оно не позволяет. Переменная, в которой лежит текст, не может вдруг начать хранить число:

```rust
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
    println!("There are {spaces} spaces");
}
```

(`spaces.len()` даёт длину текста: число байтов. `len` — это *метод*, то есть функция, привязанная к значению через точку. Методы изучаются на Этапе 04.)

```text
error[E0308]: mismatched types
 --> src/main.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`
```

`E0308 mismatched types` — одна из самых частых ошибок, которые вы будете видеть. Она говорит: «Я ожидал текст (`&str`), а вы дали число (`usize`)». Названия типов объясняет следующий урок. Следующий раздел показывает, как решить именно эту проблему.

## 5. Константы

**Константа** — это значение, зафиксированное на всё время работы программы. Её создаёт `const`:

```rust
const SECONDS_PER_HOUR: u32 = 60 * 60;
const MAX_PLAYERS: u32 = 4;

fn main() {
    let hours = 3;
    let seconds = hours * SECONDS_PER_HOUR;
    println!("{hours} hours = {seconds} seconds");
    println!("Max players: {MAX_PLAYERS}");
}
```

Что происходит:

1. `const SECONDS_PER_HOUR: u32 = 60 * 60;` определяет константу. После имени идёт `: u32` — **тип** (32-битное целое число без знака; см. Урок 02.2). Для констант тип нужно писать всегда.
2. Значение `60 * 60` вычисляет компилятор **во время компиляции**, а не когда программа работает.
3. Константы записаны вне `main`, в начале файла. Константы можно объявлять где угодно, даже вне любых функций, и использовать в любой функции.
4. `hours * SECONDS_PER_HOUR` умножает `3` на `3600`.

```text
3 hours = 10800 seconds
Max players: 4
```

Отличия `let` от `const`:

| | `let` | `const` |
|---|---|---|
| Можно ли менять? | Только с `mut` | Никогда (`const mut` — ошибка) |
| Тип пишете вы? | Обычно не нужно | Всегда обязательно |
| Значение известно, когда | Программа работает | Программа компилируется |
| Где можно использовать | Только внутри функций | Где угодно, в том числе вне функций |
| Именование | `snake_case` | `SCREAMING_SNAKE_CASE` (все буквы заглавные) |

Если дать константе значение, которое известно только во время работы программы, компилятор остановит вас:

```rust
fn main() {
    let base = 3;
    const DOUBLE: u32 = base * 2;
    println!("{DOUBLE}");
}
```

```text
error[E0435]: attempt to use a non-constant value in a constant
 --> src/main.rs:3:25
  |
3 |     const DOUBLE: u32 = base * 2;
  |                         ^^^^ non-constant value
  |
help: consider using `let` instead of `const`
```

> 📏 **Соглашение:** не оставляйте в коде «магические числа». Если вы пишете `3600` в пяти местах, никто не знает, что это значит. Именованная константа `SECONDS_PER_HOUR` объясняет себя сама и меняется в одном месте. Это часть принципа **DRY** (Don't Repeat Yourself, «не повторяйся»).

## 6. Затенение (shadowing)

Rust позволяет объявить новую переменную с **тем же именем**, что у старой. Новая *затеняет* старую: с этой строки имя означает новую переменную.

```rust
fn main() {
    let x = 5;
    let x = x + 1;
    {
        let x = x * 2;
        println!("inner x = {x}");
    }
    println!("outer x = {x}");
}
```

Что происходит:

1. `let x = 5;` создаёт `x` со значением `5`.
2. `let x = x + 1;` создаёт **новую** переменную, тоже с именем `x`. Её значение вычисляется из старого `x` (`5 + 1`), то есть равно `6`. Старый `x` теперь скрыт.
3. Фигурные скобки `{ ... }` начинают **блок**. Блок — это новая область видимости.
4. Внутри блока `let x = x * 2;` создаёт третий `x` со значением `12`. Он существует только внутри блока.
5. Первый `println!` находится внутри блока и печатает `12`.
6. На закрывающей `}` внутренний `x` исчезает. Имя `x` снова означает переменную со значением `6`.
7. Второй `println!` печатает `6`.

```text
inner x = 12
outer x = 6
```

```text
 before the block      inside the block        after the block
 +---+                 +---+                   +---+
 | 6 |  x              |12 |  x (inner)        | 6 |  x
 +---+                 +---+  [6 is hidden]    +---+
```

**Затенение — это не то же самое, что `mut`.** Два отличия:

- При затенении вы снова пишете `let`. Это создаёт новую переменную, поэтому компилятор по-прежнему защищает вас от случайных изменений: после вашего последнего `let x` переменная опять неизменяемая.
- У новой переменной может быть **другой тип**. Так решается проблема из раздела 4:

```rust
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
    println!("There are {spaces} spaces");
}
```

```text
There are 3 spaces
```

Первая `spaces` — текст. Вторая `spaces` — число, вычисленное из текста. Обе используют одно хорошее имя, и нам не нужны `spaces_text` и `spaces_count`.

Что когда выбирать:

- Используйте **`mut`**, когда одна и та же вещь меняется много раз, например счётчик в цикле.
- Используйте **затенение**, чтобы шаг за шагом *преобразовывать* значение (текст → число), сохраняя имя.

## 7. Область видимости: где живёт имя

Имя существует от строки, где вы его создали, до конца блока `{ ... }`, который его содержит. За пределами блока имени нет.

```rust
fn main() {
    {
        let inner = 7;
        println!("inside: {inner}");
    }
    println!("outside: {inner}");
}
```

```text
error[E0425]: cannot find value `inner` in this scope
 --> src/main.rs:6:25
  |
6 |     println!("outside: {inner}");
  |                         ^^^^^
  |
help: the binding `inner` is available in a different scope in the same function
 --> src/main.rs:3:13
  |
3 |         let inner = 7;
  |             ^^^^^
```

`E0425 cannot find value` говорит, что здесь такое имя неизвестно. Часть `help` умная: она нашла переменную с этим именем в другой области видимости. Когда видите эту ошибку, проверьте, не объявили ли вы переменную внутри блока, который уже закончился.

У области видимости в Rust есть и более глубокий смысл: когда блок заканчивается, значения, созданные внутри него, убираются. На этой идее строится Этап 03.

## 8. Объявить сейчас, присвоить потом

Можно создать переменную без значения, если указать тип, и присвоить значение позже. Даже без `mut` её можно присвоить один раз:

```rust
fn main() {
    let total: i32;
    total = 30;
    println!("total = {total}");
}
```

```text
total = 30
```

Компилятор проверяет, что у переменной всегда есть значение до того, как вы её читаете. Если вы забыли, получите ошибку:

```rust
fn main() {
    let total: i32;
    println!("total = {total}");
}
```

```text
error[E0381]: used binding `total` isn't initialized
 --> src/main.rs:3:24
  |
2 |     let total: i32;
  |         ----- binding declared here but left uninitialized
3 |     println!("total = {total}");
  |                        ^^^^^ `total` used here but it isn't initialized
```

В Rust нет «пустых» переменных или переменных со случайным мусором. Это ещё одна ошибка, которая не дойдёт до ваших пользователей. На практике вы чаще всего будете сразу писать `let name = value;`.

## 9. Хорошие имена

Имена — главный способ сделать код читаемым. Правила компилятора:

- Имя состоит из букв, цифр и `_` и не начинается с цифры.
- Имя не может быть ключевым словом. `let fn = 5;` даёт ошибку `expected identifier, found keyword fn`.

Соглашения сообщества Rust (компилятор их не навязывает, но все им следуют):

- Переменные и функции: `snake_case`: `total_price`, `user_count`.
- Константы: `SCREAMING_SNAKE_CASE`: `MAX_PLAYERS`.
- Выбирайте имена, которые говорят, *что значит величина*: `seconds_left` лучше, чем `s` или `data2`.
- Имя, начинающееся с `_` (например, `_ignored`), сообщает компилятору: «я знаю, что не использую это».

Компилятор предупреждает о переменных, которые вы нигде не используете:

```rust
fn main() {
    let count = 3;
    let _ignored = 4;
    println!("hello");
}
```

```text
warning: unused variable: `count`
 --> src/main.rs:2:9
  |
2 |     let count = 3;
  |         ^^^^^ help: if this is intentional, prefix it with an underscore: `_count`
  |
  = note: `#[warn(unused_variables)]` (part of `#[warn(unused)]`) on by default

hello
```

Программа работает (это всего лишь предупреждение), но `count`, вероятно, ошибка. Для `_ignored` предупреждения нет. **Относитесь к предупреждениям как к работе, которую нужно сделать**: проекту без предупреждений легче доверять.

> 💡 **Совет:** три команды, которые поддерживают код в хорошем состоянии. Используйте их часто и всегда перед коммитом:
>
> - `cargo check` — проверяет, что код компилируется, не создавая программу. Работает быстрее, чем `cargo build`.
> - `cargo fmt` — форматирует код в стандартном стиле (инструмент называется *rustfmt*).
> - `cargo clippy` — даёт дополнительные советы по стилю и вероятным ошибкам (инструмент называется *Clippy*).
>
> RustRover также показывает выведенный тип переменной рядом с ней серым цветом («подсказки inlay hints»). Это отличный способ выучить типы.

## Частые ошибки

**1. Забыли `mut`.** Вы видите `E0384 cannot assign twice to immutable variable`. Исправление: напишите `let mut`. Но сначала спросите себя: нужно ли мне действительно менять значение? Иногда новый `let` (затенение) чище.

**2. Написали `let`, когда хотели присвоить.** Строка `let score = 11;` внутри блока создаёт *новую* переменную, которая скрывает старую, и после блока старая остаётся прежней. Если вы хотите изменить старую переменную, пишите `score = 11;` без `let`.

**3. Попытка сменить тип через `mut`.** Вы видите `E0308 mismatched types`. Используйте затенение: `let spaces = spaces.len();`.

**4. `const` без типа или со значением времени выполнения.** `const MAX = 5;` — ошибка (тип обязателен). `const X: u32 = base * 2;`, где `base` — переменная `let`, даёт `E0435`.

**5. Использование переменной за пределами её блока.** Вы видите `E0425 cannot find value`. Вынесите `let` из блока или перенесите код, который её использует, внутрь блока.

> 🧪 **Тестирование:** свой код можно проверять с помощью **утверждения** (assertion). `assert_eq!(a, b)` сравнивает два значения. Если они равны, ничего не происходит. Если различаются, программа паникует (останавливается) и показывает оба значения:
>
> ```rust
> fn main() {
>     let a = 2;
>     let b = 3;
>     let sum = a + b;
>     assert_eq!(sum, 5);
>     println!("sum is correct: {sum}");
>     assert_eq!(sum, 6, "the sum of {a} and {b} should be 6");
>     println!("this line is never reached");
> }
> ```
>
> ```text
> sum is correct: 5
>
> thread 'main' (3860046) panicked at src/main.rs:7:5:
> assertion `left == right` failed: the sum of 2 and 3 should be 6
>   left: 5
>  right: 6
> note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
> ```
>
> Первое утверждение проходит молча. Второе не проходит: программа останавливается на строке 7, показывает ваше сообщение, затем `left` и `right`. (Число в скобках после `thread 'main'` при каждом запуске разное.) Урок 02.8 учит настоящей системе тестов Rust (`cargo test`). До тех пор `assert_eq!` — ваша маленькая страховочная сетка.

> 🔒 **Безопасность:** неизменяемость помогает и безопасности. Значение, которое нельзя изменить, нельзя изменить по ошибке или из-за бага в другой части программы. Проектируя данные, делайте их доступными только для чтения, если им не нужно меняться.

Если вы не помните, как это делается, повторите [Урок 01.3](../01-git-and-version-control/03-your-first-repository-and-commits.md).

> 📏 **Соглашение:** сообщение `feat(p02): …` следует стилю *Conventional Commits*, о котором рассказывал [Урок 01.9](../01-git-and-version-control/09-teamwork-pull-requests-and-conventions.md): тип (`feat`, `fix`, `docs`, `test`), область в скобках, двоеточие, затем краткое описание. Используйте его для каждого коммита на этом этапе.

## Упражнения

### Упражнение 1 — Исправьте программу (легко)

Эта программа не компилируется. Исправьте её минимальным изменением. Она должна напечатать `lives: 2`.

```rust
fn main() {
    let lives = 3;
    lives = lives - 1;
    println!("lives: {lives}");
}
```

<details>
<summary>Подсказка</summary>

Переменная меняется после того, как создана. Какое ключевое слово это разрешает?

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let mut lives = 3;
    lives = lives - 1;
    println!("lives: {lives}");
}
```

Почему это работает: `mut` разрешает второе присваивание. Вывод: `lives: 2`. (Можно было написать и `lives -= 1;`.)

</details>

### Упражнение 2 — Предскажите, затем запустите (легко)

Что напечатает эта программа? Сначала запишите свой ответ, затем запустите.

```rust
fn main() {
    let a = 1;
    let a = a + 1;
    {
        let a = a * 10;
        println!("{a}");
    }
    println!("{a}");
}
```

<details>
<summary>Подсказка</summary>

Каждый `let a` создаёт новую переменную. Та, что внутри скобок, живёт только до `}`.

</details>

<details>
<summary>Ответ</summary>

```text
20
2
```

Почему это работает: первая `a` равна `1`; вторая — `1 + 1 = 2`. Внутри блока третья `a` равна `2 * 10 = 20` и печатается. После блока имя `a` означает вторую переменную (`2`).

</details>

### Упражнение 3 — Именованная константа (средне)

Напишите программу, которая считает, сколько минут в 7 днях. Используйте константу `MINUTES_PER_DAY` (60 минут × 24 часа) и переменную `days`. Напечатайте `7 days = 10080 minutes`.

<details>
<summary>Подсказка</summary>

Константе нужен тип: `const MINUTES_PER_DAY: u32 = 60 * 24;`. Тип для `days` пусть выведет компилятор из умножения.

</details>

<details>
<summary>Ответ</summary>

```rust
const MINUTES_PER_DAY: u32 = 60 * 24;

fn main() {
    let days = 7;
    let minutes = days * MINUTES_PER_DAY;
    println!("{days} days = {minutes} minutes");
}
```

Почему это работает: компилятор видит `days * MINUTES_PER_DAY` и решает, что `days` — тоже `u32`. Вывод: `7 days = 10080 minutes`.

</details>

### Упражнение 4 — Смените тип затенением (средне)

Начните с `let input = "42";` (текст). С помощью затенения сделайте второй `input` — **длину** текста (`input.len()`), затем третий `input` — второй, умноженный на 10. Напечатайте итоговое значение. Должно получиться `20`.

<details>
<summary>Подсказка</summary>

`"42".len()` равно `2`, потому что в тексте два символа. Напишите три строки `let input = …;` подряд.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let input = "42";
    let input = input.len();
    let input = input * 10;
    println!("{input}");
}
```

Почему это работает: каждый `let` создаёт новую переменную, поэтому тип может измениться с текста на число. Вывод: `20`.

</details>

### Упражнение 5 — Напишите проверку (средне)

Напишите программу с переменными `width = 6` и `height = 4`. Вычислите `area`. С помощью `assert_eq!` проверьте, что `area` равна `24`, а `perimeter` (сумма всех четырёх сторон) равна `20`. Если обе проверки прошли, напечатайте `all checks passed`.

<details>
<summary>Подсказка</summary>

`area = width * height`, `perimeter = 2 * (width + height)`. Поставьте строки `assert_eq!` перед последним `println!`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let width = 6;
    let height = 4;
    let area = width * height;
    let perimeter = 2 * (width + height);
    assert_eq!(area, 24);
    assert_eq!(perimeter, 20);
    println!("all checks passed");
}
```

Почему это работает: оба утверждения истинны, поэтому программа доходит до `println!`. Измените число и запустите снова, чтобы увидеть сообщение о панике. Вывод: `all checks passed`.

</details>

## Вопросы для самопроверки

1. Что делает `let x = 5; x = 6;` и почему?

<details>
<summary>Ответ</summary>

Код не компилируется: ошибка `E0384 cannot assign twice to immutable variable`. Переменные по умолчанию неизменяемые. Нужно `let mut x = 5;`.

</details>

2. Чем отличается `let mut x = 1; x = 2;` от `let x = 1; let x = 2;`?

<details>
<summary>Ответ</summary>

Первый вариант меняет значение в одной переменной. Второй создаёт две разные переменные; вторая затеняет (скрывает) первую. При затенении новая переменная может даже иметь другой тип и снова неизменяема.

</details>

3. Назовите три отличия `const` от `let`.

<details>
<summary>Ответ</summary>

`const` никогда не может быть `mut`; тип для неё всегда пишете вы; её значение должно быть известно при компиляции; её можно объявлять вне функций; её имя пишется в `SCREAMING_SNAKE_CASE`. (Любые три.)

</details>

4. Где переменная перестаёт существовать?

<details>
<summary>Ответ</summary>

На закрывающей `}` блока, в котором она объявлена. После этого использование имени даёт `E0425 cannot find value`.

</details>

5. Какая команда без интернета показывает длинное объяснение кода ошибки `E0384`?

<details>
<summary>Ответ</summary>

`rustc --explain E0384`.

</details>

6. Почему компилятор предупредил о `let count = 3;`, но не о `let _ignored = 4;`?

<details>
<summary>Ответ</summary>

Переменная, которую нигде не используют, — вероятная ошибка, поэтому компилятор предупреждает. Имя, начинающееся с `_`, сообщает компилятору, что вы знаете: переменная не используется намеренно.

</details>

7. Почему мы добавляем `target/` в `.gitignore`?

<details>
<summary>Ответ</summary>

В `target/` лежит результат сборки. Она большая, её можно воссоздать командой `cargo build`, и она меняется при каждой сборке, так что только добавляла бы шум и размер в историю Git.

</details>

## Итоги

- Переменная — это имя значения в памяти. Создаётся так: `let name = value;`.
- Переменные по умолчанию неизменяемые. Используйте `let mut` только тогда, когда значение должно меняться.
- `mut` меняет значение, но никогда не тип.
- `const` определяет фиксированное значение с обязательным типом; имя пишется в `SCREAMING_SNAKE_CASE`.
- Затенение (повторный `let x = …`) создаёт новую переменную, в том числе другого типа.
- Имя живёт до конца своего блока `{ }`.
- Используйте `snake_case`, давайте именам смысл и серьёзно относитесь к предупреждениям.
- `cargo check`, `cargo fmt` и `cargo clippy` — ваши ежедневные помощники. Часто делайте коммиты в Git.
