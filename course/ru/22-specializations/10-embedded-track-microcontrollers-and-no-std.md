## Новые слова

| Слово | Значение |
|---|---|
| **встраиваемая система** (embedded system) | Компьютер, встроенный в устройство для одной задачи: контроллер стиральной машины, фитнес-браслет, датчик на заводе. |
| **MCU** (Microcontroller Unit, микроконтроллер) | Один маленький чип, в котором есть ядро CPU (Central Processing Unit, центральный процессор), флеш-память, RAM (Random Access Memory, оперативная память) и периферия. |
| **прошивка** (firmware) | Программа, которая работает на микроконтроллере. Хранится во флеш-памяти чипа. |
| **флеш-память** (flash memory) | Память, которая сохраняет содержимое без питания. В ней живёт прошивка. |
| **SRAM** (Static Random Access Memory, статическая оперативная память) | Быстрая рабочая память микроконтроллера. Без питания она очищается. |
| **периферийное устройство** (peripheral) | Аппаратный блок внутри чипа для одной задачи: выводы, таймеры, последовательные порты, аналого-цифровой преобразователь. |
| **регистр** (register, периферии) | Маленький участок памяти внутри периферийного устройства. Запись числа в него меняет поведение оборудования. |
| **GPIO** (General-Purpose Input/Output, ввод-вывод общего назначения) | Вывод (пин), который программа может включать, выключать или читать. Подробно — в Уроке 22.11. |
| **`no_std`** | Атрибут крейта: «не использовать стандартную библиотеку». Крейт может пользоваться только `core` (и `alloc`, если добавить аллокатор). |
| **`core`** | Часть стандартной библиотеки Rust, которой не нужна операционная система: `Option`, `Result`, итераторы, срезы, целочисленная арифметика, `fmt`. |
| **обработчик паники** (panic handler) | Функция, которая выполняется при панике в программе `no_std`. Она должна быть ровно одна. |
| **кросс-компиляция** (cross-compilation) | Сборка программы на одном компьютере (вашем Mac) для другого вида компьютера (микроконтроллера). |
| **тройка целевой платформы** (target triple) | Имя платформы, для которой собирает `rustc`, например `thumbv8m.main-none-eabihf`. |
| **Arm Cortex-M** | Семейство небольших процессорных ядер компании Arm для микроконтроллеров. |
| **скрипт компоновщика** (linker script) | Текстовый файл, который говорит компоновщику, где находятся флеш-память и RAM и куда положить каждую часть программы. |
| **таблица векторов** (vector table) | Таблица в начале флеш-памяти. Её первые записи сообщают процессору начальный адрес стека и адрес первой функции, которую надо выполнить. |
| **отладочный адаптер** (debug probe) | Небольшое устройство между компьютером и платой. Записывает прошивку во флеш-память и позволяет отлаживать. |
| **SWD** (Serial Wire Debug, последовательный отладочный интерфейс) | Двухпроводное подключение, через которое чипы Arm отлаживают и прошивают. |
| **ELF** (Executable and Linkable Format, формат исполняемых и компонуемых файлов) | Формат собранной прошивки до записи во флеш-память. |

## 1. Что такое микроконтроллер

У вашего Mac большой процессор, гигабайты RAM, диск и операционная система. Когда вы запускаете
программу, операционная система загружает её, выдаёт ей память и убирает за ней.

**Микроконтроллер** — это целый крошечный компьютер на одном чипе. В нём есть ядро процессора, немного
флеш-памяти для программы, немного SRAM для данных и много **периферийных устройств**: выводы, таймеры,
последовательные порты. **Операционной системы** обычно нет. Ваша программа — единственная на чипе.

| | Ваш Mac (M4) | Raspberry Pi Pico 2 (чип RP2350) |
|---|---|---|
| Процессор | 10+ ядер, около 4 ГГц | 2 небольших ядра, 150 МГц |
| Рабочая память | 16–24 ГБ | 520 КБ SRAM |
| Хранилище программ | диск на сотни ГБ | 4 МБ флеш-памяти |
| Операционная система | macOS | нет: чипом владеет ваша прошивка |
| Цена | дорого | около 5 долларов США |

Без операционной системы меняются три вещи:

1. **Никто не загружает вашу программу.** Чип запускает её прямо из флеш-памяти при подаче питания.
2. **Ваша программа никогда не заканчивается.** Возвращаться некуда. У `main` тип `fn() -> !`
   («никогда не возвращается»), и программа обычно завершается бесконечным циклом.
3. **Оборудование — это просто адреса памяти.** У регистра периферийного устройства фиксированный адрес.
   Чтобы включить вывод, программа записывает число по этому адресу. Это называется **ввод-вывод,
   отображённый в память** (memory-mapped I/O).

```text
Address space of the RP2350 (simplified)

0x1000_0000  +------------------+
             | flash (program)  |  <- your firmware lives here
0x2000_0000  +------------------+
             | SRAM (data)      |  <- stack and variables
0x4000_0000  +------------------+
             | peripherals      |  <- timers, serial ports, ...
0xd000_0000  +------------------+
             | SIO (fast GPIO)  |  <- write here to switch pins
             +------------------+
```

## 2. Почему Rust для встраиваемых систем

- **Нет среды выполнения и сборщика мусора.** Программе на Rust ничего не нужно от операционной системы.
  Выполняется ровно тот код, который вы написали, и расход памяти предсказуем.
- **Безопасность памяти на чипе без защиты.** Микроконтроллер обычно не может остановить плохой
  указатель: запись по неверному адресу молча ломает периферию или другие данные. Проверка заимствований
  (borrow checker) ловит большинство таких ошибок при компиляции.
- **Владение моделирует оборудование.** Вывод — это значение. Когда вы отдаёте `PIN_25` драйверу
  светодиода, он *перемещается*, и никакая другая часть программы не сможет по ошибке использовать тот же вывод.
- **Общие интерфейсы.** Крейт `embedded-hal` определяет трейты вроде «выходной вывод» и «задержка».
  Драйвер, написанный на этих трейтах, работает на любом чипе (Урок 22.11).
- **Современные инструменты.** Cargo собирает под чип, `probe-rs` прошивает и отлаживает его, а Embassy
  даёт `async`/`await` на «голом железе» (Урок 22.12).

## 3. Плата для этого направления: Raspberry Pi Pico 2

Это направление использует **Raspberry Pi Pico 2** — плату с чипом **RP2350**. Причины:

- **Дешёвая и легко купить.** Около 5 долларов США, продаётся у реселлеров Raspberry Pi в большинстве стран.
- **Очень хорошая поддержка Rust.** У проекта Embassy есть поддерживаемый HAL (Hardware Abstraction Layer,
  слой абстракции оборудования) для неё — `embassy-rp`, и `probe-rs` поддерживает этот чип.
- **Отличная официальная документация.** Даташит RP2350 понятно описывает каждый регистр.
- **Официальный недорогой отладочный адаптер.** Raspberry Pi Debug Probe (около 12 долларов США)
  подключается к Pico 2 одним кабелем. После этого прошивка и логи работают через `cargo run`.
- **Современное ядро Arm.** В RP2350 два ядра Arm Cortex-M33 (есть и два ядра RISC-V — открытого набора инструкций, но это
  направление их не использует; RISC — Reduced Instruction Set Computer, компьютер с сокращённым набором команд).

Список покупок для Уроков 22.11–22.13: Pico 2 («Pico 2 H» продаётся с уже припаянными штырьками),
Raspberry Pi Debug Probe, макетная плата, два светодиода, два резистора на 330 Ом, одна кнопка,
соединительные провода и кабель USB (Universal Serial Bus, универсальная последовательная шина).

> 💡 **Совет:** если у вас уже есть плата ESP32-C3, её хорошо поддерживает крейт `esp-hal`. Идеи этого
> направления те же, но имена крейтов, целевая платформа и номера выводов другие, поэтому детали
> смотрите в книге `esp-hal`.

## 4. Без стандартной библиотеки: `std`, `core` и `alloc`

Стандартная библиотека Rust состоит из трёх слоёв:

```text
+-------------------------------------------------------------+
| std   : files, threads, network, println!, time, HashMap    |  needs an OS
+-------------------------------------------------------------+
| alloc : Box, Vec, String, Rc                                |  needs a heap allocator
+-------------------------------------------------------------+
| core  : Option, Result, iterators, slices, &str, integers,  |  needs nothing
|         fmt, atomics, panic!                                |
+-------------------------------------------------------------+
```

`std` просит у операционной системы файлы, потоки и вывод, поэтому на «голом» чипе её быть не может.
Атрибут `#![no_std]` в начале крейта говорит: «компоновать только `core`». Вы сохраняете почти весь
язык: структуры, перечисления, трейты, обобщения, замыкания, итераторы, сопоставление с образцом.
Вы теряете `println!`, `Vec`, `String` и `HashMap` (`alloc` возвращает `Vec` и `String`, если добавить
аллокатор кучи, но большинство прошивок обходится без кучи).

Отличная привычка: держать **логику** в маленькой библиотеке `no_std` и тестировать её **на Mac**.
Тесты используют обычную тестовую обвязку, потому что `cargo test` собирает для Mac.

```bash
cd ~/projects/rust
cargo new --lib code/p22-sensor
cd code/p22-sensor
```

В RP2350 есть датчик температуры. Его 12-битное показание (от 0 до 4095 соответствует от 0 до 3,3 вольта)
переводится в градусы по формуле из даташита *T = 27 − (V − 0,706) / 0,001721*. Прошивки избегают
медленных вычислений с плавающей точкой в горячем коде, поэтому мы считаем в **миллиградусах** целыми
числами. Поместите это в `src/lib.rs`:

```rust
#![no_std]

/// Converts a raw 12-bit reading of the RP2350 temperature sensor
/// into thousandths of a degree Celsius (millidegrees).
pub fn temperature_millicelsius(raw: u16) -> i32 {
    // 12 bits: 0..=4095 stands for 0..=3300 millivolts.
    let microvolts = (raw as i64 * 3_300_000 / 4095) as i32;
    // Datasheet formula: T = 27 - (V - 0.706) / 0.001721
    27_000 - (microvolts - 706_000) * 1000 / 1721
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn about_27_degrees_at_706_millivolts() {
        // 706 mV is about 876 on the 12-bit scale.
        let t = temperature_millicelsius(876);
        assert!((26_000..28_000).contains(&t), "got {t}");
    }

    #[test]
    fn warmer_chip_gives_lower_voltage() {
        assert!(temperature_millicelsius(850) > temperature_millicelsius(876));
    }
}
```

**Что происходит:**

1. `#![no_std]` (с `!`, поэтому действует на весь крейт) убирает `std`. `assert!`, диапазоны и
   целочисленная арифметика приходят из `core`, поэтому код по-прежнему компилируется.
2. Умножение специально делается в `i64` (в 32 битах оно переполняется, см. «Частые ошибки»).
   Работа в микровольтах и миллиградусах позволяет обойтись целыми числами.
3. `cargo test` компилирует библиотеку для Mac и подключает тестовую обвязку, поэтому тесты запускаются здесь.

```text
running 2 tests
test tests::about_27_degrees_at_706_millivolts ... ok
test tests::warmer_chip_gives_lower_voltage ... ok

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

> 🧪 **Тестирование:** большинство ошибок в прошивках — логические: неверные формулы, неверные смены
> состояний, ошибки на единицу в таймингах. Держите эту логику в функциях `no_std` без аппаратных типов и
> тестируйте её на Mac за миллисекунды. Плата нужна только тонкому слою, который трогает выводы.

## 5. Программа для чипа: `no_main` и обработчик паники

Посмотрим, что скажет компилятор, если собрать обычную программу для чипа. Сначала установите
**целевую платформу** (target) — части стандартной библиотеки для этого вида процессора. Имя объясняется в разделе 6.

```bash
rustup target add thumbv8m.main-none-eabihf
```

```text
info: downloading component rust-std
```

Теперь свежий проект из `cargo new`, собранный для микроконтроллера:

```bash
cd ~/projects/rust
cargo new code/p22-std-on-mcu
cd code/p22-std-on-mcu
cargo build --target thumbv8m.main-none-eabihf
```

```text
error[E0463]: can't find crate for `std`
  |
  = note: the `thumbv8m.main-none-eabihf` target may not support the standard library
  = note: `std` is required by `p22_std_on_mcu` because it does not declare `#![no_std]`

error: cannot resolve a prelude import

error: cannot find macro `println` in this scope
 --> src/main.rs:2:5
  |
2 |     println!("Hello, world!");
  |     ^^^^^^^

error: `#[panic_handler]` function required, but not found

For more information about this error, try `rustc --explain E0463`.
```

Компилятор сообщает три вещи: для этой платформы нет `std`, поэтому нет `println!`, и нужен
**обработчик паники**. На обычном компьютере панику обрабатывает `std`: печатает сообщение и останавливает
поток. Без `std` вы сами решаете, что делает паника. Замените `src/main.rs`:

```rust
#![no_std]
#![no_main]

use core::panic::PanicInfo;

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}
}
```

**Что происходит:**

1. `#![no_main]` говорит «обычного `main` нет». Обычный `main` вызывает стартовый код из `std` и
   операционной системы; на чипе программу должно запустить что-то другое.
2. `#[panic_handler]` отмечает единственную функцию, которая выполняется при панике. Она получает
   `PanicInfo` (сообщение и место) и никогда не должна возвращаться, поэтому её тип `-> !`. Здесь она
   просто бесконечно крутится в цикле.
3. Программа собирается, но компоновщик предупреждает, что не знает, откуда программа начинается:

```text
warning: linker stderr: rust-lld: cannot find entry symbol _start; not setting start address
  |
  = note: `#[warn(linker_messages)]` on by default

warning: `p22-std-on-mcu` (bin "p22-std-on-mcu") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.27s
```

Это последний недостающий кусок — стартовый код. На RP2350 самым первым выполняется
**загрузочное ПЗУ** (boot ROM; ROM — Read-Only Memory, постоянное запоминающее устройство) — маленькая
программа, встроенная в чип на заводе; затем оно передаёт управление вашей программе. Когда на чип Arm Cortex-M подают питание, он читает
**таблицу векторов** в начале программы: запись 0 — начальный указатель стека, запись 1 — адрес
**обработчика сброса** (reset handler), первой функции, которая выполняется. Крейт `cortex-m-rt`
(runtime, среда выполнения) предоставляет таблицу векторов и обработчик сброса, который готовит RAM и
затем вызывает вашу функцию с пометкой `#[entry]`.

```text
power on
   |
   v
boot ROM inside the RP2350 ---- finds the IMAGE_DEF block in the first 4 KiB of flash
   |
   v
vector table (cortex-m-rt) ---- stack pointer = end of RAM, reset handler address
   |
   v
reset handler (cortex-m-rt) --- copies initial values of statics into RAM, zeroes the rest
   |
   v
your #[entry] fn main() -> !  - runs forever
```

Теперь `code/p22-std-on-mcu` можно удалить; настоящая прошивка — дальше.

## 6. Кросс-компиляция: тройка платформы, настройки и карта памяти

Имя платформы `thumbv8m.main-none-eabihf` описывает её по частям:

| Часть | Значение |
|---|---|
| `thumbv8m.main` | Набор инструкций Arm «Thumb», версия 8-M Mainline: ядро Cortex-M33 в RP2350. |
| `none` | Нет операционной системы. |
| `eabihf` | EABI (Embedded Application Binary Interface, двоичный интерфейс встраиваемых приложений: правила вызова функций и раскладки данных) с **h**ard **f**loat: в чипе есть блок вычислений с плавающей точкой. |

Каждый раз писать `--target` утомительно, поэтому в проекте прошивки есть три дополнительных файла:

```text
code/p22-hello-led/
├── .cargo/
│   └── config.toml   ← платформа по умолчанию и способ запуска прошивки
├── build.rs          ← копирует memory.x для компоновщика
├── memory.x          ← где находятся флеш-память и RAM
├── Cargo.toml
└── src/
    └── main.rs
```

Создайте пакет и папку:

```bash
cd ~/projects/rust
cargo new code/p22-hello-led
cd code/p22-hello-led
mkdir .cargo
```

`.cargo/config.toml`:

```toml
[build]
target = "thumbv8m.main-none-eabihf"

[target."thumbv8m.main-none-eabihf"]
runner = "probe-rs run --chip RP235x"
```

`[build] target` заставляет каждую команду `cargo build` собирать для чипа. `runner` — команда, которую
`cargo run` использует вместо запуска программы на Mac: она передаёт собранный файл в `probe-rs`, а тот
записывает его в чип (раздел 8). Кавычки вокруг имени платформы важны: в имени есть точка, и без кавычек
TOML (формат конфигурационных файлов Cargo) читает его как два вложенных ключа (Cargo предупреждает, что такой ключ «will be ignored or error
in a future version»).

`memory.x` — фрагмент **скрипта компоновщика**. Скрипт `link.x` из `cortex-m-rt` подключает его, чтобы
узнать карту памяти:

```text
MEMORY {
    FLASH : ORIGIN = 0x10000000, LENGTH = 4096K
    RAM   : ORIGIN = 0x20000000, LENGTH = 512K
}

SECTIONS {
    /* The RP2350 boot ROM looks for this block in the first 4 KiB of flash. */
    .start_block : ALIGN(4)
    {
        KEEP(*(.start_block));
    } > FLASH
} INSERT AFTER .vector_table;

/* Program code starts after the boot block. */
_stext = ALIGN(ADDR(.start_block) + SIZEOF(.start_block), ALIGNOF(.text));
```

**Что происходит:**

1. `MEMORY` называет две области: 4 МиБ флеш-памяти по адресу `0x1000_0000` и 512 КиБ SRAM по адресу
   `0x2000_0000` (числа взяты из даташита RP2350).
2. `.start_block` размещается сразу после таблицы векторов. `embassy-rp` кладёт туда небольшой блок
   `IMAGE_DEF`; без него загрузочное ПЗУ отказывается запускать программу.
3. `_stext` сдвигает код программы за этот блок. Примеры Embassy для RP2350 используют более длинную
   версию этого файла с необязательными секциями для утилиты Raspberry Pi `picotool`; для этого
   направления короткая версия даёт точно такой же образ флеш-памяти.

`build.rs` (**скрипт сборки**, build script: Cargo компилирует и запускает его перед сборкой вашего
крейта) копирует `memory.x` туда, где его ищет компоновщик, и передаёт скрипт компоновщика:

```rust
use std::env;
use std::fs;
use std::path::PathBuf;

fn main() {
    // Copy memory.x next to the build output so the linker finds it.
    let out = PathBuf::from(env::var_os("OUT_DIR").unwrap());
    fs::write(out.join("memory.x"), include_bytes!("memory.x")).unwrap();
    println!("cargo:rustc-link-search={}", out.display());
    println!("cargo:rerun-if-changed=memory.x");

    // Ask the linker to use the linker script from cortex-m-rt.
    println!("cargo:rustc-link-arg-bins=--nmagic");
    println!("cargo:rustc-link-arg-bins=-Tlink.x");
}
```

Скрипт сборки выполняется **на вашем Mac**, поэтому в нём можно использовать `std` и `println!`. Его
строки `println!` — это инструкции для Cargo, а не вывод для вас.

## 7. Первая прошивка: включаем светодиод

`Cargo.toml`:

```toml
[package]
name = "p22-hello-led"
version = "0.1.0"
edition = "2024"

[dependencies]
cortex-m = "0.7"
cortex-m-rt = "0.7"
embassy-rp = { version = "0.10", features = ["rp235xa", "critical-section-impl"] }

[profile.release]
debug = true
```

`embassy-rp` — это HAL для чипов RP2040 и RP2350. Фича `rp235xa` выбирает чип RP2350A на Pico 2, а
`critical-section-impl` даёт маленький примитив блокировки, который нужен HAL. `debug = true` сохраняет
отладочную информацию в релизных сборках; во флеш-память она не записывается и помогает только отладчику.

`src/main.rs`:

```rust
#![no_std]
#![no_main]

use core::panic::PanicInfo;
use cortex_m_rt::entry;
use embassy_rp::gpio::{Level, Output};

#[entry]
fn main() -> ! {
    // Take ownership of all peripherals of the chip.
    let p = embassy_rp::init(Default::default());
    // GPIO 25 is wired to the green LED on the Pico 2 board.
    let _led = Output::new(p.PIN_25, Level::High);

    loop {
        // Nothing else to do: keep the LED on forever.
        cortex_m::asm::wfi();
    }
}

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}
}
```

**Что происходит:**

1. `#[entry]` из `cortex-m-rt` делает `main` функцией, которую вызывает обработчик сброса. Её тип
   должен быть `fn() -> !`.
2. `embassy_rp::init` настраивает тактирование и возвращает структуру `p` с полем для каждого
   периферийного устройства: `p.PIN_0` … `p.PIN_29`, таймеры и так далее. Вы получаете её ровно один раз.
3. `Output::new(p.PIN_25, Level::High)` *перемещает* вывод 25 в драйвер выхода и ставит высокий уровень
   (3,3 вольта), и светодиод загорается. Имя `_led` сохраняет драйвер живым без предупреждения
   «unused variable»; если бы драйвер был уничтожен (drop), вывод сбросился бы.
4. `cortex_m::asm::wfi()` («wait for interrupt», ждать прерывания) усыпляет ядро, пока что-нибудь не
   произойдёт. Это экономит энергию по сравнению с пустым циклом.

```bash
cargo build --release
```

```text
   ...
   Compiling embassy-rp v0.10.0
   Compiling p22-hello-led v0.1.0 (/Users/you/projects/rust/code/p22-hello-led)
    Finished `release` profile [optimized + debuginfo] target(s) in 50.33s
warning: the following packages contain code that will be rejected by a future version of Rust: proc-macro-error2 v2.0.1
```

Предупреждение касается зависимости одной из зависимостей, а не вашего кода; его можно не замечать.
Результат — 32-битный ELF-файл для Arm, `target/thumbv8m.main-none-eabihf/release/p22-hello-led`.
Чтобы увидеть, сколько флеш-памяти и RAM на самом деле занимает прошивка, один раз установите `cargo-binutils`:

```bash
rustup component add llvm-tools
cargo install --locked cargo-binutils
cargo size --release
```

```text
   text	   data	    bss	    dec	    hex	filename
   7104	      0	    284	   7388	   1cdc	p22-hello-led
```

`text` — код и константы (во флеш-памяти), `data` — начальные значения статических переменных (во
флеш-памяти *и* в RAM), `bss` — статические переменные, которые начинаются с нуля (в RAM). Около 7 КБ из
4 МиБ: места ещё очень много. `cargo size --release -- -A` показывает каждую секцию с её адресом (сокращено):

```text
section               size        addr
.vector_table          276  0x10000000
.start_block            20  0x10000114
.text                 4904  0x10000128
.rodata               1904  0x10001450
.bss                   284  0x20000000
.debug_info         673245         0x0
```

Таблица векторов стоит в самом начале флеш-памяти (`0x1000_0000`), за ней загрузочный блок, потом код.
У секций `.debug_*` адрес 0: они остаются на вашем Mac и никогда не записываются во флеш-память.

> ⚡ **Производительность:** всегда измеряйте размер прошивки в режиме **release**. Отладочная сборка той
> же программы во много раз больше и медленнее, а на маленьком чипе может даже не поместиться.

## 8. Как прошивка попадает на плату

Для этого раздела нужно оборудование. Если его нет, просто прочитайте; следующие уроки работают так же.

**С Debug Probe (рекомендуется).** Подключите кабель «D» адаптера к трёхконтактному разъёму DEBUG на
Pico 2 (SWCLK — тактовый сигнал, GND — земля, SWDIO — данные; это и есть SWD), подключите оба устройства к USB и один раз установите
инструмент прошивки:

```bash
cargo install --locked probe-rs-tools
probe-rs list
```

Когда ничего не подключено, `probe-rs list` печатает:

```text
No debug probes were found.
```

С подключённым адаптером он покажет ваш Debug Probe. Теперь `cargo run` собирает
прошивку и вызывает `runner` из `.cargo/config.toml`:

```bash
cargo run --release
```

Без адаптера сборка проходит, а `runner` останавливается с сообщением `Error: No connected probes were found.`
С подключённой платой вывод выглядит так (пример; у вас будет похожий):

```text
    Finished `release` profile [optimized + debuginfo] target(s) in 0.05s
     Running `probe-rs run --chip RP235x target/thumbv8m.main-none-eabihf/release/p22-hello-led`
      Erasing ✔ 100% [####################]   8.00 KiB @  57.23 KiB/s (took 0s)
  Programming ✔ 100% [####################]   8.00 KiB @  38.42 KiB/s (took 0s)
     Finished in 0.71s
```

Зелёный светодиод горит. `probe-rs run` продолжает работать и показывал бы сообщения логов (Урок 22.12);
остановите его клавишами Ctrl+C. Прошивка остаётся во флеш-памяти и запускается снова при каждом включении.

**Без адаптера.** Удерживайте кнопку BOOTSEL (boot select, выбор режима загрузки), пока подключаете USB. Pico 2 появится как USB-накопитель, и
утилита Raspberry Pi `picotool` (`picotool load -u -v -x -t elf <file>`) запишет на неё ELF-файл. Это
работает, но без логов и без отладчика, поэтому направление использует адаптер.

> 🔒 **Безопасность:** прошивку из флеш-памяти обычно может прочитать любой, у кого есть отладочный
> адаптер. Никогда не кладите секреты вроде паролей Wi-Fi или ключей API (Application Programming Interface, программный интерфейс) в прошивку устройства, которое
> вы кому-то отдаёте, если не настроены функции безопасной загрузки и блокировки чипа (в RP2350 они есть).

## Частые ошибки

> ⚠️ **Частая ошибка: переполнение целых чисел в расчётах датчика.** Первая версия
> `temperature_millicelsius` использовала `raw as i32 * 3_300_000`. Для `raw = 876` это около
> 2,9 миллиарда, больше, чем `i32::MAX` (около 2,1 миллиарда). Тесты на Mac поймали это в отладочном режиме:
>
> ```text
> thread 'tests::about_27_degrees_at_706_millivolts' (5817275) panicked at src/lib.rs:7:22:
> attempt to multiply with overflow
> ```
>
> В релизной сборке на чипе число молча «перевернулось» бы и дало неверную температуру. Исправление:
> умножать в `i64` или делить раньше. Это ещё одна причина тестировать логику на хосте.

> ⚠️ **Частая ошибка: нет `memory.x`.** Если `memory.x` отсутствует (или `build.rs` его не копирует),
> компоновщик останавливается:
>
> ```text
>   = note: rust-lld: error: .../cortex-m-rt/.../out/link.x:23: cannot find linker script memory.x
>           >>> INCLUDE memory.x
> ```
>
> Исправление: положите `memory.x` в корень пакета и используйте `build.rs` из раздела 6.

> ⚠️ **Частая ошибка: платформа не установлена.** Сборка до `rustup target add` даёт:
>
> ```text
> error[E0463]: can't find crate for `core`
>   |
>   = note: the `thumbv8m.main-none-eabihf` target may not be installed
>   = help: consider downloading the target with `rustup target add thumbv8m.main-none-eabihf`
> ```
>
> Исправление: выполните команду из строки `help`.

## Упражнения

### Упражнение 1 — Прочитайте тройку (легко)

Объясните каждую часть имени платформы `thumbv6m-none-eabi` (её использует более старый чип RP2040).
Чем она отличается от `thumbv8m.main-none-eabihf`?

<details>
<summary>Подсказка</summary>

Сравните части по очереди с таблицей из раздела 6. Что означает отсутствие `hf`?

</details>

<details>
<summary>Ответ</summary>

`thumbv6m` — набор инструкций Thumb архитектуры Armv6-M (ядро Cortex-M0+ в RP2040), `none` — нет
операционной системы, `eabi` — встраиваемый ABI. `hf` нет: у Cortex-M0+ нет блока вычислений с
плавающей точкой, поэтому такие вычисления выполняются программно. В RP2350 более новые ядра
Armv8-M Mainline и аппаратный блок плавающей точки, отсюда `thumbv8m.main` и `eabihf`.

</details>

### Упражнение 2 — Протестированное преобразование (средне)

В `code/p22-sensor` напишите `pub fn millivolts(raw: u16) -> u32`, которая переводит 12-битное показание
в милливольты (0 → 0, 4095 → 3300) без переполнения, и **напишите тесты** для 0, 4095 и 2048. Крейт
должен остаться `#![no_std]`.

<details>
<summary>Подсказка</summary>

Сначала умножьте, потом разделите, в достаточно большом типе: 4095 × 3300 = 13 513 500 помещается в `u32`.

</details>

<details>
<summary>Ответ</summary>

```rust
pub fn millivolts(raw: u16) -> u32 {
    raw as u32 * 3300 / 4095
}

#[cfg(test)]
mod millivolt_tests {
    use super::*;

    #[test]
    fn edges_and_middle() {
        assert_eq!(millivolts(0), 0);
        assert_eq!(millivolts(4095), 3300);
        assert_eq!(millivolts(2048), 1650);
    }
}
```

Почему это работает: `u32` вмещает примерно до 4,29 миллиарда, а самое большое произведение — 13,5 миллиона.
Целочисленное деление округляет вниз, поэтому 2048 × 3300 / 4095 = 1650,4… превращается в 1650.

</details>

### Упражнение 3 — Что делает паника? (сложно)

В `code/p22-hello-led` паника сейчас бесконечно крутится в цикле, а светодиод остаётся в том состоянии,
в котором был. Измените обработчик паники так, чтобы вместо цикла он вызывал `cortex_m::asm::udf()`.
Объясните, что делает `udf` и почему отладчик показывает это лучше, чем бесконечный цикл.
Соберите командой `cargo build --release`.

<details>
<summary>Подсказка</summary>

`udf` означает «permanently undefined instruction» — «навсегда неопределённая инструкция». Что делает
процессор, когда встречает инструкцию, которой не существует?

</details>

<details>
<summary>Ответ</summary>

```rust
#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    cortex_m::asm::udf()
}
```

`udf` выполняет неопределённую инструкцию, и процессор поднимает отказ (исключение `HardFault`).
Отладчик вроде `probe-rs` останавливается там и показывает, что что-то пошло не так, а бесконечный цикл
выглядит в точности как работающая программа, которая просто занята. В Уроке 22.12 используется
`panic-probe` — готовый обработчик, который ещё и печатает сообщение паники через адаптер.

</details>

## Вопросы для самопроверки

1. Назовите три вещи, которых нет у программы на микроконтроллере по сравнению с программой на macOS.

<details>
<summary>Ответ</summary>

Нет операционной системы (никто не загружает программу, не выдаёт память и не убирает за ней), нет `std`
(нет файлов, потоков, `println!`) и очень мало памяти (сотни килобайт RAM). А ещё она никогда не
возвращается из `main`.

</details>

2. Чем `core` отличается от `std`?

<details>
<summary>Ответ</summary>

`core` — часть стандартной библиотеки, которой ничего не нужно от операционной системы: типы, трейты,
итераторы, целочисленная арифметика, форматирование. `std` добавляет то, что требует операционной
системы: файлы, потоки, сеть, печать. Крейты `no_std` используют только `core` (и, возможно, `alloc`).

</details>

3. Почему у обработчика паники и у `main` тип возврата `!`?

<details>
<summary>Ответ</summary>

Возвращаться некуда: нет ни операционной системы, ни вызывающего кода. `!` («никогда») говорит
компилятору, что функция никогда не возвращается, например потому что крутится в бесконечном цикле или
останавливает процессор.

</details>

4. Что делают `memory.x` и `build.rs` в проекте прошивки?

<details>
<summary>Ответ</summary>

`memory.x` говорит компоновщику, где находятся флеш-память и RAM (а для RP2350 — куда класть загрузочный
блок). `build.rs` выполняется на Mac перед сборкой, копирует `memory.x` туда, где его найдёт компоновщик,
и передаёт скрипт компоновщика `link.x` из `cortex-m-rt`.

</details>

5. Что строка `let _led = Output::new(p.PIN_25, Level::High);` делает с владением?

<details>
<summary>Ответ</summary>

Она перемещает `PIN_25` из структуры периферии в драйвер `Output`. После этого никакой другой код не
сможет случайно использовать вывод 25. Переменная сохраняет драйвер живым всё время работы программы.

</details>

## Итоги

- Микроконтроллер — целый маленький компьютер на одном чипе: ядро процессора, флеш-память, SRAM и
  периферия, обычно без операционной системы.
- Прошивка запускается из флеш-памяти при включении, никогда не возвращается и управляет оборудованием,
  записывая значения в регистры, отображённые в память.
- `#![no_std]` компонует только `core`; `#![no_main]` убирает обычный `main`; `#[panic_handler]` решает,
  что делает паника; `cortex-m-rt` даёт таблицу векторов и `#[entry]`.
- Для кросс-компиляции нужны целевая платформа (`rustup target add thumbv8m.main-none-eabihf`),
  платформа по умолчанию в `.cargo/config.toml` и карта памяти в `memory.x`.
- Держите логику в маленьких библиотеках `no_std` и тестируйте её на Mac; плата нужна только аппаратному слою.
- `probe-rs` с отладочным адаптером записывает прошивку через `cargo run`.

## Источники и что почитать

- [The Embedded Rust Book](https://docs.rust-embedded.org/book/) — официальное введение во встраиваемый Rust, включая `no_std` и процесс запуска.
- [The Embedonomicon](https://docs.rust-embedded.org/embedonomicon/) — как с нуля устроены `cortex-m-rt`, таблица векторов и скрипты компоновщика.
- [Raspberry Pi Pico 2 datasheet](https://datasheets.raspberrypi.com/pico/pico-2-datasheet.pdf) — плата, её выводы и светодиод.
- [RP2350 datasheet](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf) — чип: карта памяти, загрузочное ПЗУ, формула датчика температуры.
- [`embassy-rp` на docs.rs](https://docs.rs/embassy-rp/0.10.0/embassy_rp/) — HAL, который используется в этом направлении.
- [rustc platform support: thumbv8m.main-none-eabihf](https://doc.rust-lang.org/rustc/platform-support/thumbv8m.main-none-eabi.html) — что поддерживает эта платформа.
- [probe-rs](https://probe.rs/) — установка и использование инструмента прошивки и отладки.
