## Новые слова

| Слово | Значение |
|---|---|
| **`NULL`** | Метка SQL для «нет значения» или «неизвестно». В CSV-файле — пустое поле. |
| **трёхзначная логика** (three-valued logic) | Логика SQL с тремя результатами: истина, ложь и неизвестно (`NULL`). `NULL = 1` — неизвестно, а не ложь. |
| **вывод схемы** (schema inference) | Угадывание типа каждого столбца по его значениям. |
| **приведение типов** (type coercion) | Преобразование значения в другой тип, чтобы два значения можно было сравнить, например `Int 7` в `Float 7.0`. |
| **порядок `NULL`** (null ordering) | Правило, которое говорит, куда попадает `NULL` при сортировке: в начало или в конец. |

## 1. `NULL` в пяти правилах

В реальных данных бывают дыры: человек, возраст которого неизвестен. SQL отмечает их через `NULL`, и `NULL`
— не такое значение, как остальные. Оно означает «неизвестно», поэтому большинство операций с ним тоже
дают «неизвестно»:

| Выражение | Результат | Почему |
|---|---|---|
| `NULL = 30`, `NULL < 30`, `NULL = NULL` | `NULL` | сравнение с неизвестным даёт неизвестное |
| `age IS NULL` | `true` или `false` | единственный безопасный способ проверить на `NULL` |
| `NOT NULL` | `NULL` | противоположность неизвестного — всё ещё неизвестное |
| `false AND NULL` / `true OR NULL` | `false` / `true` | результат известен, каким бы ни было неизвестное |
| `true AND NULL` / `false OR NULL` | `NULL` | результат зависит от неизвестного |

Условие `WHERE` оставляет строку, **только если** условие равно `true`; и `false`, и `NULL` её отбрасывают.
Для агрегатов: `COUNT(*)` считает строки, `COUNT(col)` считает значения, не равные `NULL`, а `SUM`, `AVG`,
`MIN`, `MAX` пропускают `NULL`; по пустому набору значений они возвращают `NULL`.

> ⚠️ **Частая ошибка:** `WHERE age <> 30` **не** возвращает строки, где `age` равен `NULL`. «Неизвестное не
> равно 30» — это неизвестно. Если они нужны, пишите `WHERE age <> 30 OR age IS NULL`.

## Проект

### Что вы создадите

`p22-minisql` — инструмент командной строки, который выполняет один SQL-запрос над одним CSV-файлом
(Comma-Separated Values, значения, разделённые запятыми) и печатает результат в формате CSV. Это небольшой,
но честный движок запросов: фронтенд-парсер, план, типизированные столбцы с `NULL`, фильтр, проекция,
хеш-агрегация, сортировка и ограничение, протестированные против Apache DataFusion.

```text
$ minisql people.csv "SELECT city, COUNT(*) AS n FROM people GROUP BY city ORDER BY city"
city,n
Lisbon,3
Oslo,3
Tartu,2
```

Используйте этот файл как `people.csv` в папке проекта (возраст Hana и оценка Dana пустые, то есть `NULL`):

```text
name,age,city,score
Ana,34,Lisbon,7.5
Ben,27,Oslo,6.0
Chen,41,Lisbon,8.25
Dana,19,Oslo,
Eli,52,Tartu,9.0
Fay,30,Oslo,5.5
Gus,45,Tartu,7.0
Hana,,Lisbon,6.5
```

### Контракт

**Командная строка** (используйте `clap`):

```text
minisql <FILE.csv> "<SQL>"      run one query, print the result as CSV to stdout
minisql --schema <FILE.csv>     print one line "<column>: <type>" per column, then "<N> rows"
```

- Имя таблицы во `FROM` должно совпадать с именем файла без `.csv` (`people` для `people.csv`). Иначе:
  `error: unknown table `<name>``.
- Каждая ошибка печатается в stderr как `error: <message>`, код возврата — 1. Успех завершается с кодом 0.

**Типы и значения:**

- Типы столбцов выводятся по столбцу: `Int` (`i64`), если каждое непустое поле разбирается как `i64`;
  иначе `Float` (`f64`), если каждое непустое поле разбирается как `f64`; иначе `Text`. Пустое поле — `NULL`.
- `Int` и `Float` сравниваются между собой численно (`score > 7`); `Text` сравнивается только с `Text`.
  Любое другое сравнение — `error: type mismatch: …`.
- Вывод: одна строка заголовка, затем по строке на запись; значения разделены `,`; `NULL` печатается как
  пустое поле; числа с плавающей точкой печатаются в формате Rust `{:?}` (`6.0`, `8.25`,
  `25.333333333333332`). Текст с запятой или кавычкой берётся в кавычки по правилам CSV (используйте
  writer крейта `csv`).

**Подмножество SQL:**

| Часть | Поддерживается |
|---|---|
| `SELECT` | `*`, столбцы, `COUNT(*)`, `COUNT(col)`, `SUM`, `AVG`, `MIN`, `MAX` от столбца, каждый с необязательным `AS alias` |
| `FROM` | ровно одна таблица, без соединений и подзапросов |
| `WHERE` | `= <> < <= > >=`, `AND`, `OR`, `NOT`, скобки, `IS NULL`, `IS NOT NULL`, целые, дробные и `'текстовые'` литералы |
| `GROUP BY` | один или несколько столбцов |
| `ORDER BY` | один или несколько выходных столбцов, каждый `ASC` (по умолчанию) или `DESC`; `NULL` больше любого значения, поэтому при `ASC` идёт последним, а при `DESC` — первым |
| `LIMIT` | неотрицательное целое число |

Имена выходных столбцов: псевдоним, если он задан; иначе имя столбца или `count`, `sum_<col>`,
`avg_<col>`, `min_<col>`, `max_<col>` (`count_<col>` для `COUNT(col)`). Семантика агрегатов — как в
разделе 1. `AVG` всегда `Float`; `SUM` сохраняет тип столбца. Агрегатный запрос без `GROUP BY` возвращает
ровно одну строку. Всё остальное — `error: not supported: …`.

### Пошаговый план

#### M1 — Командная строка, CSV и вывод схемы

Создайте проект, добавьте `clap` (с фичей `derive`), `csv`, `sqlparser` и крейт для ошибок. Напишите
`read_table(path) -> Result<Table, …>` по правилам вывода типов выше и команду `--schema`. Логику
держите в `src/lib.rs` (и модулях), `src/main.rs` — маленьким.

<details>
<summary>Подсказка</summary>

Сначала прочитайте все записи (`Vec<csv::StringRecord>`), затем вторым проходом по строкам определите тип
каждого столбца, потом преобразуйте. Столбец только из пустых полей может быть `Text`. Храните значения
перечислением с вариантом `Null`: `enum Value { Null, Int(i64), Float(f64), Text(String) }`.

</details>

**Готово, когда:**

```bash
cargo run -q -- --schema people.csv
```

```text
name: Text
age: Int
city: Text
score: Float
8 rows
```

Модульные тесты покрывают три типа, пустое поле и столбец, в котором смешаны `1` и `1.5` (он должен быть
`Float`). Коммит: `M1: CSV and schema inference`.

#### M2 — План

Расширьте преобразователь из Урока 22.15 на всё подмножество: `*`, псевдонимы, все агрегаты, `NOT`,
`IS NULL`, дробные литералы, `ORDER BY` и `LIMIT`. Здесь же разверните `*` в столбцы таблицы и проверьте
имя таблицы.

<details>
<summary>Подсказка</summary>

В `sqlparser` 0.64: псевдоним — это `SelectItem::ExprWithAlias { expr, alias }`; `*` —
`SelectItem::Wildcard(_)`; `NOT x` — `Expr::UnaryOp { op: UnaryOperator::Not, expr }`; `x IS NULL` —
`Expr::IsNull(expr)`. `query.order_by` — это `Option<OrderBy>`, а `OrderBy.kind` —
`OrderByKind::Expressions(Vec<OrderByExpr>)`; у каждого `OrderByExpr` есть `expr` и
`options.sort: Option<OrderBySort>` (`Asc` или `Desc`). Число с `.` становится дробным литералом.

</details>

**Готово, когда:** `cargo test` проходит с тестами минимум на десять принимаемых и пять отклоняемых запросов, и:

```bash
cargo run -q -- people.csv "SELECT name FROM people JOIN pets ON people.name = pets.owner"
echo "exit code: $?"
```

```text
error: not supported: JOIN
exit code: 1
```

Коммит: `M2: plan`.

#### M3 — Фильтр и проекция с `NULL`

Напишите вычислитель с трёхзначной логикой: сравнения возвращают `Value::Null`, когда одна из сторон —
`NULL`; `AND`, `OR` и `NOT` следуют таблице из раздела 1; `IS NULL` никогда не возвращает `NULL`. Фильтр
оставляет только строки, чьё условие равно `true`. Проекция сохраняет исходный порядок строк.

<details>
<summary>Подсказка</summary>

Внутри вычислителя представляйте результат условия как `Option<bool>` (`None` — неизвестно). Тогда `AND` —
это маленький `match` по `(Option<bool>, Option<bool>)`: `(Some(false), _) | (_, Some(false)) => Some(false)`,
`(Some(true), Some(true)) => Some(true)`, всё остальное — `None`.

</details>

**Готово, когда** эти три команды печатают ровно:

```bash
cargo run -q -- people.csv "SELECT name, age FROM people WHERE age >= 30 AND city <> 'Oslo'"
cargo run -q -- people.csv "SELECT name FROM people WHERE age < 30"
cargo run -q -- people.csv "SELECT name, score FROM people WHERE score > 7"
```

```text
name,age
Ana,34
Chen,41
Eli,52
Gus,45
name
Ben
Dana
name,score
Ana,7.5
Chen,8.25
Eli,9.0
```

Заметьте, что Hana (возраст `NULL`) нет ни в одном из первых двух результатов и что `score > 7` сравнивает
столбец `Float` с литералом `Int`. Коммит: `M3: filter and projection`.

#### M4 — Агрегаты, ORDER BY и LIMIT

Реализуйте пять агрегатов с правилами `NULL`, `GROUP BY`, `ORDER BY` с порядком `NULL` из контракта и
`LIMIT`. Сортировка выполняется после агрегации и проекции, а `LIMIT` — последним.

<details>
<summary>Подсказка</summary>

Дайте каждому агрегату структуру-аккумулятор, например `Avg { sum: f64, count: i64 }`, с методами
`update(&Value)` и `finish() -> Value`. Для сортировки напишите одну функцию
`fn compare(a: &Value, b: &Value) -> Ordering`, которая ставит `Null` после всего, и используйте `sort_by`
с замыканием, которое проходит по ключам `ORDER BY` и переворачивает результат для `DESC`. `sort_by`
стабилен, и это сохраняет вывод предсказуемым.

</details>

**Готово, когда:**

```bash
cargo run -q -- people.csv "SELECT city, COUNT(*) AS n, COUNT(age) AS with_age, AVG(age) AS avg_age, MAX(score) AS best FROM people GROUP BY city ORDER BY city"
cargo run -q -- people.csv "SELECT name, score FROM people ORDER BY score DESC LIMIT 3"
cargo run -q -- people.csv "SELECT COUNT(*) AS n, SUM(age) AS total, MIN(name) AS first FROM people WHERE city = 'Paris'"
```

```text
city,n,with_age,avg_age,best
Lisbon,3,2,37.5,8.25
Oslo,3,3,25.333333333333332,6.0
Tartu,2,2,48.5,9.0
name,score
Dana,
Eli,9.0
Chen,8.25
n,total,first
0,,
```

Dana идёт первой во втором результате, потому что её оценка — `NULL`, а `NULL` сортируется как самое большое
значение. Третий запрос не находит ни одной строки, но всё равно возвращает одну строку. Коммит:
`M4: aggregates, ORDER BY, LIMIT`.

### Дополнительные цели

- **Столбцовый движок:** храните каждый столбец как типизированный `Vec` (или массив Arrow) и фильтруйте
  масками, как в Уроке 22.16. Сравните бенчмарк до и после.
- **Связывание:** один раз до выполнения замените имена столбцов позициями и измерьте разницу.
- **Больше SQL:** `HAVING`, `COUNT(DISTINCT col)`, арифметика (`age + 1`), `LIKE`.
- **Вторая таблица:** `minisql a.csv b.csv "… JOIN … ON …"` с хеш-соединением (постройте словарь из
  меньшей таблицы и проверяйте по нему строки большей).
- **DataFusion как библиотека:** напишите `TableProvider`, чтобы DataFusion мог выполнять запросы к
  собственному формату, например к вашему хранилищу «ключ-значение» из Урока 17.14.

## Частые ошибки

> ⚠️ **Частая ошибка: сравнивать дробные числа через `==` в тестах.** `25.333333333333332` — точный
> результат `76.0 / 3.0` в `f64`; немного другой порядок сложений может изменить последнюю цифру. Для `AVG`
> складывайте в том же порядке, что и эталон, или сравнивайте с небольшим допуском в собственных модульных тестах.

> ⚠️ **Частая ошибка: сортировать до агрегации.** `ORDER BY` ссылается на выходные столбцы (`n`,
> `avg_age`), которые существуют только после агрегации и проекции. Сортируйте таблицу результата, а не
> входные строки.

> ⚠️ **Частая ошибка: `f64` и `Ord`.** `f64` не реализует `Ord` (из-за `NaN`, «Not a Number», «не число»,
> которое не равно даже самому себе), поэтому выведенный `Ord` для `Value` с `Float(f64)` не скомпилируется.
> Напишите сравнение сами через `f64::total_cmp` или оберните дробные числа в тип, реализующий `Ord`.

## Вопросы для самопроверки

1. Какие строки возвращает `SELECT name FROM people WHERE age < 30` для `people.csv` из проекта и почему
   среди них нет Hana?

<details>
<summary>Ответ</summary>

Ben (27) и Dana (19). Возраст Hana — `NULL`, поэтому `NULL < 30` — неизвестно, а `WHERE` оставляет только
строки, чьё условие равно `true`.

</details>

2. Что возвращают `COUNT(*)` и `COUNT(age)` для группы Lisbon и почему они различаются?

<details>
<summary>Ответ</summary>

3 и 2. `COUNT(*)` считает строки (Ana, Chen, Hana); `COUNT(age)` считает возрасты, не равные `NULL`, а
возраст Hana — `NULL`.

</details>

3. Почему `ORDER BY score DESC LIMIT 3` возвращает Dana первой?

<details>
<summary>Ответ</summary>

По контракту (то же правило, что в PostgreSQL и DataFusion) `NULL` больше любого значения. При убывающем
порядке самое большое идёт первым, а оценка Dana — `NULL`.

</details>

4. Почему DataFusion — хороший тестовый оракул для этого проекта и что нужно делать для запросов без `ORDER BY`?

<details>
<summary>Ответ</summary>

Это зрелый, хорошо протестированный движок, который следует стандартным правилам SQL, поэтому расхождение
обычно означает ошибку в вашем движке (или намеренное отличие в контракте). Без `ORDER BY` порядок строк не
определён, поэтому перед сравнением отсортируйте оба вывода (или используйте один раздел и сравнивайте только
запросы, сохраняющие порядок).

</details>

5. Почему сортировка выполняется после агрегации?

<details>
<summary>Ответ</summary>

`ORDER BY` называет выходные столбцы, а агрегированные столбцы вроде `n` или `avg_age` появляются только после
агрегации. Сортировка входных строк отсортировала бы не то.

</details>

## Итоги

- `p22-minisql` соединяет фронтенд-парсер, типизированный план и исполнитель в настоящий инструмент.
- Вывод типа по столбцу, `NULL` в пустых полях и численное приведение между `Int` и `Float` позволяют движку
  работать с реальными CSV-данными.
- `NULL` следует трёхзначной логике: сравнения дают неизвестное, `WHERE` оставляет только `true`, агрегаты
  пропускают `NULL`, а у `NULL` есть определённое место в порядке сортировки.
- Сортировка и `LIMIT` выполняются последними, над таблицей результата.
- Дифференциальные тесты против DataFusion и бенчмарк `hyperfine` делают движок надёжным и измеримым.
- Следующие шаги: How Query Engines Work, курсы CMU и вклад в DataFusion, sqlparser-rs и arrow-rs.
