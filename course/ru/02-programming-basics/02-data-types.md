## 1. Что такое тип?

У каждого значения в программе есть **тип**. Тип говорит, какие это данные: целое число, число с дробью, буква, ответ «да/нет». Тип определяет, сколько байтов значение занимает в памяти и какие операции разрешены. Два числа можно сложить, а число с буквой — нельзя.

Rust — **статически типизированный** язык: компилятор должен знать тип каждой переменной до запуска программы. Это звучит строго, но даёт большой подарок. Целый класс ошибок («я использовал текст там, где нужно число») ловится, пока вы пишете код, а не тогда, когда пользователь запускает программу.

Обычно писать типы не приходится. Компилятор **выводит** их из значений:

```rust
fn main() {
    let a = 5;
    let b = 2.5;
    let c = true;
    let d = 'x';
    let e = "text";
    let f: u8 = 5;
    println!("a: {}", std::any::type_name_of_val(&a));
    println!("b: {}", std::any::type_name_of_val(&b));
    println!("c: {}", std::any::type_name_of_val(&c));
    println!("d: {}", std::any::type_name_of_val(&d));
    println!("e: {}", std::any::type_name_of_val(&e));
    println!("f: {}", std::any::type_name_of_val(&f));
}
```

Что происходит:

1. Создаются шесть переменных. У пяти тип не записан; компилятор выводит его сам. Для `f` мы записали **аннотацию типа**: `: u8` после имени.
2. `std::any::type_name_of_val(&a)` спрашивает у стандартной библиотеки название типа переменной `a`. (`&` перед `a` значит «посмотреть на `a`, не забирая её». Подробно это объясняет Этап 03. Пока просто копируйте.)
3. Каждый `println!` печатает букву и название типа.

```text
a: i32
b: f64
c: bool
d: char
e: &str
f: u8
```

Итак: целое число без аннотации становится `i32`, число с точкой — `f64`, а текст в двойных кавычках — `&str` («срез строки», кусок текста; его объясняет Этап 03).

> 💡 **Совет:** чтобы увидеть тип, длинная функция не нужна. RustRover показывает выведенный тип серым цветом рядом с переменной. Ещё один приём — намеренно написать неверную аннотацию и прочитать ошибку.

Аннотацию типа вы пишете, когда компилятор не может угадать или когда вам нужен конкретный тип:

```rust
fn main() {
    let number = "42".parse().unwrap();
    println!("{number}");
}
```

```text
error[E0284]: type annotations needed
 --> src/main.rs:2:9
  |
2 |     let number = "42".parse().unwrap();
  |         ^^^^^^        ----- type must be known at this point
  |
help: consider giving `number` an explicit type
  |
2 |     let number: /* Type */ = "42".parse().unwrap();
  |               ++++++++++++
```

(`parse` превращает текст в число; ему учит Урок 02.7.) Текст `"42"` мог бы стать `i32`, `u8` или `f64`. Компилятор просит вас выбрать: `let number: i32 = "42".parse().unwrap();`.

## 2. Целочисленные типы

**Целое число** (integer) — число без дробной части. В Rust много целочисленных типов. Их названия говорят о двух вещах: первая буква показывает, **знаковый** тип (`i`) или **беззнаковый** (`u`), а число — это количество **битов**.

| Длина | Знаковый | Беззнаковый |
|---|---|---|
| 8 битов | `i8` | `u8` |
| 16 битов | `i16` | `u16` |
| 32 бита | `i32` | `u32` |
| 64 бита | `i64` | `u64` |
| 128 битов | `i128` | `u128` |
| зависит от архитектуры | `isize` | `usize` |

**Бит** — это `0` или `1`. Из *n* битов можно составить 2ⁿ разных комбинаций. 8 битов дают 256 комбинаций, поэтому `u8` хранит числа от `0` до `255`. Знаковый тип тратит часть комбинаций на знак, поэтому `i8` хранит от `-128` до `127`.

Формулы:

- беззнаковый, *n* битов: от `0` до 2ⁿ − 1
- знаковый, *n* битов: от −2ⁿ⁻¹ до 2ⁿ⁻¹ − 1

У каждого типа есть константы с границами: `i32::MAX`, `u8::MIN`.

```rust
fn main() {
    println!("i8:   {} to {}", i8::MIN, i8::MAX);
    println!("u8:   {} to {}", u8::MIN, u8::MAX);
    println!("i16:  {} to {}", i16::MIN, i16::MAX);
    println!("i32:  {} to {}", i32::MIN, i32::MAX);
    println!("u32:  {} to {}", u32::MIN, u32::MAX);
    println!("i64:  {} to {}", i64::MIN, i64::MAX);
    println!("u64:  {} to {}", u64::MIN, u64::MAX);
    println!("usize max: {}", usize::MAX);
}
```

```text
i8:   -128 to 127
u8:   0 to 255
i16:  -32768 to 32767
i32:  -2147483648 to 2147483647
u32:  0 to 4294967295
i64:  -9223372036854775808 to 9223372036854775807
u64:  0 to 18446744073709551615
usize max: 18446744073709551615
```

**`isize` и `usize`** имеют размер адреса памяти на компьютере, где работает программа. На вашем Mac с Apple M4 (64-битный CPU, Central Processing Unit) они занимают 64 бита. Rust использует `usize` для **подсчёта и для индексов**: длина массива — это `usize`.

**Что выбрать?**

- Если нет причины выбирать, берите `i32`. Это тип по умолчанию.
- `usize` — для индексов и размеров коллекций.
- `u8` — для «сырого» байта (0–255) и небольших ограниченных чисел.
- `u64` или `i64` — для больших счётчиков, денег в копейках, размеров файлов, времени в секундах.
- Беззнаковый тип используйте только тогда, когда отрицательные числа не имеют смысла **и** вы уверены, что никогда не вычтете ниже нуля.

Сколько памяти занимает каждый тип? Это скажет функция `size_of` — в байтах (**байт** — это 8 битов):

```rust
use std::mem::size_of;

fn main() {
    println!("u8:    {} byte", size_of::<u8>());
    println!("i32:   {} bytes", size_of::<i32>());
    println!("i64:   {} bytes", size_of::<i64>());
    println!("u128:  {} bytes", size_of::<u128>());
    println!("usize: {} bytes", size_of::<usize>());
    println!("f32:   {} bytes", size_of::<f32>());
    println!("f64:   {} bytes", size_of::<f64>());
    println!("bool:  {} byte", size_of::<bool>());
    println!("char:  {} bytes", size_of::<char>());
    println!("():    {} bytes", size_of::<()>());
}
```

Что происходит:

1. `use std::mem::size_of;` подключает функцию `size_of` к файлу, чтобы писать её короткое имя. (`use` объясняется на Этапе 04, урок 6. Пока считайте, что это сокращение для длинного имени.)
2. `size_of::<u8>()` — часть `::<u8>` сообщает функции, *какой тип* измерять. (Это называется *обобщённым аргументом*; обобщения объясняет Этап 05.)
3. Каждая строка печатает размер в байтах.

```text
u8:    1 byte
i32:   4 bytes
i64:   8 bytes
u128:  16 bytes
usize: 8 bytes
f32:   4 bytes
f64:   8 bytes
bool:  1 byte
char:  4 bytes
():    0 bytes
```

### Числовые литералы

**Литерал** (literal) — значение, записанное прямо в коде. Rust принимает несколько форм:

```rust
fn main() {
    let million = 1_000_000;
    let hex = 0xff;
    let octal = 0o77;
    let binary = 0b1111_0000;
    let byte = b'A';
    let typed = 42u8;
    println!("{million} {hex} {octal} {binary} {byte} {typed}");
}
```

```text
1000000 255 63 240 65 42
```

- `1_000_000` — подчёркивания игнорируются; они делают длинные числа читаемыми.
- `0xff` — шестнадцатеричное (основание 16). `0o77` — восьмеричное (основание 8). `0b1111_0000` — двоичное (основание 2).
- `b'A'` — номер кода ASCII (American Standard Code for Information Interchange) буквы `A` в виде `u8`: `65`.
- `42u8` — суффикс после числа задаёт его тип.

> 📏 **Соглашение:** вставляйте подчёркивания в числа длиннее четырёх цифр (`1_000_000`). Двоичные и шестнадцатеричные числа записывайте, когда работаете с битами и байтами: так думают системные инженеры.

## 3. Переполнение

Что будет, если в `u8` лежит `255`, а вы прибавляете `1`? Результат `256` не помещается в 8 битов. Это называется **переполнением** (overflow). Поведение Rust зависит от того, как вы собираете программу:

```rust
fn add_one(x: u8) -> u8 {
    x + 1
}

fn main() {
    println!("{}", add_one(254));
    println!("{}", add_one(255));
}
```

(*Функция* — это именованный кусок кода со входами и выходом. Функциям учит Урок 02.4; здесь `add_one` принимает `u8` и возвращает `u8`.)

В обычной **отладочной сборке** (её делает `cargo run`) программа паникует:

```text
255

thread 'main' (3887855) panicked at src/main.rs:2:5:
attempt to add with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

В **релизной сборке** (`cargo run --release`) проверки переполнения отключены, чтобы программа работала быстрее, и число тихо **заворачивается по кругу**, как одометр в машине:

```text
255
0
```

Ни один из этих результатов не является «правильным» ответом. Поэтому, если переполнение возможно, ясно скажите, чего вы хотите. У каждого целочисленного типа есть для этого методы:

```rust
fn main() {
    let big: u8 = 250;
    println!("checked_add(10):    {:?}", big.checked_add(10));
    println!("checked_add(5):     {:?}", big.checked_add(5));
    println!("wrapping_add(10):   {}", big.wrapping_add(10));
    println!("saturating_add(10): {}", big.saturating_add(10));
    println!("overflowing_add(10): {:?}", big.overflowing_add(10));
}
```

```text
checked_add(10):    None
checked_add(5):     Some(255)
wrapping_add(10):   4
saturating_add(10): 255
overflowing_add(10): (4, true)
```

| Метод | Что делает при переполнении |
|---|---|
| `checked_add` | Возвращает `None` («ничего»), если происходит переполнение, или `Some(result)`, если результат помещается. `Some`/`None` относятся к типу **Option**, который изучает Этап 04. |
| `wrapping_add` | Заворачивает по кругу: `250 + 10` превращается в `4`. |
| `saturating_add` | Останавливается на границе: `255`. |
| `overflowing_add` | Возвращает пару: завёрнутый результат и `true`, если переполнение произошло. |

Такое же семейство есть для вычитания и умножения (`checked_sub`, `wrapping_mul`, …). Формат `{:?}` печатает значение в «отладочном» виде; его объясняет Урок 02.6.

> 🔒 **Безопасность:** переполнение целых чисел — реальный источник ошибок безопасности. Если программа вычисляет размер буфера как `count * size`, а результат заворачивается в маленькое число, программа может выделить слишком мало памяти и затем писать за её пределы. Когда числа приходят снаружи (из файла, сети, от пользователя), используйте методы `checked_*`. На Этапе 10 вы увидите настоящие примеры.

Компилятор также ловит переполнение, которое видит во время компиляции:

```rust
fn main() {
    let x: u8 = 256;
    println!("{x}");
}
```

```text
error: literal out of range for `u8`
 --> src/main.rs:2:17
  |
2 |     let x: u8 = 256;
  |                 ^^^
  |
  = note: the literal `256` does not fit into the type `u8` whose range is `0..=255`
  = note: `#[deny(overflowing_literals)]` on by default
```

А отрицательное число нельзя положить в беззнаковый тип:

```text
error[E0600]: cannot apply unary operator `-` to type `u32`
 --> src/main.rs:2:24
  |
2 |     let balance: u32 = -5;
  |                        ^^ cannot apply unary operator `-`
  |
  = note: unsigned values cannot be negated
```

## 4. Числа с плавающей точкой

Для чисел с дробной частью в Rust есть два типа **float**: `f32` (32 бита) и `f64` (64 бита). По умолчанию используется `f64`: на современных CPU он почти так же быстр, как `f32`, и гораздо точнее.

```rust
fn main() {
    let a = 0.1 + 0.2;
    println!("0.1 + 0.2 = {a}");
    println!("equal to 0.3? {}", a == 0.3);
    let close = (a - 0.3_f64).abs() < 1e-9;
    println!("close to 0.3? {close}");
    let x: f32 = 1.0 / 3.0;
    let y: f64 = 1.0 / 3.0;
    println!("f32: {x}");
    println!("f64: {y}");
    println!("1.0 / 0.0 = {}", 1.0_f64 / 0.0);
    println!("0.0 / 0.0 = {}", 0.0_f64 / 0.0);
}
```

Что происходит:

1. `0.1 + 0.2` в компьютере не равно в точности `0.3`. Числа с плавающей точкой хранятся в двоичном виде (стандарт **IEEE 754**), а числа вроде `0.1` нельзя записать в двоичной системе точно — так же как 1/3 нельзя записать точно в десятичной.
2. `a == 0.3` сравнивает с помощью `==` («равно») и даёт `false`.
3. Правильный способ сравнивать числа с плавающей точкой — спросить «разница крошечная?»: `(a - 0.3).abs() < 1e-9`. Метод `abs()` убирает знак минус. `1e-9` значит 1 × 10⁻⁹ = 0.000000001. Суффикс в `0.3_f64` задаёт тип.
4. `f32` хранит около 7 верных цифр, `f64` — около 15–16.
5. Деление числа с плавающей точкой на ноль не приводит к краху: `1.0 / 0.0` равно `inf` (бесконечность), а `0.0 / 0.0` равно `NaN` (Not a Number, «не число»).

```text
0.1 + 0.2 = 0.30000000000000004
equal to 0.3? false
close to 0.3? true
f32: 0.33333334
f64: 0.3333333333333333
1.0 / 0.0 = inf
0.0 / 0.0 = NaN
```

> ⚠️ **Частая ошибка:** никогда не сравнивайте числа с плавающей точкой через `==` и никогда не храните деньги в них. Используйте целые числа: храните цены в копейках (`i64`).

## 5. Логический тип

У типа `bool` ровно два значения: `true` и `false`. Это результат любого сравнения и вход любого условия (Урок 02.5).

```rust
fn main() {
    let is_ready = true;
    let is_big: bool = 10 > 5;
    println!("{is_ready} {is_big}");
}
```

```text
true true
```

`bool` занимает 1 байт. Rust строг: число — это не `bool`. `let h: bool = 1;` — ошибка (`E0308 mismatched types`). Если вы имеете в виду «это число не ноль?», напишите сравнение: `n != 0`.

## 6. Символы

Тип `char` хранит **один символ**, записанный в **одинарных кавычках**. В Rust это символ **Unicode**, поэтому им может быть латинская буква, кириллическая буква, эмодзи и многое другое. Он занимает 4 байта.

```rust
fn main() {
    let letter = 'A';
    let heart = '❤';
    let cyrillic = 'Ж';
    let crab = '🦀';
    println!("{letter} {heart} {cyrillic} {crab}");
    println!("'A' as number: {}", letter as u32);
    println!("is 'Ж' alphabetic? {}", cyrillic.is_alphabetic());
    println!("is '7' a digit? {}", '7'.is_ascii_digit());
}
```

```text
A ❤ Ж 🦀
'A' as number: 65
is 'Ж' alphabetic? true
is '7' a digit? true
```

Запомните: `'A'` (одинарные кавычки) — это `char`; `"A"` (двойные кавычки) — это текст типа `&str`. Это разные типы. Текст сложнее, чем кажется, и Rust обращается с ним аккуратно; подробно текст разбирают Этап 03 (урок 6) и Этап 04 (урок 8). Пока вы можете использовать текстовые литералы в `println!` и сравнивать их.

## 7. Преобразование чисел с помощью `as`

Rust никогда не смешивает числовые типы молча. Сложить `i32` с `i64` — ошибка:

```rust
fn main() {
    let small: i32 = 10;
    let big: i64 = 20;
    let sum = small + big;
    println!("{sum}");
}
```

```text
error[E0308]: mismatched types
 --> src/main.rs:4:23
  |
4 |     let sum = small + big;
  |                       ^^^ expected `i32`, found `i64`

error[E0277]: cannot add `i64` to `i32`
 --> src/main.rs:4:21
  |
4 |     let sum = small + big;
  |                     ^ no implementation for `i32 + i64`
  |
  = help: the trait `Add<i64>` is not implemented for `i32`
```

(После этого компилятор печатает длинный список заметок; сейчас они не нужны. Сначала читайте первые строки ошибки.)

Исправление — преобразовать одно из чисел ключевым словом `as`:

```rust
fn main() {
    let small: i32 = 10;
    let big: i64 = 20;
    let sum = small as i64 + big;
    println!("sum = {sum}");

    println!("300 as u8   = {}", 300_i32 as u8);
    println!("-1 as u32   = {}", -1_i32 as u32);
    println!("3.99 as i32 = {}", 3.99_f64 as i32);
    println!("7 as f64    = {}", 7_i32 as f64);
    println!("'a' as u8   = {}", 'a' as u8);
    println!("97 as char  = {}", 97_u8 as char);
}
```

```text
sum = 30
300 as u8   = 44
-1 as u32   = 4294967295
3.99 as i32 = 3
7 as f64    = 7
'a' as u8   = 97
97 as char  = a
```

Что происходит:

1. `small as i64` создаёт новое `i64` с тем же числом. Теперь обе стороны `+` имеют тип `i64`.
2. `300 as u8` **не** вызывает ошибку. Остаются только младшие 8 битов: `300 − 256 = 44`.
3. `-1 as u32` по-другому истолковывает биты числа `-1`: все 32 бита — единицы, что как беззнаковое число равно `4294967295`.
4. `3.99 as i32` отбрасывает дробную часть (не округляет): `3`.
5. `as f64` превращает целое число в число с плавающей точкой. Заметьте, что `{}` печатает `7.0` как `7`.
6. Между `char` и `u8` оператор `as` превращает символ в его код и обратно (таким способом `char` можно получить только из `u8`).

`as` мощен, но он может **молча терять информацию** (случаи 2, 3, 4). Расширяющие преобразования (`i32` в `i64`, `u8` в `u32`) всегда безопасны. Для сужающих лучше использовать проверяемые преобразования, которые вы встретите на Этапе 05 (`try_from`). Урок 02.3 снова покажет оператор `as` вместе с остальными операторами.

## 8. Кортежи и единичный тип

**Кортеж** (tuple) объединяет несколько значений в одно. Значения могут быть разных типов, а размер фиксируется при записи.

```rust
fn main() {
    let person = ("Aziza", 29, 1.68);
    println!("{:?}", person);
    println!("name = {}", person.0);
    println!("age = {}", person.1);

    let (name, age, height) = person;
    println!("{name} is {age} years old and {height} m tall");

    let nothing = ();
    println!("{:?}", nothing);
}
```

Что происходит:

1. `("Aziza", 29, 1.68)` — кортеж из трёх значений: `&str`, `i32` и `f64`. Его тип — `(&str, i32, f64)`.
2. `{:?}` печатает кортеж целиком (обычный `{}` кортежи печатать не умеет, потому что нет одного очевидного способа их показать).
3. `person.0` и `person.1` читают первый и второй элементы. Счёт начинается с **0**.
4. `let (name, age, height) = person;` — это **деструктуризация**: она разбирает кортеж на три отдельные переменные в одной строке.
5. `()` — **единичный тип** (unit): пустой кортеж, значение, не несущее информации. Функция, которая «ничего не возвращает», на самом деле возвращает `()`. Он занимает 0 байтов.

```text
("Aziza", 29, 1.68)
name = Aziza
age = 29
Aziza is 29 years old and 1.68 m tall
()
```

## 9. Массивы

**Массив** хранит несколько значений **одного типа**, а его длина фиксирована. Тип записывается как `[Type; length]`.

```rust
fn main() {
    let days = [31, 28, 31, 30];
    println!("{:?}", days);
    println!("first = {}, last = {}", days[0], days[3]);
    println!("count = {}", days.len());

    let zeros = [0; 5];
    println!("{:?}", zeros);

    let names: [&str; 3] = ["Ann", "Bob", "Cy"];
    println!("{:?}", names);

    let mut scores = [10, 20, 30];
    scores[1] = 99;
    println!("{:?}", scores);
}
```

Что происходит:

1. `[31, 28, 31, 30]` — массив из четырёх чисел `i32`: его тип `[i32; 4]`.
2. `days[0]` читает элемент с **индексом** 0 (первый). `days[3]` — последний. Сам индекс имеет тип `usize`.
3. `days.len()` — число элементов: `4`.
4. `[0; 5]` — сокращение: значение `0`, повторённое 5 раз.
5. `let names: [&str; 3]` показывает аннотацию: три элемента типа `&str`.
6. `scores[1] = 99;` меняет один элемент. Это разрешено только потому, что `scores` объявлен с `mut`.

```text
[31, 28, 31, 30]
first = 31, last = 30
count = 4
[0, 0, 0, 0, 0]
["Ann", "Bob", "Cy"]
[10, 99, 30]
```

Массив лежит в одном непрерывном блоке памяти, элемент за элементом:

```text
index:   0     1     2     3
       +-----+-----+-----+-----+
days   |  31 |  28 |  31 |  30 |     4 items x 4 bytes = 16 bytes
       +-----+-----+-----+-----+
```

### Выход индекса за границы

А если запросить элемент, которого нет? Rust проверяет каждый индекс и паникует, вместо того чтобы читать случайную память. Во многих более старых языках такая же ошибка молча читает или пишет память, которая не принадлежит массиву, — известный источник дыр в безопасности.

```rust
fn main() {
    let days = [31, 28, 31, 30];
    let index = days.len() + 2;
    println!("trying index {index}");
    let value = days[index];
    println!("value = {value}");
}
```

```text
trying index 6

thread 'main' (3888423) panicked at src/main.rs:5:17:
index out of bounds: the len is 4 but the index is 6
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

Если компилятор уже видит ошибку, он останавливает вас раньше. Если написать `days[7]` прямо, он откажется собирать программу:

```text
error: this operation will panic at runtime
 --> src/main.rs:3:17
  |
3 |     let value = days[7];
  |                 ^^^^^^^ index out of bounds: the length is 4 but the index is 7
  |
  = note: `#[deny(unconditional_panic)]` on by default
```

У массивов фиксированный размер. Когда нужен список, который может расти, вы будете использовать *вектор* (`Vec`), который изучается на Этапе 04, в уроке 7.

## Частые ошибки

**1. Смешивание числовых типов.** `i32 + i64` даёт `E0308` и `E0277`. Преобразуйте через `as` (или сразу выберите один тип).

**2. Ожидание, что `/` для целых чисел даст десятичную дробь.** `7 / 2` равно `3`, потому что оба числа целые. Это объясняет Урок 02.3. Для `3.5` используйте `7.0 / 2.0`.

**3. Слишком маленький тип.** Счётчик `u8`, выросший выше 255, паникует в отладочном режиме и заворачивается в релизном. Выберите тип побольше или используйте `checked_add`.

**4. `==` для чисел с плавающей точкой.** Сравнивайте с малым допуском, как в разделе 4.

**5. Путаница между `'a'` и `"a"`.** Одно — `char`, другое — текст (`&str`). `let c: char = "x";` даёт `E0308 mismatched types: expected char, found &str`.

**6. Неверный индекс.** Индекс, равный длине, уже выходит за границы. У последнего элемента массива из 4 элементов индекс `3`.

> 🧪 **Тестирование:** границы и преобразования легко проверять утверждениями. Запишите, чего вы ожидаете, и пусть компьютер подтвердит:
>
> ```rust
> use std::mem::size_of;
>
> fn main() {
>     assert_eq!(size_of::<u16>(), 2);
>     assert_eq!(size_of::<i128>(), 16);
>     assert_eq!(u16::MAX, 65535);
>     assert_eq!(i16::MIN, -32768);
>     assert_eq!(200_u8.checked_add(100), None);
>     assert_eq!(200_u8.wrapping_add(100), 44);
>     assert_eq!(200_u8.saturating_add(100), 255);
>     println!("all checks passed");
> }
> ```
>
> ```text
> all checks passed
> ```
>
> Всегда проверяйте **границы**: наименьшее значение, наибольшее и один шаг за ними. Ошибки живут на границах.

> ⚡ **Производительность:** меньший тип занимает меньше памяти: массив из миллиона `u8` занимает 1 MB (мегабайт), а миллион `i64` — 8 MB. Но не уменьшайте типы без причины: сначала корректность, а оптимизировать — только после измерений. В оптимизированной сборке (`--release`) целочисленная арифметика превращается в отдельные инструкции процессора; отладочная сборка добавляет только проверку переполнения, которую вы видели в разделе 3.

### Упражнение 5 — Выберите правильный тип (сложно)

Выберите лучший тип для каждого значения, затем докажите утверждениями, что ваш выбор вмещает ожидаемые значения: (a) возраст человека, от 0 до 150; (b) население Земли, около 8 миллиардов; (c) яркость пикселя, от 0 до 255; (d) банковский баланс, который может быть отрицательным. В конце напечатайте `all type choices fit`.

<details>
<summary>Подсказка</summary>

`u32::MAX` — около 4,29 миллиарда, этого мало для 8 миллиардов. Чтобы сравнить `u32` с большим числом, сначала преобразуйте его: `u32::MAX as u64`. `assert!(condition)` паникует, когда условие ложно.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    // age 0..=150 fits in u8 (0..=255)

    assert!((u32::MAX as u64) < 8_000_000_000);

}
```

Почему это работает: (a) `u8`, (b) `u64`, (c) `u8`, (d) `i64` (знаковый и достаточно большой для сумм в копейках). Вывод: `all type choices fit`.

</details>

## Вопросы для самопроверки

1. Какой тип у `let x = 5;` и какой у `let y = 5.0;`?

<details>
<summary>Ответ</summary>

`x` имеет тип `i32`, а `y` — `f64`. Это типы по умолчанию.

</details>

2. Каков диапазон `u8`? А `i8`?

<details>
<summary>Ответ</summary>

`u8`: от 0 до 255. `i8`: от −128 до 127. В обоих 8 битов, то есть 256 значений.

</details>

3. Что происходит при вычислении `255_u8 + 1` во время работы программы в отладочной сборке? В релизной?

<details>
<summary>Ответ</summary>

Отладочная: программа паникует с сообщением `attempt to add with overflow`. Релизная: результат заворачивается и становится `0`.

</details>

4. Какой метод возвращает `None` при переполнении, а какой останавливается на максимуме?

<details>
<summary>Ответ</summary>

`checked_add` возвращает `None` при переполнении. `saturating_add` останавливается на максимальном (или минимальном) значении.

</details>

5. Чем отличается `'a'` от `"a"`?

<details>
<summary>Ответ</summary>

`'a'` — это `char` (один символ Unicode, 4 байта). `"a"` — текст типа `&str`.

</details>

6. Как прочитать второй элемент массива `a` и какой у индекса тип?

<details>
<summary>Ответ</summary>

`a[1]`. Индексы начинаются с 0, а сам индекс имеет тип `usize`.

</details>

7. Что даёт `3.99 as i32` и чем может быть опасен `as`?

<details>
<summary>Ответ</summary>

Даёт `3` (дробная часть отбрасывается). `as` может молча терять информацию: `300 as u8` превращается в `44`, а `-1 as u32` — в `4294967295`.

</details>

8. Почему `0.1 + 0.2 == 0.3` ложно?

<details>
<summary>Ответ</summary>

Числа с плавающей точкой хранятся в двоичном виде, а `0.1` и `0.2` нельзя сохранить точно. Сумма равна `0.30000000000000004`. Вместо этого сравнивайте числа с плавающей точкой с малым допуском.

</details>

## Итоги

- Rust статически типизирован; компилятор выводит большинство типов. Типы по умолчанию: `i32` и `f64`.
- Целочисленные типы: `i8…i128`, `u8…u128`, `isize` и `usize`. Для индексов и размеров используйте `usize`.
- Переполнение вызывает панику в отладочных сборках и заворачивается в релизных. Когда оно возможно, используйте `checked_*`, `wrapping_*` или `saturating_*`.
- Числа с плавающей точкой (`f32`, `f64`) приближённые. Не сравнивайте их через `==`.
- `bool` — это `true`/`false`; `char` — один символ Unicode в одинарных кавычках.
- Кортежи объединяют значения разных типов; массивы — значения одного типа, с фиксированной длиной.
- Индексы массива начинаются с 0 и проверяются; неверный индекс вызывает панику.
- `as` преобразует числа, но может терять информацию; Rust никогда не преобразует числа молча.
