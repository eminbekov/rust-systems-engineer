# Урок 00.7 — Как читать ошибки и где искать помощь

> **Этап 00 — Начало пути** · Урок 7 из 8 · ⏱ около 2,5 часа (2 занятия)

## Что вы узнаете

- Четыре вида неприятностей, с которыми вы встретитесь: ошибки компиляции, предупреждения, паники и логические баги.
- Как читать каждую часть сообщения об ошибке компилятора Rust.
- Спокойный порядок исправления множества ошибок: сверху вниз, по одной.
- Как пользоваться `rustc --explain`, офлайн-документацией и интернетом.
- Как задать хороший вопрос людям или ИИ-помощнику.

## Перед началом

- Вы прошли [Урок 00.6 — Ваша первая программа на Rust](06-your-first-rust-program.md). Вы умеете создавать проект командой `cargo new` и запускать его командой `cargo run`.
- Создайте черновой проект для экспериментов: `cd ~/projects/rust && cargo new code/p00-errors`.

## Новые слова

| Слово | Значение |
|---|---|
| **ошибка компиляции** (compile error) | Ошибка, которую компилятор находит до запуска программы. Исполняемый файл не создаётся. |
| **предупреждение** (warning) | Сообщение о коде, который компилируется, но выглядит подозрительно. Программа всё равно собирается. |
| **паника** (panic) | Сбой во время работы: программа запускается, потом сама останавливается с сообщением об ошибке, потому что произошло что-то невозможное. |
| **логический баг** (logic bug) | Программа работает и не жалуется, но выдаёт неверный результат. |
| **код ошибки** (error code) | Имя вроде `E0425`, которое определяет вид ошибки компиляции. У каждого кода есть написанное объяснение. |
| **фрагмент** (span) | Часть кода, на которую указывает сообщение; показывается значками `^^^^`. |
| **код завершения** (exit code) | Число, которое каждая программа возвращает при завершении. `0` означает успех; всё остальное — неудачу. Оболочка показывает его в `$?`. |
| **трассировка стека** (backtrace) | Список вызовов функций, которые привели к панике, от места сбоя назад к началу. |
| **минимальный воспроизводимый пример** (minimal reproducible example) | Самая маленькая полная программа, которая всё ещё показывает вашу проблему, чтобы другие могли её запустить и увидеть. |
| **документация** (documentation, docs) | Официальное описание языка, библиотеки или инструмента. |
| **API** (Application Programming Interface, программный интерфейс приложения) | Набор функций и типов, которые библиотека предлагает использующим её программам. |
| **ИИ-помощник** (AI, Artificial Intelligence — искусственный интеллект) | Программа вроде Claude, которая отвечает на вопросы на обычном языке. |

## 1. Четыре вида неприятностей

| Вид | Когда | Что вы видите | Пример |
|---|---|---|---|
| **Ошибка компиляции** | `cargo build` / `cargo run` | `error[E....]` и никакой программы | неверно написанное имя |
| **Предупреждение** | в то же время | `warning: ...`; программа всё равно работает | неиспользуемая переменная |
| **Паника** | пока программа работает | `thread 'main' panicked at ...`, код завершения 101 | код вызывает `panic!` |
| **Логический баг** | пока программа работает | ничего: результат просто неверный | `+` вместо `*` |

Каждому нужен свой подход. Этот урок учит всем четырём.

> 💡 **Совет:** ошибки компиляции могут раздражать, но это хорошая новость: компилятор нашёл
> ошибку *за* вас, раньше пользователя, и сказал, где она. В Rust многие баги, которые в других
> языках обнаруживаются только при работе программы, являются ошибками компиляции.

## 2. Устройство ошибки компилятора

Возьмите эту крошечную программу (в `src/main.rs` чернового проекта). Переменная называется `city`, а
в строке печати написано `citi`:

```rust
fn main() {
    let city = "Tashkent";
    println!("Hello from {}!", citi);
}
```

`let city = "Tashkent";` создаёт переменную `city` (её учит Урок 02.1). Теперь `cargo run`:

```text
   Compiling p00-errors v0.1.0 (/Users/student/projects/rust/code/p00-errors)
error[E0425]: cannot find value `citi` in this scope
 --> src/main.rs:3:32
  |
3 |     println!("Hello from {}!", citi);
  |                                ^^^^ not found in this scope
  |
help: a local variable with a similar name exists
  |
3 -     println!("Hello from {}!", citi);
3 +     println!("Hello from {}!", city);
  |

For more information about this error, try `rustc --explain E0425`.
error: could not compile `p00-errors` (bin "p00-errors") due to 1 previous error
```

У каждой части есть значение:

| Часть | Текст | Значение |
|---|---|---|
| Серьёзность | `error` | Это ошибка: программа не будет собрана. (`warning` было бы менее серьёзно.) |
| Код | `[E0425]` | Вид ошибки. Можно запросить её объяснение. |
| Сообщение | `cannot find value `citi` in this scope` | Одно предложение о том, что не так: имя `citi` здесь неизвестно. |
| Место | `--> src/main.rs:3:32` | `файл : строка : столбец`. Строка 3, 32-й символ. RustRover делает это кликабельной ссылкой. |
| Фрагмент | `3 \|     println!(...)` | Строка кода с её номером. |
| Метка | `^^^^ not found in this scope` | Точная часть (*фрагмент*, span) и короткая пометка. |
| Подсказка | `help: a local variable with a similar name exists` | Предложение. В маленьком diff под ней строка с `-` — то, что у вас сейчас, `+` — предлагаемый новый текст. |
| Подвал | `For more information ... rustc --explain E0425` | Как прочитать больше об этой ошибке. |
| Итог | `error: could not compile ... due to 1 previous error` | Количество ошибок. |

> 📏 **Соглашение:** когда говорите об ошибке, указывайте место как `file:line:column`. Все
> понимают эту запись, и большинство редакторов умеют переходить по ней.

Ошибка компилятора, которая начинается со слов `warning` или `error`, — это *сообщение от компилятора*: это
не оценка вас. Компилятор — самый терпеливый учитель, который у вас будет. Читайте его.

## 3. Много ошибок? Начинайте с первой

Иногда вы получаете целый экран ошибок. Не паникуйте. Вот программа с несколькими ошибками:

```rust
fn main() {
    let city = "Tashkent"
    println("Hello from {}!", citi);
    let age: i32 = "twenty";
}
```

Запуск показывает **четыре** ошибки (здесь сокращено; настоящий вывод длиннее из-за блоков help):

```text
error: expected `;`, found `println`
 --> src/main.rs:2:26
  |
2 |     let city = "Tashkent"
  |                          ^ help: add `;` here
...
error[E0425]: cannot find value `citi` in this scope
 --> src/main.rs:3:31
...
error[E0423]: cannot find function `println` in this scope
 --> src/main.rs:3:5
...
error[E0308]: mismatched types
 --> src/main.rs:4:20
  |
4 |     let age: i32 = "twenty";
  |              ---   ^^^^^^^^ expected `i32`, found `&str`
  |              |
  |              expected due to this
...
error: could not compile `p00-errors` (bin "p00-errors") due to 4 previous errors
```

Порядок действий:

1. **Прочитайте первую ошибку.** Не последнюю. Поздние ошибки могут быть *вызваны* ранними.
2. **Исправьте только её** (или очевидную группу в одной строке).
3. **Запустите снова.** Список изменится.
4. Повторяйте, пока ошибок не останется.

Проследим за этим:

| Раунд | Ошибок | Что исправляем |
|---|---|---|
| 1 | 4 | строка 2: добавить пропущенную `;` после `"Tashkent"` |
| 2 | 3 | строка 3: `println` → `println!` |
| 3 | 2 | строка 3: `citi` → `city` |
| 4 | 1 | строка 4: `"twenty"` — это текст, а `age` объявлена как число (`i32`) → написать `20` |
| 5 | 0 | программа работает |

(Можно исправить две ошибки за один раунд; таблица показывает по одному изменению за раунд, чтобы идея была яснее. Я запускал
каждый раунд, чтобы получить настоящие числа: 4, 3, 2, 1 и 0.) Итоговая программа печатает:

```text
Hello from Tashkent!
Age: 20
```

(после того как мы добавили `println!("Age: {}", age);`, чтобы использовать переменную.)

### Подсказка компилятора — это догадка

Посмотрите на это:

```rust
fn main() {
    let nmae = "Ada";
    println!("Hello, {}!", name);
    println!("Bye, {}!", name);
}
```

```text
error[E0425]: cannot find value `name` in this scope
 --> src/main.rs:3:28
...
help: a local variable with a similar name exists
3 -     println!("Hello, {}!", name);
3 +     println!("Hello, {}!", nmae);
...
error[E0425]: cannot find value `name` in this scope
 --> src/main.rs:4:26
...
error: could not compile `p00-errors` (bin "p00-errors") due to 2 previous errors
```

Компилятор предлагает заменить *использования* на `nmae`, потому что это найденное им похожее имя. Но настоящая
ошибка — опечатка в **объявлении** (`nmae` должно быть `name`). Одно исправление там убирает обе ошибки.
**Компилятор знает синтаксис, а вы знаете замысел.** Всегда спрашивайте: «какое исправление — то, что я имел в виду?»

## 4. `rustc --explain`: справочник по каждой ошибке

У каждой ошибки с кодом есть длинное объяснение с примерами. Оно поставляется вместе с тулчейном, так что работает и офлайн:

```text
% rustc --explain E0425
An unresolved name was used.

Erroneous code examples:

...

Please verify that the name wasn't misspelled and ensure that the
identifier being referred to is valid for the given situation.
```

(Сокращено.) Первая строка простыми словами говорит, что означает код. Затем идут примеры неверного кода и
исправления. Те же тексты есть в интернете на
[doc.rust-lang.org/error_codes/E0425.html](https://doc.rust-lang.org/error_codes/E0425.html) и офлайн
через `rustup doc --error-codes`.

Ещё один очень частый код — `E0308`, «несовпадение типов» (mismatched types): найдено значение одного типа там, где нужен другой:

```text
error[E0308]: mismatched types
 --> src/main.rs:2:20
  |
2 |     let age: i32 = "twenty";
  |              ---   ^^^^^^^^ expected `i32`, found `&str`
  |              |
  |              expected due to this
```

Как читать: `---` отмечает, *почему* компилятор ожидал число (рядом с `age` написан `i32`), `^^^^` отмечает то, что он нашёл
вместо этого (`&str` — тип текста в кавычках). Запись `expected X, found Y` одинакова во всех таких ошибках. Типы — тема Урока 02.2.

## 5. Предупреждения: не игнорируйте их

Предупреждение означает: «это компилируется, но выглядит неправильно».

```rust
fn main() {
    let name = "Ada";
    println!("Hello!");
}
```

```text
warning: unused variable: `name`
 --> src/main.rs:2:9
  |
2 |     let name = "Ada";
  |         ^^^^ help: if this is intentional, prefix it with an underscore: `_name`
  |
  = note: `#[warn(unused_variables)]` (part of `#[warn(unused)]`) on by default

warning: `p00-errors` (bin "p00-errors") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.07s
     Running `target/debug/p00-errors`
Hello!
```

Что происходит:

1. Программа собрана и запущена (см. `Finished` и `Hello!`). Предупреждение её не останавливает.
2. Компилятор заметил, что `name` создана, но нигде не используется. Возможно, вы забыли её напечатать.
3. Есть два честных исправления: использовать переменную (`println!("Hello, {}!", name);`) или, если она действительно не нужна, переименовать её в `_name`. Начальное подчёркивание означает «я знаю, что она не используется».

> 📏 **Соглашение:** в профессиональном проекте **ноль предупреждений**. Одно проигнорированное предупреждение скрывает следующее, которое
> важно. Относитесь так же и к сообщениям `cargo clippy`.

## 6. Паники: ошибки, которые происходят во время работы программы

```rust
fn main() {
    println!("Starting.");
    panic!("something went wrong");
}
```

`panic!` — это макрос, который намеренно останавливает программу с сообщением. Настоящие программы паникуют, когда происходит что-то
невозможное (с настоящими причинами вы встретитесь на Этапах 02–04). Программа компилируется без проблем и падает во время работы:

```text
Starting.

thread 'main' (3893372) panicked at src/main.rs:3:5:
something went wrong
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

Что происходит:

1. `Starting.` — программа нормально работала до паники.
2. `thread 'main' ... panicked at src/main.rs:3:5:` — какая часть программы («поток», Урок 05.10; `main` — первый), где (`file:line:column`) и что: сообщение на следующей строке. Число в скобках — внутренний идентификатор, он разный при каждом запуске.
3. `note: run with RUST_BACKTRACE=1 ...` — предложение показать больше подробностей.
4. Программа завершается с **кодом завершения 101**. Оболочка помнит код завершения последней команды в `$?`:

```text
% ./target/debug/p00-errors
Starting.

thread 'main' (3893401) panicked at src/main.rs:3:5:
something went wrong
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
% echo $?
101
```

(Успех — это `0`. `cargo run` тоже завершается с `101`, когда *сборка* не удалась.)

Задайте переменную окружения `RUST_BACKTRACE=1` на один запуск, чтобы увидеть **трассировку стека**:

```text
% RUST_BACKTRACE=1 cargo run
Starting.

thread 'main' (3893401) panicked at src/main.rs:3:5:
something went wrong
stack backtrace:
   0: __rustc::rust_begin_unwind
   1: core::panicking::panic_fmt
   2: p00_errors::main
             at ./src/main.rs:3:5
   3: <fn() as core::ops::function::FnOnce<()>>::call_once
note: Some details are omitted, run with `RUST_BACKTRACE=full` for a verbose backtrace.
```

Как читать: список показывает, кто кого вызвал. Большинство строк принадлежат собственной библиотеке Rust. **Ищите строки с
именем вашего проекта** (`p00_errors::main` и `at ./src/main.rs:3:5`): это место в *вашем* коде. Здесь
это та же строка, которую назвало первое сообщение. В больших программах трассировка показывает *путь*, который
привёл к сбою.

## 7. Логические баги: сообщения нет совсем

Эта программа переводит градусы Цельсия в Фаренгейт. Формула `F = C × 9 / 5 + 32`, и 100 °C должно давать 212 °F:

```rust
fn main() {
    let celsius = 100;
    let fahrenheit = celsius * 9 / 5 - 32;
    println!("{} C is {} F", celsius, fahrenheit);
}
```

```text
100 C is 148 F
```

Она компилируется и работает, но 148 — неверно. Ничто не говорит, где проблема. Ваши инструменты:

1. **Знайте правильный ответ.** Вы знаете, что 100 °C = 212 °F. Без ожидаемого результата баг не увидеть.
2. **Посмотрите на шаги.** Напечатайте промежуточные значения:

```rust
fn main() {
    let celsius = 100;
    let scaled = celsius * 9 / 5;
    println!("scaled = {}", scaled);
    let fahrenheit = scaled - 32;
    println!("{} C is {} F", celsius, fahrenheit);
}
```

```text
scaled = 180
100 C is 148 F
```

3. `scaled` верно (100 × 9 / 5 = 180). Следующая строка неверна: `scaled - 32`. В формуле нужно `+ 32`. После исправления программа печатает `100 C is 212 F`.
4. **Объясните свой код «резиновой уточке»** (игрушке, другу или записке самому себе). Произнесение каждой строки вслух часто показывает
   ошибку.
5. **Уменьшите проблему.** Удалите всё, что не нужно для воспроизведения бага.

Печать промежуточных значений (приём, который называется «отладка печатью», print debugging) — самый простой инструмент. Этап 02
(Урок 02.9) учит следующему — настоящему отладчику, а Этап 09 учит отладке подробно.

> 🧪 **Тестирование:** лучшая защита от логических багов — **тест**: маленькая программа, которая проверяет,
> что 100 °C даёт 212 °F. Свои первые тесты вы напишете в Уроке 02.8.

## 8. Поиск ответов: где искать по порядку

Когда вы застряли, идите от ближайшего и быстрейшего источника к самому дальнему:

1. **Само сообщение об ошибке.** Прочитайте его дважды, медленно. Посмотрите строки `help:` и `note:`.
2. **`rustc --explain E....`** для ошибок с кодом.
3. **Офлайн-документация:** `rustup doc --std` (стандартная библиотека), `rustup doc --book`. В веб-версии документации стандартной библиотеки нажмите `S`, чтобы перейти в поле поиска, и введите имя, например `println`.
4. **Онлайн-документация:** [docs.rs](https://docs.rs/) содержит документацию каждой библиотеки (крейта) с crates.io; [Rust by Example](https://doc.rust-lang.org/rust-by-example/) — короткие примеры для запуска.
5. **Поиск в интернете.** Скопируйте текст сообщения *без* ваших собственных имён и путей и возьмите его в кавычки, например `"cannot find value" "in this scope"`. Предпочитайте результаты с `doc.rust-lang.org`, `users.rust-lang.org` и Stack Overflow и смотрите, насколько старый ответ (Rust меняется; ответ 2016 года может устареть).
6. **Спросите людей.** Официальный форум — [users.rust-lang.org](https://users.rust-lang.org/); страница [rust-lang.org/community](https://www.rust-lang.org/community) перечисляет чаты и другие места.
7. **Спросите ИИ-помощника** по правилам из Урока 00.1: сначала попробуйте сами, просите объяснение или подсказку и проверяйте ответ, запуская код.

> 💡 **Совет — как читать документацию на английском:** Не нужно понимать каждое слово. Прочитайте
> *сигнатуру* (код вверху, показывающий имя и типы), первое предложение описания и раздел
> *Examples*. Ведите в заметках небольшой список часто встречающихся слов (например, *expected*,
> *found*, *borrowed*, *moved*) с переводом. Через месяц он вам не понадобится.

## 9. Как задать хороший вопрос

Хороший вопрос получает быстрый ответ. Плохой вопрос («не работает, помогите») не получает ничего. Включите:

1. **Цель:** что вы пытаетесь сделать.
2. **Код:** **минимальный воспроизводимый пример**: самая маленькая программа, которая всё ещё показывает проблему. Текстом, а не фото или скриншотом.
3. **Точное сообщение об ошибке**, скопированное текстом.
4. **Что вы ожидали и что произошло.**
5. **Что вы уже пробовали.**
6. **Версии и система:** вывод `rustc --version` и «macOS на Apple M4».

Пример хорошего вопроса:

```text
Title: "cannot find value in this scope" although the variable exists

Goal: print a greeting that uses the variable `city`.

Code:
    fn main() {
        let city = "Tashkent";
        println!("Hello from {}!", citi);
    }

Error:
    error[E0425]: cannot find value `citi` in this scope
     --> src/main.rs:3:32

I expected to see "Hello from Tashkent!".
I checked that the variable `city` is declared on line 2.
rustc 1.100.0 (0ef1bc386 2026-11-09), macOS on Apple M4.
```

Пока вы пишете такой вопрос, вы часто сами замечаете опечатку. Это называется эффектом «резиновой уточки», и это
одна из главных причин писать вопрос тщательно.

> 🔒 **Безопасность:** прежде чем вставлять код или логи куда-либо (форум, чат, ИИ-помощник), удалите
> **пароли, ключи API, токены, закрытые ключи и личные данные**. Будьте осторожны и с длинными путями: в них есть ваше
> имя пользователя. Секрет, опубликованный в интернете, нужно считать украденным.

## Частые ошибки

1. **Чтение только последней строки.** `error: could not compile ... due to 4 previous errors` ничего полезного не говорит. Информация *выше*. *Исправление:* начните с первого `error`.
2. **Исправление последней ошибки первой.** Часто она исчезает после исправления первой. *Исправление:* сверху вниз.
3. **Много изменений сразу.** Вы больше не знаете, какое из них помогло. *Исправление:* одно изменение — один запуск.
4. **Слепое применение каждой подсказки.** `help:` — догадка (см. `nmae`). *Исправление:* спросите себя, что вы имели в виду.
5. **Игнорирование предупреждений.** Они накапливаются и скрывают настоящие проблемы. *Исправление:* ноль предупреждений.
6. **Случайные изменения** («может, если добавить здесь `&`...»). *Исправление:* прочитайте сообщение, сформулируйте гипотезу, проверьте её.
7. **Вопросы «не работает»** без кода, ошибки и версий. *Исправление:* используйте шаблон из раздела 9.
8. **Отправка скриншотов текста.** Из картинки нельзя скопировать текст и нельзя найти его поиском. *Исправление:* вставляйте текст в блок кода.

## Попробуйте сами

1. В вашем черновом проекте `~/projects/rust/code/p00-errors` поместите в `src/main.rs`:

```rust
fn main() {
    let city = "Tashkent"
    println("Hello from {}!", citi);
    let age: i32 = "twenty";
}
```

2. Выполните `cargo run`. Посчитайте ошибки. Запишите число: должно получиться 4.
3. Исправьте **только первую** ошибку. Запустите снова. Изменилось ли число?
4. Продолжайте, по одному исправлению за запуск, пока программа не заработает. Добавьте в конец `println!("Age: {}", age);`, чтобы `age` использовалась.
5. Выполните `rustc --explain E0308` и прочитайте первые строки. Напишите одно предложение своими словами.
6. Добавьте в конец `main` строку `panic!("test");`, запустите и найдите в выводе строку и столбец. Затем выполните `echo $?`.
7. Удалите `panic!`.

## Упражнения

### Упражнение 1 — Прочитайте сообщение (легко)

Посмотрите на эту ошибку и ответьте: (a) код ошибки, (b) файл, строка и столбец, (c) что не так, одним
предложением, (d) исправление, которое предлагает компилятор.

```text
error[E0425]: cannot find value `citi` in this scope
 --> src/main.rs:3:32
  |
3 |     println!("Hello from {}!", citi);
  |                                ^^^^ not found in this scope
  |
help: a local variable with a similar name exists
  |
3 -     println!("Hello from {}!", citi);
3 +     println!("Hello from {}!", city);
  |
```

<details>
<summary>Подсказка</summary>

Код стоит в квадратных скобках после `error`. Место — после `-->`. Предложение — в блоке `help:`.

</details>

<details>
<summary>Ответ</summary>

(a) `E0425`. (b) `src/main.rs`, строка 3, столбец 32. (c) Имени `citi` в этом месте не существует; вероятно, опечатка. (d) Заменить `citi` на `city`.

Почему это работает: вся информация находится в стандартных местах сообщения; нужно лишь знать, куда смотреть.

</details>

### Упражнение 2 — Исправьте программу шаг за шагом (средне)

Исправьте эту программу, по одной ошибке за раз. Запишите число ошибок в каждом раунде и сделанное исправление.

```rust
fn main() {
    let word = "Rust"
    println("I like {}", word);
}
```

<details>
<summary>Подсказка</summary>

Первое сообщение — о пропущенной `;`. После неё посмотрите на имя `println`.

</details>

<details>
<summary>Ответ</summary>

Раунд 1 (2 ошибки): добавить `;` после `"Rust"`. Раунд 2 (1 ошибка): `println` → `println!`. Раунд 3: ошибок нет.

```rust
fn main() {
    let word = "Rust";
    println!("I like {}", word);
}
```

Вывод:

```text
I like Rust
```

Почему это работает: каждая ошибка независима и имеет понятное сообщение. Поскольку вы запускаете после каждого исправления, вы всегда знаете, какое изменение что сделало.

</details>

### Упражнение 3 — Найдите логический баг (средне)

Эта программа должна печатать площадь прямоугольника шириной 6 и высотой 4 (24). Она печатает 10. Найдите баг без
компилятора, а затем исправьте его.

```rust
fn main() {
    let width = 6;
    let height = 4;
    println!("Area: {}", width + height);
}
```

<details>
<summary>Подсказка</summary>

Программа компилируется, значит, проблема в логике. Проверьте формулу площади (в Уроке 00.2 есть именно эта программа).

</details>

<details>
<summary>Ответ</summary>

`width + height` равно 10: это сумма, а не площадь. Площадь — произведение:

```rust
fn main() {
    let width = 6;
    let height = 4;
    println!("Area: {}", width * height);
}
```

Вывод:

```text
Area: 24
```

Почему это работает: компьютер сделал то, что сказал код (сложил), а не то, что имелось в виду (умножил). Знание ожидаемого результата (24) сделало баг видимым.

</details>

### Упражнение 4 — Предскажите код завершения (средне)

```rust
fn main() {
    println!("one");
    panic!("stop");
    println!("two");
}
```

Что напечатает программа? Напечатает ли она «two»? Каков код завершения? (Компилятор выдаёт предупреждение
об этой программе; как вы думаете, о чём оно?)

<details>
<summary>Подсказка</summary>

Паника сразу завершает программу. Подумайте о строке после неё.

</details>

<details>
<summary>Ответ</summary>

Она печатает `one`, затем сообщение о панике (`thread 'main' ... panicked at src/main.rs:3:5:` и `stop`). `two` она не печатает никогда. Код завершения — `101`. Компилятор предупреждает `unreachable statement`: код после `panic!` никогда не выполнится.

Почему это работает: `panic!` останавливает программу; ничто после него не выполняется. Оболочка хранит код завершения в `$?`, и Rust использует 101 для паники.

</details>

### Упражнение 5 — Напишите вопрос (сложно)

Вы запустили программу с пропущенной точкой с запятой:

```rust
fn main() {
    println!("first")
    println!("second");
}
```

и она вывела `error: expected `;`, found `println``. Напишите хороший вопрос для форума об этом.
(Включите всё из раздела 9.)

<details>
<summary>Подсказка</summary>

Цель, код, точная ошибка, ожидание, что пробовали, версия.

</details>

<details>
<summary>Ответ</summary>

```text
Title: "expected `;`, found `println`" in a two-line program

Goal: print two lines, "first" and "second".

Code:
    fn main() {
        println!("first")
        println!("second");
    }

Error:
    error: expected `;`, found `println`
     --> src/main.rs:2:22

Expected: two lines of output.
I tried: reading the error; I think line 2 needs a `;`, but I do not understand
why the error mentions `println` (which is on line 3).
rustc 1.100.0, macOS on Apple M4.
```

Почему это работает: кто-то может скопировать код, воспроизвести проблему за минуту и увидеть, о чём именно вы спрашиваете. (Ответ на вопрос: компилятор читает оператор, пока не найдёт `;`; он доходит до `println` в строке 3, не найдя её, поэтому указывает на конец строки 2.)

</details>

## Вопросы для самопроверки

1. К какому виду проблем относится «программа работает и печатает неверное число»?

<details>
<summary>Ответ</summary>

К логическому багу. Сообщения нет; нужно знать ожидаемый результат и смотреть на шаги.

</details>

2. Что означают числа в `--> src/main.rs:3:32`?

<details>
<summary>Ответ</summary>

Строка 3, столбец (символ) 32 файла `src/main.rs`.

</details>

3. Почему сначала исправляют первую ошибку?

<details>
<summary>Ответ</summary>

Поздние ошибки часто вызваны ранними и исчезают, когда исправлена первая.

</details>

4. Как прочитать длинное объяснение ошибки `E0308` офлайн?

<details>
<summary>Ответ</summary>

`rustc --explain E0308` в терминале или `rustup doc --error-codes` в браузере.

</details>

5. Какой код завершения даёт паника и как его увидеть?

<details>
<summary>Ответ</summary>

101. Выполните `echo $?` сразу после программы.

</details>

6. Назовите четыре вещи, которые содержит хороший вопрос на форуме или ИИ-помощнику.

<details>
<summary>Ответ</summary>

Любые четыре из: цель, минимальный воспроизводимый пример, точный текст ошибки, что вы ожидали, что пробовали, `rustc --version` и система.

</details>

7. Что нельзя вставлять в публичный вопрос?

<details>
<summary>Ответ</summary>

Пароли, ключи API, токены, закрытые ключи и другие личные данные (также проверьте длинные пути, содержащие ваше имя пользователя).

</details>

## Итоги

- Четыре вида неприятностей: ошибки компиляции, предупреждения, паники (во время работы) и логические баги (без сообщения).
- У ошибки компилятора есть серьёзность, код, сообщение, место `file:line:column`, размеченный фрагмент и часто `help:`.
- Много ошибок: прочитайте первую, исправьте одно, запустите снова.
- `help:` компилятора — хорошая догадка, а не приказ. Что вы имели в виду, знаете вы.
- `rustc --explain E....` и `rustup doc` работают офлайн.
- Предупреждения нужно исправлять: держите проект на нуле предупреждений.
- Паника завершает программу с кодом 101; трассировка стека (`RUST_BACKTRACE=1`) показывает путь к ней; ищите строки с именем вашего проекта.
- Для логических багов: знайте ожидаемый результат, печатайте промежуточные значения, уменьшайте проблему.
- Спрашивайте хорошо: цель, минимальный код, точный текст ошибки, ожидание, попытки, версии. Никогда не вставляйте секреты.
