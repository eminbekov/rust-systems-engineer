## Новые слова

| Слово | Значение |
|---|---|
| **stdout** (standard output, стандартный вывод) | Обычный поток вывода программы. `println!` пишет сюда. |
| **stderr** (standard error, стандартный поток ошибок) | Второй поток вывода для ошибок и диагностики. `eprintln!` пишет сюда. |
| **поток** (stream) | Поток байтов, в который программа пишет или из которого читает. |
| **форматная строка** (format string) | Текст в кавычках, идущий первым в `println!`; содержит заполнители `{}`. |
| **заполнитель** (placeholder) | `{ }` в форматной строке; заменяется значением. |
| **спецификатор формата** (format specifier) | Часть после двоеточия в заполнителе, например `:>8.2`. Говорит, как показать значение. |
| **Display** | Способ показать значение «для людей»: его использует `{}`. |
| **Debug** | Способ показать значение «для программистов»: его использует `{:?}`. |
| **ширина** (width) | Минимальное число символов, которое значение занимает при печати. |
| **точность** (precision) | Число цифр после десятичной точки для дробных чисел (`.2`). |
| **управляющая последовательность** (escape sequence) | Обратная косая черта с буквой, означающая особый символ: `\n` (новая строка), `\t` (табуляция). |
| **сырая строка** (raw string) | Текст вида `r"…"`, в котором обратная косая черта не имеет особого смысла. |
| **`String`** | Тип для текста, которым владеет ваша программа и который может расти. Его возвращает `format!`. Подробно его объясняет Этап 04, урок 8. |
| **комментарий** (comment) | Текст для людей, который компилятор игнорирует. |
| **документирующий комментарий** (doc comment) | Комментарий, начинающийся с `///` (или `//!`). Инструменты превращают его в документацию. |
| **трейт** (trait) | Набор возможностей, которые может иметь тип, например «можно показать через `{}`». Трейты изучает Этап 05. |

## 1. Макросы вывода

`println!` вы знаете. Таких макросов четыре:

| Макрос | Куда пишет | Перевод строки в конце? |
|---|---|---|
| `println!` | stdout | да |
| `print!` | stdout | нет |
| `eprintln!` | stderr | да |
| `eprint!` | stderr | нет |

```rust
fn main() {
    println!("Hello");
    print!("one ");
    print!("two ");
    println!("three");
    println!();
    eprintln!("this goes to the error stream");
    eprint!("so does this ");
    eprintln!("one");
    println!("done");
}
```

```text
Hello
one two three

this goes to the error stream
so does this one
done
```

Что происходит:

1. `println!("Hello")` печатает текст и переходит на следующую строку.
2. Три строки с `print!` и `println!` собирают одну строку, `one two three`.
3. `println!()` без аргументов печатает пустую строку.
4. `eprintln!` и `eprint!` пишут в **stderr**, «стандартный поток ошибок». В терминале вы видите оба потока вперемешку, поэтому выглядит одинаково.

Зачем два потока? Программы часто соединяют друг с другом или с файлами. Обычные результаты идут в **stdout**; предупреждения и ошибки — в **stderr**, чтобы не смешиваться с результатами. Разницу можно увидеть, перенаправив один из потоков в терминале:

Сохраните программу выше как `src/bin/06_streams.rs` и выполните:

```bash
cargo run -q --bin 06_streams 2>/dev/null      # hide stderr
cargo run -q --bin 06_streams >/dev/null       # hide stdout
```

```text
Hello
one two three

done
```

```text
this goes to the error stream
so does this one
```

`2>/dev/null` отправляет поток номер 2 (stderr) в «чёрную дыру» — устройство `/dev/null`, а `>/dev/null` делает то же для потока 1 (stdout). Первая команда показывает только результаты; вторая — только ошибки. (`-q` делает тихим сам Cargo.)

> 📏 **Соглашение:** результаты идут в stdout (`println!`). Сообщения об ошибках, предупреждения и сведения о ходе работы идут в stderr (`eprintln!`). Программы командной строки, следующие этому правилу, можно использовать в конвейерах и скриптах.

> ⚠️ **Частая ошибка:** `print!` может показать текст не сразу. Rust отправляет stdout построчно, поэтому текст без перевода строки может ждать в буфере. Если вы печатаете приглашение вроде `Enter a number: ` через `print!`, нужно «сбросить» буфер; как это сделать, показывает Урок 02.7.

## 2. Заполнители: `{}`

Первый аргумент `println!` — это **форматная строка**. Каждый `{}` в ней — **заполнитель**, который заменяется значением:

```rust
fn main() {
    let name = "Aziza";
    let age = 29;
    println!("{} is {} years old", name, age);
    println!("{0} is {1}; {1} is {1}; {0} again", name, age);
    println!("{who} is {years} years old", who = name, years = age);
    println!("{name} is {age} years old");
    println!("braces: {{ and }}");
    println!("2 + 3 = {}", 2 + 3);
    println!("tab:\there, newline:\nnext line");
    println!("quote: \"hi\", backslash: \\");
    println!(r"raw: C:\Users\new\table");
}
```

Что происходит:

1. Пустые `{}` берут аргументы по порядку: первый `{}` получает `name`, второй — `age`.
2. `{0}` и `{1}` выбирают аргументы **по позиции**, поэтому одно значение можно использовать несколько раз.
3. `{who}` берёт **именованный аргумент**, заданный как `who = name`.
4. `{name}` берёт **переменную с таким именем** из окружающего кода. Это самая короткая форма, и ей стоит отдавать предпочтение. Она работает только для простых имён переменных. Для выражений вроде `2 + 3` используйте `{}` и передайте выражение как аргумент.
5. Чтобы напечатать символ фигурной скобки, удвойте его: `{{` и `}}`.
6. Внутри кавычек обратная косая черта начинает **управляющую последовательность**: `\t` — табуляция, `\n` — новая строка, `\"` — кавычка, `\\` — обратная косая черта.
7. **Сырая строка** `r"…"` игнорирует управляющие последовательности, что удобно для путей Windows и регулярных выражений.

```text
Aziza is 29 years old
Aziza is 29; 29 is 29; Aziza again
Aziza is 29 years old
Aziza is 29 years old
braces: { and }
2 + 3 = 5
tab:	here, newline:
next line
quote: "hi", backslash: \
raw: C:\Users\new\table
```

Компилятор проверяет форматную строку при компиляции, поэтому ошибки никогда не доходят до ваших пользователей:

```rust
fn main() {
    println!("{} and {}", 1);
}
```

```text
error: 2 positional arguments in format string, but there is 1 argument
 --> src/main.rs:2:15
  |
2 |     println!("{} and {}", 1);
  |               ^^     ^^   -
```

Лишний аргумент даёт `error: argument never used`, а несуществующее имя — `E0425 cannot find value`.

Текст может занимать несколько строк, а обратная косая черта в конце строки убирает перевод строки и пробелы после него. Символ можно записать по его номеру в Unicode:

```rust
fn main() {
    let text = "line one
line two";
    println!("{text}");
    let joined = "first part, \
                  second part";
    println!("{joined}");
    println!("crab: \u{1F980}");
}
```

```text
line one
line two
first part, second part
crab: 🦀
```

## 3. Display и Debug

`{}` использует формат **Display**: красивый вид для людей. `{:?}` использует формат **Debug**: вид для программистов, который показывает структуру. Не каждый тип можно показать через `{}`, но почти любой можно показать через `{:?}`.

```rust
fn main() {
    let pair = (1, "two");
    let numbers = [1, 2, 3];
    println!("{:?}", pair);
    println!("{:?}", numbers);
    println!("{:?} and {}", "text", "text");
    println!("{:?} and {}", 'x', 'x');
    println!("{:?} and {}", 7.0, 7.0);
    println!("{:#?}", pair);
}
```

```text
(1, "two")
[1, 2, 3]
"text" and text
'x' and x
7.0 and 7
(
    1,
    "two",
)
```

Что происходит:

1. У кортежей и массивов нет формата Display, потому что нет единственного очевидного способа их показать. `{:?}` показывает их в виде, похожем на код.
2. С `{:?}` текст сохраняет кавычки, а символ — одинарные кавычки. Это очень помогает при отладке: вы видите невидимое, например лишний пробел в конце строки (`"abc "`).
3. Дробное число, равное целому, показывается как `7.0` в Debug и как `7` в Display.
4. `{:#?}` — **красивый** формат Debug: каждый элемент на своей строке с отступом. Это инструмент выбора для больших структур.

Что будет, если использовать `{}` для того, у чего нет формата Display?

```text
error[E0277]: `({integer}, {integer})` doesn't implement `std::fmt::Display`
 --> src/main.rs:3:20
  |
3 |     println!("{}", pair);
  |               --   ^^^^ `({integer}, {integer})` cannot be formatted with the default formatter
  |
  = help: the trait `std::fmt::Display` is not implemented for `({integer}, {integer})`
  = note: in format strings you may be able to use `{:?}` (or `{:#?}` for pretty-print) instead
```

Сообщение говорит, что у этого типа нет **трейта** `Display`. Трейт — это набор возможностей; их изучает Этап 05, и тогда вы научите свои типы возможностям `Display` и `Debug`. Заметка компилятора уже показывает исправление: используйте `{:?}`.

## 4. Ширина, выравнивание и заполнение

После двоеточия **спецификатор формата** говорит, как показать значение. Общий вид:

```text
{ : [fill][alignment][sign][#][0][width][.precision][type] }
```

Знать всё это не обязательно. Для большей части работы хватает таких частей:

| Часть | Значение | Пример |
|---|---|---|
| `width` | минимальное число символов | `{:5}` |
| `<` `>` `^` | выровнять влево, вправо, по центру | `{:<5}` `{:>5}` `{:^5}` |
| символ заполнения перед выравниванием | чем заполнять | `{:*^9}` |
| `0` | заполнить число нулями | `{:05}` |
| `.N` | цифр после точки | `{:.2}` |
| `+` | всегда показывать знак | `{:+}` |

```rust
fn main() {
    println!("[{:5}]", 42);
    println!("[{:5}]", "ab");
    println!("[{:<5}]", 42);
    println!("[{:>5}]", "ab");
    println!("[{:^5}]", "ab");
    println!("[{:*^9}]", "mid");
    println!("[{:->8}]", 123);
    println!("[{:05}]", 42);
    let width = 8;
    println!("[{:>width$}]", "dyn");
    println!("[{:>1$}]", "dyn", 6);
}
```

```text
[   42]
[ab   ]
[42   ]
[   ab]
[ ab  ]
[***mid***]
[-----123]
[00042]
[     dyn]
[   dyn]
```

Что происходит:

1. Ширина `5` делает поле шириной 5 символов. По умолчанию **числа выравниваются вправо**, а **текст — влево**.
2. `<`, `>` и `^` задают выравнивание явно. При `^` (по центру) и нечётном числе свободных пробелов лишний пробел достаётся правой стороне.
3. Символ перед выравниванием — это **заполнитель** (fill): `*^9` значит «по центру в 9 символах, заполнить `*`».
4. `05` дополняет число нулями.
5. `{:>width$}` берёт ширину из переменной с именем `width`. `{:>1$}` берёт ширину из аргумента с индексом 1.

Именно выравнивание делает таблицы похожими на таблицы:

```rust
fn main() {
    println!("{:>3} | {:>4} | {:>5}", "n", "n^2", "n^3");
    println!("{:-<3}-+-{:-<4}-+-{:-<5}", "", "", "");
    for n in 1..=5 {
        println!("{:>3} | {:>4} | {:>5}", n, n * n, n * n * n);
    }
}
```

```text
  n |  n^2 |   n^3
----+------+------
  1 |    1 |     1
  2 |    4 |     8
  3 |    9 |    27
  4 |   16 |    64
  5 |   25 |   125
```

## 5. Точность и системы счисления

Для чисел с плавающей точкой `.N` задаёт, сколько цифр показывать после десятичной точки. Он **округляет** выводимое значение; само число не меняется.

```rust
fn main() {
    let pi = 3.14159265;
    println!("{}", pi);
    println!("{:.2}", pi);
    println!("{:.0}", pi);
    println!("[{:8.3}]", pi);
    println!("[{:08.3}]", pi);
    println!("[{:<8.1}]", pi);
    println!("{:+}", 5);
    println!("{:+.1}", 2.0);
    println!("{:e}", 1234.5);
    let digits = 4;
    println!("{:.digits$}", pi);
    println!("{:.1}", 0.25);
    println!("{:.1}", 0.35);
    println!("{:.1}", 2.5);
}
```

```text
3.14159265
3.14
3
[   3.142]
[0003.142]
[3.1     ]
+5
+2.0
1.2345e3
3.1416
0.2
0.3
2.5
```

Что происходит:

1. `{:.2}` показывает два знака после точки; `{:.0}` — ни одного.
2. `{:8.3}` сочетает ширину 8 и точность 3. `{:08.3}` добавляет заполнение нулями.
3. `{:+}` показывает знак плюс для положительных чисел. `{:e}` показывает научную запись: `1.2345e3` — это 1,2345 × 10³.
4. `{:.digits$}` берёт точность из переменной.
5. Последние три строки показывают, что округление следует *хранимому* двоичному значению (Урок 02.2): `0.35` хранится как число чуть меньше 0,35, поэтому показывается `0.3`; а точная середина `0.25` округляется к чётной цифре, `0.2`. Не удивляйтесь этому; это ещё одна причина хранить деньги в целых копейках.

Для целых чисел можно выбрать **систему счисления**:

```rust
fn main() {
    let n = 255;
    println!("decimal:  {}", n);
    println!("binary:   {:b}", n);
    println!("octal:    {:o}", n);
    println!("hex:      {:x}", n);
    println!("HEX:      {:X}", n);
    println!("0x hex:   {:#x}", n);
    println!("0b bin:   {:#b}", n);
    println!("8 bits:   {:08b}", 5u8);
    println!("padded:   {:#010x}", 255);
}
```

```text
decimal:  255
binary:   11111111
octal:    377
hex:      ff
HEX:      FF
0x hex:   0xff
0b bin:   0b11111111
8 bits:   00000101
padded:   0x000000ff
```

Буквы после двоеточия такие: `b` — двоичная, `o` — восьмеричная, `x` — шестнадцатеричная строчными, `X` — шестнадцатеричная заглавными. `#` добавляет префикс `0x` или `0b`. `{:08b}` — формат, который вы видели в Уроке 02.3, — значит «двоичная, минимум 8 символов, заполнить нулями».

## 6. Сборка текста с помощью `format!`

`format!` работает так же, как `println!`, но вместо печати **возвращает** текст в виде `String`. `String` — это текст, которым владеет ваша программа (подробно его объясняет Этап 04, урок 8; пока его можно печатать, сравнивать с литералом и спрашивать у него `.len()`).

```rust
fn main() {
    let label = format!("{:>5}", 42);
    println!("[{label}]");
    assert_eq!(label, "   42");
    assert_eq!(format!("{:.2}", 3.14159), "3.14");
    assert_eq!(format!("{}-{}", 1, 2), "1-2");
    assert_eq!(format!("{:03}", 7), "007");
    assert_eq!(format!("{:?}", (1, "a")), "(1, \"a\")");
    println!("format checks passed");
}
```

```text
[   42]
format checks passed
```

Поскольку результат — значение, а не напечатанный вывод, `format!` — способ **тестировать** код форматирования: сравните результат с ожидаемым текстом. Функцию, которая возвращает `String`, тестировать легче, чем функцию, которая печатает.

> 🧪 **Тестирование:** разделяйте *создание* текста и его *печать*. Напишите `fn format_money(cents: u32) -> String` и проверьте её через `assert_eq!`; затем напечатайте результат в `main`. Упражнение 3 просит сделать именно это.

## 7. Комментарии

**Комментарий** — это заметка для людей. Компилятор его игнорирует.

```rust
//! This file shows the kinds of comments.

/// Adds two numbers.
///
/// # Examples
/// ```
/// assert_eq!(add(2, 3), 5);
/// ```
fn add(a: i32, b: i32) -> i32 {
    a + b // inline comment: the sum
}

fn main() {
    // A normal line comment.
    /* A block comment
       over two lines. */
    let total = add(2, 3); // 5
    println!("{total}");
}
```

```text
5
```

Виды:

| Вид | Как выглядит | Для чего |
|---|---|---|
| Строчный комментарий | `// text` | Обычный комментарий. Идёт до конца строки. |
| Блочный комментарий | `/* text */` | Может занимать много строк. Используется редко; многие команды предпочитают `//` на каждой строке. |
| Документирующий комментарий для следующего элемента | `/// text` | Документирует функцию, тип или константу, которая идёт следом. |
| Документирующий комментарий для охватывающего элемента | `//! text` | Документирует сам файл или модуль; пишется в его начале. |

**Документирующие комментарии** особенные: их читают инструменты. Команда `cargo doc --open` строит сайт документации из ваших комментариев `///`, а примеры кода внутри них запускаются как тесты командой `cargo test`. Документацию подробно разбирает Этап 05, урок 7.

### Как комментировать хорошо

- Комментируйте **почему**, а не **что**. Код уже говорит, что он делает. Комментарий `// add 1 to counter` над `counter += 1;` — шум. Комментарий вроде `// the API counts pages from 1, not from 0` — золото.
- Предпочитайте понятные имена комментариям. Если хочется объяснить переменную, переименуйте её.
- Держите комментарии правдивыми. Комментарий, который противоречит коду, хуже, чем его отсутствие; обновляйте его, когда меняете код.
- Используйте `TODO:` для работы, о незавершённости которой вы знаете. Многие редакторы перечисляют все `TODO`.
- Не оставляйте старый код в комментариях. Его помнит Git ([Урок 01.4](../01-git-and-version-control/04-viewing-history-and-changes.md)).

> 🔒 **Безопасность:** никогда не кладите пароли, ключи API (Application Programming Interface, программный интерфейс приложения) или токены в комментарии или сообщения `println!`. Комментарии остаются в истории Git навсегда, а журналы часто передают другим. Раздел 1 даёт ещё одну причину использовать `eprintln!` для диагностики: она не попадает в обычный вывод.

## Частые ошибки

**1. `{}` для кортежа, массива или вашего собственного типа.** `E0277 … doesn't implement std::fmt::Display`. Используйте `{:?}`.

**2. Неверное число аргументов.** `println!("{} {}", 1)` — ошибка компиляции; компилятор считает за вас.

**3. `{name}` для выражения.** `println!("{a + b}")` не работает. Напишите `println!("{}", a + b)` или сначала `let sum = a + b;`.

**4. Забыли, что у `print!` нет перевода строки.** Приглашение и следующий вывод могут оказаться на одной строке.

**5. Печать дробных чисел для денег.** Используйте целые копейки и печатайте `{}.{:02}`.

**6. Комментарий, повторяющий код.** Говорите «почему», а не «что».

> 📏 **Соглашение:** предпочитайте встроенную форму `{name}`, когда переменная — простое имя, и ставьте спецификатор формата после двоеточия: `{price:>8.2}`.

> ⚡ **Производительность:** печать медленна по сравнению с вычислениями, потому что она общается с терминалом. Цикл, который печатает миллион строк, может работать дольше, чем вся остальная работа. Когда нужна скорость, печатайте меньше или соберите текст и напечатайте его один раз (как измерять, покажет Этап 05, Урок 12).

## Упражнения

### Упражнение 1 — Чек (легко)

Напечатайте этот чек в точности (названия позиций выровнены влево в 10 символах, цены выровнены вправо в 8 символах с 2 знаками после точки, а итог считает программа, а не набирается вручную):

```text
Item         Price
Tea           2.50
Cake          4.75
Water         1.00
------------------
Total         8.25
```

<details>
<summary>Подсказка</summary>

Используйте `{:<10}` для названия и `{:>8.2}` для цены. Разделитель — `{:-<18}`, применённый к пустому тексту `""`. Итог — `2.5 + 4.75 + 1.0`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("{:<10}{:>8}", "Item", "Price");
    println!("{:<10}{:>8.2}", "Tea", 2.5);
    println!("{:<10}{:>8.2}", "Cake", 4.75);
    println!("{:<10}{:>8.2}", "Water", 1.0);
    println!("{:-<18}", "");
    println!("{:<10}{:>8.2}", "Total", 2.5 + 4.75 + 1.0);
}
```

Почему это работает: `{:-<18}` значит «заполнить `-`, выровнять влево, ширина 18»; выравниваемый текст пуст, поэтому получается 18 дефисов. Ширины 10 + 8 в сумме дают 18.

</details>

### Упражнение 2 — Предскажите скобки (легко)

Запишите вывод каждой строки, затем запустите и проверьте.

```rust
fn main() {
    println!("[{:>6}]", 42);
    println!("[{:<6}]", "ab");
    println!("[{:^7}]", "abc");
    println!("[{:06.2}]", 3.14159);
    println!("[{:x}]", 255);
    println!("[{:#b}]", 5);
    println!("[{:?}]", "hi");
    println!("[{:+}]", 7);
}
```

<details>
<summary>Подсказка</summary>

Посчитайте символы между скобками. `06.2` значит: заполнение нулями, ширина 6, два знака после точки.

</details>

<details>
<summary>Ответ</summary>

```text
[    42]
[ab    ]
[  abc  ]
[003.14]
[ff]
[0b101]
["hi"]
[+7]
```

Почему это работает: `42` выровнено вправо в 6; `ab` выровнено влево в 6; `abc` по центру в 7 (по два пробела с каждой стороны); в `3.14` 4 символа, поэтому добавлено два нуля до 6; `255` в шестнадцатеричной записи — `ff`; `5` в двоичной — `101` с префиксом `0b`; Debug показывает кавычки; `+` показывает знак.

</details>

### Упражнение 3 — Деньги без чисел с плавающей точкой (средне)

Напишите `fn format_money(cents: u32) -> String`, которая превращает цену в копейках в текст с двумя знаками после точки: `1999` становится `"19.99"`, `5` — `"0.05"`, `100` — `"1.00"`, `0` — `"0.00"`. Проверьте её через `assert_eq!`, затем напечатайте `format_money(123456)`.

<details>
<summary>Подсказка</summary>

Целая часть — `cents / 100`; остаток `cents % 100` нужно печатать минимум с двумя цифрами и заполнением нулями: `{:02}`. Используйте `format!`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn format_money(cents: u32) -> String {
    format!("{}.{:02}", cents / 100, cents % 100)
}

fn main() {
    assert_eq!(format_money(1999), "19.99");
    assert_eq!(format_money(5), "0.05");
    assert_eq!(format_money(100), "1.00");
    assert_eq!(format_money(0), "0.00");
    println!("{}", format_money(123456));
    println!("format_money: all checks passed");
}
```

```text
1234.56
format_money: all checks passed
```

Почему это работает: `5 / 100` равно `0`, а `5 % 100` равно `5`, что печатается как `05`. Числа с плавающей точкой не используются, поэтому нет сюрпризов с округлением. Текст сравнивается через `assert_eq!`, потому что функция возвращает его, а не печатает.

</details>

### Упражнение 4 — Таблица систем счисления (средне)

Напечатайте таблицу чисел от 0 до 16 с тремя столбцами: десятичное число (ширина 3), двоичная запись с префиксом `0b` (ширина 10) и шестнадцатеричная запись с префиксом `0x` (ширина 6). Все столбцы выровнены вправо. Напечатайте заголовки `n`, `binary`, `hex`.

<details>
<summary>Подсказка</summary>

Ширина учитывает и префикс. Поставьте флаг `#` после выравнивания: `{:>#10b}` значит «выровнять вправо, с префиксом `0b`, двоичная, шириной 10 символов». Шестнадцатеричный вариант — `{:>#6x}`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    println!("{:>3} {:>10} {:>6}", "n", "binary", "hex");
    for n in 0..=16 {
        println!("{:>3} {:>#10b} {:>#6x}", n, n, n);
    }
}
```

Первые и последние строки вывода:

```text
  n     binary    hex
  0        0b0    0x0
  1        0b1    0x1
  2       0b10    0x2
  3       0b11    0x3
 ...
 15     0b1111    0xf
 16    0b10000   0x10
```

Почему это работает: в `{:>#10b}` части идут в порядке выравнивание, `#`, ширина, тип. (Можно также сначала собрать текст через `format!("{:#b}", n)` и выровнять этот текст через `{:>10}`; результат тот же.) В настоящем выводе все 17 строк.

</details>

### Упражнение 5 — Таблица, подстраивающаяся под числа (сложно)

Напечатайте таблицу умножения 5 × 5 (строки 1..=5, столбцы 1..=5). Все числа должны быть выровнены вправо в столбцах, ширина которых **вычисляется** по самому большому числу (25), а не задаётся константой. Подсказка: ширина — это длина текста самого большого числа.

<details>
<summary>Подсказка</summary>

`format!("{}", max).len()` даёт число символов в `max`. Затем используйте `{:>width$}`. Печатайте каждую ячейку через `print!`, а в конце каждой строки вызывайте `println!()`.

</details>

<details>
<summary>Ответ</summary>

```rust
fn main() {
    let max = 5 * 5;
    let width = format!("{}", max).len();
    for row in 1..=5 {
        for col in 1..=5 {
            print!("{:>width$} ", row * col);
        }
        println!();
    }
}
```

```text
 1  2  3  4  5 
 2  4  6  8 10 
 3  6  9 12 15 
 4  8 12 16 20 
 5 10 15 20 25 
```

Почему это работает: `width` равна 2, потому что в `25` два символа. Если изменить таблицу на 10 × 10, ширина сама станет 3, и таблица останется выровненной. Каждая строка заканчивается пробелом, потому что `print!("{:>width$} ", …)` добавляет его после каждой ячейки.

</details>

## Вопросы для самопроверки

1. Какой макрос пишет в stderr и добавляет перевод строки?

<details>
<summary>Ответ</summary>

`eprintln!`.

</details>

2. Чем отличаются `{}` и `{:?}`?

<details>
<summary>Ответ</summary>

`{}` использует Display (читаемый вид для людей); `{:?}` использует Debug (вид для программистов, который показывает кавычки и структуру). Кортежи и массивы можно печатать только через `{:?}`.

</details>

3. Как напечатать символ `{`?

<details>
<summary>Ответ</summary>

Удвоить его: `println!("{{")`.

</details>

4. Что означает `{:>8.2}`?

<details>
<summary>Ответ</summary>

Выровнять вправо в поле шириной 8 символов, с 2 цифрами после десятичной точки.

</details>

5. Что возвращает `format!` и чем это полезно для тестов?

<details>
<summary>Ответ</summary>

`String` с отформатированным текстом (ничего не печатается). Его можно сравнить с ожидаемым текстом в `assert_eq!`.

</details>

6. Чем отличаются `//` и `///`?

<details>
<summary>Ответ</summary>

`//` — обычный комментарий. `///` — документирующий комментарий: инструменты вроде `cargo doc` превращают его в документацию для следующего элемента.

</details>

7. Почему комментарий должен объяснять «почему», а не «что»?

<details>
<summary>Ответ</summary>

Код уже показывает, что он делает; только комментарий может объяснить причины, ограничения и неожиданности, которых в коде не видно. Комментарии «что» устаревают и добавляют шум.

</details>

## Итоги

- `println!` и `print!` пишут в stdout; `eprintln!` и `eprint!` пишут в stderr. Результаты идут в stdout, диагностика — в stderr.
- `{}` — это Display (для людей); `{:?}` — Debug (для программистов); `{:#?}` — красивый Debug.
- Предпочитайте `{name}` для простых переменных. Для настоящих фигурных скобок используйте `{{` и `}}`.
- Спецификаторы: ширина, `<` `>` `^`, символы заполнения, `0`, точность `.N`, `+`, а также `b` `o` `x` `X` `e` с `#` для префиксов.
- `format!` возвращает `String`; разделяйте «создание текста» и «его печать», чтобы можно было тестировать.
- Комментарии: `//` для заметок, `///` и `//!` для документации. Объясняйте «почему», а не «что».
